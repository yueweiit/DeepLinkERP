## 协作计划（2026-10-09，本地试用）

入口：项目管理 → 协作计划，地址 `/#/collaboration-plans`。

- 三个页签：市场资料、模具交付、累计产量。默认宽屏，每页 50 条，单格编辑与 Excel 区域粘贴先进入草稿，批量保存后才写入数据库。
- 品牌独立成列；新建、导入及完成型号编辑时识别明确的 Apple、Samsung 等品牌前缀，只补空白，不覆盖已有品牌。长文本可展开为大输入框。
- 协作档案按款式与兼容型号组归并颜色项目；PC、TPU、成品累计数独立维护，未知与零不同，不推算库存。重新开模新增 PC＋TPU 模具套，不覆盖原套。
- 固定字段组职责由现有管理员配置。普通账号的字段授权由服务端校验，填写人来自真实登录账号，不支持用预览身份绕过权限。
- 保存提交修改字段和原值；不同字段允许合并，同字段冲突需确认，其他无冲突行可保存。数量下调、清空和异常日期需说明，历史记录保留新旧值、账号和时间。
- 到厂建议日期为计划交付日期加 7 天，需负责人确认；计划变更提示复核，不覆盖已确认日期。实际抵达墨西哥不等同于到厂完成。
- Excel 使用预览、修正映射、确认提交三步。歧义行默认不选；不从备注猜产量、不从 `$` 猜币种。标准及当前页模板保留档案、模具套 ID，重复来源行不重复创建。
- 项目立项复用原创建表单、发布和正式颜色校验；工作台、模具编码、附件、日志和快递只作关联入口，不改写历史项目、编码、流程确认时间或 BOM。

- 每套实物编号为 `MS-` 加不可变内部 ID，部件分别加 `-PC`、`-TPU`；原模具编码单独保留，可由多套实物复用。复制必须选择来源套，仅复制档案、原码及编码/来源资料关联，不复制日期、位置、签收、验收、厂家和负责人。

### ERP 编码来源与钉钉双写

模具管理的“ERP / 钉钉编码资料”打开 96% 宽度的只读核对区，默认 50 条，可选 20/50/100。来源资料与实物台账分开：保存来源编码不会创建模具套、库存、颜色项目或交付记录，历史编码、别名及名称中的原始内容保留。按款式编码和四位手机型号编码精确查询现有协作档案；没有唯一对应时不自动关联。

本地已通过只读查询取得 DeepLinkERP 主站 Item 模具分类的 3,770 条记录：1,240 组完整 PC/TPU 编码对、277 组缺少单部件、13 组部件名称不一致，另有 1,013 条非标准编码。数字表示编码关系，不表示实物套数。来源分类中还包含模架、治具等，仍需人工分类；实物台账保持 0 套。原始 JSON 快照在仓库外的本地工作区 `../erp-molds-source-20261009.json`。

新增迁移 `V20261009_1300__mold_code_sources.sql`；迁移前本地备份 `/tmp/plm-mold-sync-backup.lTrZbf/snapshot.dump`（临时目录可能被系统清理）。新增表仅存来源核对资料，审计继续使用原集成记录，不另建实物台账。

- `GET /api/v1/molds/source-codes`：分页、来源、原编码/名称/规格/别名搜索、部件及核对情况。支持缺部件、部件名称冲突、跨来源同码名称冲突和停用过滤。摘要和关联档案批量查询，不逐行加载项目。
- `GET /api/v1/molds/source-codes/summary`：来源和编码对统计。
- `POST /api/v1/molds/source-codes/erp-previews`：仅真实管理员载入来源快照，重复快照不新增；已有来源基线发生变化时返回冲突，不覆盖原值，也不提交正式实物资料。
- `POST /api/v1/integrations/dingtalk/mold-codes`：真实登录认证及工程字段组授权，不加入匿名白名单。事件 ID 幂等；相同事件内容变化或已有同码不同名称/规格拒绝覆盖。ERP 与钉钉原资料分别保留，跨来源不一致在核对区显示。账号由服务端读取，客户端不能指定审计身份。

当前运行的 `dingtalk_all` 已只读核对：`task_mould_code_sync(item_code_raw, item_name_raw, notify_users)` 写入 ERP 和自己的 `public.material_sync` 表，尚无 PLM 写入。两个开模回调分发仅带编码、名称和通知对象，没有审批实例 ID；这不能作为已核验审批的依据。

本地接入组件在 `services/dingtalk-mold-sync/`：

- `plm_mold_dual_write.py`：保留现有 ERP Item 载荷和推送函数；SQLite 持久重试队列分别确认 ERP/PLM 结果，已经成功的目标不因另一端失败而重发。工作线程租约避免同一目标被并发发送；网络超时后的投递仍是至少一次，最终去重依靠稳定事件 ID 和原编码。认证错误、冲突、无有效业务回执均保留待处理记录，不当作成功。
- `prepare_local_patch.py`：只生成私有目录中的离线候选文件，不覆盖来源文件、不连接或重启服务器。校验实际函数和两处分发形态，仅将模具推送接到双写组件，并传递完整回调上下文供白名单取值；不同服务版本需要人工核对。ERP 函数、原数据库同步和其他任务不修改。
- 回调可附带真实 `approvalInstanceId`（或 `processInstanceId`）和 `approvalStatus=approved`；声明通过时必须携带实例 ID。缺失元数据时仅记录 `code_received`，明确标记“未提供审批实例 ID”，不虚构审批。上线前还需核对上游审批校验及调用来源，服务账号认证不替代钉钉审批真实性校验。
- 双写默认关闭：`PLM_MOLD_SYNC_ENABLED=false`。启用需要明确配置 `PLM_MOLD_SYNC_URL`、私有目录中的绝对 `PLM_MOLD_SYNC_OUTBOX` 路径和运行时 `PLM_MOLD_SYNC_TOKEN`。代码不含真实密码、令牌或新账号；生产使用现有已授权账号或经另行批准的接入身份，凭据到期须刷新，队列不会因到期丢失。组件也接受可刷新凭据提供器。
- 除回环地址外，PLM 接口必须使用 HTTPS，保留证书验证，并禁止携带认证头跟随重定向。队列仅存白名单业务字段及简化错误类型，不存回调密码、令牌、完整响应或来路账号作为审计身份。
