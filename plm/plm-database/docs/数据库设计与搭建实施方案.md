# PLM 数据库设计与搭建实施方案

## 1. 任务理解

本次任务是实现手机壳制造业 PLM 系统的数据库设计与基础搭建，交付可评审的数据库方案文档和可执行 PostgreSQL 初始化脚本。当前只建设 PLM 内部数据库能力，不实现 ERP、MES、WMS、CRM、OA、钉钉等外部系统正式集成。

数据库设计必须围绕全系统唯一 7 个核心对象展开：

- Customer
- Product
- Order
- ProductionOrder
- Process
- Inventory
- Workstation

BOM、样品、报价、图纸文件、工程变更、质量资料、后续集成预留等能力只作为上述对象下的扩展表、附件表、日志表、审批表或映射表，不作为新的一级根对象。

## 3. 所属 PLM 业务链路

本次数据库搭建覆盖两条主线：

- 新产品线：客户/市场需求 -> 新产品线立项 -> Product 建档 -> 样品/工艺/BOM/文件/质量资料确认 -> 冻结/发布 -> 追溯。
- 新型号线：已有 Product -> 型号/颜色/客户版本扩展 -> 差异样品/工艺/BOM 确认 -> 文件冻结 -> 子版本发布。

同时支撑五类横向链路：

- 需求线：Customer / 内部机会 -> Order。
- 执行线：Order -> ProductionOrder -> Process -> Workstation。
- 资料线：Product -> BOM / Attachment / Quality / Cost / Inventory。
- 审批线：ApprovalDefinition -> ApprovalInstance -> ApprovalTask。
- 追溯线：OperationLog / DownloadLog / ImportLog / IntegrationMapping / IntegrationLog。

## 4. 涉及前端页面

本次不实现前端页面，但数据库结构为以下页面提供数据基础：

- Product 列表、详情、型号颜色矩阵、版本历史、发布审批。
- Customer、Order、ProductionOrder 列表与详情。
- BOM 资料编辑、版本对比、审批、发布。
- Inventory 物料/模具治具档案、单位换算、供应商物料、补货预留。
- Process 工艺路线编辑、工艺确认、变更历史。
- Attachment 文件中心、对象文件页签、下载日志。
- 质量资料、成本报价、工程变更、审批待办、操作日志、数据导入、集成映射预留。

## 5. 涉及后端模块

后端建议按 Spring Boot 分层实现：

- `customer`：客户主数据。
- `product`：产品主数据、属性、BOM、成本、质量资料。
- `order`：需求、样品、报价 Order。
- `productionorder`：打样、试产、试模任务。
- `process`：工艺路线、工序参数、工程变更记录。
- `inventory`：物料、半成品、成品、包材、模具治具。
- `workstation`：机台、工位、产线。
- `attachment`：文件元数据、下载日志。
- `approval`：审批定义、实例、任务。
- `admin`：用户、角色、权限、字典、编码规则、系统配置。
- `log`：操作日志、导入日志、集成预留日志。

## 6. 涉及数据对象、状态与 API

### 6.1 核心状态机

| 对象 | 状态机 |
| --- | --- |
| Customer | `draft -> active -> inactive` |
| Product | `draft -> developing -> reviewing -> released -> archived` |
| Order | `draft -> confirmed -> in_production -> completed -> closed` |
| ProductionOrder | `draft -> scheduled -> in_progress -> completed -> closed` |
| Process | `draft -> confirmed -> locked -> changed -> archived` |
| Inventory | `draft -> available -> reserved -> consumed -> closed` |
| Workstation | `draft -> available -> in_use -> maintenance -> inactive` |

### 6.2 API 资源前缀建议

- `/api/v1/customers`
- `/api/v1/products`
- `/api/v1/orders`
- `/api/v1/production-orders`
- `/api/v1/processes`
- `/api/v1/inventories`
- `/api/v1/workstations`
- `/api/v1/attachments`
- `/api/v1/approvals`
- `/api/v1/imports`
- `/api/v1/integration-mappings`

发布、冻结、审批、作废、下载等动作后续应使用明确动作接口，例如 `/publish`、`/freeze`、`/approve`、`/void`、`/download`。

## 8. 搭建产物

当前已形成以下 PostgreSQL 脚本：

- `postgres/V1.0__init_schema.sql`：完整建表、主外键、唯一约束、索引、状态约束、字段注释。
- `postgres/V1.1__init_seed_data.sql`：核心字典、角色、权限、编码规则和基础审批定义初始化。
- `postgres/V1.2__erp_item_bom_alignment.sql`：参考 ERPNext `tabItem`、`tabBOM` 及其子表，补充后续映射友好的预留字段。
- `postgres/V1.3__workflow_locking_alignment.sql`：补齐审批、冻结、锁定、导入/集成状态机、报价版本锚点、模具机台关系等结构增强。
- `postgres/V1.3__workflow_locking_seed_data.sql`：补齐 V1.3 对应的字典、权限、超级管理员、系统配置种子数据。

建议后续进入正式 Spring Boot 项目后，将脚本放入：

```text
src/main/resources/db/migration/
├── V1.0__init_schema.sql
├── V1.1__init_seed_data.sql
├── V1.2__erp_item_bom_alignment.sql
├── V1.3__workflow_locking_alignment.sql
└── V1.3__workflow_locking_seed_data.sql
```

也可按部署规范放入：

```text
deploy/postgres/init/

├── 03-erp-item-bom-alignment.sql
```

## 11. V1.3 工作流与锁定增强

### 11.1 增强目的

根据最新权限/审批、文件冻结、质量闭环、模具治具和导入集成文档，补齐此前数据库中尚未显式落库的以下能力：

- 发起人与确认人分离
- 超级管理员强制推进/禁止/紧急解锁
- 冻结与发布显式分离
- 版本资料锁定与审计
- 导入与后续集成状态机对齐
- 模具/治具与机台安装归属追溯
- 报价引用成本版本号锚点

### 11.2 关键新增结构

新增表：

- `plm_inventory_workstation_binding`

关键新增字段示例：

- `plm_approval_instance.initiator_user_id`
- `plm_approval_instance.confirmer_user_id`
- `plm_approval_instance.super_admin_action_type`
- `plm_product.frozen_at`
- `plm_product.lock_status`
- `plm_process.released_at`
- `plm_order_quote.product_cost_version_no`
- `plm_integration_log.next_retry_at`

### 11.3 对后续开发的直接价值

- 后端可以直接做“发起人与确认人不得同人”的结构化校验
- 冻结、发布、超管锁定不再混用一个 `status`
- 工艺、BOM、附件、质量资料具备正式版本门禁支撑能力
- 模具/治具和机台的历史关系可以回写并追溯
- 导入失败、部分成功、人工补偿、自动重试有了明确状态语义
## 12. 风险点

- `plm_attachment.owner_object_id` 是多态关联，数据库不能对 7 个核心对象同时建立强外键，后端必须校验 `owner_object_type + owner_object_id` 的真实存在性。
- 审批流配置使用 JSONB 存储节点定义，数据库只校验基础结构存在，循环、节点合法性、权限匹配需要后端校验。
- BOM 头、BOM 明细、BOM 工序属于 Product 扩展资料，不是一级业务根对象；后续代码命名也应避免把 BOM 作为独立领域根聚合。
- `plm_inventory` 预留 ERP 友好字段，但不承担 ERP 库存交易、财务、采购执行逻辑。
- 成本、报价、利润率属于敏感字段，数据库层不能替代后端权限控制。

## 13. 待确认问题

- 正式版本号规则采用 `A/B/C` 还是 `V1/V2/V3`，目前字典同时预留。
- 币种默认值暂按 `CNY/USD/MXN` 预留，需结合公司真实报价币种确认。
- 部门、岗位、用户数据是否从现有系统导入，目前只初始化角色和权限，不初始化真实用户。
- 供应商是否独立做轻量资料表目前未纳入，本期按 `supplier_code`、`supplier_name` 字段和 Inventory 扩展表预留。
- ERPNext 字段中的 `company`、`warehouse`、`account`、`price_list`、`project` 当前均按编码/名称快照预留，不建立独立根对象。

## 14. 验收建议

- 执行建表脚本无错误。
- 七个核心主表存在且字段符合 `xxx_id`、`status`、`quantity`、`created_at`、`updated_at` 命名规范。
- 不存在 `sku`、`phone_model`、`bom_line`、`sample_request`、`routing`、`tooling`、`quote`、`ecr`、`ecn`、`quality_document`、`integration_job` 等一级根对象表。
- 字典数据包含核心对象状态、类型、BOM 类型、附件类型、审批动作、集成目标系统。
- 能插入一个测试链路：Customer -> Order -> Product -> ProductionOrder -> Process -> Inventory -> BOM -> Attachment -> Approval -> OperationLog。
