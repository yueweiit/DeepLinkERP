## 2. 执行方式

本次通过 Docker 容器内的 `psql` 执行远程初始化。

本地运行口径统一约定为：

- Docker 运行时使用 Docker Desktop
- 本地数据库验证通过 `plm-database/postgres/docker-compose.database.yml`
- 本地默认映射端口使用 `5433`

执行口径：

- 先做只读探测，确认可连通
- 确认远程库中不存在 `plm` schema
- 按 `V1.0 -> V1.1 -> V1.2` 顺序执行
- 后续本地增强按 `V1.3` 增量补齐审批、冻结、锁定、导入/集成状态机
- 执行后验证表、字段、字典、权限、审批定义

## 5. 风险与说明

- 当前数据库已初始化完成，后续重复执行 `V1.0` 和 `V1.1` 不适合作为日常升级方式。
- 以后如有结构变更，建议继续新增 `V1.3`、`V1.4` 这类增量迁移脚本。
- 当前 `V1.3` 仍为增量迁移写法，适合作为后续 Flyway 目录继续演进的基础。
- 当前库名是 `plm_data_management`，但 schema 名仍然是 `plm`，这符合当前脚本设计。
- 本次只完成数据库结构和初始化数据落库，不代表后端服务、对象存储、Redis、审批流程引擎已联调。
