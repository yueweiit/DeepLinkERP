# 产品编码规则说明

## 1. 适用范围

本文档用于说明产品相关编码的组成规则，包括：

- 模具编码
- 成品编码
- 半成品编码
- 工序状态编码
- BOM 零件编码导入规则
- 颜色编码使用规则

## 2. 基础编码信息

以以下产品为例：

| 项目 | 示例 |
| --- | --- |
| 手机型号 | Xiaomi Redmi A7 Pro |
| 手机型号编码 | 1291 |
| 产品名称 | 幻影 Fantasia Case |
| 产品特定编码 | FA |

## 3. 模具编码规则

### 3.1 编码格式

模具编码导入时不重组、不改写，直接保留来源文件中的 `mould_code` 原值：

```text
mould_code = 文件传入的原始模具编码
product_specific_code = mould_code.substring(1, 3)
```

### 3.2 字段说明

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `mould_code` | 来源文件中的原始模具编码，不因系统规则重组 | `MBA10`、`LLT10` |
| `product_specific_code` | 模具编码第 2、3 位的产品本身特征编码 | `BA`、`LT` |
| 第 4、5 位 | 材质、结构件或工艺短码，按原码保留 | `10`、`20`、`21` |
| 其他字符 | 仅作为来源编码的一部分保留，不参与产品特征码提取 | `1291` |

### 3.3 示例

```text
MBA10
LLT10
```

拆分说明：

| 模具编码 | 拆分 | 含义 |
| --- | --- | --- |
| MBA10 | 原值 / BA / 10 | 模具原码保留，产品本身特征编码为 BA |
| LLT10 | 原值 / LT / 10 | 非 M 开头也允许导入，产品本身特征编码为 LT |

### 3.4 规则补充

同一个产品可能只有一种材质，也可能有两种或三种材质。因此，同一个产品和同一个手机型号下，可能对应一个、两个或多个模具编码。

## 4. 成品、半成品及工序编码规则

成品编码、半成品编码和工序状态编码使用同一套编码规则。

### 4.1 编码格式

```text
N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码
```

### 4.2 字段说明

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| N | 成品、半成品、工序状态编码固定开头 | N |
| 产品特定编码 | 产品对应的编码前缀 | FA |
| 工序编码 | 产品完成某一道工序后的状态编码 | 1020、4030 |
| 手机型号编码 | 手机型号在系统中的编码 | 1291 |
| 颜色编码 | SKU 对应颜色编码 | 01 |

### 4.3 成品编码示例

```text
NFA4030129101
```

拆分为：

```text
N / FA / 4030 / 1291 / 01
```

含义：

| 字段 | 值 | 说明 |
| --- | --- | --- |
| 固定开头 | N | 成品、半成品、工序状态编码 |
| 产品特定编码 | FA | 幻影 Fantasia Case |
| 工序编码 | 4030 | 组装完成工序，通常为最后一步 |
| 手机型号编码 | 1291 | Xiaomi Redmi A7 Pro |
| 颜色编码 | 01 | SKU 对应颜色 |

说明：`4030` 一般是最后一道工序，表示产品已经完成组装，可视为成品。

### 4.4 半成品编码示例

```text
NFA1020129101
```

拆分为：

```text
N / FA / 1020 / 1291 / 01
```

含义：

| 字段 | 值 | 说明 |
| --- | --- | --- |
| 固定开头 | N | 成品、半成品、工序状态编码 |
| 产品特定编码 | FA | 幻影 Fantasia Case |
| 工序编码 | 1020 | 某一道中间工序 |
| 手机型号编码 | 1291 | Xiaomi Redmi A7 Pro |
| 颜色编码 | 01 | SKU 对应颜色 |

说明：半成品编码表示产品执行完某一道工序后的状态编码。每个工序下对应的半成品编码，就是该工序完成后的产品状态编码。

## 5. 工序编码说明

工序编码用于表示产品执行到某一道工序后的状态。

规则要点：

- 每一道工序可以对应一个半成品编码。
- 半成品编码不是单独的一套规则，而是使用 `N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码` 生成。
- `4030` 通常表示最后一道工序，即组装完成。
- 当工序编码为最终工序时，该编码即为成品编码。
- 工序编码可以在系统中直接选择。

## 6. 成品编码与 SKU 总编码关系

成品编码可以直接对应 SKU 的总编码和产品成品编码。

规则要点：

- 成品编码可以作为 SKU 对应的总编码使用。
- 当工序编码为最终工序，例如 `4030` 时，生成的 `N` 开头编码即为成品编码。
- 成品编码与具体产品、手机型号、颜色一一对应。

## 7. BOM 管理编码规则

BOM 管理中的零件编码不需要按照上述规则逐个手动生成，应通过批量导入方式维护。

规则要点：

- BOM 零件编码需要支持批量导入。
- 零件编码作为 BOM 组成部分，在系统中与产品、半成品或成品建立对应关系。
- 批量导入时，应保证零件编码与系统中已有基础资料一致。

## 8. 颜色编码规则

颜色编码已经提前导入系统。

规则要点：

- 颜色编码不需要在生成成品或半成品编码时重新建立。
- 成品和半成品编码末尾的颜色编码，应从系统已有颜色编码中选择或匹配。
- 示例中的 `01` 表示某一个已存在的颜色编码。

## 9. 编码示例汇总

| 类型 | 编码 | 拆分 | 说明 |
| --- | --- | --- | --- |
| 模具编码 | MBA10 | 原值 / BA / 10 | 产品本身特征编码 BA |
| 模具编码 | LLT10 | 原值 / LT / 10 | 非 M 开头，产品本身特征编码 LT |
| 半成品编码 | NFA1020129101 | N / FA / 1020 / 1291 / 01 | 完成 1020 工序后的半成品状态 |
| 成品编码 | NFA4030129101 | N / FA / 4030 / 1291 / 01 | 完成 4030 工序后的成品状态 |

## 10. 总结

目前系统中的编码逻辑可以概括为：

```text
mould_code = 来源文件中的模具编码原值
product_specific_code = mould_code.substring(1, 3)

成品 / 半成品 / 工序状态编码 = N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码
```

其中：

- 模具编码关注来源原值；产品映射只取第 2、3 位，不重组模具编码。
- 成品和半成品编码关注产品、工序状态、手机型号和颜色。
- 最终工序编码通常为 `4030`，对应成品状态。
- 颜色编码已在系统中维护。
- BOM 零件编码通过批量导入维护。
