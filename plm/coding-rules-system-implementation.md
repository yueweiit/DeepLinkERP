# 编码规则系统落地使用说明

## 1. 文档目的

本文档用于说明产品编码规则如何在系统中实际使用，包括基础资料维护、编码生成逻辑、业务模块调用方式、校验规则、BOM 导入方式以及后续维护要求。

本文档适用于系统开发、实施、产品资料维护、BOM 管理、生产管理、仓库管理等相关人员。

## 2. 编码规则总览

当前编码主要分为两类：

| 编码类型 | 编码格式 | 使用对象 |
| --- | --- | --- |
| 模具编码 | 来源模具码原值，产品特征码取第 2、3 位 | 模具 |
| 成品 / 半成品 / 工序状态编码 | N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码 | 半成品、成品、SKU |

示例：

| 类型 | 示例编码 | 拆分 |
| --- | --- | --- |
| 模具编码 | MBA10 | 原值 / BA / 10 |
| 模具编码 | LLT10 | 原值 / LT / 10 |
| 半成品编码 | NFA1020129101 | N / FA / 1020 / 1291 / 01 |
| 成品编码 | NFA4030129101 | N / FA / 4030 / 1291 / 01 |

## 3. 系统基础资料要求

编码规则要在系统中正常使用，必须先维护以下基础资料。

### 3.1 产品资料

产品资料中需要维护产品名称和产品特定编码。

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 产品名称 | 幻影 Fantasia Case | 产品业务名称 |
| 产品特定编码 | FA | 用于生成模具、半成品、成品编码 |

要求：

- 产品特定编码必须唯一。
- 产品特定编码创建后原则上不允许随意修改。
- 所有后续编码都依赖产品特定编码。

### 3.2 手机型号资料

手机型号资料中需要维护手机型号和手机型号编码。

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 手机型号 | Xiaomi Redmi A7 Pro | 手机型号名称 |
| 手机型号编码 | 1291 | 用于生成模具、半成品、成品编码 |

要求：

- 手机型号编码必须唯一。
- 同一个手机型号只能对应一个手机型号编码。
- 所有产品在引用手机型号时，应从系统已有手机型号中选择。

### 3.3 材质资料

材质资料中需要维护材质编码。

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 材质名称 | TPU | 材质名称 |
| 材质编码 | 10 | 用于生成模具编码 |
| 材质名称 | PC | 材质名称 |
| 材质编码 | 20 | 用于生成模具编码 |

要求：

- 一个产品可以对应一个或多个材质。
- 每个材质编码应在系统中统一维护。
- 模具编码生成时，需要根据产品所使用的材质自动生成对应数量的模具编码。

### 3.4 工序资料

工序资料中需要维护工序编码。

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 工序名称 | 某中间工序 | 工序名称 |
| 工序编码 | 1020 | 完成该工序后的半成品状态 |
| 工序名称 | 组装完成 | 最终工序 |
| 工序编码 | 4030 | 完成后为成品 |

要求：

- 工序编码由系统基础资料维护。
- 用户在生成半成品或成品编码时，应从系统已有工序中选择。
- 每个工序编码代表“完成该工序后的产品状态”。
- `4030` 通常作为最终工序编码，表示成品状态。

### 3.5 颜色资料

颜色编码已经提前导入系统。

要求：

- 生成成品或半成品编码时，颜色编码从系统已有颜色资料中选择。
- 不在编码生成页面临时新建颜色编码。
- 颜色编码用于区分不同 SKU。

## 4. 编码生成方式

系统中建议采用“基础资料选择 + 自动生成编码”的方式。

用户不应手动拼接工艺业务编码。模具编码以来源文件原值为准，工艺/半成品/成品编码由系统生成。

### 4.1 模具编码接入

模具编码不在系统中重组，直接保留来源文件中的 `mould_code` 原值：

```text
mould_code = 来源文件中的模具编码原值
product_specific_code = mould_code.substring(1, 3)
```

示例：

```text
MBA10 -> BA
LLT10 -> LT
```

使用建议：

- 不再要求模具编码必须以 `M` 开头。
- 模具编码原值用于模具主数据和匹配；第 2、3 位仅用于产品映射。
- 长度不足时标记为解析异常，长度足够时提取产品本身特征编码。

### 4.2 半成品编码生成

生成条件：

- 已选择产品
- 已选择工序
- 已选择手机型号
- 已选择颜色

生成公式：

```text
半成品编码 = N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码
```

示例：

```text
N + FA + 1020 + 1291 + 01 = NFA1020129101
```

使用建议：

- 在工序管理、半成品管理或 BOM 管理中生成。
- 每个工序生成的编码表示完成该工序后的产品状态。
- 系统应允许同一产品、同一手机型号、同一颜色下，根据不同工序生成多个半成品编码。

### 4.3 成品编码生成

生成条件：

- 已选择产品
- 已选择最终工序
- 已选择手机型号
- 已选择颜色

生成公式：

```text
成品编码 = N + 产品特定编码 + 最终工序编码 + 手机型号编码 + 颜色编码
```

示例：

```text
N + FA + 4030 + 1291 + 01 = NFA4030129101
```

使用建议：

- `4030` 通常表示最终组装完成工序。
- 当工序为最终工序时，生成的编码即为成品编码。
- 成品编码可以直接作为 SKU 总编码使用。

## 5. 系统模块使用方式

### 5.1 产品资料模块

用途：

- 维护产品名称。
- 维护产品特定编码。
- 定义产品适用的材质、工序路线等基础关系。

系统要求：

- 产品特定编码唯一。
- 产品被其他模块引用后，应限制随意修改产品特定编码。

### 5.2 手机型号模块

用途：

- 维护手机型号名称。
- 维护手机型号编码。

系统要求：

- 手机型号编码唯一。
- 供模具编码、半成品编码、成品编码引用。

### 5.3 材质模块

用途：

- 维护 TPU、PC 等材质及对应编码。
- 供模具编码生成时选择。

系统要求：

- 材质编码唯一。
- 支持产品与多个材质建立关系。

### 5.4 工序模块

用途：

- 维护工序名称和工序编码。
- 定义哪些工序是中间工序，哪些是最终工序。

系统要求：

- 工序编码可直接选择。
- 系统应能识别最终工序，例如 `4030`。
- 最终工序生成的编码应标记为成品编码。

### 5.5 颜色模块

用途：

- 维护颜色名称和颜色编码。
- 供 SKU、成品、半成品编码引用。

系统要求：

- 颜色编码已经导入系统。
- 编码生成时只能选择已有颜色编码。

### 5.6 模具管理模块

用途：

- 根据产品、材质、手机型号生成模具编码。
- 管理模具资料。

系统要求：

- 支持单个生成和批量生成。
- 同一产品、手机型号、材质组合下，模具编码不可重复。

### 5.7 半成品管理模块

用途：

- 管理不同工序完成后的半成品状态。
- 根据产品、工序、手机型号、颜色生成半成品编码。

系统要求：

- 半成品编码跟工序绑定。
- 每个工序完成后对应一个产品状态编码。
- 半成品编码可用于 BOM、生产流转和库存管理。

### 5.8 成品 / SKU 管理模块

用途：

- 生成和维护最终成品编码。
- 建立 SKU 与成品编码的对应关系。

系统要求：

- 成品编码可以直接作为 SKU 总编码。
- SKU 应关联产品、手机型号、颜色和最终工序。
- 同一产品、手机型号、颜色下，最终成品编码不可重复。

### 5.9 BOM 管理模块

用途：

- 维护产品、半成品、成品所需零件。
- 将批量导入的零件编码与产品结构建立关系。

系统要求：

- BOM 零件编码通过批量导入维护。
- BOM 中引用的零件编码必须已存在或通过导入创建。
- BOM 可以关联成品编码，也可以根据生产需要关联半成品编码。
- 系统应支持通过成品编码追溯对应 BOM 结构。

### 5.10 生产管理模块

用途：

- 根据成品编码或半成品编码创建生产工单。
- 根据工序流转识别当前产品状态。

系统要求：

- 工单应引用成品编码或半成品编码。
- 系统应能根据编码识别产品、手机型号、颜色和工序状态。
- 工序完成后，可流转到下一道工序对应的半成品或成品状态。

### 5.11 库存管理模块

用途：

- 管理模具、半成品、成品库存。

系统要求：

- `M` 开头编码识别为模具。
- `N` 开头且非最终工序的编码识别为半成品。
- `N` 开头且最终工序为 `4030` 的编码识别为成品。
- 库存出入库、盘点、扫码都应使用对应编码。

## 6. 推荐业务流程

### 6.1 新产品建档流程

1. 维护产品资料，录入产品名称和产品特定编码。
2. 选择或维护适用手机型号。
3. 选择产品适用材质。
4. 选择产品适用颜色。
5. 配置产品工序路线。
6. 系统根据规则生成模具编码。
7. 系统根据工序生成半成品编码。
8. 系统根据最终工序生成成品编码。
9. 成品编码同步为 SKU 总编码。
10. 导入 BOM 零件编码并建立 BOM 结构。

### 6.2 模具编码使用流程

1. 在模具管理模块选择产品。
2. 选择手机型号。
3. 选择一个或多个材质。
4. 系统自动生成模具编码。
5. 系统校验重复。
6. 保存模具资料。

### 6.3 成品 / SKU 编码使用流程

1. 在 SKU 或成品管理模块选择产品。
2. 选择手机型号。
3. 选择颜色。
4. 选择最终工序，例如 `4030`。
5. 系统自动生成成品编码。
6. 成品编码作为 SKU 总编码保存。

### 6.4 半成品编码使用流程

1. 在半成品或工序管理模块选择产品。
2. 选择手机型号。
3. 选择颜色。
4. 选择当前已完成工序。
5. 系统自动生成半成品编码。
6. 半成品编码用于生产流转、BOM 关联和库存管理。

### 6.5 BOM 导入流程

1. 整理 BOM 零件编码导入模板。
2. 批量导入零件编码。
3. 系统校验零件编码是否重复或缺失。
4. 将零件编码关联到对应成品或半成品。
5. 保存 BOM 版本。
6. 后续生产工单根据成品编码带出 BOM。

## 7. 系统校验规则

为保证编码可用，系统需要增加以下校验：

| 校验项 | 校验规则 |
| --- | --- |
| 产品特定编码 | 不允许为空，不允许重复 |
| 手机型号编码 | 不允许为空，不允许重复 |
| 材质编码 | 不允许为空，不允许重复 |
| 工序编码 | 不允许为空，应从系统工序资料中选择 |
| 颜色编码 | 不允许为空，应从系统已有颜色资料中选择 |
| 模具编码 | 同一产品 + 手机型号 + 材质下不可重复 |
| 半成品编码 | 同一产品 + 工序 + 手机型号 + 颜色下不可重复 |
| 成品编码 | 同一产品 + 最终工序 + 手机型号 + 颜色下不可重复 |
| SKU 总编码 | 若使用成品编码作为总编码，则不可重复 |
| BOM 零件编码 | 批量导入时校验重复、空值和格式 |

## 8. 权限与维护建议

建议将编码相关维护权限分开管理：

| 角色 | 权限建议 |
| --- | --- |
| 系统管理员 | 维护编码规则、基础字典、最终工序标记 |
| 产品资料人员 | 维护产品资料、手机型号、材质、颜色 |
| 工艺人员 | 维护工序编码和工序路线 |
| BOM 人员 | 批量导入零件编码，维护 BOM 结构 |
| 生产人员 | 使用成品、半成品编码创建和流转工单 |
| 仓库人员 | 使用编码进行入库、出库、盘点和扫码 |

要求：

- 编码一旦被业务单据引用，不建议修改。
- 如确需修改，应保留历史编码与新编码的映射关系。
- 基础资料变更需要记录操作人、操作时间和变更原因。

## 9. 系统实现建议

### 9.1 编码生成器

系统中建议建立统一的编码生成器，不同模块调用同一套生成逻辑。

输入参数：

| 参数 | 用于模具编码 | 用于成品 / 半成品编码 |
| --- | --- | --- |
| 产品特定编码 | 是 | 是 |
| 材质编码 | 是 | 否 |
| 工序编码 | 否 | 是 |
| 手机型号编码 | 是 | 是 |
| 颜色编码 | 否 | 是 |

输出结果：

- 模具编码
- 半成品编码
- 成品编码
- SKU 总编码

### 9.2 编码预览

在保存前，系统应显示编码预览。

示例：

```text
当前选择：
产品：幻影 Fantasia Case
手机型号：Xiaomi Redmi A7 Pro
材质：TPU

系统生成：
MFA101291
```

这样可以让用户在保存前确认编码是否正确。

### 9.3 编码反查

系统应支持通过编码反查业务信息。

例如输入：

```text
NFA4030129101
```

系统可解析出：

| 字段 | 解析结果 |
| --- | --- |
| 编码类型 | 成品 / SKU |
| 产品特定编码 | FA |
| 工序编码 | 4030 |
| 手机型号编码 | 1291 |
| 颜色编码 | 01 |

再通过基础资料表显示完整名称。

## 10. 上线落地步骤

建议按以下顺序推进：

1. 确认产品特定编码、手机型号编码、材质编码、工序编码、颜色编码的基础资料。
2. 将颜色编码、手机型号编码、材质编码、工序编码导入系统。
3. 在产品资料模块维护产品特定编码。
4. 开发或配置统一编码生成器。
5. 在模具管理模块启用模具编码生成。
6. 在半成品和工序模块启用半成品编码生成。
7. 在成品 / SKU 模块启用成品编码生成，并支持作为 SKU 总编码。
8. 在 BOM 模块支持零件编码批量导入。
9. 增加编码唯一性、必填项、来源合法性校验。
10. 选择一两个产品做试运行。
11. 确认无误后批量推广到全部产品。

## 11. 钉钉新型号开模申请对接规则

钉钉表单中的“新型号开模申请”会把申请数据传入系统，其中会包含模具编码。系统收到钉钉数据后，应以模具编码作为关键字段，完成自动解析、匹配、校验和建档。

### 11.1 钉钉表单建议传入字段

钉钉表单建议至少传入以下字段：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 申请单号 | DD202607230001 | 钉钉申请单唯一编号 |
| 产品名称 | 幻影 Fantasia Case | 产品业务名称 |
| 产品特定编码 | FA | 用于校验模具编码 |
| 手机型号 | Xiaomi Redmi A7 Pro | 手机型号名称 |
| 手机型号编码 | 1291 | 用于校验模具编码 |
| 材质 | TPU、PC | 开模材质 |
| 材质编码 | 10、20 | 用于校验模具编码 |
| 模具编码 | MFA101291、MFA201291 | 钉钉表单传入的模具编码 |
| 申请人 | 张三 | 发起开模申请的人 |
| 申请时间 | 2026-07-23 | 开模申请时间 |

如果一个产品对应多个材质，钉钉表单可以传入多个模具编码，例如：

```text
MFA101291
MFA201291
```

系统接收时应支持用逗号、分号、换行等方式拆分多个模具编码。

### 11.2 模具编码自动解析规则

系统收到模具编码后，应按照模具编码规则进行解析：

```text
mould_code = 来源文件中的模具编码原值
product_specific_code = mould_code.substring(1, 3)
```

示例：

```text
MBA10 = 原值 / BA / 10
LLT10 = 原值 / LT / 10
```

解析结果：

| 模具编码 | 产品本身特征编码 | 材质/结构短码 | 其他来源字段 |
| --- | --- | --- | --- |
| MBA10 | BA | 10 | - |
| LLT10 | LT | 10 | - |

实现建议：

- 不以 `M` 开头作为导入阻断条件。
- 产品本身特征编码固定取第 2、3 位。
- 第 4、5 位及其余字符按来源原值保留，不用于重组模具编码。
- 需要匹配材质、机型等业务字段时，优先使用来源字段或业务字典，不反向改写 `mould_code`。

### 11.3 自动匹配逻辑

系统收到钉钉传入的模具编码后，按以下顺序处理：

1. 校验模具编码格式是否正确。
2. 根据模具编码精确查找系统中是否已存在该模具。
3. 如果已存在，则将钉钉开模申请关联到已有模具档案。
4. 如果不存在，则解析模具编码中的产品特定编码、材质编码、手机型号编码。
5. 使用解析出的字段匹配系统基础资料。
6. 如果基础资料均存在，则自动创建新的模具待开模记录。
7. 如果基础资料缺失，则生成异常记录，提示补充产品、材质或手机型号资料。

匹配优先级建议：

| 优先级 | 匹配方式 | 处理结果 |
| --- | --- | --- |
| 1 | 模具编码完全一致 | 直接关联已有模具 |
| 2 | 产品特定编码 + 材质编码 + 手机型号编码一致 | 判断为同一模具，防止重复创建 |
| 3 | 编码可解析但基础资料缺失 | 进入待补资料状态 |
| 4 | 编码格式不符合规则 | 进入异常状态 |

### 11.4 自动生成与传入编码的关系

钉钉表单传入模具编码时，系统不应盲目重新生成并覆盖，而应采用“系统生成预期编码 + 对比钉钉传入编码”的方式。

处理逻辑：

1. 根据钉钉传入的产品特定编码、材质编码、手机型号编码，系统自动生成预期模具编码。
2. 将系统生成的预期模具编码与钉钉传入的模具编码进行比对。
3. 如果一致，则通过校验。
4. 如果不一致，则不自动保存为正式模具，应进入异常待确认。

示例：

| 钉钉传入字段 | 值 |
| --- | --- |
| 产品特定编码 | FA |
| 材质编码 | 10 |
| 手机型号编码 | 1291 |

系统生成预期编码：

```text
M + FA + 10 + 1291 = MFA101291
```

如果钉钉传入模具编码也是 `MFA101291`，则匹配成功。

如果钉钉传入模具编码是 `MFA101292`，则说明手机型号编码不一致，需要人工确认。

### 11.5 多材质模具编码处理

一个产品可能有多个材质，因此钉钉一张开模申请可能传入多个模具编码。

示例：

```text
MFA101291
MFA201291
```

系统应解析为两条模具记录：

| 模具编码 | 产品 | 材质 | 手机型号 |
| --- | --- | --- | --- |
| MFA101291 | FA | 10 / TPU | 1291 / Xiaomi Redmi A7 Pro |
| MFA201291 | FA | 20 / PC | 1291 / Xiaomi Redmi A7 Pro |

要求：

- 同一张钉钉申请单可以关联多个模具编码。
- 多个模具编码应共用同一个产品和手机型号。
- 每个模具编码对应一个材质。
- 系统应校验是否漏传、多传或传错材质编码。

### 11.6 异常处理规则

钉钉数据进入系统时，建议设置以下异常状态：

| 异常类型 | 示例 | 处理方式 |
| --- | --- | --- |
| 模具编码为空 | 未传来源模具码 | 不自动拼接，退回补填来源模具码 |
| 模具编码过短 | `AB` | 标记无法提取第 2、3 位 |
| 产品特征码无法映射 | `MXX101291` | 提示先维护产品映射 |
| 来源字段不一致 | 模具码与业务单据字段不一致 | 保留原码并进入人工确认 |
| 非 M 开头模具码 | `LLT10` | 允许导入，提取产品特征码 `LT` |
| 模具编码已存在 | `MBA10` | 直接关联已有模具，不重复创建 |

### 11.7 钉钉到系统的推荐流程

推荐流程如下：

1. 钉钉提交新型号开模申请。
2. 钉钉将申请单号、产品、手机型号、材质、模具编码等字段传入系统。
3. 系统接收数据并记录原始钉钉报文。
4. 系统拆分多个模具编码。
5. 系统解析每一个模具编码。
6. 系统根据基础资料匹配产品、材质、手机型号。
7. 系统根据字段自动生成预期模具编码。
8. 系统比对预期编码和钉钉传入编码。
9. 匹配成功后，创建或关联模具档案。
10. 匹配失败时，进入异常待处理。
11. 模具档案创建后，可继续进入 BOM、生产、库存等后续模块。

### 11.8 与后续模块的关系

钉钉传入的模具编码主要用于开模阶段，但它会影响后续产品资料和生产资料的建立。

关系如下：

| 后续模块 | 使用方式 |
| --- | --- |
| 模具管理 | 创建或关联模具档案 |
| 产品资料 | 校验产品特定编码是否存在 |
| 手机型号资料 | 校验手机型号编码是否存在 |
| 材质资料 | 校验材质编码是否存在 |
| BOM 管理 | 后续根据产品和机型建立 BOM |
| SKU 管理 | 后续结合颜色和最终工序生成成品编码 |
| 生产管理 | 开模完成后进入生产准备 |
| 库存管理 | 模具入库时使用模具编码 |

注意：模具编码本身不包含颜色编码，因此它不能直接生成 SKU。SKU 或成品编码需要在后续选择颜色和最终工序后生成。

## 12. 关键结论

这套编码规则在系统中落地时，核心不是让用户手工录入完整编码，而是通过系统基础资料自动组合生成。

系统需要做到：

- 基础资料先维护。
- 用户选择业务对象。
- 系统自动生成编码。
- 保存前校验唯一性和完整性。
- 成品编码可作为 SKU 总编码。
- BOM 零件编码通过批量导入维护。
- 生产、库存、扫码等模块统一使用这些编码流转。
- 钉钉新型号开模申请传入模具编码时，系统应先解析、匹配和校验，再创建或关联模具档案。

最终效果是：系统可以通过一个编码识别产品、手机型号、材质、工序状态和颜色，并把产品资料、BOM、生产、库存和 SKU 管理串联起来。
