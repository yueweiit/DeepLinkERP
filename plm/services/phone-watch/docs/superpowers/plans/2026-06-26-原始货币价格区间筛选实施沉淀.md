# 原始货币价格区间筛选实施沉淀

## 目标

在现有手机上新监控系统中，为列表筛选增加“货币选择 + 价格区间”能力。筛选只基于价格文本本身识别到的原始货币，不做汇率换算。

本次方案先沉淀设计与实施路径，不直接修改业务代码。

## 业务背景

当前系统已经采集并展示手机价格，但价格字段以文本形式保存，例如：

- `MXN 4,999`
- `$4,999`
- `CNY 1999`
- `¥1999`
- `KRW 599000`
- `₩599,000`
- `USD 299`
- `US$299`

现有筛选主要包含国家、品牌、开模状态、标签等维度，缺少价格筛选。业务上希望可以快速筛出某个币种下某个价格区间内的机型，用于判断候选机型优先级。

## 方案选择

采用“按原始货币筛选”：

- 选择 `MXN` 时，只筛选价格文本本来能识别为墨西哥比索的记录。
- 选择 `CNY` 时，只筛选价格文本本来能识别为人民币的记录。
- 选择 `KRW` 时，只筛选价格文本本来能识别为韩元的记录。
- 选择 `USD` 时，只筛选价格文本本来能识别为美元的记录。
- 不做跨币种换算。

这样实现简单、风险低、长期维护成本可控。缺点是不同币种不能直接比较，后续如果需要跨币种对比，应单独设计“汇率换算价格筛选”功能。

## 原始货币识别规则

| 货币 | 识别示例 | 说明 |
| --- | --- | --- |
| MXN | `MXN 4,999`、`$4,999`、`$ 4,999`、`4,999 MXN` | 当前项目主要抓墨西哥零售源，普通 `$` 默认按 MXN 处理。 |
| CNY | `CNY 1999`、`¥1999`、`￥1999`、`RMB 1999`、`1999 元` | 当前不抓日本源，因此 `¥` 按 CNY 处理。 |
| KRW | `KRW 599000`、`₩599,000`、`599,000원` | 韩元通常没有小数。 |
| USD | `USD 299`、`US$299` | 普通 `$299` 不按 USD 处理，避免和 MXN 冲突。 |

## 改后效果

页面工具栏增加三个控件：

- 货币：全部、MXN、CNY、KRW、USD
- 最低价：数字输入框
- 最高价：数字输入框
- 价格分类：全部、有价格、无价格/未识别

示例效果：

- 选择 `MXN`，最低价 `3000`，最高价 `8000`：只展示原始价格识别为 MXN，且数值在 3000 到 8000 之间的机型。
- 选择 `CNY`，最低价 `1000`，最高价留空：只展示原始价格识别为 CNY，且价格大于等于 1000 的机型。
- 货币留空，最低价 `1000`，最高价 `5000`：展示所有能识别出价格数值且数值在区间内的记录。该模式只是便捷筛选，不代表不同币种之间可直接比较。
- 货币留空、最低价留空、最高价留空、价格分类为“全部”：不限制价格，展示当前地区、品牌、状态、标签条件下的全部机型。
- 选择某个地区但价格区间为空：展示该地区全部机型，不因为价格为空或无法识别而被过滤掉。
- 价格分类选择“无价格/未识别”：单独展示没有价格文本，或价格文本无法识别出货币和数值的机型，方便后续补价格或排查采集质量。

## 筛选空值规则

价格筛选必须遵循以下空值语义，避免误伤数据：

| 条件 | 行为 |
| --- | --- |
| 未选择货币、最低价为空、最高价为空、价格分类为全部 | 不启用价格筛选，展示当前地区等其他条件下的全部机型。 |
| 已选择地区，但价格区间为空 | 按地区展示全部机型，不排除无价格机型。 |
| 未选择货币，但填写了最低价或最高价 | 对所有可识别原始货币的记录做数值区间筛选；无价格/未识别记录默认不进入结果。 |
| 已选择货币，但区间为空 | 展示该原始货币下全部可识别价格记录，不限制价格大小。 |
| 已选择货币，并填写区间 | 同时匹配原始货币和价格区间。 |
| 价格分类为无价格/未识别 | 忽略货币和区间，单独展示无价格或无法识别价格的记录。 |
| 价格分类为有价格 | 展示能识别出货币和数值的记录，可继续叠加货币和区间。 |

这里的“无价格/未识别”不等于错误。它是一个独立分类，代表当前记录暂时不能用于价格区间判断，但仍然应该能被业务人员看到。

## 后端实现逻辑

### 1. 新增价格解析函数

建议在 `phone_watch/db.py` 中新增：

```python
PRICE_FILTER_CURRENCIES = {"MXN", "CNY", "KRW", "USD"}


def parse_price_for_filter(price: Any) -> tuple[str | None, float | None]:
    text = str(price or "").strip()
    if not text:
        return None, None

    upper = text.upper()
    currency: str | None = None
    if "US$" in upper or re.search(r"\bUSD\b", upper):
        currency = "USD"
    elif "MXN" in upper or re.search(r"\bMX\$", upper) or "$" in text:
        currency = "MXN"
    elif "CNY" in upper or "RMB" in upper or "¥" in text or "￥" in text or "元" in text:
        currency = "CNY"
    elif "KRW" in upper or "₩" in text or "원" in text:
        currency = "KRW"

    if currency is None:
        return None, None

    match = re.search(r"\d[\d,.\s]*", text)
    if not match:
        return currency, None

    raw_number = re.sub(r"[\s,]", "", match.group(0))
    try:
        amount = float(raw_number)
    except ValueError:
        return currency, None
    return currency, amount
```

### 2. 新增通用筛选函数

建议在 `phone_watch/db.py` 中新增：

```python
def filter_rows_by_price(
    rows: list[Any],
    currency: str | None = None,
    min_price: float | None = None,
    max_price: float | None = None,
    price_bucket: str | None = None,
) -> list[Any]:
    selected_currency = str(currency or "").strip().upper() or None
    selected_bucket = str(price_bucket or "").strip() or "all"
    if selected_currency and selected_currency not in PRICE_FILTER_CURRENCIES:
        return []
    if selected_bucket not in {"all", "priced", "unpriced"}:
        return []
    if selected_bucket == "all" and selected_currency is None and min_price is None and max_price is None:
        return rows

    filtered: list[Any] = []
    for row in rows:
        row_currency, amount = parse_price_for_filter(row["price"] if "price" in row.keys() else "")
        has_price = bool(row_currency and amount is not None)
        if selected_bucket == "unpriced":
            if not has_price:
                filtered.append(row)
            continue
        if selected_bucket == "priced" and not has_price:
            continue
        if selected_currency and row_currency != selected_currency:
            continue
        if amount is None:
            continue
        if min_price is not None and amount < min_price:
            continue
        if max_price is not None and amount > max_price:
            continue
        filtered.append(row)
    return filtered
```

## API 实现逻辑

在 `phone_watch/webapp.py` 中新增参数解析：

```python
def parse_optional_float(value: str | None) -> float | None:
    text = str(value or "").strip()
    if not text:
        return None
    return float(text)


def price_filter_args(query: dict[str, str]) -> dict[str, object]:
    return {
        "price_currency": query.get("price_currency") or None,
        "price_min": parse_optional_float(query.get("price_min")),
        "price_max": parse_optional_float(query.get("price_max")),
        "price_bucket": query.get("price_bucket") or "all",
    }
```

以下接口需要传入价格筛选参数：

- `/api/phones`
- `/api/candidates`
- `/api/today`
- `/api/new-today`
- `/export/phones.csv`
- `/export/candidates.csv`

示例：

```python
rows = db.list_phones(
    conn,
    country=query.get("country") or None,
    brand=query.get("brand") or None,
    status=query.get("status") or None,
    badge=query.get("badge") or None,

```

### 4. 静态模式前端筛选

静态导出页面无法调用后端筛选，因此需要在 `ui.py` 的脚本中加入 JS 版本解析逻辑：

```javascript
function parsePriceForFilter(price) {
  const text = String(price || "").trim();
  if (!text) return { currency: "", amount: null };
  const upper = text.toUpperCase();
  let currency = "";
  if (upper.includes("US$") || /\bUSD\b/.test(upper)) currency = "USD";
  else if (upper.includes("MXN") || /\bMX\$/.test(upper) || text.includes("$")) currency = "MXN";
  else if (upper.includes("CNY") || upper.includes("RMB") || text.includes("¥") || text.includes("￥") || text.includes("元")) currency = "CNY";
  else if (upper.includes("KRW") || text.includes("₩") || text.includes("원")) currency = "KRW";
  if (!currency) return { currency: "", amount: null };
  const match = text.match(/\d[\d,.\s]*/);
  if (!match) return { currency, amount: null };
  const amount = Number(match[0].replace(/[\s,]/g, ""));
  return Number.isFinite(amount) ? { currency, amount } : { currency, amount: null };
}

function priceMatches(row, f) {
  const bucket = f.price_bucket || "all";
  if (bucket === "all" && !f.price_currency && !f.price_min && !f.price_max) return true;
  const parsed = parsePriceForFilter(row.price);
  const hasPrice = Boolean(parsed.currency && parsed.amount !== null);
  if (bucket === "unpriced") return !hasPrice;
  if (bucket === "priced" && !hasPrice) return false;
  if (f.price_currency && parsed.currency !== f.price_currency) return false;
  if (parsed.amount === null) return false;
  const min = f.price_min ? Number(f.price_min) : null;
  const max = f.price_max ? Number(f.price_max) : null;
  if (min !== null && parsed.amount < min) return false;
  if (max !== null && parsed.amount > max) return false;
  return true;
}
```

在 `visibleRows()` 的静态筛选条件中加入：

```javascript
priceMatches(row, f)
```

## 长期可用性说明

- 本方案不改表结构，适合当前系统快速增强。
- 价格解析集中在 `db.py`，避免各接口重复写规则。
- 静态导出页面保留一份 JS 解析逻辑，保证离线 HTML 也能筛选。
- 普通 `$` 固定按 MXN 处理。未来如果增加美国来源，不要直接把 `$` 改成 USD，应增加来源国家辅助判断。
- 如果后续数据量变大、价格筛选变慢，再考虑新增派生字段：
  - `price_currency TEXT`
  - `price_amount REAL`
- 如果未来要做汇率换算，应另起功能，保存汇率来源、汇率日期和换算说明，避免和本功能混在一起。

## 风险与边界

- 文本价格不规范时可能无法识别，开启价格筛选后这类记录会被排除。
- 不同币种之间不做换算，不能用本功能判断跨国家真实价格高低。
- `¥` 在国际上也可表示日元，但当前系统不抓日本源，因此暂按 CNY 处理。
- 普通 `$` 固定按 MXN 处理，符合当前墨西哥业务场景。
