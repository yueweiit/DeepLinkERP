# 2026-07-27 PLM ECOUNT 新物料编码总表导入规则与物料组分类沉淀

## 1. 背景与目标

本沉淀基于用户提供的 ECOUNT 历史物料主数据：

- `D:\work\资料\PLM\01 ECOUNT 新物料编码总表.xlsx`
- `D:\work\资料\PLM\01 ECOUNT 新物料编码总表.csv`

目标是在不修改代码的前提下，先明确后续“物料/库存主数据批量导入”的规则：

- 识别 ECOUNT 原始表结构和字段含义。
- 设计 ECOUNT 字段到 PLM Inventory 导入字段的映射关系。
- 沉淀物料组分类口径，避免把历史分类信息压扁丢失。
- 标注需要兼容、预警或人工清洗的数据问题。

本文件只作为方案与规则沉淀，不包含本次代码修改。

## 2. 源工作簿结构

`01 ECOUNT 新物料编码总表.xlsx` 主要包含以下 sheet：

| Sheet | 用途 | 后续导入建议 |
| --- | --- | --- |
| `1-5级编码` | ECOUNT 存货分类编码目录，包含大类编码、名称、流水编码、示例物料编码等 | 作为物料组字典和编码规则参考 |
| `物料编码表` | 物料明细主表，包含 7,988 条有效物料记录 | 作为 Inventory 批量导入主数据来源 |
| `计量单位` | 标准计量单位及中西文说明 | 作为单位标准化字典 |
| `Sheet1` | 原表维护说明，例如筛选、排序、生成编码流程 | 作为人工维护规则参考，不直接导入 |
| `Sheet4`、`WpsReserved_CellImgList` | 空白或 WPS 内部保留内容 | 不导入 |

`物料编码表` 不是普通首行表头：

- 第 1 行：标题 `物料编码明细表`。
- 第 2 行：主表头，例如 `序号`、`一级`、`二级`、`旧编码`、`新物料编码`、`物料名称`。
- 第 3 行：`一级`、`二级` 的子表头，例如 `大类编码`、`名称`、`流水编码`、`名称`。
- 第 4 行：存在辅助状态文字，例如 `良好`，不属于物料数据。
- 第 5 行开始：真实物料数据。

因此后续导入逻辑不能只读第 1 行作为表头，应支持：

- 自动定位 `物料编码表` sheet。
- 在前 5 行内扫描包含 `新物料编码`、`物料名称`、`规格型号`、`基本单位` 的表头行。
- 将第 2/3 行复合表头组合成内部字段，例如 `一级.大类编码`、`一级.名称`、`二级.流水编码`、`二级.名称`。

## 4. ECOUNT 字段含义与 PLM 字段映射

### 4.1 源字段定义

| ECOUNT 列 | 原始位置 | 含义 | 是否建议导入 |
| --- | --- | --- | --- |
| 序号 | A 列 | 原表行序号 | 不入库，仅用于错误定位 |
| 一级.大类编码 | B 列 | 一级物料组编码，例如 `YL`、`FL`、`GJ` | 建议保留 |
| 一级.名称 | C 列 | 一级物料组名称，例如 `原料`、`辅料`、`工具` | 建议保留 |
| 二级.流水编码 | D 列 | 二级分类或流水码，例如 `000001` | 建议保留 |
| 二级.名称 | E 列 | 二级物料组或物料族名称 | 建议保留 |
| 旧编码 | F 列 | 历史旧编码 | 建议保留 |
| 新物料编码 | G 列 | 现行 ECOUNT 物料编码 | 必填，映射为 PLM `inventory_code` |
| 物料名称 | H 列 | 物料中文/中西文名称 | 必填，映射为 PLM `inventory_name` |
| 规格型号 | I 列 | 规格、颜色、尺寸、包装信息 | 建议映射为 PLM `specification` |
| 基本单位 | J 列 | 库存单位 | 必填或预警，映射为 PLM `unit`/`stock_uom` |
| 条形码 | K 列 | ECOUNT 条码 | 可选，`#N/A` 视为空 |
| 新增日期 | L 列 | ECOUNT 建档日期 | 可选，建议保留为来源日期 |
| 备注 | M 列 | 历史备注 | 可选，映射为 PLM `remark` |

### 4.2 当前 PLM 兼容映射

当前 Inventory 导入模板字段较少：

`inventory_code`、`inventory_name`、`inventory_type`、`specification`、`unit`、`supplier_name`、`unit_cost`、`currency_code`、`status`、`remark`

在不扩表的情况下，建议采用以下兼容导入映射：

| PLM 导入字段 | 来源 | 规则 |
| --- | --- | --- |
| `inventory_code` | `新物料编码` | 必填，按文本保留，去除首尾空格，不自动生成 |
| `inventory_name` | `物料名称` | 必填，去除首尾空格 |
| `inventory_type` | `一级.大类编码` + `一级.名称` | 先按粗粒度类型派生，详见第 5 节 |
| `specification` | `规格型号` | 可为空，原样保留 |
| `unit` | `基本单位` | 建议标准化为中文主单位或 `kg/L/m²` 等标准符号 |
| `supplier_name` | 源表无供应商列 | 统一默认 `默认供应商` |
| `unit_cost` | 源表无单价 | 空 |
| `currency_code` | 源表无币种 | 默认 `CNY` |
| `status` | 第 4 行辅助状态或默认值 | 建议默认 `available`，不读取第 4 行 `良好` 作为每行状态 |
| `remark` | `备注` + 来源元数据 | 建议追加 ECOUNT 分类、旧编码、条码、新增日期等信息 |

兼容导入时，`remark` 建议格式：

```text
<原备注>；ECOUNT导入：一级=<大类编码>/<大类名称>，二级=<流水编码>/<二级名称>，旧编码=<旧编码>，条码=<条形码>，新增日期=<新增日期>
```

空值字段不追加，避免备注过长。

### 4.3 建议扩展字段

长期看，不建议把 ECOUNT 分类、条码、旧编码全部塞进 `remark`。建议后续给 Inventory 或物料基础表补充以下字段：

## 5. 物料组分类规则

### 5.1 分类层级

建议在 PLM 中沉淀两层 ECOUNT 物料组：

- 一级物料组：`一级.大类编码 + 一级.名称`
- 二级物料组：`二级.流水编码 + 二级.名称`

二级物料组必须挂在一级物料组下。由于历史表中存在同一级编码对应多个名称的情况，物料组展示应同时保留编码和名称，不能只用编码判断。

推荐显示格式：

```text
一级：YL 原料
二级：000001 原料TPU
```

### 5.3 一级编码冲突处理

以下编码存在“同编码不同名称”的历史数据：

| 一级编码 | 出现名称 | 处理建议 |
| --- | --- | --- |
| `MJ` | 模具、模架、模芯 | 建议统一展示为 `MJ 模具/模架`，原始名称保存在 `ecount_major_name` |
| `GL` | 钢料、铜料、辅料 | 建议统一展示为 `GL 金属材料`，但 `GL/辅料` 标为异常 |
| `SB` | 设备、工具 | 建议以 `SB 设备` 为准，`SB/工具` 标为异常 |
| `KGFL` | 客供辅料、辅料 | 建议统一展示为 `KGFL 客供辅料`，原始名称保留 |

原则：

- 导入主数据时不因为名称冲突直接覆盖原始值。
- 物料组字典可以有“规范显示名”，但每条物料仍应保留 ECOUNT 原始编码和名称。
- 冲突记录在预览阶段给出 warning，不建议作为 fatal error，除非编码为空或物料编码重复。

### 5.4 `inventory_type` 粗粒度派生规则

当前 PLM `inventory_type` 是粗粒度类型，不足以完整表达 ECOUNT 物料组。因此建议后续区分：

- `inventory_type`：系统业务类型，用于现有筛选和导入校验。
- `material_group`：ECOUNT 物料组，用于分类树和历史追溯。

在当前兼容导入阶段，可临时按以下规则派生 `inventory_type`：

| ECOUNT 一级编码/名称 | 建议 `inventory_type` | 说明 |
| --- | --- | --- |
| `YL 原料`、`GL 钢料`、`GL 铜料` | `material` | 原材料、金属材料 |
| `FL 辅料`、`KGFL 客供辅料/辅料`、`NHA/NAR/0 辅料` | `packaging` 或后续新增 `auxiliary` | 现有枚举无“辅料”，短期用 `packaging` 有失真，建议扩展枚举 |
| `GJ 工具`、`HE 工具`、`WJ 工具` | `tooling` | 工具、刀具、治工具 |
| `MJ 模具/模架/模芯`、`KGMJ 客供模具` | `tooling` 或后续新增 `mold` | 当前枚举无“模具”，建议扩展枚举 |
| `SB 设备`、`KGSB 设备` | `tooling` 或后续新增 `equipment` | 当前枚举无“设备”，建议扩展枚举 |
| `JG 加工`、`RC 日常工作`、`WX 费用` | 不建议自动导入 Inventory | 更像服务/费用类，建议人工确认 |

推荐方向：后续扩展 `inventory_type`，至少补充 `auxiliary`、`mold`、`equipment`、`service`，否则 ECOUNT 分类会被过度压缩。

## 6. 单位标准化规则

`计量单位` sheet 给出的标准单位包括：

`kg`、`m²`、`把`、`包`、`份`、`个`、`罐`、`盒`、`件`、`卷`、`米`、`啤`、`片`、`瓶`、`双`、`台`、`套`、`条`、`桶`、`箱`、`张`、`支`、`对`、`辆`、`袋`、`筒`、`付`、`块`、`本`

源表 `基本单位` 存在大量中西文混写，例如：

- `个 PIEZA`
- `套 PIEZA`
- `个 unidad`
- `卷Rollo`
- `米Metros`
- `个：pieza`
- `KG`

| 原始单位示例 | 标准单位 |
| --- | --- |
| `个 PIEZA`、`个Piezas`、`个PIEZA`、`个 unidad`、`个：pieza` | `个` |
| `套 PIEZA`、`套set`、`套：conjunto` | `套` |
| `件 PIEZA` | `件` |
| `台 PIEZA`、`台 unidad` | `台` |
| `支 PIEZA`、`支 piece` | `支` |
| `片 PIEZA` | `片` |
| `张 PIEZA`、`张 hoja` | `张` |
| `卷Rollo`、`卷 ROL` | `卷` |

## 7. 导入校验规则

### 7.1 必填规则

建议自动导入必填字段：

| 字段 | 规则 |
| --- | --- |
| `新物料编码` | 必填，去空格后不能为空 |
| `物料名称` | 必填，去空格后不能为空 |
| `基本单位` | 建议必填；如果业务选择兼容历史空单位，可进入 warning 队列 |
| `一级.大类编码` | 建议必填，用于物料组归类 |
| `一级.名称` | 建议必填，用于物料组展示 |

建议非必填字段：

- `规格型号`
- `二级.流水编码`
- `二级.名称`
- `旧编码`
- `条形码`
- `新增日期`
- `备注`

### 7.2 编码规则

导入主键以 `新物料编码` 为准。

校验建议：

- 文件内 `新物料编码` 重复：fatal error，同一个编码不应导入多条。
- 数据库中已存在 `inventory_code`：fatal error 或进入“跳过已存在”模式，取决于导入场景。
- `新物料编码 != 一级.大类编码 + 二级.流水编码`：warning，不自动改写。
- `新物料编码` 含空格、引号等异常字符：warning，保留原值供人工确认。
- `旧编码 != 新物料编码`：warning，并保留旧编码。

当前源表发现：

- 文件内有 128 个重复 `新物料编码`。
- 有 34 条 `新物料编码` 与 `大类编码 + 流水编码` 不一致。
- 有 4 条 `旧编码` 与 `新物料编码` 不一致。

### 7.3 条形码规则

条形码可选：

- 空值视为空。
- `#N/A`、`N/A`、`NA` 视为空。
- 数字条码按文本保留，不做科学计数法转换。
- 条码重复只做 warning，不阻断物料导入，除非后续业务要求条码唯一。

### 7.4 日期规则

`新增日期` 可选：

- 支持 `yyyy/M/d`、`yyyy-MM-dd`、Excel 日期单元格。
- 转换为 `yyyy-MM-dd`。
- 空日期不阻断导入。
- 无法解析日期给 warning，原始值保留到备注或源字段。

## 9. 预览与导入模式建议

建议提供两种模式：

| 模式 | 适用场景 | 规则 |
| --- | --- | --- |
| 严格模式 | 日常用户导入 | 必填缺失、编码重复、单位缺失、类型无法识别均阻断 |
| 历史迁移模式 | 首次 ECOUNT 全量迁移 | 编码重复仍阻断；单位缺失、分类冲突、编码规则不一致可 warning 并生成异常报告 |

历史迁移模式仍不建议跳过文件内重复编码，因为重复编码会直接破坏 Inventory 主键语义。

## 11. 验收口径

后续代码实现完成后，应满足：

- 直接上传 `01 ECOUNT 新物料编码总表.xlsx` 的 `物料编码表` 可进入预览，不再报 `模板缺少必填列：inventory_code`。
- 预览能识别 7,988 条有效物料记录。
- `新物料编码`、`物料名称`、`规格型号`、`基本单位` 能正确映射到 PLM 字段。
- 源表无供应商时，供应商默认 `默认供应商`。
- `基本单位` 能从 `个 PIEZA`、`套 PIEZA`、`KG` 等混写形式归一化。
- 文件内重复编码会明确列出，不静默覆盖。
- `MJ`、`GL`、`SB`、`KGFL` 等一级编码冲突会保留原始分类并给出 warning。
- 不支持或非库存性质的 `费用`、`加工`、`日常工作` 类记录能被识别并提示人工确认。
