# PLM 钉钉新型号未继承工艺路线修复方案

日期：2026-08-04  
范围：方案文档，不修改代码  
问题项目示例：`projectId=19206`  

## 1. 问题现象

钉钉新型号审批回调已经成功创建 PLM 新型号项目：

```text
projectId = 19206
integrationRecordId = 29
status = success
idempotentHit = false
```

模具编码也已正常匹配：

```text
MBA101292 -> inventoryId 95
MBA201292 -> inventoryId 96
```

但进入工作台或项目详情后，新型号没有看到对应父产品的工艺路线。

## 2. 根因判断

根因不是钉钉入站失败，而是钉钉入站创建链路没有接入普通新型号创建时的继承逻辑。

普通工作台新建新型号走：

```text
ProductServiceImpl.create
  -> 创建 Product
  -> createVariantColorSnapshots
  -> processRouteInheritanceService.inheritLatestReleasedFormalBomRoutesByColors
  -> bomInheritanceService.inheritLatestReleasedByColors
```

钉钉新型号创建走：

```text
DingTalkModelVariantService.receive
  -> 创建 Product
  -> moldCodeIntakeService.sync
  -> attachmentArchiveService.archiveMetadata
  -> 创建 RequirementForm
  -> 创建 ProductVariantColor 颜色快照
  -> 创建 IntegrationRecord
```

当前钉钉链路没有调用：

```text
ProcessRouteInheritanceService
BomInheritanceService
```

所以项目能创建，颜色快照和模具匹配能创建，但工艺路线和 BOM 不会自动继承。

## 3. 目标效果

钉钉新型号审批创建项目后，应与工作台手工新建新型号保持一致：

```text
钉钉审批通过
  -> 创建 model_variant 项目
  -> 继承父产品已确认投产颜色
  -> 按颜色继承父产品最新 released formal BOM 对应的工艺路线
  -> 继承父产品最新 released formal BOM
  -> BOM route 指向新继承出来的工艺路线
  -> 工作台项目详情可看到工艺路线和 BOM
```

创建成功返回仍保持：

```text
data.status = success
data.projectId 有值
data.idempotentHit = false
```

## 4. 前置数据条件

补上继承代码后，仍需要父产品满足以下条件，否则应明确失败或记录失败原因：

1. 父产品存在。
2. 父产品类型是 `product_line`。
3. 父产品状态是 `released`。
4. 父产品存在已确认投产颜色：

```text
plm_product_production_color_decision.selected_flag = 1
plm_product_production_color_decision.status = confirmed
deleted_flag = 0
```

5. 父产品存在最新 released formal BOM：

```text
plm_product_bom.product_id = parentProductId
plm_product_bom.bom_scope = formal
plm_product_bom.status = released
deleted_flag = 0
```

6. 父产品 formal BOM 下存在 active BOM route。
7. BOM route 下存在 active 颜色，并且颜色名能匹配新型号继承颜色。
8. BOM route 如果有关联 `process_id`，对应父产品工艺路线应存在且未删除。

## 5. 推荐实现方案

### 5.1 抽取共用继承编排

不要在 `DingTalkModelVariantService` 里复制一大段普通创建逻辑。建议抽取一个内部服务，例如：

```text
ModelVariantInheritanceOrchestrator
```

职责：

```java
Map<Long, Long> inheritFromParent(
    Product parent,
    Product target,
    List<ProductProductionColorDecision> inheritedColors,
    String operator
)
```

内部执行：

```java
List<String> inheritedColorNames = inheritedColors.stream()
    .map(ProductProductionColorDecision::getColorName)
    .filter(StringUtils::hasText)
    .map(String::trim)
    .distinct()
    .toList();

Map<Long, Long> processIdMapping =
    processRouteInheritanceService.inheritLatestReleasedFormalBomRoutesByColors(
        parent.getProductId(),
        target,
        inheritedColorNames,
        operator
    );

bomInheritanceService.inheritLatestReleasedByColors(
    parent.getProductId(),
    target.getProductId(),
    inheritedColorNames,
    processIdMapping
);
```

然后让两条入口都调用它：

```text
ProductServiceImpl.create
DingTalkModelVariantService.receive
```

这样后续工艺/BOM继承规则只维护一处。

### 5.2 钉钉创建链路接入点

建议在 `DingTalkModelVariantService.receive()` 中，完成颜色快照后、写入集成记录前调用继承：

```text
productRepository.insert(project)
-> moldCodeIntakeService.sync(...)
-> attachmentArchiveService.archiveMetadata(...)
-> formRepository.insert(form)
-> variantColorRepository.insert(snapshot...)
-> inheritFromParent(parent, project, decisions, dto.getCreatedBy())
-> integrationRepository.insert(record)
```

理由：

1. `project.productId` 已经生成。
2. `decisions` 已经是父产品已确认投产颜色。
3. 继承失败时可以让整个钉钉创建事务回滚，避免出现“项目成功但核心资料缺失”的半成品。
4. 继承成功后再写 inbound success 记录，更符合真实业务状态。

### 5.3 是否允许继承失败但项目创建成功

有两个选择：

方案 A：强一致，推荐。

```text
工艺/BOM继承失败
  -> 钉钉入站创建失败
  -> 事务回滚
  -> 返回明确错误
```

优点：不会产生缺资料的新型号半成品。  
缺点：如果父产品历史数据不完整，钉钉审批会暂时无法创建项目。

方案 B：弱一致。

```text
项目先创建
  -> 工艺/BOM继承失败记录到 integration_record
  -> 项目进入待补偿状态
```

优点：钉钉审批不被父产品资料问题阻断。  
缺点：后续需要补偿页面或补偿接口，否则工作台仍会看到缺资料项目。

建议采用方案 A。PLM 中新型号如果没有继承父产品工艺/BOM，后续流程价值会很低，应该让问题前置暴露。

## 6. 已创建项目的补偿方案

`projectId=19206` 已经创建成功，重新用同一个审批实例回调会命中幂等，不会再执行创建逻辑。

需要单独做补偿。

### 6.1 临时补偿方式

新增一次性后端管理接口或脚本：

```text
POST /api/v1/projects/{projectId}/inherit-parent-process-bom
```

处理逻辑：

1. 查询目标项目。
2. 校验 `product_type=model_variant`。
3. 查询 `parent_product_id`。
4. 查询父产品 confirmed selected 颜色。
5. 如果目标项目已有工艺路线或 BOM，默认不重复执行，除非传 `force=true`。
6. 调用共用继承编排服务。
7. 返回继承结果：

```json
{
  "projectId": 19206,
  "parentProductId": 123,
  "inheritedProcessRouteCount": 2,
  "inheritedBomId": 456,
  "status": "success"
}
```

### 6.2 后续正式化

可以在系统管理中增加“集成记录补偿”能力：

```text
按 projectId 查询
-> 检查缺失工艺/BOM
-> 点击补继承
-> 写 operation log
-> 写 integration_record outbound/internal compensation 记录
```

## 7. 幂等规则

继承补偿必须幂等，避免重复复制工艺路线和 BOM。

建议判断：

```sql
select count(*)
from plm_process
where product_id = :projectId
  and process_type = 'routing'
  and deleted_flag = 0;
```

如果已有工艺路线，默认返回：

```text
already_inherited
```

BOM 判断：

```sql
select count(*)
from plm_product_bom
where product_id = :projectId
  and bom_scope = 'formal'
  and deleted_flag = 0;
```

如果已有 formal BOM，默认不重复继承。

如确实需要重跑，应提供 `force=true`，并明确是：

```text
软删除旧继承数据后重跑
```

不能直接叠加复制。

## 8. 验收 SQL

### 8.1 查项目与父产品

```sql
select
    product_id,
    parent_product_id,
    product_code,
    product_name,
    product_type,
    status,
    source_system,
    source_instance_id
from plm_product
where product_id in (
    19206,
    (select parent_product_id from plm_product where product_id = 19206)
);
```

### 8.2 查项目工艺路线

```sql
select
    process_id,
    product_id,
    process_code,
    process_name,
    process_type,
    status,
    process_param_json
from plm_process
where product_id = 19206
  and process_type = 'routing'
  and deleted_flag = 0
order by process_id desc;
```

预期：

```text
至少 1 条 routing
status = draft 或 inherited 逻辑对应状态
process_param_json 可识别 inherited/sourceProductCode 等继承信息
```

### 8.3 查项目 BOM

```sql
select
    product_bom_id,
    product_id,
    bom_code,
    bom_scope,
    source_type,
    source_product_id,
    source_product_bom_id,
    status,
    version_no
from plm_product_bom
where product_id = 19206
  and deleted_flag = 0
order by product_bom_id desc;
```

预期：

```text
存在 formal BOM
source_type = inherited
source_product_id = 父产品 ID
status = draft
```

### 8.4 查 BOM route 是否关联新工艺路线

```sql
select
    r.product_bom_route_id,
    r.product_bom_id,
    r.product_id,
    r.process_id,
    r.route_code,
    r.route_name,
    p.process_code,
    p.process_name
from plm_product_bom_route r
left join plm_process p on p.process_id = r.process_id
where r.product_id = 19206
  and r.deleted_flag = 0
order by r.product_bom_route_id;
```

预期：

```text
r.process_id 指向 projectId=19206 下新复制出来的工艺路线
```

### 8.5 查颜色是否继承

```sql
select
    variant_color_id,
    project_product_id,
    source_product_id,
    color_code,
    color_name,
    selected_flag,
    default_selected_flag,
    snapshot_status
from plm_product_variant_color
where project_product_id = 19206
  and deleted_flag = 0
order by variant_color_id;
```

预期：

```text
颜色来自父产品
selected_flag = 1
default_selected_flag = 1
snapshot_status = active
```

## 9. 测试建议

### 9.1 单元测试

新增或调整：

```text
DingTalkModelVariantServiceTest
```

覆盖：

1. 钉钉 approved 新型号创建后调用工艺继承。
2. 钉钉 approved 新型号创建后调用 BOM 继承，并传入 processIdMapping。
3. 继承颜色名来自父产品 confirmed selected 颜色，而不是钉钉表单手填颜色。
4. 继承失败时事务回滚，不写入 success integration record。
5. 重复审批实例命中幂等时，不重复调用继承。

### 9.2 集成测试

构造父产品：

```text
product_line
```

提交钉钉新型号回调后断言：

```text
新型号 Product 存在

BOM route process_id 指向新型号工艺路线
```

## 10. 实施步骤建议

1. 抽取共用继承编排服务。
2. 将 `ProductServiceImpl.create` 中现有继承逻辑迁移到共用服务。
3. 在 `DingTalkModelVariantService.receive` 中接入共用服务。
4. 补充单元测试，先验证失败，再修复。
5. 增加 `19206` 这类历史项目补偿入口或一次性脚本。
6. 用验收 SQL 核对继承结果。
7. 再做一次完整钉钉审批回调联调。

## 11. 风险点

1. 父产品没有 released formal BOM 时，接入强一致继承会导致钉钉建项失败。
2. 父产品 BOM route 颜色名与生产颜色名不一致时，会继承不到对应路线。
3. 现有钉钉项目已经创建，不能靠重复回调修复，必须补偿。
4. 若补偿接口没有幂等判断，会重复复制工艺和 BOM。
5. 如果只继承工艺路线、不继承 BOM，BOM route 与工艺路线映射仍然缺失，项目详情可能仍不完整。

## 12. 推荐结论

推荐按“强一致 + 补偿接口”实施：

```text
新钉钉项目：创建时必须同步继承工艺路线和 BOM，失败则整体失败。
历史项目：通过补偿接口按 projectId 补继承。
```

这样可以保证钉钉入口和工作台入口对新型号项目的业务结果一致，避免再出现“项目有了，但工艺/BOM核心资料缺失”的半成品。
