# PLM 宝塔部署前工作台进行中产品与测试数据清理方案

日期：2026-08-11  
执行阶段：方案沉淀与清单确认，尚未执行删除  
目标环境：当前 Docker 本地库 `plm-postgres / plm`，后续同口径用于宝塔部署前清理  

## 1. 任务理解

部署到宝塔前，需要清理当前工作台中仍处于“进行中”的产品/项目，以及它们在新建、测试、时间轴推动过程中产生的关联业务数据。当前先输出方案文档和清理清单，不直接修改业务代码，不直接执行 `DELETE` 或 `TRUNCATE`。

本系统工作台项目的核心承载对象是 `plm_product`，`projectId` 当前等同 `product_id`。因此清理必须以 Product 为根集合，按依赖表从子到父清理。

## 3. 清理目标

默认目标：

- 清理工作台“进行中”项目：`plm_product.deleted_flag = 0 and status in ('draft', 'developing')`。
- 同步清理这些项目直接产生的订单、钉钉集成记录、需求表单、BOM、BOM 路线、投产确认、工艺、附件、项目成本、运模快递、库存模具/物料等依赖数据。
- 如果进行中新型号下已经产生 SKU，清理 SQL 通过 `parent_product_id` 递归纳入子级 SKU，避免工作台清空后 SKU 残留。
- 清理后，工作台“进行中”列表为空，不影响已发布/已归档的历史产品线和正式资料。

非默认目标，需再次确认后才执行：

- 清理 2026-08-04 之后 E2E 测试产生但已经 `released/archived` 的数据，例如 `19209`、`19224`、`19249`、`19250` 及其 SKU。
- 清理开发阶段由钉钉新型号流程投产确认派生出的 SKU；这类 SKU 通常自身为 `released`，父级新型号来自 `source_system = 'dingtalk'`，因此不属于工作台默认进行中口径。
- 清理历史种子数据和正式产品线，例如 `NHA4030`、`NFB4020`、`NDN4030`、`NBA4030`、`NWV4030`。

## 4. 保留范围

默认保留：

- `released` / `archived` 产品、型号、SKU。
- 系统用户、角色、权限、工作流模板、编码字典、颜色/机型/物料基础资料。
- 历史导入的归档 SKU/型号数据。
- 钉钉自动同意配置、Docker 环境变量、宝塔部署配置。

特别注意：

- 附件表必须使用 `owner_object_type + owner_object_id` 成组匹配。不能只按 `owner_object_id in (...)` 清理，否则可能误删 `Product=1` 等已发布产品附件。
- 物理附件文件位于 Docker volume `plm_uploads:/app/data/uploads`，数据库清理前要先导出 `storage_key` 清单，数据库清理后再按清单删除文件，不能清空整个 uploads。

## 10. 预检 SQL

```sql
with recursive target_products as (
  select product_id
  from plm_product
  where deleted_flag = 0
    and status in ('draft', 'developing')
  union
  select child.product_id
  from plm_product child
  join target_products parent on child.parent_product_id = parent.product_id
  where child.deleted_flag = 0
),
target_boms as (
  select product_bom_id
  from plm_product_bom
  where deleted_flag = 0 and product_id in (select product_id from target_products)
),
target_routes as (
  select product_bom_route_id
  from plm_product_bom_route
  where deleted_flag = 0
    and (
      product_id in (select product_id from target_products)
      or product_bom_id in (select product_bom_id from target_boms)
    )
),
target_processes as (
  select process_id
  from plm_process
  where deleted_flag = 0 and product_id in (select product_id from target_products)
),
target_orders as (
  select order_id
  from plm_order
  where deleted_flag = 0
    and (
      product_id in (select product_id from target_products)
      or project_id in (select product_id from target_products)
    )
),
target_attachments as (
  select attachment_id
  from plm_attachment
  where deleted_flag = 0
    and (
      (owner_object_type = 'Product' and owner_object_id in (select product_id from target_products))
      or (owner_object_type = 'Order' and owner_object_id in (select order_id from target_orders))
      or (owner_object_type = 'Process' and owner_object_id in (select process_id from target_processes))
    )
)
select 'plm_product' as table_name, count(*) from plm_product where deleted_flag = 0 and product_id in (select product_id from target_products)
union all select 'plm_attachment', count(*) from plm_attachment where deleted_flag = 0 and attachment_id in (select attachment_id from target_attachments)
union all select 'plm_order', count(*) from plm_order where deleted_flag = 0 and order_id in (select order_id from target_orders)
union all select 'plm_integration_record', count(*) from plm_integration_record where deleted_flag = 0 and project_id in (select product_id from target_products)
union all select 'plm_process', count(*) from plm_process where deleted_flag = 0 and process_id in (select process_id from target_processes)
union all select 'plm_product_bom', count(*) from plm_product_bom where deleted_flag = 0 and product_bom_id in (select product_bom_id from target_boms)
order by table_name;
```
