# 2026-08-07 PLM 产品详情分区导航恢复修复沉淀

## 1. 任务理解

产品详情弹窗打开后只显示项目时间轴，原有的 BOM 管理、工序明细和资料区入口消失。

本次任务目标：

- 查明入口消失的实际原因。
- 恢复产品详情页完整分区导航。
- 保留现有 BOM、工序、资料组件和业务流程。
- 增加回归测试，避免同类问题再次发生。

本次任务只涉及前端详情页导航逻辑，不新增 Product 以外的业务根对象，不新增 API、数据库字段、状态或外部系统集成。

## 4. 问题表现

产品详情弹窗可以正常打开，项目时间轴和发布风险检查仍然显示，但详情导航只剩下“项目时间轴”。

因此用户无法从产品详情进入：

- BOM 管理
- 工序明细
- 资料区
- 成本、商务和质量区

截图中出现的 `PRODUCT_STATUS_NOT_REVIEWING`、`BOM_NOT_FROZEN` 等发布风险属于独立的发布门禁提示，不是详情入口消失的原因。

## 5. 根因分析

产品详情页原本已经定义了完整分区：

```ts
const productDetailSections = [
  { key: 'current_node', label: '当前节点' },
  { key: 'basic', label: '基础信息' },
  { key: 'project_flow', label: '项目流程' },
  { key: 'bom_manage', label: 'BOM管理' },
  { key: 'cost', label: '成本管理' },
  { key: 'process_detail', label: '工序明细' },
  { key: 'materials', label: '资料区' },
  { key: 'business', label: '商务区' },
  { key: 'quality', label: '质量区' }
]
```

但当前工作区中的 `activeDetailSections` 被改成了固定只返回一个分区：

```ts
const activeDetailSections = computed(() => [
  { key: 'project_flow', label: '项目时间轴' }
])
```

详情模板的导航使用 `activeDetailSections` 渲染：

```vue
<button
  v-for="section in activeDetailSections"
  :key="section.key"
  class="detail-breadcrumb__item"
  type="button"
  @click="activeDetailSection = section.key"
>
  {{ section.label }}
</button>
```

因此不是组件删除，也不是后端返回数据缺失，而是导航数据源被缩减为一个固定项目流程入口。

## 6. 实施方案

采用最小范围修复：

1. 恢复产品线和 SKU 的详情分区选择逻辑。
2. 产品线详情使用 `productDetailSections`。
3. SKU 详情继续使用 `skuDetailSections`。
4. 不改动 BOM、工序、资料组件的实现。
5. 增加产品详情导航回归测试。
