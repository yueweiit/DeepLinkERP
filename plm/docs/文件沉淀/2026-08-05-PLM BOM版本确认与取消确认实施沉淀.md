# PLM BOM 版本确认与取消确认实施沉淀

日期：2026-08-05  
状态：已实施  
范围：BOM 工作台的版本确认、取消确认，以及取消冻结按钮对编辑流程的影响。

## 1. 需求理解

当前 BOM 工作台的“确认当前 BOM 版本”会打开生产工序确认弹窗，实际操作链路较长；同时冻结按钮会让使用者误以为确认后不能再修正导入错误。

本次调整后的规则：

1. 点击“确认当前 BOM 版本”直接确认当前选中的 BOM 版本。
2. 当前正式版本显示“取消确认”，可以撤销当前正式关系。
3. 确认和取消确认都不冻结 BOM，确认后仍允许维护 BOM 明细、工艺路线和导入数据。
4. `archived` 仍然只读；删除正式发布版本的保守限制仍保留。

## 2. 后端实现

### 2.1 新增接口

| 接口 | 作用 |
|---|---|
| `POST /api/v1/boms/{bomId}/confirm-current-version` | 将当前 BOM 版本设为正式确认版本 |
| `POST /api/v1/boms/{bomId}/cancel-confirmation` | 取消该 BOM 版本的正式确认关系 |

### 2.2 确认规则

后端确认前校验：

- BOM 不能是 `archived`；
- 至少有一条有效工艺路线；
- 每条路线至少有一个有效颜色；
- 每条路线至少有一条有效 BOM 明细；
- 同一个工艺路线不能同时确认多条 BOM 路线。

确认成功后：

- 写入 `plm_product_bom_route_formal_selection` 的 `active` 记录；
- 同一产品、同一工艺路线的旧正式关系改为 `invalidated`；
- BOM 设置为 `bom_scope = formal`、`status = released`；
- 清除 `frozen_flag`、`frozen_at`、`frozen_by`；
- 写入确认时间、确认人和操作日志。

### 2.3 取消确认规则

取消确认只处理当前 BOM 版本对应的有效正式关系：

- 将正式关系改为 `invalidated`；
- 记录失效时间、失效原因和操作人；
- 当前 BOM 不再标记为正式版本，`bom_scope` 回到 `candidate`；
- 清除确认和冻结字段；
- 写入取消确认操作日志。

取消确认不会物理删除历史正式关系，便于审计和追溯。

### 2.4 发布兼容调整

保留旧发布接口以兼容已有调用，但发布不再要求先冻结。当前工作台不再展示冻结和发布按钮，版本正式切换以“确认当前 BOM 版本”为准。

## 3. 前端实现

文件：

- `plm-web/src/views/project/components/ProjectBomPanel.vue`
- `plm-web/src/api/modules/bom.ts`
- `plm-web/src/views/project/ProjectCenterView.vue`

调整内容：

1. 删除 BOM 工作台冻结按钮、冻结标签和冻结状态下的编辑禁用。
2. 确认按钮直接调用确认当前版本接口，并刷新版本列表和工作台。
3. 当前正式版本显示“取消确认”按钮，取消前二次确认，成功后刷新页面状态。
4. 移除 BOM 面板到生产工序确认弹窗的旧事件跳转。
5. 保留归档只读、正式版本不可删除等保守约束。

## 5. 后期维护建议

1. 后续新增“版本确认”入口时统一复用这两个接口，不要直接更新 `currentFormal` 或绕过正式关系表。
2. 如果未来要求取消确认时同步撤销投产工序和投产颜色，应在同一事务中补充对应选择记录的失效处理，并增加跨表测试。
3. 建议后续将 `frozen` 状态逐步收敛为历史兼容状态，避免新流程继续产生冻结数据。
4. 确认前的颜色、明细和成本校验应继续放在后端，前端只负责友好提示。

## 6. 2026-08-05 追加排查与修正

用户复测仍出现 `BOM 已冻结或发布，请复制新版本后修改`。本次复核结论：

1. 当前源码主路径已不存在该错误文案，`ProductBomWorkflowService.requireEditable`、`ProductBomServiceImpl.requireEditableBom` 和 `BomImportServiceImpl` 均已取消冻结/发布导致的编辑拦截，仅保留 `archived` 的只读保护。
2. 本机 `8080` 端口和开发库 `localhost:5433` 均未监听，说明复测错误来自未重启的旧后端、旧 jar/class，或前端代理命中了其他后端实例，而不是当前源码。
3. 为避免残留入口继续把数据推回不可编辑状态，本次进一步移除工艺路线面板的“锁定”操作入口，并允许 `locked`、`confirmed` 路线继续进入编辑。
4. BOM 删除逻辑取消 `frozenFlag=1`、`status=frozen`、`status=released` 的删除拦截；当前正式选用的 BOM 仍建议先执行“取消确认”再删除，避免正式关系被误删。
5. 工艺路线删除逻辑取消 `status=locked` 的删除拦截；仍保留“已被有效 BOM 路线引用时不可直接删除”的数据完整性保护。

后续定位同类问题时，先确认浏览器请求实际命中的后端地址，再确认该后端是否已基于当前源码重新编译并重启；不要只看前端页面状态判断代码是否生效。
