# PLM 钉钉新型号继承来源产品工艺路线、BOM 与生产颜色规则

日期：2026-08-05  
状态：已实施（2026-08-05）

## 1. 业务目标

钉钉新型号审批匹配到已有来源 Product 后，新型号默认继承来源产品的正式研发资料：

1. 工艺路线；
2. 正式 BOM；
3. 已确认的生产颜色。

新型号不是来源产品的简单复制。继承基础资料后，需要根据新手机型号重新生成与手机型号相关的工艺编码和业务编码。

示例：

```text
来源产品：超级队 3.0
来源产品手机型号编码：1291
新型号手机型号编码：1296

继承：
  来源产品正式工艺路线
  来源产品正式 BOM
  来源产品已确认生产颜色

替换：
  工艺路线及工序中与手机型号相关的编码：1291 -> 1296
```

## 2. 来源产品匹配

来源产品只允许是系统中已经存在的 Product，不自动创建来源产品。

匹配优先级应调整为：

1. 钉钉 `TIPO 类型` 字段与 `Product.product_name` 精确匹配；
2. 产品-模具编码关联，用于辅助校验或在 `TIPO 类型` 缺失时兜底；
3. 明确传入的 `parentProductId`；
4. 模具编码提取的 `product_specific_code` 作为历史兜底。

当前业务已确认：钉钉表单中的 `TIPO 类型` 就是来源产品名称，不是泛化类型，也不是产品分类；并且系统内每个产品只有一个名称。因此 `TIPO 类型` 应作为来源产品主匹配字段，必须使用精确匹配，不能使用模糊包含。

名称匹配条件：

```sql
product_name = :tipo
and product_type = 'product_line'
and deleted_flag = 0
```

匹配结果要求：

- 匹配到 1 个产品：继续创建新型号；
- 匹配不到：返回来源产品不存在；
- 匹配到多个：返回主数据重复错误；
- 名称匹配与模具编码关系匹配到不同产品：直接阻断，不允许静默覆盖；
- 不允许因为匹配失败而创建新的来源 Product。

这也解释了当前报错 `模具编码未匹配到系统已有来源产品: BA/HC` 的根因：当前钉钉流程仍主要依赖模具编码关系或从模具编码解析出的产品特定编码，尚未把 `TIPO 类型` 作为产品名称优先匹配。因此只要产品-模具编码关系未导入，或 `BA/HC` 这类编码无法直接对应到已发布来源产品，就会被阻断，即使钉钉表单里已经传了正确的产品名称。

字段口径：

| 钉钉字段 | PLM 含义 | 处理规则 |
| --- | --- | --- |
| `TIPO 类型` | 来源产品名称 | 精确匹配 `plm_product.product_name` |
| `model` / `Modelos 型号` | 新手机型号 | 写入新型号 `model` |
| `phoneModelCode` / `手机型号编码` | 新手机型号编码 | 写入新型号 `phone_model_code`，并用于重生成工艺编码 |
| `moldCodes` / `生成的编码` / `模具编码` | 新型号模具编码 | 用于产品-模具编码关系匹配和模具资料同步 |

## 3. 新型号 Product 主数据

新型号仍然创建为新的 `Product`，类型为 `model_variant`：

| 字段 | 处理规则 |
| --- | --- |
| `parent_product_id` | 写入匹配到的来源产品 ID |
| `product_name` | 使用钉钉 `TIPO 类型` 和手机型号生成 |
| `series_name` | 继承来源产品系列 |
| `model` | 使用钉钉新手机型号 |
| `phone_model_code` | 使用钉钉新手机型号编码 |
| `product_specific_code` | 继承来源产品或从已校验模具编码解析 |
| `color` | 新型号按生产颜色明细管理，不直接复制单一来源颜色 |
| `status` | 新建为 `developing` |

来源产品的 `phone_model_code` 不得覆盖新型号的手机型号编码。

## 4. 生产颜色继承

来源产品必须存在已确认的生产颜色决策：

```text
ProductProductionColorDecision.selected_flag = 1
ProductProductionColorDecision.status = confirmed
deleted_flag = 0
```

继承规则：

1. 读取来源产品全部已确认生产颜色；
2. 在新型号下创建颜色快照；
3. 保留颜色编码、颜色名称、来源决策批次和确认时间；
4. 新型号颜色默认选中；
5. 后续新型号可以在需求确认阶段取消某些颜色；
6. 取消或新增颜色不修改来源产品颜色决策。

如果来源产品没有已确认生产颜色，阻断新型号创建并返回明确错误。

## 5. 工艺路线继承

工艺路线必须从来源产品最新已发布正式 BOM 关联的路线开始继承。

处理流程：

```text
来源产品最新 released formal BOM
  -> 读取 BOM 关联工艺路线
  -> 按新型号生产颜色筛选路线
  -> 复制工艺路线树
  -> 复制工序
  -> 替换新型号手机型号编码
  -> 重新生成目标工序业务编码
  -> 工艺路线状态为 draft
```

### 5.1 需要继承的内容

- 路线名称和路线结构；
- 工序顺序；
- 工序名称；
- 工序类型；
- 工艺参数；
- 标准工时；
- 质量要求；
- 工艺与 BOM 的关联关系；
- 来源工艺路线和来源工序 ID。

### 5.2 必须替换的内容

新型号相关工序中，手机型号编码必须使用新型号的编码：

```text
source.phone_model_code -> target.phone_model_code
```

同时重新生成依赖手机型号编码的字段：

- `business_operation_code`；
- `generated_finished_product_code`；
- 工序参数 JSON 中的 `phoneModelCode`；
- 工艺路线编码中包含的手机型号片段。

不能直接对编码字符串做简单的全局替换。必须根据产品业务编码规则重新生成，避免替换位数不一致或误替换其他字段。

### 5.3 不替换的内容

以下内容原则上沿用来源工艺路线：

- 工序名称；
- 工艺类型；
- 操作工艺编码；
- 物料状态编码；
- 标准工时；
- 质量要求；
- 工艺参数中与手机型号无关的内容。

如果工艺参数中存在结构化手机型号字段，应只更新对应字段，不修改其他参数。

## 6. BOM 继承

BOM 继承来源产品最新已发布正式 BOM：

```text
bom_scope = formal
status = released
deleted_flag = 0
```

继承流程：

```text
来源正式 BOM
  -> 创建新型号 BOM
  -> BOM 来源标记 inherited
  -> 复制已选生产颜色对应的 BOM 路线
  -> 复制 BOM 物料明细
  -> 复制成本快照
  -> 关联新型号复制后的工艺路线
  -> 新 BOM 状态为 draft
```

继承字段：

- 物料；
- 物料数量；
- 单位；
- 损耗率；
- 替代料标记；
- 库存物料关联；
- 单价和币种快照；
- BOM 路线颜色关系；
- 成本快照。

不应直接复用来源 BOM 的主键、路线主键或工序主键。新型号必须创建自己的 BOM、BOM 路线和工艺路线记录，并记录来源 ID。

## 7. 手机型号编码替换规则

新型号手机型号编码来源优先级：

1. 钉钉表单明确传入的 `phoneModelCode`；
2. 模具编码解析出的手机型号编码；
3. 从钉钉手机型号 `model` 中按已确认规则提取。

无法唯一确定手机型号编码时，阻断继承，不使用来源产品的旧编码。

示例：

```text
来源工序业务编码：
NBA1010129101

新型号 phoneModelCode：
1296

新工序业务编码：
根据产品特定编码、工艺编码、新手机型号编码和颜色编码重新生成
```

具体编码格式必须统一调用现有 `ProductBusinessCodeGenerator`，不能在钉钉服务中自行拼接另一套格式。

## 8. 本次实施范围

本次只完成两个目标，不扩大到钉钉字段匹配、连接器代同意、产品-模具编码导入等其他问题：

1. 新型号已经匹配到来源产品后，自动继承来源产品的工艺路线、正式 BOM、生产颜色；
2. 继承过程中，工艺路线/BOM 中依赖手机型号编码的位置必须改为新型号编码。

### 8.1 接入位置

接入点放在钉钉新型号入站创建流程中，即 `DingTalkModelVariantService.receive` 创建新型号 `Product` 成功之后、写入成功集成记录之前。

调用顺序必须保持为：

```text
已匹配来源 Product
  -> 创建新型号 Product
  -> 创建/确认新型号生产颜色快照
  -> 提取新型号已选生产颜色名称
  -> 继承来源产品正式 BOM 关联的工艺路线
  -> 得到 sourceProcessId -> targetProcessId 映射
  -> 继承来源产品最新 released formal BOM
  -> BOM 路线使用新工艺路线 ID 映射
  -> 写入成功集成记录
```

普通产品创建流程已经有可复用实现，钉钉流程应复用同一套服务，不另写一套继承逻辑：

```java
Map<Long, Long> processIdMapping =
    processRouteInheritanceService.inheritLatestReleasedFormalBomRoutesByColors(
        parent.getProductId(),
        targetProduct,
        inheritedColorNames,
        operator
    );

bomInheritanceService.inheritLatestReleasedByColors(
    parent.getProductId(),
    targetProduct.getProductId(),
    inheritedColorNames,
    processIdMapping
);
```

### 8.2 生产颜色继承要求

生产颜色是工艺路线和 BOM 筛选的前置条件。

本次要求：

- 读取来源产品已确认且已选中的生产颜色；
- 在新型号下生成颜色快照；
- `inheritedColorNames` 使用新型号实际继承到的颜色名称；
- 工艺路线继承和 BOM 继承都使用同一组颜色名称；
- 来源产品没有已确认生产颜色时，直接阻断，不创建半成品新型号。

### 8.3 工艺路线继承要求

工艺路线必须从来源产品最新已发布正式 BOM 的关联路线继承，不能从历史 draft 路线或无 BOM 绑定的路线继承。

本次要求：

- 新型号创建自己的工艺路线和工序记录；
- 新路线状态为 `draft`；
- 工序顺序、工序名称、工艺类型、标准工时、质量要求沿用来源；
- 依赖手机型号编码的字段用新型号 `phone_model_code` 重生成；
- 工序业务编码使用 `ProductBusinessCodeGenerator`，不能简单字符串替换；
- 继承后返回 `sourceProcessId -> targetProcessId` 映射，供 BOM 路线重挂。

### 8.4 BOM 继承要求

BOM 必须继承来源产品最新 `released + formal` BOM。

本次要求：

- 新型号创建自己的 BOM 主记录，状态为 `draft`；
- BOM 来源标记为 `inherited`；
- 复制命中生产颜色的 BOM 路线、颜色关系、物料明细、成本快照；
- BOM 路线上的 `process_id` 必须优先使用工艺路线继承返回的新工艺路线 ID；
- 不得继续挂来源产品的旧工艺路线 ID；
- 不得复用来源 BOM、来源 BOM 路线、来源 BOM 明细的主键。

### 8.5 手机型号编码替换边界

新型号编码来自目标 `Product.phone_model_code`。继承前必须保证目标新型号已经写入正确的新手机型号编码。

必须更新或重生成：

- 工序 `phone_model_code`；
- 工序 `business_operation_code`；
- 工序 `generated_finished_product_code`；
- 工序参数 JSON 中结构化的 `phoneModelCode`；
- 由业务编码生成器派生出的成品编码。

不做简单全文替换。来源工艺参数中无法结构化识别的旧文本先保留，并在后续专项治理；本次只处理已有结构化字段和现有编码生成器覆盖的字段。

## 9. 事务与幂等

来源产品匹配、新型号创建、颜色快照、工艺路线继承、BOM 继承和集成记录写入必须处于同一个事务中：

```text
任一步骤失败
  -> 回滚新型号 Product
  -> 回滚颜色快照
  -> 回滚工艺路线
  -> 回滚 BOM
  -> 不写入成功集成记录
```

同一审批实例重复提交时，继续使用现有幂等规则：

- 审批实例内容一致：返回原项目；
- 审批实例内容不一致：返回审批实例 ID 重复错误；
- 不得重复创建新型号、BOM、工艺路线和生产颜色。

## 10. 当前代码差距

当前普通 Product 新型号创建流程已经具备工艺路线和 BOM 继承能力：

- `ProductServiceImpl.create`
- `ProcessRouteInheritanceService`
- `BomInheritanceService`

当前钉钉新型号流程已经完成：

- 来源 Product 匹配；
- 新型号 Product 创建；
- 生产颜色快照；
- 模具资料关联。

但钉钉新型号流程还需要将以下继承动作接入同一事务：

1. 调用 `ProcessRouteInheritanceService.inheritLatestReleasedFormalBomRoutesByColors`；
2. 使用返回的工艺路线 ID 映射调用 `BomInheritanceService.inheritLatestReleasedByColors`；
3. 将目标 Product 的 `phone_model_code` 作为工艺编码重生成上下文；
4. 继承失败时回滚整个钉钉新型号创建。

## 11. 验收标准

1. 在已成功匹配来源产品的前提下，新型号自动复制来源产品已确认生产颜色；
2. 新型号自动继承来源产品最新 `released + formal` BOM；
3. 新型号自动复制来源产品正式 BOM 关联的工艺路线；
4. 新工艺路线和工序属于新型号 Product；
5. 新 BOM 和 BOM 路线属于新型号 Product；
6. BOM 路线关联的是新复制出来的工艺路线 ID，不是来源产品旧工艺路线 ID；
7. 新工艺路线中的手机型号编码为新型号编码；
8. 依赖手机型号的业务编码重新生成；
9. 来源产品旧手机型号编码不出现在新型号工艺路线的结构化编码字段中；
10. 任一步骤失败时不产生半成品项目；
11. 重复审批实例不会重复创建 BOM、工艺路线和颜色快照。

## 12. 实施记录（2026-08-05）

本次仅实施第 8 章定义的两个目标，未调整钉钉连接器配置、来源产品匹配优先级和产品-模具编码导入规则。

### 12.1 已落地代码

在 `DingTalkModelVariantService.receive` 中，新型号创建流程调整为：

```text
创建新型号 Product
  -> 同步模具编码并回填产品特定编码、手机型号编码
  -> 更新新型号 Product 的业务编码字段
  -> 创建来源生产颜色快照
  -> 继承正式 BOM 关联的工艺路线
  -> 使用工艺路线 ID 映射继承正式 BOM
  -> 写入钉钉入站集成成功记录
```

复用现有服务：

- `ProcessRouteInheritanceService.inheritLatestReleasedFormalBomRoutesByColors`
- `BomInheritanceService.inheritLatestReleasedByColors`

### 12.2 手机型号编码处理

新型号 `Product` 在创建时优先写入钉钉传入的 `phone_model_code`；如模具编码同步后解析到更明确的手机型号编码，则在继承前更新目标 Product。

工艺路线继承服务基于目标 Product 的编码上下文重生成：

- 工序 `phone_model_code`；
- `business_operation_code`；
- `generated_finished_product_code`；
- 工序参数 JSON 中的 `phoneModelCode`；
- 与新工艺路线关联的 BOM 路线 `process_id` 和 `route_code`。

### 12.4 后续维护建议

1. 保持钉钉流程与普通 Product 新型号创建流程共用两项继承服务，不复制或分叉继承实现；
2. 后续修改工艺业务编码规则时，同步维护 `ProductBusinessCodeGenerator` 和 `ProcessRouteInheritanceService` 的覆盖测试；
3. 当来源 BOM 或来源生产颜色数据缺失时，保留当前事务回滚策略，不允许生成只有 Product 主数据、没有 BOM/工艺的半成品新型号；
4. 新增多颜色工艺编码规则前，先明确 `Product.color_code` 与单路线颜色编码的关系，再调整工艺路线继承服务。
