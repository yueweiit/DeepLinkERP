# PLM 新产品时间轴完成态收口与项目发布风险折叠方案

## 1. 问题描述

新产品线详情里，时间轴在最后一步确认完成后，页面仍可能保留“进行中 / 当前节点”的视觉语义。

同一张详情页里，“项目发布风险”区域目前是完整展开的长块内容，包含风险项、统计项和发布相关动作，页面占用较高，阅读负担偏重。红框处希望改成折叠形式，默认收起，只在需要时展开查看。

## 2. 现状判断

从当前代码看，这个页面并不是单独一套逻辑，而是和项目中心详情共用一组时间轴与发布门禁能力：

- 时间轴终态依赖后端 `timelineCompleted` 与前端映射。
- 发布风险展示依赖 `ProjectReleaseGatePanel.vue` 的门禁查询结果。
- 产品详情对外展示主要在 `ProjectCenterView.vue` 内完成。

也就是说，这次不是新起一套对象，而是把同一套 Product 详情能力做得更收口。

## 3. 修改目标

1. 新产品线最后一步完成后，时间轴阶段显示“已完成”。
2. 时间轴最后节点不再显示“进行中”。
3. “项目发布风险”区域默认折叠，减少详情页纵向占用。
4. 展开后仍能看到风险项、统计项和发布动作，前后端逻辑不变。
5. 不破坏现有发布、冻结、归档和门禁校验。

## 5. 拟调整逻辑

### 5.1 时间轴完成态

继续沿用统一终态字段 `timelineCompleted`，让新产品线和新型号线共用同一套完成态判断，不再按页面分叉。

示意代码：

```java
boolean timelineCompleted = Boolean.TRUE.equals(product.getTimelineCurrentConfirmed())
    && product.getCurrentStepNo() != null
    && product.getCurrentStepNo() >= definitions.size()
    && isTerminalProductStatus(product.getStatus());

private String resolveNodeStatus(int stepNo, int currentStepNo, boolean timelineCompleted) {
    if (timelineCompleted && stepNo <= currentStepNo) {
        return TimelineNodeConstants.NODE_STATUS_COMPLETED;
    }
    if (stepNo < currentStepNo) {
        return TimelineNodeConstants.NODE_STATUS_COMPLETED;
    }
    if (stepNo == currentStepNo) {
        return TimelineNodeConstants.NODE_STATUS_CURRENT;
    }
    return TimelineNodeConstants.NODE_STATUS_PENDING;
}
```

前端映射继续优先识别 `timelineCompleted`，并在没有 current 节点时回退选中最后一步，避免新产品线在完成后回到第一步。

### 5.2 发布风险折叠

建议把红框里的风险明细和统计信息收进折叠面板，头部保留标题、摘要和“重新预检”按钮。

示意代码：

```vue
<section class="release-gate-panel">
  <div class="release-gate-panel__head">
    <div>
      <h4 class="release-gate-panel__title">项目发布风险</h4>
      <p class="release-gate-panel__desc">检查当前流程与资料完整度；资料缺口会提示确认，不再作为 Product 发布的硬门禁。</p>
    </div>
    <el-button size="small" :loading="loading" @click="loadReleaseGate">重新预检</el-button>
  </div>

  <el-collapse v-model="expandedKeys" class="release-gate-panel__collapse">
    <el-collapse-item name="risk">
      <template #title>
        <span>风险明细</span>
        <el-tag :type="hasBlockingIssues ? 'danger' : hasReleaseRisks ? 'warning' : 'success'" effect="light">
          {{ visibleMissingItems.length ? `待确认 ${visibleMissingItems.length}` : '资料齐备' }}
        </el-tag>
      </template>

      <ul v-if="visibleMissingItems.length" class="release-gate-panel__missing">
        ...
      </ul>

      <div v-if="gate" class="release-gate-panel__stats">
        ...
      </div>
    </el-collapse-item>
  </el-collapse>
</section>
```

折叠后，发布 / 冻结 / 归档按钮仍保留在面板底部，操作链路不变。

## 6. 目标效果

1. 新产品线完成最后一步后，时间轴状态与新型号线一致，统一显示“已完成”。
2. 时间轴最后节点不再持续占用“进行中”语义。
3. 发布风险默认收起，页面更短、更清爽。
4. 用户需要查看资料缺口时再展开，不影响原有发布门禁判断。

## 7. 验收逻辑

1. 打开任一新产品线详情。
2. 完成最后一步确认后刷新。
3. 检查：
   - 时间轴阶段是否显示“已完成”；
   - 最后节点是否仍可查看但不再显示“进行中”；
   - “项目发布风险”是否默认折叠；
   - 展开后风险项、统计项和按钮是否仍可正常操作。
4. 对新产品线和新型号线都要验一次，避免只改到单一流程。

## 8. 风险点

1. 如果只改前端折叠，后端门禁语义不变，发布逻辑不会受影响，但页面只是更省空间。
2. 如果只改时间轴终态，风险区仍会很长，详情页体验还不够收口。
3. 这次建议继续沿用同一套 `timelineCompleted` 和发布门禁接口，不再拆成两套实现。

### 10.4 测试过程中发现并处理的问题
