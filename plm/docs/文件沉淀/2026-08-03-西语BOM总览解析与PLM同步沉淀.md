# 2026-08-03 西语 BOM 总览解析与 PLM 同步沉淀

## 1. 文件结论

解析文件：`Gestión BOM-2026-08-03 (1).xlsx`

这份表**不是完整的 BOM 明细表**，而是一个 ERP 风格的 **BOM 总览/管理清单**。它能支撑：
- BOM 头信息登记
- 父产品与 BOM 编码对照
- 颜色/规格级别的版本归档

如果按正式 BOM 成本和工艺闭环计算，它仍然**缺少关键明细**，尤其是：
- 工艺路线
- 行号
- 物料编码、物料名称、单位、用量
- 单价、行成本、损耗率、替代料标记

但考虑到这批数据已经在历史系统/ERP 中存在，本轮同步目标可以收敛为：**先把 BOM 编码、父产品、颜色规格、来源状态归档到 PLM，缺失字段先用 `--` 或默认值占位，不要求参与复杂成本计算和路线计算。**

## 5. 与 PLM 现状的对齐判断

PLM 里现有 BOM 导入链路是“先预览，再提交”，而且提交时要把**路线 + 颜色 + 物料行**一起落库。当前导入实现依赖的字段远多于这份 Excel。

现有历史 BOM 导入模板至少需要：
- 产品编码
- BOM 版本
- 行号
- 路线编码/名称
- 适用颜色
- 物料编码/名称/规格/单位
- 用量、单价、行成本、损耗率、替代料标记、备注

因此这份文件不建议直接走当前“完整 BOM 明细导入器”。更合适的方式是增加或复用一个**简化历史 BOM 归档口径**：
- 能识别 BOM 头
- 能关联父产品
- 能保留颜色/规格
- 能保留来源和状态
- 缺失路线、物料行和成本字段先占位
- 后续需要精算时，再补完整 BOM 明细

## 6. 推荐同步边界

### 6.1 先简化归档，不做复杂计算

建议把这份表先沉淀成：
- `BOM 总览清单`
- `BOM 编码对照表`
- `后续导入待补数清单`

本轮可以同步，但同步结果应标记为“历史/ERP 归档数据”，不作为新项目正式 BOM 的成本计算依据。

### 6.2 缺失字段默认值

| 缺失字段 | 占位/默认值 | 说明 |
| --- | --- | --- |
| 工艺路线编码 | `--` | 仅表示来源未提供，不自动生成正式路线 |
| 工艺路线名称 | `--` | 不参与工艺中心统计 |
| 行号 | `1` | 如只建占位行，可固定为 1 |
| 物料编码 | `--` | 不匹配库存物料 |
| 物料名称 | `--` | 不进入真实物料成本 |
| 规格 | 来源 `Especificación` | 可作为 BOM 颜色/规格摘要 |
| 单位 | `pcs` | 占位单位 |
| 用量 | `1` | 占位数量，避免数量为空 |
| 单价 | `0` | 不参与成本核算 |
| 行成本 | `0` | 不参与成本核算 |
| 损耗率 | `0` | 不参与成本核算 |
| 替代料标记 | `0` | 默认非替代料 |
| 币种 | `CNY` | 占位币种，可后续按来源调整 |

### 6.3 同步层次

优先做两层同步：

1. **BOM 头登记**
   - `Código BOM`
   - `Código padre`
   - `Nombre padre`
   - `Estado`
   - `Especificación`
   - `Origen`

2. **占位明细登记**
   - 缺失路线使用 `--`
   - 缺失物料使用 `--`
   - 数量、单价、损耗率使用默认值
   - 备注中保留 `Componentes`、`SKUs asociados`、`Especificación`

这样可以先完成历史 BOM 的归档可见性，后续再按真实明细补齐。

## 7. 建议的 PLM 映射口径

| 目标对象 | 可用字段 | 处理方式 |
| --- | --- | --- |
| `Product` | `Código padre`、`Nombre padre` | 作为产品主数据识别键和名称快照 |
| `ProductBom` | `Código BOM`、`Estado`、`Origen` | 可作为历史/ERP 归档 BOM 头 |
| `ProductBomRoute` | 无 | 使用 `--` 占位，不进入正式工艺路线统计 |
| `ProductBomItem` | 无 | 使用 `--` 占位物料，数量 `1`，成本 `0` |
| `归档备注` | `Componentes`、`SKUs asociados`、`Especificación` | 可作为摘要字段保留 |

## 8. 最终判断

这份 Excel 更适合进入 PLM 的**历史/ERP BOM 归档层**，不建议作为需要成本核算和工艺闭环的新项目正式 BOM。

当前建议是：
- 可以先导入或同步 BOM 头及占位明细
- 缺失字段统一使用 `--` 或默认值
- 已导入的历史数据不做复杂成本计算
- 后续若要参与正式报价、生产和成本分析，再补齐 BOM 明细和路线数据

## 9. 本次代码实施沉淀

### 9.1 后端改动

修改 `HistoricalBomImportService`，历史 BOM 导入接口现在同时识别两种文件：

1. 原有历史 BOM 明细模板
2. `Gestión BOM` ERP BOM 总览模板

ERP BOM 总览识别规则：
- 在前 20 行内寻找西语表头
- 读取 `Código BOM`、`Código padre`、`Nombre padre`、`Componentes`、`SKUs asociados`、`Estado`、`Especificación`、`Origen`
- 父级产品先按完整 `Código padre` 匹配，匹配不到时按前 7 位产品线编码匹配，例如 `NBA4030000001` 匹配 `NBA4030`
- `Código BOM` 直接作为 PLM BOM 编码和历史版本号，避免同一产品不同颜色版本冲突

### 9.2 占位归档规则

ERP 总览提交后：
- 创建 `formal` 范围的已发布、已冻结历史 BOM
- `source_type` 使用来源字段，默认 `erp`
- 创建一条占位路线：`route_code=--`、`route_name=--`、`process_id=0`
- 创建一条占位颜色/规格记录
- 创建一条占位 BOM 明细：物料编码和名称为 `--`，数量为 `1`，单位为 `pcs`，单价、行成本、损耗率为 `0`
- 占位行标记 `unmatched_flag=1`、`material_source=manual`
- 组件数、关联 SKU 数、来源状态等原始摘要写入 BOM 和明细备注
- 不调用正式 BOM 工作台的路线校验和成本计算逻辑

`process_id=0` 仅用于兼容现有 `plm_product_bom_route.process_id` 非空表结构；该路线通过 `variant_source_type=erp_archive_placeholder` 标识为归档占位路线，不作为真实工艺路线使用。
