# 2026-08-07 PLM 产品工序编码分阶段手工填写与机型颜色追加修订方案

## 0. 文档目的

本方案用于沉淀“新产品 / 新型号线 / 具体 SKU”三阶段产品工序编码规则修订。

新口径：

1. 新产品线阶段，产品工序编码允许人工填写。
2. 新型号线阶段，在产品线手工产品工序编码基础上追加手机型号编码。
3. 创建具体 SKU，即具体颜色阶段，在新型号线编码基础上追加颜色编码。

本次只沉淀方案和代码草稿，不修改业务源码、不调整数据库、不执行生产数据修正。

## 2. 任务理解

上一版方案把 `businessOperationCode` 主要定义为 SKU 级正式产品工序编码，产品线阶段保持为空。

本次修订后，业务口径变为“产品工序编码逐级成形”：

| 阶段 | 允许填写 / 生成 | 示例 | 字段建议 |
| --- | --- | --- | --- |
| 新产品线 | 人工填写产品工序基础编码 | `NHD1010` | `businessOperationCode` |
| 新型号线 | 在产品线编码后追加手机型号编码 | `NHD10101801` | `businessOperationCode` |
| 具体 SKU / 颜色 | 在新型号线编码后追加颜色编码 | `NHD1010180102` | `businessOperationCode` |

其中：

- `operationCraftCode` 仍表示工序编码段，例如 `1010`、`1020`、`4030`。
- `businessOperationCode` 表示业务侧产品工序编码，从产品线阶段开始存在，并在后续阶段追加后缀。
- `phoneModelCode` 为 4 位手机型号编码。
- `colorCode` 为 2 位颜色编码。
- 不新增 `SKU`、`PhoneModel`、`Routing`、`Operation` 等根对象。

## 3. 所属 PLM 业务链路

所属主线：

- 新产品线。
- 新型号线。

业务链路：

```text
新产品线立项
  -> 新建产品线工艺路线
  -> 人工填写工序名称、工序编码段、产品工序基础编码
  -> 新型号线继承产品线工艺路线
  -> 系统追加手机型号编码
  -> 创建具体 SKU / 颜色
  -> 系统追加颜色编码
  -> 形成最终 SKU 级产品工序编码
```

核心对象：

- `Product`：承载产品线、新型号、具体 SKU / 颜色维度。
- `Process`：承载工艺路线、工序、编码和参数。

## 4. 目标效果

### 4.1 产品线阶段

用户新建工艺路线时可以人工填写：

- 工序名称：`processName`
- 工序编码段：`operationCraftCode`
- 产品工序编码：`businessOperationCode`

示例：

```json
{
  "processName": "注塑成型",
  "operationCraftCode": "1010",
  "businessOperationCode": "NHD1010",
  "productSpecificCode": "HD",
  "phoneModelCode": null,
  "colorCode": null,
  "codeGenerationContext": "product_line_route"
}
```

### 4.2 新型号线阶段

新型号线继承产品线工艺路线后，系统在产品线产品工序编码后追加手机型号编码。

示例：

```json
{
  "processName": "注塑成型",
  "operationCraftCode": "1010",
  "businessOperationCode": "NHD10101801",
  "productSpecificCode": "HD",
  "phoneModelCode": "1801",
  "colorCode": null,
  "codeGenerationContext": "model_variant_route"
}
```

### 4.3 具体 SKU / 颜色阶段

具体 SKU 生成时，在新型号线产品工序编码后追加颜色编码。

示例：

```json
{
  "processName": "注塑成型",
  "operationCraftCode": "1010",
  "businessOperationCode": "NHD1010180102",
  "productSpecificCode": "HD",
  "phoneModelCode": "1801",
  "colorCode": "02",
  "codeGenerationContext": "sku_route"
}
```

## 5. 编码逻辑

### 5.1 推荐规则

为保持可追溯和可校验，推荐产品线阶段的人工产品工序编码采用以下基础结构：

```text
产品线产品工序编码 = N + product_specific_code + operation_craft_code
```

新型号线追加：

```text
新型号线产品工序编码 = 产品线产品工序编码 + phone_model_code
```

具体 SKU 追加：

```text
SKU 产品工序编码 = 新型号线产品工序编码 + color_code
```

完整示例：

```text
产品线：NHD1010
新型号：NHD10101801
SKU：NHD1010180102
```

### 5.2 人工覆盖规则

产品线阶段：

- 用户可以人工填写 `businessOperationCode`。
- 前端可根据 `productSpecificCode + operationCraftCode` 给出默认预览，但不能强制覆盖用户输入。
- 后端必须校验人工编码格式。

新型号线阶段：

- 默认从产品线继承基础产品工序编码。
- 如果目标产品具备 `phoneModelCode`，系统追加 4 位手机型号编码。
- 如果用户已有人工覆盖的新型号产品工序编码，应保留人工值，但必须校验其后缀与 `phoneModelCode` 一致。

具体 SKU 阶段：

- 默认从新型号线继承产品工序编码。
- 如果目标 SKU 具备 `colorCode`，系统追加 2 位颜色编码。
- 如果用户已有人工覆盖的 SKU 产品工序编码，应保留人工值，但必须校验其后缀与 `phoneModelCode + colorCode` 一致。

### 5.3 上下文标识

继续复用 `codeGenerationContext`：

| 上下文 | 编码长度口径 | 后缀要求 |
| --- | --- | --- |
| `product_line_route` | `N + productSpecific + operationCraftCode` | 不要求手机型号和颜色 |
| `model_variant_route` | 产品线编码 + 4 位手机型号编码 | 必须有 `phoneModelCode` |
| `sku_route` | 新型号编码 + 2 位颜色编码 | 必须有 `phoneModelCode` 和 `colorCode` |

```ts
function baseBusinessOperationCode(operation: ProcessOperationSavePayload) {
  const manual = operation.businessOperationCode?.trim().toUpperCase()
  if (manual) return manual
  const productSpecificCode = normalizeBusinessCode(
    operation.productSpecificCode || props.productSpecificCode || deriveProductSpecificCode(),
    ''
  )
  const operationCraftCode = findOperationCraftCode(operation)
  if (!productSpecificCode || !operationCraftCode) return ''
  return `N${productSpecificCode}${operationCraftCode}`.toUpperCase()
}

function stagedBusinessOperationCode(operation: ProcessOperationSavePayload) {
  const baseCode = baseBusinessOperationCode(operation)
  if (!baseCode) return ''
  if (isProductLineRoute.value) return baseCode

  const phoneModelCode = normalizeBusinessCode(operation.phoneModelCode || props.phoneModelCode, '')
  if (!phoneModelCode) return baseCode
  if (props.productType === 'model_variant') return `${baseCode}${phoneModelCode}`.toUpperCase()

  const colorCode = normalizeBusinessCode(operation.colorCode || props.colorCode, '')
  if (!colorCode) return `${baseCode}${phoneModelCode}`.toUpperCase()
  return `${baseCode}${phoneModelCode}${colorCode}`.toUpperCase()
}

function businessOperationCodePlaceholder(operation: ProcessOperationSavePayload) {
  const preview = stagedBusinessOperationCode(operation)
  if (preview) return `建议：${preview}`
  if (isProductLineRoute.value) return '输入产品工序编码，如 NHD1010'
  if (props.productType === 'model_variant') return '继承产品线编码后追加手机型号编码'
  return '继承新型号编码后追加颜色编码'
}
```

```ts
function validateBusinessOperationCodeByStage(operation: ProcessOperationSavePayload) {
  const code = operation.businessOperationCode?.trim().toUpperCase()
  if (!code) return `顺序 ${operation.sequenceNo} 的产品工序编码不能为空`
  if (!/^[A-Z0-9_-]{2,80}$/.test(code)) {
    return `顺序 ${operation.sequenceNo} 的产品工序编码格式不正确`
  }
  if (!code.startsWith('N')) {
    return `顺序 ${operation.sequenceNo} 的产品工序编码必须以 N 开头`
  }
  const phoneModelCode = normalizeBusinessCode(operation.phoneModelCode || props.phoneModelCode, '')
  const colorCode = normalizeBusinessCode(operation.colorCode || props.colorCode, '')
  if (props.productType === 'model_variant' && phoneModelCode && !code.endsWith(phoneModelCode)) {
    return `顺序 ${operation.sequenceNo} 的产品工序编码必须追加手机型号编码 ${phoneModelCode}`
  }
  if (props.productType === 'sku' && phoneModelCode && colorCode && !code.endsWith(`${phoneModelCode}${colorCode}`)) {
    return `顺序 ${operation.sequenceNo} 的产品工序编码必须追加手机型号编码 ${phoneModelCode} 和颜色编码 ${colorCode}`
  }
  return ''
}
```

### 8.1 分阶段产品工序编码解析

```java
private String resolveBusinessOperationCode(ProcessOperationDTO dto, String operationCraftCode,
                                            CodeGenerationContext codeContext) {
    String manualCode = normalizeBusinessOperationCode(dto.getBusinessOperationCode());
    String baseCode = StringUtils.hasText(manualCode)
        ? manualCode
        : buildProductLineBusinessOperationCode(codeContext.productSpecificCode(), operationCraftCode);

    if ("product_line_route".equals(codeContext.contextName())) {
        validateProductLineBusinessOperationCode(baseCode, codeContext.productSpecificCode(), operationCraftCode);
        return baseCode;
    }

    if ("model_variant_route".equals(codeContext.contextName())) {
        String modelCode = appendSuffixIfMissing(baseCode, codeContext.phoneModelCode());
        validateModelVariantBusinessOperationCode(modelCode, codeContext.phoneModelCode());
        return modelCode;
    }

    String skuCode = appendSuffixIfMissing(
        appendSuffixIfMissing(baseCode, codeContext.phoneModelCode()),
        codeContext.colorCode()
    );
    validateSkuBusinessOperationCode(skuCode, codeContext.phoneModelCode(), codeContext.colorCode());
    return skuCode;
}

private String buildProductLineBusinessOperationCode(String productSpecificCode, String operationCraftCode) {
    if (!StringUtils.hasText(productSpecificCode) || !StringUtils.hasText(operationCraftCode)) {
        return null;
    }
    return ProductBusinessCodeGenerator.PRODUCT_STATE_PREFIX
        + normalizeCompactCode(productSpecificCode)
        + normalizeOperationCraftCode(operationCraftCode);
}

private String appendSuffixIfMissing(String value, String suffix) {
    if (!StringUtils.hasText(value) || !StringUtils.hasText(suffix)) {
        return value;
    }
    String normalizedValue = normalizeBusinessOperationCode(value);
    String normalizedSuffix = normalizeCompactCode(suffix);
    return normalizedValue.endsWith(normalizedSuffix)
        ? normalizedValue
        : normalizedValue + normalizedSuffix;
}
```

### 8.2 后端分阶段校验

```java
private void validateProductLineBusinessOperationCode(String code, String productSpecificCode,
                                                      String operationCraftCode) {
    validateBusinessOperationCode(code);
    if (!code.startsWith(ProductBusinessCodeGenerator.PRODUCT_STATE_PREFIX)) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "产品工序编码必须以 N 开头");
    }
    String expectedSuffix = normalizeCompactCode(productSpecificCode) + normalizeOperationCraftCode(operationCraftCode);
    if (StringUtils.hasText(expectedSuffix) && !code.endsWith(expectedSuffix)) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR,
            "产品线产品工序编码必须包含产品特定编码和工序编码");
    }
}

private void validateModelVariantBusinessOperationCode(String code, String phoneModelCode) {
    validateBusinessOperationCode(code);
    if (!StringUtils.hasText(phoneModelCode) || !phoneModelCode.matches("[A-Z0-9]{4}")) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR,
            "新型号线产品工序编码必须具备 4 位手机型号编码");
    }
    if (!code.endsWith(phoneModelCode)) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR,
            "新型号线产品工序编码必须追加手机型号编码");
    }
}

private void validateSkuBusinessOperationCode(String code, String phoneModelCode, String colorCode) {
    validateModelVariantBusinessOperationCode(code, phoneModelCode);
    if (!StringUtils.hasText(colorCode) || !colorCode.matches("[A-Z0-9]{2}")) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR,
            "SKU 产品工序编码必须具备 2 位颜色编码");
    }
    if (!code.endsWith(phoneModelCode + colorCode)) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR,
            "SKU 产品工序编码必须追加手机型号编码和颜色编码");
    }
}
```

```java
private CodeGenerationContext resolveCodeGenerationContext(Product product, ProcessOperationDTO dto,
                                                           String operationCraftCode) {
    String contextName = resolveCodeGenerationContextName(product);
    String productSpecificCode = normalizeCompactCode(firstText(
        dto.getProductSpecificCode(),
        product.getProductSpecificCode()
    ));
    String phoneModelCode = normalizeCodeOrNull(firstText(
        dto.getPhoneModelCode(),
        product.getPhoneModelCode()
    ));
    String colorCode = normalizeCodeOrNull(firstText(dto.getColorCode(), product.getColorCode()));

    if ("product_line_route".equals(contextName)) {
        phoneModelCode = null;
        colorCode = null;
    }
    if ("model_variant_route".equals(contextName)) {
        colorCode = null;
        validatePhoneModelCode(phoneModelCode);
    }
    if ("sku_route".equals(contextName)) {
        validateConcreteCodeContext(phoneModelCode, colorCode);
    }

    return new CodeGenerationContext(
        productSpecificCode,
        normalizeOperationCraftCode(operationCraftCode),
        phoneModelCode,
        colorCode,
        contextName
    );
}
```

```java
private String resolveInheritedBusinessOperationCode(ProcessEntity source, CodeGenerationContext targetContext) {
    String sourceCode = normalizeBusinessOperationCode(source.getBusinessOperationCode());
    String baseCode = StringUtils.hasText(sourceCode)
        ? sourceCode
        : buildProductLineBusinessOperationCode(
            targetContext.productSpecificCode(),
            source.getOperationCraftCode()

            targetContext.colorCode()
        );
    }
    return baseCode;
}
```

## 11. 验收标准

1. 新产品线新建工艺路线时，产品工序编码输入框可编辑。
2. 产品线阶段可保存 `NHD1010` 这类人工产品工序基础编码。
3. 新型号线具备 `phoneModelCode=1801` 时，继承后编码变为 `NHD10101801`。
4. 具体 SKU 具备 `colorCode=02` 时，继承后编码变为 `NHD1010180102`。
5. 人工覆盖编码时，系统不随意覆盖用户输入，但必须校验后缀和当前阶段上下文一致。
6. 后端校验缺少手机型号编码、颜色编码、编码格式错误时返回业务错误，不进入数据库异常。
7. 操作日志、状态流转、冻结、删除、BOM 关联保护保持现有逻辑。
8. 前端单测、后端单测、类型检查和 Playwright 验证通过。

## 12. 风险点

1. 如果继续在产品线阶段清空 `businessOperationCode`，将不满足“新产品时产品工序编码也可人工填写”的新口径。
2. 如果产品线人工编码不校验产品特定编码和工序编码段，后续追加手机型号和颜色时可能生成不可追溯编码。
3. 如果新型号线重复追加手机型号编码，可能出现 `NHD101018011801`。
4. 如果 SKU 阶段重复追加颜色编码，可能出现 `NHD101018010202`。
5. 如果人工覆盖允许与当前 `phoneModelCode`、`colorCode` 不一致，会破坏 SKU 编码追溯。

## 13. 结论

推荐将 `businessOperationCode` 调整为“分阶段产品工序编码”：

```text
产品线：人工填写基础产品工序编码
新型号线：基础产品工序编码 + 手机型号编码
SKU：基础产品工序编码 + 手机型号编码 + 颜色编码
```

这样既满足产品线阶段人工填写产品工序编码，又能在新型号线和具体 SKU 阶段保持自动追加、校验和追溯一致。

### 14.2 已落地逻辑

1. 产品线阶段：`businessOperationCode` 支持人工填写并保存，例如 `NHD1010A`；如用户未填写且产品特定码、工序编码齐全，前后端可生成基础码，例如 `NHD1010`。
2. 新型号线阶段：以前一阶段基础产品工序编码为基础，自动追加 4 位 `phoneModelCode`，例如 `NHD1010` -> `NHD10101801`。
3. SKU 阶段：在新型号线编码后继续追加 2 位 `colorCode`，例如 `NHD10101801` -> `NHD1010180102`。

6. 人工覆盖时不随意覆盖用户输入，但会校验当前阶段应追加的后缀，避免重复追加或漏追加导致追溯断裂。
7. 不新增 `SKU`、`PhoneModel`、`Routing` 等根对象，不新增数据库字段，不引入 ERP/MES 正式集成。
