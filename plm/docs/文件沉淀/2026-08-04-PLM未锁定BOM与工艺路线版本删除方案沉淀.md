# 2026-08-04 PLM 未锁定 BOM 与工艺路线版本删除方案沉淀

## 1. 背景

当前项目中心已经支持：

- BOM 明细删除：`DELETE /api/v1/boms/{bomId}/items/{itemId}`
- BOM 冻结 / 发布：`POST /api/v1/boms/{bomId}/freeze`、`POST /api/v1/boms/{bomId}/publish`
- 工艺路线锁定：`POST /api/v1/process-routes/{processId}/freeze`
- 工艺路线编辑：`PUT /api/v1/process-routes/{processId}`

但还没有完整的“删除 BOM 版本”和“删除工艺路线版本”能力。业务诉求是：

> 未锁定的 BOM 和工艺路线，可以删除对应版本。

本方案只沉淀规则和实施口径，先不改代码。

## 2. 所属业务链路

| 业务链路 | 说明 |
| --- | --- |
| Product 研发资料维护 | BOM 版本、工艺路线版本都归属 Product，不新增 BOM / Routing 根对象 |
| BOM 资料维护 | 删除未冻结、未发布的 BOM 版本 |
| Process 工艺路线维护 | 删除未锁定的工艺路线版本及其子级工序 |
| 版本追溯 | 已锁定、已冻结、已发布资料不能物理删除，只能保留追溯或后续走归档/作废流程 |

核心对象仍然只使用：

- `Product`
- `Process`

BOM 仍然是 `Product` 下的业务资料表，不作为根对象；工艺路线仍然是 `Process` 的 `process_type=routing`，不新增 `Routing` 根对象。

## 3. 删除定义

本方案中的“删除版本”统一采用软删除：

```text
deleted_flag = 1
updated_at = now()
updated_by = currentUser
```

不做物理删除。原因：

- 便于操作日志追溯。
- 避免破坏历史导入、成本快照、BOM 与工艺关联链路。
- 符合现有表结构中的 `deleted_flag` 口径。

## 4. 状态边界

### 4.1 BOM 可删除条件

BOM 版本允许删除的条件：

| 条件 | 规则 |
| --- | --- |
| `deleted_flag` | 必须为 `0` |
| `status` | 只能是 `draft`、`reviewing` 等未发布状态 |
| `frozen_flag` | 不能为 `1` |
| 发布状态 | `status=released` 禁止删除 |
| 正式选用 | 如果已被当前正式 BOM 选择记录引用，禁止直接删除 |
| 成本/发布追溯 | 已冻结、已发布、已产生正式投产确认的 BOM 禁止删除 |

当前明确禁止删除：

```text
status in ('released', 'archived')
frozen_flag = 1
```

### 4.2 工艺路线可删除条件

工艺路线版本允许删除的条件：

| 条件 | 规则 |
| --- | --- |
| `process_type` | 必须为 `routing` |
| `deleted_flag` | 必须为 `0` |
| `status` | 不能是 `locked` |
| 子级工序 | 随路线一起软删除 |
| BOM 引用 | 如果被已冻结 / 已发布 BOM 引用，禁止删除 |
| 未锁定 BOM 引用 | 可提示影响范围，建议先删除或解除 BOM 关联 |

当前明确禁止删除：

```text
process_type = 'routing'
status = 'locked'
```

## 5. BOM 删除范围

删除一个 BOM 版本时，应软删除以下数据：

| 表 | 条件 |
| --- | --- |
| `plm_product_bom` | `product_bom_id = bomId` |
| `plm_product_bom_route` | `product_bom_id = bomId` |
| `plm_product_bom_route_color` | `product_bom_id = bomId` |
| `plm_product_bom_item` | `product_bom_id = bomId` |
| `plm_product_bom_cost_snapshot` | `product_bom_id = bomId`，如果表结构使用软删除则同步软删；否则保留为历史快照 |
| `plm_product_bom_route_formal_selection` | 如引用该 BOM，需先校验并阻止删除，或同步软删除未生效选择 |

建议第一版实现采用保守策略：

- 如果 BOM 已经被正式选用或发布，直接禁止删除。
- 如果只是草稿 / 审核中版本，允许删除，同时软删其路线、颜色、明细。

## 6. 工艺路线删除范围

删除一个工艺路线版本时，应软删除：

| 表 | 条件 |
| --- | --- |
| `plm_process` 路线头 | `process_id = processId`、`process_type = routing` |
| `plm_process` 子级工序 | `parent_process_id = processId`、`process_type = operation` |

删除前必须检查 BOM 引用：

```sql
select *
from plm_product_bom_route r
join plm_product_bom b on b.product_bom_id = r.product_bom_id
where r.process_id = :processId
  and r.deleted_flag = 0
  and b.deleted_flag = 0;
```

处理建议：

| 引用情况 | 处理 |
| --- | --- |
| 没有 BOM 引用 | 允许删除路线和子级工序 |
| 仅被未锁定 BOM 引用 | 第一版建议提示“请先删除/调整关联 BOM 版本”，不自动级联 |
| 被冻结 / 发布 BOM 引用 | 禁止删除 |

不建议第一版自动级联删除关联 BOM。原因是工艺路线可能被多个 BOM 版本共享，自动级联容易误删 Product 下的 BOM 资料。

## 7. 后端接口草案

### 7.1 删除 BOM 版本

```text
DELETE /api/v1/boms/{bomId}
```

返回：

```json
{
  "code": 0,
  "message": "success",
  "data": null
}
```

后端服务方法建议：

```java
ProductBomVO deleteVersion(Long bomId, HttpServletRequest request);
```

校验失败示例：

| 场景 | 错误 |
| --- | --- |
| BOM 不存在 | `RESOURCE_NOT_FOUND` |
| BOM 已冻结 | `VERSION_FROZEN` |
| BOM 已发布 | `VALIDATION_ERROR` |
| BOM 已被正式选用 | `VALIDATION_ERROR` |

### 7.2 删除工艺路线版本

```text
DELETE /api/v1/process-routes/{processId}
```

后端服务方法建议：

```java
ProcessRouteVO deleteVersion(Long processId, HttpServletRequest request);
```

或返回 `Void`：

```java
void deleteVersion(Long processId, HttpServletRequest request);
```

校验失败示例：

| 场景 | 错误 |
| --- | --- |
| 工艺路线不存在 | `RESOURCE_NOT_FOUND` |
| 工艺路线已锁定 | `VERSION_FROZEN` |
| 被冻结 / 发布 BOM 引用 | `VALIDATION_ERROR` |
| 被未锁定 BOM 引用 | `VALIDATION_ERROR`，提示先解除 BOM 关联 |

## 8. 操作日志

必须记录操作日志。

建议新增或复用动作常量：

| 动作 | 说明 |
| --- | --- |
| `BOM_DELETE` | 删除 BOM 版本 |
| `PROCESS_ROUTE_DELETE` | 删除工艺路线版本 |

日志内容建议：

```json
{
  "action": "delete",
  "bomId": 123,
  "versionNo": "V1",
  "reason": "未锁定版本删除"
}
```


## 9. 前端交互

### 9.1 BOM 面板

位置：

```text
plm-web/src/views/project/components/ProjectBomPanel.vue
```

建议增加按钮：

```text
删除版本
```

显示条件：

- 当前选中 BOM 存在。
- `status !== released`
- `frozenFlag !== 1`
- 当前不是正式选用版本。

交互：

- 二次确认。
- 确认文案必须包含 BOM 编码和版本号。
- 删除成功后刷新 BOM 列表。
- 如果删除的是当前选中项，自动选中剩余第一条。

### 9.2 工艺路线面板

位置：

```text
plm-web/src/views/project/components/ProjectProcessRoutePanel.vue
```

建议增加按钮：

```text
删除路线版本
```

显示条件：

- 当前选中路线存在。
- `status !== locked`

交互：

- 二次确认。
- 确认文案必须包含路线编码、路线名称、版本号。
- 删除成功后刷新路线列表。
- 如果该路线被 BOM 引用，后端返回清晰提示，前端直接展示。

## 10. 测试验收

### 10.1 BOM 删除测试

| 用例 | 预期 |
| --- | --- |
| 删除 `draft` BOM | BOM 头、路线、颜色、明细均软删除 |
| 删除 `reviewing` 且未冻结 BOM | 允许删除 |
| 删除 `frozen_flag=1` BOM | 拒绝 |
| 删除 `status=released` BOM | 拒绝 |
| 删除被正式选用 BOM | 拒绝 |
| 删除后列表刷新 | 不再展示该 BOM |

### 10.2 工艺路线删除测试

| 用例 | 预期 |
| --- | --- |
| 删除 `draft` 路线 | 路线头和子级工序均软删除 |
| 删除 `locked` 路线 | 拒绝 |
| 删除被冻结 / 发布 BOM 引用路线 | 拒绝 |
| 删除被未锁定 BOM 引用路线 | 第一版拒绝并提示先处理 BOM |
| 删除后列表刷新 | 不再展示该路线 |

## 11. 风险点

1. 工艺路线可能被多个 BOM 版本引用，不能直接级联误删。
2. BOM 成本快照是否软删取决于实体和表结构，实施前要确认 `plm_product_bom_cost_snapshot` 是否有 `deleted_flag`。
3. 已导入历史 BOM 可能处于 `released` 状态但来源是 ERP 归档，是否允许删除需要业务确认。建议默认不允许删除 released 历史归档。
4. 删除不是作废。后续如果需要保留“已作废但可见”的版本，应新增 `archive/void` 动作，而不是复用删除。
5. 前端按钮隐藏不能替代后端校验，后端必须强制判断状态和引用关系。

## 12. 第一版实施建议

第一版按保守策略实现：

- 只允许删除未冻结 / 未发布 BOM。
- 只允许删除未锁定工艺路线。
- 工艺路线若被任何 active BOM 引用，先拒绝删除。
- 全部采用软删除。
- 必须写操作日志。
- 不新增核心对象，不新增 BOM / Routing 根对象。

这样可以满足“未锁定版本可删除”的主需求，同时避免误删已进入正式 BOM、投产确认或历史追溯的数据。
## 13. 实施结果

本次代码已按沉淀文档落地：

- BOM 版本删除接口已增加：`DELETE /api/v1/boms/{bomId}`
- 工艺路线版本删除接口已增加：`DELETE /api/v1/process-routes/{processId}`
- BOM 删除采用软删，已同步处理：
  - `plm_product_bom`
  - `plm_product_bom_route`
  - `plm_product_bom_route_color`
  - `plm_product_bom_item`
  - `plm_product_bom_cost_snapshot`
  - `plm_product_bom_route_formal_selection`
- 工艺路线删除采用软删，已同步处理：
  - 路线主表 `plm_process`
  - 子工序 `plm_process` 记录
- 前端已补入口按钮：
  - BOM 工作台增加“删除版本”
  - 工艺路线面板增加“删除版本”
- 约束已生效：
  - 已冻结 / 已发布 / 已归档 BOM 不可删
  - 已正式选用 BOM 不可删
  - 已锁定工艺路线不可删
  - 仍被有效 BOM 关联的工艺路线不可删
- 2026-08-04 追加修复：
  - 操作日志写入改为不参与业务事务，避免日志表结构、约束或临时写入异常把 BOM / 工艺路线删除主事务打成 500。

当前目标效果已达成：未锁定、未发布、未正式选用的 BOM 版本和未锁定且未被有效 BOM 关联的工艺路线版本，可以在系统内删除对应版本，且全程只做软删除。
