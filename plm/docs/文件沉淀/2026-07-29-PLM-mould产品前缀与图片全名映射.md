## 2. 编码识别规则

模具编码导入时不重组、不改写：

```text
模具编码 = 文件中传过来的 mould_code 原值
```

产品本身特征编码只用于映射产品，不改变模具编码本身。取值规则为：

```text
产品本身特征编码 = 模具编码第 2 位 + 第 3 位
```

示例：

```text
MBA10 -> 模具编码 MBA10，产品本身特征编码 BA
MBD20 -> 模具编码 MBD20，产品本身特征编码 BD
MHB10 -> 模具编码 MHB10，产品本身特征编码 HB
LLT10 -> 模具编码 LLT10，产品本身特征编码 LT
```

说明：

- 第 1 位不是产品特征编码的一部分，当前多数为 `M`，但如 `LLT10` 也按原值保留。
- 第 4、5 位是材质、结构件或工艺短码，不参与产品本身特征编码提取。
- `10` 常见对应 TPU，`20` 常见对应 PC；`21/23/24/25/26/40/42` 等是特殊结构件或特殊工序短码。
- 后续导入模具资料时，`mould_code` 应保持原始值；产品映射字段使用第 2、3 位得到的产品本身特征编码。

## 6. 后续使用建议

1. 导入产品主数据时，优先把 `产品编码前缀` 落到 `product_specific_code`。
2. 图片 / 选项里的展示名可以作为 `product_name` 或别名沉淀，但自动匹配应优先使用产品编码前缀。
3. 对 `MPO10` 这类多名称共用编码的数据，不建议静默自动映射，应在导入前人工确认；`LLT10` 可按第 2、3 位提取 LT，但模具编码仍保留 `LLT10` 原值。
4. 如果后续要生成导入模板，可按第 3 节映射先生成 11 条已有产品数据，再按 `product_specific_code` 关联模具、工艺和成品编码。

## 7. 清理旧规则方案

旧规则中曾将模具编码理解为：

```text
模具编码 = M + 产品编码前缀 + 材质 / 工艺短码
产品编码前缀 = 去掉首位 M，再去掉末尾两位短码
```

该规则需要清理，避免后续导入或匹配时错误改写模具编码。

清理目标：

1. 删除或废弃“模具编码必须以 M 开头”的判断。
2. 删除或废弃“去掉首位 M、再去掉末尾两位”的产品前缀解析逻辑。
3. 保留 `mould_code` 原值作为模具编码主数据，不做重组、不做标准化改写。
4. 新增或统一使用“第 2、3 位”为产品本身特征编码的解析方式。
5. 将历史文档、导入转换脚本、模板说明中涉及旧规则的描述统一替换为本方案。

建议实施步骤：

1. 全局搜索旧规则关键词：`去掉首位 M`、`去掉末尾两位`、`必须以 M 开头`、`M + 产品编码前缀`。
2. 对代码或脚本中的旧解析逻辑，改为：

```text
product_specific_code = mould_code.substring(1, 3)
```

3. 对 `LLT10` 这类非 `M` 开头编码，不再标记为编码异常；只要长度足够且第 2、3 位可取，就能提取产品特征编码。
4. 对数据库已有数据做只读核查，重点检查是否存在被旧规则改写过的模具编码；如果有，应回填为来源文件中的 `mould_code` 原值。
5. 后续导入预览中建议同时展示：

| 字段 | 含义 |
| --- | --- |
| `mould_code` | 原始模具编码，保持文件原值 |
| `product_specific_code` | 从模具编码第 2、3 位提取的产品本身特征编码 |
| `mould_code_parse_status` | 解析状态，如 `parsed`、`too_short`、`empty` |

验收标准：

1. `MBA10` 导入后模具编码仍为 `MBA10`，产品特征编码为 `BA`。
2. `LLT10` 导入后模具编码仍为 `LLT10`，产品特征编码为 `LT`。
3. 系统不再因为模具编码不是 `M` 开头而阻断导入。
4. 文档、脚本、导入模板说明中不再出现“去掉首位 M 再去掉末尾两位”的旧规则作为正式规则。

## 8. 工艺路线添加时自动生成编码规则

工艺路线添加时，系统应自动生成工艺业务编码。该编码不是模具编码，也不改写模具编码。

### 8.1 编码生成公式

```text
工艺业务编码 = N + 产品本身特征编码 + 工艺 / 工序编码 + 手机型号编码 + 颜色编码
```

字段来源：

| 组成段 | 来源 | 示例 | 说明 |
| --- | --- | --- | --- |
| `N` | 固定前缀 | `N` | 表示半成品 / 成品 / 工艺状态编码 |
| 产品本身特征编码 | Product 的 `product_specific_code`；如来源是模具编码，则取模具编码第 2、3 位 | `BA`、`BD`、`HB` | 不从模具编码首尾裁剪，只取第 2、3 位 |
| 工艺 / 工序编码 | 当前添加的工艺节点编码 | `1010`、`1020`、`4030` | `4030` 通常表示最终成品工序 |
| 手机型号编码 | 新型号 / SKU 的真实手机型号编码；产品线通用路线用占位 | `1291` 或 `0000` | 产品线通用路线没有具体型号时用 `0000` |
| 颜色编码 | SKU / 颜色明细的真实颜色编码；产品线通用路线用占位 | `01` 或 `00` | 产品线通用路线没有具体颜色时用 `00` |

### 8.2 生成场景

| 场景 | 生成方式 | 示例 |
| --- | --- | --- |
| 产品线通用工艺路线 | `N + 产品本身特征编码 + 工序编码 + 0000 + 00` | `NBA1010000000` |
| 新型号继承 / 添加工艺路线 | `N + 产品本身特征编码 + 工序编码 + 手机型号编码 + 00`，如尚未区分颜色 | `NBA1010129100` |
| SKU / 颜色明细工艺路线 | `N + 产品本身特征编码 + 工序编码 + 手机型号编码 + 颜色编码` | `NBA1010129101` |
| 最终工序 / 成品工序 | 工序编码为 `4030` 时，生成结果同时可作为成品编码 | `NBA4030129101` |

### 8.3 与模具编码的关系

1. 模具编码原值保留，例如 `MBA10`、`LLT10`，不参与重组。
2. 工艺编码只需要使用产品本身特征编码，例如 `MBA10 -> BA`、`LLT10 -> LT`。
3. 同一个产品本身特征编码下，可以有多个模具编码和多个工艺节点。
4. 工艺路线编码生成时，不能把模具编码的第 4、5 位当作工序编码；第 4、5 位只属于模具短码。

### 8.4 自动生成验收标准

1. 产品 `亮甲Rainbow 2.0` 的产品本身特征编码为 `BA`，新增产品线通用工序 `1010` 时，自动生成 `NBA1010000000`。
2. 同一产品新增 SKU 工序 `1010`，手机型号编码 `1291`，颜色编码 `01` 时，自动生成 `NBA1010129101`。
3. 同一产品新增最终工序 `4030`，手机型号编码 `1291`，颜色编码 `01` 时，自动生成 `NBA4030129101`，并可写入成品编码字段。
4. 模具编码 `MBA10` 在任何场景下仍保持 `MBA10` 原值，不应被工艺编码生成逻辑改写。
5. 模具编码 `LLT10` 提取产品本身特征编码为 `LT`，新增通用工序 `1010` 时可生成 `NLT1010000000`。
