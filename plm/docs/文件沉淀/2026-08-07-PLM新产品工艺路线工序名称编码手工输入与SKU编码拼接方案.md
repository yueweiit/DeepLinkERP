# 2026-08-07 PLM 新产品工艺路线工序名称编码手工输入与 SKU 编码拼接方案

## 0. 文档目的

本方案用于沉淀“新产品新建工艺路线”改造口径：新产品线阶段新增工序时，工序名称支持人工手动输入，工序编码也支持人工手动输入；进入具体 SKU 后，在手工工序编码基础上追加手机型号编码和颜色编码，生成 SKU 级正式产品工序编码。

本次只沉淀文档和代码草稿，不修改业务源码、不调整数据库、不执行生产数据修正。

## 1. 任务理解

当前 `ProjectProcessRoutePanel.vue` 的新建工艺路线弹窗已经有工序明细表，但页面倾向于从工序主数据选择：

- `operationMasterProcessId` 未选择时，前端会阻止保存。
- `operationCode` 输入框禁用，只能由主数据带出。
- `processName` 虽然在 DTO 中存在，但页面主要由下拉选项写入。
- 产品线阶段 `businessOperationCode` 被禁用并清空，用于避免提前生成 SKU 级编码。

本次需求不是新增对象，而是调整工艺路线编辑规则：

1. 产品线阶段可以直接手工录入工序名称。
2. 产品线阶段可以直接手工录入工序编码段。
3. 工序主数据仍可选，但从“必选”变成“可选辅助”。
4. 具体 SKU 阶段用同一套工序编码段，追加 `phone_model_code` 和 `color_code` 后形成正式编码。
5. 后端必须最终校验名称、编码、顺序、JSON、SKU 编码上下文和唯一性。

## 2. 所属 PLM 业务链路

所属主线：新产品线。

业务链路：

```text
客户/市场需求
  -> 新产品线立项
  -> Product 建档
  -> 新建通用工艺路线
  -> 人工录入工序名称和工序编码段
  -> 工艺与 BOM 验证
  -> 新型号/颜色/SKU 确认
  -> 基于 SKU 的 phone_model_code + color_code 生成正式产品工序编码
  -> 冻结/发布/追溯
```

核心对象：

- `Product`：承载产品线、型号、颜色、SKU 维度。
- `Process`：承载工艺路线、工序、工艺参数和工序编码。

不新增 `SKU`、`PhoneModel`、`Routing`、`Operation` 等根对象。

## 6. 不确定点

1. “编码”在业务口语中可能指两类编码：
   - 工序编码段：如 `1010`、`1020`、`4030`。
   - SKU 级产品工序编码：如 `NHD4030180102`。
2. 为避免产品线阶段提前产生假 SKU，本方案推荐：
   - 新产品线阶段人工输入的是 `operation_craft_code`，即工序编码段。
   - `business_operation_code` 只在具体 SKU/单色阶段生成。
3. 如果业务希望产品线阶段也展示 `NHD4030` 这种“基础产品工序编码”，建议只作为前端预览或 `process_param_json.baseBusinessOperationCode` 快照，不写入 `business_operation_code`。

推荐口径：

```text
产品线阶段：保存工序名称 + 工序编码段，不保存 SKU 级正式编码。
SKU 阶段：正式编码 = N + product_specific_code + operation_craft_code + phone_model_code + color_code。
```

## 7. 实施方案

### 7.1 前端交互调整

工序主数据选择从必填项改为可选项。用户可以：

- 选择工序主数据，自动带出名称、编码段、工时、质量要求。
- 不选择工序主数据，直接输入工序名称和工序编码段。
- 选择主数据后仍可覆盖本路线内的工序名称和编码段。

产品线阶段：

```json
{
  "processName": "注塑成型",
  "operationCraftCode": "1010",
  "businessOperationCode": null,
  "phoneModelCode": null,
  "colorCode": null,
  "codeGenerationContext": "product_line_route"
}
```

SKU 阶段：

```json
{
  "processName": "注塑成型",
  "operationCraftCode": "1010",
  "productSpecificCode": "HD",
  "phoneModelCode": "1801",
  "colorCode": "02",
  "businessOperationCode": "NHD1010180102",
  "codeGenerationContext": "sku_route"
}
```

### 7.2 后端保存调整

后端保持最终兜底：

1. `sequenceNo` 必填且同一路线内不重复。
2. `processName` 必填，允许来自 DTO。
3. `operationCraftCode` 必填，允许人工输入。
4. `operationMasterProcessId` 可为空。
5. 产品线阶段不校验手机型号编码和颜色编码。
6. SKU/具体型号阶段必须校验：
   - `phoneModelCode` 为 4 位 `[A-Z0-9]`。
   - `colorCode` 为 2 位 `[A-Z0-9]`。
7. SKU 正式编码生成继续复用 `ProductBusinessCodeGenerator.generateProductStateCode()`。
8. 冻结、删除、BOM 引用和操作日志逻辑不变。

### 7.3 SKU 拼接逻辑

编码拼接规则：

```text
product_state_code = "N" + product_specific_code + operation_craft_code + phone_model_code + color_code
```

示例：

| 阶段 | 输入 | 输出 |
| --- | --- | --- |
| 产品线 | `operation_craft_code=4030` | 不生成 `business_operation_code` |
| SKU | `product_specific_code=HD, operation_craft_code=4030, phone_model_code=1801, color_code=02` | `NHD4030180102` |

## 8. 风险点

1. 如果把产品线阶段的半成品编码写入 `business_operation_code`，可能和 SKU 正式编码混淆。
2. 如果仍强制选择工序主数据，用户无法录入临时新工序，需求无法满足。
3. 如果 SKU 缺少手机型号编码或颜色编码仍允许保存，会生成不可追溯编码。
4. 如果手工编码不做格式校验，可能破坏后续 ERP/MES 映射预留。
5. 如果前端只放开输入、后端不放开校验，页面仍会保存失败。

## 10. 当前现状

### 10.1 前端现状

当前 `ProjectProcessRoutePanel.vue` 中：

```ts
if (!operation.operationMasterProcessId && operation.operationSource !== 'imported_snapshot') {
  return `顺序 ${operation.sequenceNo} 请选择工序库中的工序`
}
```

这会导致普通新产品线无法纯手工新增工序。

当前系统工序编码输入框为禁用：

```vue
<el-input v-model="operation.operationCode" disabled />
```

当前工序名称主要由主数据下拉写入：

```ts
operation.processName = master.processName
```

### 10.2 后端现状

后端已经基本支持无主数据的工序名称：

```java
if (operation.getOperationMasterProcessId() == null && !StringUtils.hasText(operation.getProcessName())) {
    throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "工序名称不能为空");
}
```

但保存时如果选择了主数据，名称会被主数据覆盖：

```java
operation.setProcessName(master == null ? dto.getProcessName() : master.getProcessName());
```

编码解析也会优先取主数据编码：

```java
private String resolveOperationCode(ProcessOperationDTO dto, ProcessEntity master) {
    if (master != null) {
        return master.getProcessCode();
    }
    return StringUtils.hasText(dto.getOperationCode()) ? dto.getOperationCode() : "OP-" + dto.getSequenceNo();
}
```

这与“人工手动输入名称和编码”存在冲突。

## 11. 目标效果

1. 新产品线新建工艺路线时，不选择工序主数据也能保存。
2. 每一道工序都能人工输入：
   - 工序名称：`processName`
   - 工序编码段：`operationCraftCode`
   - 可选工序识别码：`operationCode`
3. 选择工序主数据后，可自动带出默认值，但用户仍可覆盖。
4. 产品线阶段不生成 SKU 级 `businessOperationCode`。
5. SKU 阶段根据产品特定编码、工序编码段、手机型号编码、颜色编码生成正式编码。
6. 后端校验失败时返回明确业务错误，不进入数据库异常。
7. 操作日志、状态流转、冻结、删除、BOM 关联保护保持现有逻辑。

```java
private String resolveOperationName(ProcessOperationDTO dto, ProcessEntity master) {
    if (StringUtils.hasText(dto.getProcessName())) {
        return dto.getProcessName().trim();
    }
    if (master != null && StringUtils.hasText(master.getProcessName())) {
        return master.getProcessName();
    }
    throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "工序名称不能为空");
}

private String resolveOperationCode(ProcessOperationDTO dto, ProcessEntity master) {
    if (StringUtils.hasText(dto.getOperationCode())) {
        return normalizeCode(dto.getOperationCode());
    }
    if (master != null && StringUtils.hasText(master.getProcessCode())) {
        return normalizeCode(master.getProcessCode());
    }
    return "OP-" + dto.getSequenceNo();
}
```

替换保存逻辑：

```java
String operationName = resolveOperationName(dto, master);
String operationCode = resolveOperationCode(dto, master);

operation.setProcessCode(buildRouteOperationProcessCode(route, dto, operationCode));
operation.setOperationMasterProcessId(master == null ? null : master.getProcessId());
```

### 13.2 后端校验手工工序编码段

代码草稿：

```java
private void validateOperationCraftCode(String operationCraftCode) {
    if (!StringUtils.hasText(operationCraftCode)) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "工序编码不能为空");
    }
    String normalized = normalizeOperationCraftCode(operationCraftCode);
    if (!StringUtils.hasText(normalized) || !normalized.matches("[A-Z0-9_-]{1,20}")) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "工序编码格式不正确");
    }
}
```

在 `validateOperations()` 中增加：

```java
String operationCraftCode = resolveOperationCraftCode(operation, resolveOperationMaster(operation.getOperationMasterProcessId()));
validateOperationCraftCode(operationCraftCode);
```

说明：实际落地时建议避免重复查询 `resolveOperationMaster()`，可在 `rebuildOperations()` 前统一缓存主数据，或者在校验阶段只校验 DTO 显式值，保存阶段再兜底。

### 13.3 SKU 正式编码生成

现有逻辑可保留，明确只在非产品线阶段生成：

```java
private String resolveBusinessOperationCode(ProcessOperationDTO dto, String operationCraftCode,
                                            CodeGenerationContext codeContext) {
    if ("product_line_route".equals(codeContext.contextName())) {
        return null;
    }
    if (Boolean.TRUE.equals(dto.getBusinessOperationCodeManualFlag())
        && StringUtils.hasText(dto.getBusinessOperationCode())) {
        return normalizeBusinessOperationCode(dto.getBusinessOperationCode());
    }
    if (!StringUtils.hasText(operationCraftCode) || !codeContext.ready()) {
        return null;
    }
    return businessCodeGenerator.generateProductStateCode(
        codeContext.productSpecificCode(),
        operationCraftCode,
        codeContext.phoneModelCode(),
        codeContext.colorCode()
    );
}
```

生成效果：

```text
N + HD + 4030 + 1801 + 02 = NHD4030180102
```

```java
private ProcessEntity copyOperation(ProcessEntity source, ProcessEntity targetRoute, Product targetProduct,
                                    LocalDateTime now, String operator) {
    ProcessEntity target = new ProcessEntity();
    String operationCraftCode = normalizeOperationCraftCode(source.getOperationCraftCode());
    CodeGenerationContext context = resolveCodeGenerationContext(targetProduct, operationCraftCode);
    String businessOperationCode = resolveBusinessOperationCode(source, context);

    target.setParentProcessId(targetRoute.getProcessId());
    target.setProductId(targetProduct.getProductId());
    target.setProcessName(source.getProcessName());
    target.setOperationCraftCode(operationCraftCode);
    target.setBusinessOperationCode(businessOperationCode);
    target.setPhoneModelCode(context.phoneModelCode());
    target.setColorCode(context.colorCode());
    target.setGeneratedFinishedProductCode(
        resolveGeneratedFinishedProductCode(operationCraftCode, businessOperationCode)
    );
    target.setCodeGenerationContext(context.contextName());
    return target;
}
```

```ts
function applyOperationMaster(operation: ProcessOperationSavePayload, processId: number | null) {
  const master = operationMasterOptions.value.find((item) => item.processId === processId)
  if (!master) return
  operation.operationMasterProcessId = master.processId
  operation.operationSource = 'master'
  operation.operationCode = master.processCode
  operation.operationCraftCode = master.operationCraftCode || operationCraftCodeMap[master.processCode] || ''

  operation.standardTimeMins = master.defaultStandardTimeMins ?? 0
  operation.qualityRequirement = master.defaultQualityRequirement || ''
  operation.processParamJson = master.defaultProcessParamJson || '{}'
  refreshBusinessOperationCode(operation)
}
```

```ts
    : previewBusinessOperationCode(item) || item.businessOperationCode?.trim().toUpperCase() || undefined,
  businessOperationCodeManualFlag: isProductLineRoute.value
    ? false
    : Boolean(item.businessOperationCodeManualFlag),
  phoneModelCode: isProductLineRoute.value
    ? undefined
    : item.phoneModelCode?.trim().toUpperCase() || props.phoneModelCode,
  colorCode: isProductLineRoute.value
    ? undefined
    : item.colorCode?.trim().toUpperCase() || props.colorCode,
  generatedFinishedProductCode: isProductLineRoute.value
    ? undefined
    : item.operationCraftCode === '4030'
      ? previewBusinessOperationCode(item)
      : undefined,
  codeGenerationContext: isProductLineRoute.value
    ? 'product_line_route'
    : props.productType === 'sku'
      ? 'sku_route'
      : 'model_variant_route'
}))
```

## 18. 结论

推荐实施“手工工序名称 + 手工工序编码段 + SKU 阶段追加型号和颜色”的方案。

产品线阶段只沉淀通用工艺结构，不写 SKU 正式编码；具体 SKU 阶段再读取真实 `phone_model_code` 和 `color_code` 生成正式编码。这样既满足人工输入，又不会破坏 Product/Process 对象边界、状态机、唯一性和后续追溯。

### 19.2 实施后目标效果

1. 新产品线新建工艺路线时，用户不选择工序库也可以保存工序。

### 19.3 关键逻辑

#### 前端逻辑

- `newOperation()` 默认创建 `manual_snapshot` 工序，`operationCode` 不再默认填 `OP-顺序号`，`operationCraftCode` 和 `processName` 由用户输入。
- `validateForm()` 移除“必须选择工序库”的限制，改为校验：
  - 顺序必须大于 0 且不重复。
  - 工序名称不能为空。
  - 工序编码段不能为空。
  - 工序编码段必须符合 `[A-Z0-9_-]{1,20}`。
  - 质量要求不能为空。
- `applyOperationMaster()` 支持清空选择，清空后恢复为 `manual_snapshot`；选择主数据后只做默认带入，用户后续仍可覆盖。
- 保存 payload 时：
  - 产品线：`businessOperationCode=undefined`、`codeGenerationContext=product_line_route`。
  - 具体型号/SKU：优先提交手工覆盖的 `businessOperationCode`，否则提交预览生成值。
- 节点配置核对表中的“工序编码”已改为显示工序编码段口径，避免与 `PROC_*` 系统工序码混淆；模板默认值补齐 `PROC_TRIMMING`、`PROC_FINAL_INSPECTION` 等常见工序映射。

#### 后端逻辑

- `resolveOperationName()` 采用 DTO 手工名称优先，主数据名称兜底。
- `resolveOperationCode()` 采用 DTO 手工系统工序编码优先，主数据编码兜底，最后才使用 `OP-顺序号`。
- `validateOperationCraftCode()` 对最终解析出的工序编码段做必填和格式校验。
- `resolveBusinessOperationCode()` 产品线阶段返回 `null`；具体型号/SKU 阶段继续调用 `ProductBusinessCodeGenerator.generateProductStateCode()`。
