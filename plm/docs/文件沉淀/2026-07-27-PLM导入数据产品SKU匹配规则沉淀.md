# 2026-07-27 PLM 导入数据产品与 SKU 匹配规则沉淀

## 1. 背景与目标

后续导入历史数据、ECOUNT 数据或外部表格时，产品名、型号名、SKU 信息、成品编码等字段可能不是一次性完整导入，而是分批、分表或分字段进入系统。为了避免仅靠名称匹配造成误关联，需要先沉淀一套稳定的产品与 SKU 匹配规则。

本规则的核心目标：

- 按编码长度识别导入行属于产品层还是 SKU 层。
- 产品名、型号名只作为辅助信息，不作为自动匹配主键。
- SKU 关联优先使用成品编码。
- 一个新型号默认只对应一个成品编码，导入时需要校验一对一关系。
- 不同产品下的同一个手机型号，应视为不同新型号，对应的新型号编码和成品编码也不同。
- 对缺失、重复、冲突的数据在导入预览阶段提前提示，避免静默覆盖。

## 2. 业务对象口径

| 对象 | 业务含义 | 主要识别依据 | 说明 |
| --- | --- | --- | --- |
| 产品 / 手机型号 | PLM 中承载手机型号、项目或产品主数据的对象 | 模具编码产品编码，长度 5 位 | 5 位包含字母和数字，按文本处理 |
| SKU / 成品 | 可用于 BOM、工艺、订单、库存或后续 ERP 关联的成品级对象 | 成品编码或新型号编码，长度 9 位 | 9 位包含字母和数字，按文本处理 |
| 产品名 / 型号名 | 展示和人工核对信息 | 不作为唯一匹配键 | 同名、别名、大小写和历史写法都可能导致误匹配 |

### 2.1 正式编码规则来源

本规则需要与 `D:\work\Yuewei\coding-rules-system-implementation.md` 保持一致。正式系统编码不只按长度判断，还需要按编码前缀和组合公式解析：

| 编码类型 | 公式 | 示例 | 说明 |
| --- | --- | --- | --- |
| 模具编码 | `M + 产品特定编码 + 材质编码 + 手机型号编码` | `MFA101291` | 用于模具档案，不直接等同 SKU |
| 半成品编码 | `N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码` | `NFA1020129101` | `N` 开头但工序不是最终工序 |
| 成品 / SKU 编码 | `N + 产品特定编码 + 最终工序编码 + 手机型号编码 + 颜色编码` | `NFA4030129101` | 最终工序通常为 `4030`，可作为 SKU 总编码 |

因此导入识别分两层：

- 如果导入的是完整系统编码，优先按 `M` / `N` 前缀和编码规则解析。
- 如果导入的是业务短码或外部表格编码，再按 5 位产品码、9 位新型号 / 成品码进行辅助识别。
- 完整成品编码中的产品、工序、手机型号、颜色都应能反查到基础资料，不能只凭名称匹配。

## 3. 编码识别规则

导入时先对编码做标准化，再判断是完整系统编码还是业务短码。

### 3.1 编码标准化

导入系统读取编码字段后，应先做以下处理：

1. 去除首尾空格。
2. 英文字母统一转大写。
3. 按文本保存，不能按数字处理，避免前导 0 丢失。
4. 长度按标准化后的字符数计算，字母也计入长度。
5. 中间空格、横杠、斜杠等特殊字符默认不自动删除，应在导入预览中提示人工确认。

### 3.2 类型判断

| 编码形态 | 识别结果 | 处理规则 |
| --- | --- | --- |
| `M` 开头，且可按模具公式解析 | 模具编码 | 解析产品特定编码、材质编码、手机型号编码，匹配或创建模具档案 |
| `N` 开头，且可按成品 / 半成品公式解析 | 半成品或成品 / SKU 编码 | 解析产品特定编码、工序编码、手机型号编码、颜色编码；工序为最终工序 `4030` 时识别为成品 / SKU |
| 5 位短码 | 产品编码 | 识别为导入用产品层编码，对应产品 / 手机型号层 |
| 9 位短码 | 新型号 / 成品短码 | 识别为导入用新型号或成品编码，对应 SKU / 成品层 |
| 其他形态 | 无法自动识别 | 导入预览标记为异常，需人工指定类型或修正编码 |

规则说明：

- 完整系统编码优先按 `coding-rules-system-implementation.md` 的公式解析，不能只按长度截取。
- 5 位短码用于识别产品层，不能直接当作 SKU 主键。
- 9 位短码用于识别新型号 / 成品层，后续 SKU 关联优先使用该编码。
- `N` 开头完整成品编码可以直接作为 SKU 总编码使用。
- 同一导入行如果同时出现 5 位产品编码和 9 位短码或完整 `N` 成品编码，应同时校验两者的归属关系。
- 如果字段名明确为“成品编码”，即使导入表中还有产品名，也应优先按成品编码匹配 SKU。

## 4. SKU 关联规则

SKU 关联的主口径是成品编码。

### 4.1 主匹配键

| 优先级 | 匹配依据 | 适用场景 | 处理方式 |
| ---: | --- | --- | --- |
| 1 | 完整成品编码，`N + 产品特定编码 + 4030 + 手机型号编码 + 颜色编码` | SKU 表、BOM 表、订单表、工艺表导入 | 精确匹配 SKU，并反查产品、手机型号、颜色 |
| 2 | 成品编码 / 新型号编码，9 位短码 | 外部表格未使用完整 `N` 编码时 | 精确匹配 SKU 或新型号候选 |
| 3 | 产品编码，5 位 + 成品编码，9 位或完整 `N` 编码 | 同一行同时包含产品和 SKU 信息 | 先匹配产品，再校验 SKU 是否归属该产品 |
| 4 | 产品编码，5 位 | 只导入产品主数据或产品名时 | 匹配或创建产品，不自动创建 SKU |
| 5 | 产品名 / 型号名 | 缺少编码时 | 仅用于人工核对，不做自动关联 |

### 4.2 新型号与成品编码一对一约束

一个新型号默认只有一个成品编码。这里的“新型号”不是单纯的手机型号文本，而是“产品 + 手机型号”组合后的业务型号。

例如，同一个手机型号如果分别归属于不同产品，应识别为不同新型号，并分别绑定不同的新型号编码 / 成品编码。

导入时应校验：

- 同一个产品编码 + 手机型号组合只能关联一个有效成品编码。
- 同一个新型号如果已经绑定成品编码，再导入不同成品编码时应提示冲突。
- 同一个手机型号名称允许出现在不同产品下，但必须形成不同新型号，并对应不同成品编码。
- 同一个成品编码不能同时归属多个新型号。
- 重复导入同一产品编码和同一成品编码时，允许更新名称、规格、备注等非主键字段，但不得改写归属关系。

## 5. 分批导入时的处理规则

### 5.1 先导入产品名

如果先导入的是产品名、型号名等文本信息：

- 有 5 位产品编码：匹配或创建产品。
- 没有产品编码：进入待匹配池，不自动创建正式产品。
- 后续再导入成品编码或 SKU 数据时，通过编码补齐关联。

### 5.2 后导入 SKU 或成品编码

如果导入行包含 9 位成品编码：

- 已存在 SKU：直接匹配该 SKU。
- 不存在 SKU，但能通过 5 位产品编码找到产品：创建或预创建 SKU，并关联该产品。
- 不存在 SKU，且没有 5 位产品编码：进入待匹配池，等待人工指定产品。

### 5.3 同时导入产品和 SKU

如果一行同时包含 5 位产品编码和 9 位成品编码：

1. 先按 5 位编码匹配产品。
2. 再按 9 位编码匹配 SKU。
3. 如果 SKU 已存在，校验其产品归属是否与 5 位产品编码一致。
4. 如果 SKU 不存在，按该产品创建 SKU 或进入导入确认队列。
5. 如果归属不一致，导入预览应标记为冲突，禁止静默覆盖。

## 6. 异常与冲突处理

| 场景 | 处理等级 | 处理规则 |
| --- | --- | --- |
| 编码为空 | 错误 | 不自动导入，进入待清洗数据 |
| 业务短码长度不是 5 位或 9 位，且不是完整 `M` / `N` 系统编码 | 错误 | 无法识别产品或 SKU，需要人工修正 |
| 完整编码不符合 `M` / `N` 公式 | 错误 | 不自动导入，提示按编码规则修正 |
| `N` 开头编码的工序不是最终工序 `4030` | 警告 / 分流 | 识别为半成品，不作为成品 SKU 直接关联 |
| 5 位编码重复但名称一致 | 可通过 | 视为同一产品重复导入，可合并或更新 |
| 5 位编码重复但名称不同 | 警告 / 冲突 | 不自动覆盖名称，导入预览提示人工确认 |
| 9 位成品编码重复且归属一致 | 可通过 | 视为同一 SKU 重复导入，可更新非关键字段 |
| 9 位成品编码重复但归属不同 | 错误 | 禁止导入，必须人工处理 |
| 同一产品编码 + 手机型号组合对应多个成品编码 | 错误 | 违反一个新型号一个成品编码的规则 |
| 同一手机型号出现在不同产品下，但成品编码相同 | 错误 | 不同产品下的同一手机型号应视为不同新型号，成品编码也应不同 |
| 只有产品名没有编码 | 待匹配 | 不做自动关联，仅展示给人工核对 |

## 7. 导入预览建议字段

导入预览阶段建议给每一行生成以下识别结果，方便用户确认：

| 字段 | 含义 |
| --- | --- |
| `normalized_code` | 标准化后的编码 |
| `detected_object_type` | 自动识别类型：`product`、`sku`、`unknown` |
| `matched_product_code` | 匹配到的 5 位产品编码 |
| `matched_finished_code` | 匹配到的 9 位成品编码 |
| `match_status` | `matched`、`create_candidate`、`pending_manual`、`conflict` |
| `match_message` | 面向用户的匹配说明或异常原因 |

状态口径：

- `matched`：已找到现有产品或 SKU，关系一致。
- `create_candidate`：编码合法但系统中不存在，可作为新产品或新 SKU 候选。
- `pending_manual`：信息不足，需人工指定归属。
- `conflict`：编码重复、归属冲突或违反一对一规则，禁止直接导入。

## 8. 示例

| 导入编码 | 标准化后长度 | 识别结果 | 导入动作 |
| --- | ---: | --- | --- |
| `AB123` | 5 | 产品 | 匹配或创建产品 |
| `AB1234567` | 9 | SKU / 成品 | 按成品编码匹配 SKU |
| `MFA101291` | 9 | 模具 | 按 `M + FA + 10 + 1291` 解析为模具编码 |
| `NFA4030129101` | 13 | 成品 / SKU | 按 `N + FA + 4030 + 1291 + 01` 解析并匹配 SKU |
| `NFA1020129101` | 13 | 半成品 | 工序 `1020` 不是最终工序，不作为成品 SKU |
| ` ab123 ` | 5 | 产品 | 标准化为 `AB123` 后匹配产品 |
| `AB-123` | 6 | 异常 | 不自动删除横杠，提示人工确认 |
| 空值 | 0 | 异常 | 不导入，进入待清洗数据 |

## 9. 后续落地建议

1. 导入模板中明确区分“产品编码 5 位短码”“新型号 / 成品 9 位短码”和“完整系统编码”字段。
2. 系统导入预览先做编码标准化和类型识别，再执行正式写入。
3. SKU 与产品的关联表中保留 `product_code`、`finished_product_code`、`product_specific_code`、`phone_model_code`、`color_code`，便于追溯。
4. 产品名、型号名、规格名允许更新，但更新前应展示差异，避免历史名称被误覆盖。
5. 对于只有名称没有编码的数据，先进入待匹配池，不进入正式主数据。
6. 后续如果出现一个新型号多个成品编码的业务变化，需要先调整本规则，再改导入逻辑。

## 10. 本次结论

本次匹配规则先确定为：

- 5 位编码识别为产品 / 手机型号。
- 9 位编码识别为 SKU / 成品。
- 完整系统编码优先按 `M` / `N` 前缀和正式公式解析。
- SKU 关联以成品编码为准。
- 一个新型号默认只能绑定一个成品编码。
- 不同产品下的同一个手机型号视为不同新型号，成品编码也必须不同。
- 名称字段只做辅助展示和人工核对，不作为自动匹配主键。
