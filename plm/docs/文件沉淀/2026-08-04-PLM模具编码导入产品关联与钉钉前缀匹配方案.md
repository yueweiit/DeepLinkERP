# PLM 模具编码导入、产品关联与钉钉前缀匹配方案

日期：2026-08-04  
状态：方案已落地，已同步补充代码实现沉淀

## 1. 目标

本方案解决三个问题：

1. 将 `mould.xlsx` 中的模具编码归属到对应产品。
2. 在产品详情页展示该产品下的模具编码。
3. 钉钉新型号审批只传模具编码时，直接按已导入的模具编码关联关系匹配来源产品。

目标效果：

```text
模具编码 MHA101296
  -> 查询产品-模具编码关联
  -> 找到来源产品 NHA4030
  -> 创建新型号并记录 parentProductId
```

## 2. Excel 数据现状

文件包含一个工作表：

```text
工作表：mould
数据行：78
字段：id、mould_name、mould_code、key_code
```

字段含义：

| Excel 字段 | 含义 | 示例 |
| --- | --- | --- |
| `id` | Excel 内部序号 | `1` |
| `mould_name` | 模具或产品名称 | `亮甲2.0` |
| `mould_code` | 模具编码 | `MBA10` |
| `key_code` | 模具前缀、名称和材质等组合信息 | `MBA/亮甲PC` |

当前文件约有 37 个模具编码前缀。一个产品可能有多个模具编码，例如：

```text
MBA10
MBA20
```

同一个前缀下可以存在多个材质编码、部件编码或模具用途编码。

## 3. 编码匹配规则

### 3.1 首选规则：直接按完整模具编码匹配

`mould.xlsx` 导入后，系统应保存完整的模具编码与产品的关联关系：

```text
MHA10 -> 产品 NHA4030
MHA20 -> 产品 NHA4030
```

钉钉新型号收到模具编码时，直接查询：

```sql
select product_id
from plm_product_mold_code
where mold_code = :moldCode
  and deleted_flag = 0
  and status = 'active';
```

匹配成功后直接使用关联的 `product_id` 作为新型号的 `parent_product_id`。

这种方式不需要把 `MHA` 转换为 `NHA`，也不依赖产品编码命名规则，优先级高于所有前缀和名称推导。

### 3.2 前缀规则：只作为历史数据兜底

模具编码采用以下结构：

```text
M + 产品特定编码 + 材质/用途编码 + 其他型号编码
```

对于尚未建立产品-模具编码关联的历史数据，才使用产品编码前缀兜底：

```text
模具前缀 MHA -> 产品前缀 NHA
模具前缀 MBA -> 产品前缀 NBA
模具前缀 MFA -> 产品前缀 NFA
模具前缀 MDP -> 产品前缀 NDP
```

转换规则：

```text
productCodePrefix = "N" + moldCode.substring(1, 3)
```

示例：

| 模具编码 | 模具前缀 | 产品前缀 | 目标产品示例 |
| --- | --- | --- | --- |
| `MHA10` | `MHA` | `NHA` | `NHA4030` |
| `MBA10` | `MBA` | `NBA` | `NBA4030` |
| `MFA10` | `MFA` | `NFA` | `NFA4020` |
| `MDN10` | `MDN` | `NDN` | `NDN4030` |
| `MRU10` | `MRU` | `NRU` | `NRU4030` |

### 3.3 产品匹配优先级

按以下顺序匹配来源产品：

1. 完整模具编码直接查询产品-模具编码关联。
2. 模具编码前缀转换后的产品编码前缀，例如 `MHA -> NHA`。
3. 产品特定编码，例如 `MHA -> HA`，匹配 `product_specific_code=HA`。
4. `mould_name` 与产品名称/系列名称的精确别名匹配。
5. 无法唯一匹配时返回错误，不允许随机取第一条产品。

产品编码前缀匹配建议使用：

```sql
product_code like 'NHA%'
and product_type = 'product_line'
and deleted_flag = 0
```

产品状态处理：

- `released`：优先作为正常来源产品。
- `archived`：如果产品仍有完整正式 BOM、工艺路线和生产颜色，可作为历史来源产品参与匹配，但应记录来源状态。
- 其他状态：不作为新型号来源产品。

### 3.3 多个模具编码

审批表中可以传多个模具编码，例如：

```text
MHA101296 / MHA201296
```

处理规则：

1. 拆分成独立编码。
2. 所有编码的产品前缀必须一致。
3. `MHA101296` 和 `MHA201296` 都匹配产品前缀 `NHA`。
4. 每个模具编码独立保存和匹配 Inventory。
5. 材质或用途编码可以不同。
6. 如果出现 `MHA...` 与 `MBA...` 混用，直接报错：

```text
多个模具编码的产品前缀不一致
```

## 4. Excel 导入产品关联方案

### 4.1 建议的数据模型

建议增加产品与模具编码的关联明细，不直接把多个编码拼成 Product 的单个字符串字段。

建议表：`plm_product_mold_code`

核心字段：

| 字段 | 说明 |
| --- | --- |
| `product_mold_code_id` | 主键 |
| `product_id` | 关联产品线或新型号项目 |
| `mold_code` | 模具编码，例如 `MBA10` |
| `mold_prefix` | 模具前缀，例如 `MBA` |
| `product_code_prefix` | 对应产品前缀，例如 `NBA` |
| `product_specific_code` | 产品特定编码，例如 `BA` |
| `mold_name` | Excel 模具名称 |
| `key_code` | Excel 原始 `key_code` |
| `source_file` | 来源文件名 |
| `source_row_no` | 来源行号 |
| `status` | `active`、`archived` |
| `created_at` / `updated_at` | 审计字段 |
| `deleted_flag` | 逻辑删除标记 |

唯一性建议：

```text
同一产品下，mold_code 不重复
同一有效 mold_code 全局不重复
```

模具编码的库存资料仍可继续使用 `plm_inventory` 承载；产品关联表用于产品详情展示和产品前缀匹配，避免把“模具档案”和“产品关联关系”混为一个字段。

### 4.2 导入处理流程

```text
读取 mould.xlsx
  -> 校验表头
  -> 清洗 mould_code、mould_name、key_code
  -> 提取 mold_prefix
  -> 生成 product_code_prefix
  -> 匹配产品线
  -> 写入产品-模具关联
  -> 已存在则更新，不重复插入
  -> 输出成功、跳过和失败明细
```

每行导入结果至少记录：

```text
sourceRowNo
moldCode
matchedProductId
matchedProductCode
matchRule
status
message
```

### 4.3 导入匹配示例

```text
Excel:
  mould_name = 亮甲2.0
  mould_code = MBA10
  key_code = MBA/亮甲TPU

系统:
  mold_prefix = MBA
  product_code_prefix = NBA
  product_specific_code = BA
  匹配产品 = NBA4030 亮甲Rainbow 2.0
```

如果 `NBA4030` 当前是归档产品：

- 保留导入关联；
- 标记 `sourceProductStatus=archived`；
- 新型号创建前校验正式 BOM、工艺路线和生产颜色是否完整；
- 不要静默把归档产品当作当前有效产品。

## 5. 产品详情展示方案

产品详情增加“模具编码”区域，建议展示：

| 列 | 内容 |
| --- | --- |
| 模具编码 | `MBA10` |
| 模具名称 | `亮甲2.0` |
| 产品前缀 | `NBA` |
| 产品特定编码 | `BA` |
| `key_code` | `MBA/亮甲TPU` |
| 关联库存资料 | 已匹配的 Inventory |
| 状态 | 有效、归档或待开模 |
| 来源 | `mould.xlsx` 或钉钉审批 |

展示原则：

1. 产品详情只展示当前产品关联的模具编码。
2. 同一产品的多个模具编码按编码排序。
3. 模具编码不存在时显示“暂无模具编码”，不能显示为异常。
4. 同一个模具编码关联了多个产品时，应显示数据异常并禁止静默覆盖。
5. 从钉钉新型号创建的模具编码，应同时显示来源审批单号和 Inventory 匹配状态。

## 6. 钉钉新型号匹配方案

钉钉审批连接器只需要传：

```json
{
  "moldCodes": "MHA101296 / MHA201296",
  "model": "SM S267",
  "tipo": "超级队长"
}
```

不再强制要求审批表单传 `parentProductId`。

后端处理：

```text
moldCodes
  -> splitCodes
  -> 逐个查询产品-模具编码关联
  -> 多个模具编码归并为同一个来源产品
  -> 匹配产品线
  -> 写入 project.parent_product_id
  -> 继承产品颜色、工艺路线和正式 BOM
```

只有在产品-模具编码关联表查不到时，才进入 `MHA -> NHA` 前缀兜底逻辑。

如果同时传了 `parentProductId`：

1. 优先按完整模具编码关联查找产品。
2. 两者匹配到不同产品时直接报错。
3. 不允许用错误的固定 ID 覆盖模具编码匹配结果。

## 7. 异常处理

| 场景 | 处理 |
| --- | --- |
| 模具编码为空 | 返回缺少模具编码 |
| 编码长度不足 | 返回无法提取前缀 |
| 多个模具编码前缀不一致 | 阻断创建 |
| 产品前缀匹配不到 | 返回待处理异常，不创建半成品项目 |
| 匹配到多个产品 | 阻断并要求维护主数据 |
| 只匹配到归档产品 | 校验 BOM、工艺路线和颜色后再决定是否允许 |
| 产品没有正式 BOM | 阻断继承并返回明确原因 |
| 产品没有已确认生产颜色 | 阻断新型号创建 |

## 8. 验收标准

### 8.1 Excel 导入

1. `mould.xlsx` 78 条记录完成预览。
2. 每条记录能生成 `mold_prefix` 和 `product_code_prefix`。
3. `MBA10` 能匹配 `NBA4030`。
4. `MHA10` 能通过已导入的产品-模具编码关联直接匹配来源产品。
5. 重复执行导入不会产生重复产品-模具关联。
6. 无法匹配的记录能导出失败明细。

### 8.2 产品详情

1. 打开 `NBA4030` 产品详情能看到 `MBA10`、`MBA20`。
2. 能看到模具名称和 `key_code`。
3. 能看到关联 Inventory 状态。
4. 多个模具编码不会覆盖或拼接丢失。

### 8.3 钉钉新型号

1. 只传已导入的 `MHA...` 模具编码，不传 `parentProductId`，能直接匹配关联产品。
2. 传多个同前缀模具编码时，能创建一个新型号项目。
3. 传不同前缀模具编码时，接口返回 400，不创建项目。
4. 匹配成功后，项目的 `parent_product_id` 正确写入。
5. 项目继承来源产品颜色、工艺路线和正式 BOM。
6. 重复审批实例仍然遵守幂等规则。

## 10. 当前结论

`mould.xlsx` 可以作为产品模具编码基础资料来源。运行时应优先按完整模具编码关联：

```text
MHA10 -> 产品关联 -> NHA4030
MBA10 -> 产品关联 -> NBA4030
```

只有历史数据没有产品-模具编码关联时，才按以下规则兜底：

```text
MHA -> NHA
MBA -> NBA
MFA -> NFA
```

进行产品前缀匹配。产品详情应展示产品下的模具编码明细；钉钉新型号应根据完整模具编码关联自动解析来源产品，不再依赖人工填写产品名称或固定 `parentProductId`。

本次方案已落地到后端与前端接口层，新增产品-模具编码关系表、导入校验与钉钉匹配逻辑。产品详情数据已可返回模具编码明细；前端详情展示页仍按现有页面结构逐步接入。
