## 3. 任务理解













截图中的“DHL 运模进度”区域目前包含：













- DHL 单号。













- 发件方、收件方、发出地、目的地、备注。













- 保存 DHL 单号。













- 刷新轨迹按钮。













- 承运商、最新状态、最近刷新、物流轨迹时间线。













用户新的目标是：快递单号只需要保存“单号”和“时间”，物流轨迹插件不再使用。也就是该区域应从“物流轨迹查询面板”收敛为“运模单号登记面板”。













## 4. 所属 PLM 业务链路













所属链路：Product 新型号线 / 新产品线项目流程中的运模节点。













```text












小批量测试 -> 运模 -> 确认批量投产 / MX 承接 -> 项目完成或发布












```













核心对象仍为：













- Product：承载项目、新型号、SKU 及流程节点。













- Process：承载工艺和投产相关节点。













不新增物流、快递、轨迹等根对象。

## 6. 改造原则













1. 只保留运模登记所需字段：快递单号、发运时间。



2. 前端去掉物流轨迹插件入口，不显示刷新轨迹按钮和轨迹列表。



3. 后端不再注入和调用 `ExpressTrackingClient`。



4. API 保留原 `GET/PUT` 路径，减少前端调用面变化；`/refresh` 接口建议删除或标记废弃并不再由前端调用。


5. 数据库暂不删字段，只使用 `tracking_no`、`shipped_at`、`status`、审计字段。


6. 操作日志保留保存动作，但日志文案从 DHL 轨迹改为运模单号登记。
