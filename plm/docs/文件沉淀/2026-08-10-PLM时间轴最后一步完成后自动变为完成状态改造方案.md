# PLM 时间轴最后一步完成后自动变为完成状态改造方案

## 1. 问题描述

当前项目时间轴在最后一步确认完成后，页面仍会把最后一步显示成“进行中”。
这会让用户看到“最后一步已做完，但状态没收口”的矛盾表现。

截图中的场景属于 `MODEL_VARIANT_MOLD_TRANSFER` 最后节点：

- 节点已经确认完成。
- 项目主状态已经进入完成后的状态流转。
- 但时间轴左侧阶段卡片、右侧当前节点卡片仍按“current / 进行中”渲染。

## 2. 现状原因

现有链路里有三处会导致终态没有收口：

1. 后端 `TimelineActionServiceImpl.confirm()` 在最后一步确认后，已经把产品状态推进到了完成后的状态，但时间轴查询接口仍按当前步数返回“当前节点”。
2. 后端 `TimelineServiceImpl.resolveNodeStatus()` 目前对 `stepNo == currentStepNo` 直接返回 `current`。
3. 前端 `timelineAdapter.ts` 和 `ProjectCenterView.vue` 会优先把 `status === 'current'` 的节点和阶段渲染成“进行中”，导致最后一步即使已确认，仍保留当前态。

## 3. 修改目标

1. 最后一步确认完成后，时间轴阶段显示为“已完成”。
2. 最后一步节点不再显示成“进行中”。
3. 详情面板仍能展示最后一步的内容，但不再出现继续推进按钮。
4. 前后端返回和前端渲染保持一致，不出现一个地方已完成、另一个地方仍进行中的分裂状态。

## 5. 拟调整逻辑

### 5.1 后端

建议在时间轴查询接口中增加一个终态判断：

- 当前步数已经到最后一步。
- 最后一步已经确认。
- 项目状态已经进入完成后的状态。

当满足上述条件时：

- 当前节点返回 `completed`。
- 时间轴详情增加一个只读终态字段，例如 `timelineCompleted`。

示意代码：

```java
boolean timelineCompleted = Boolean.TRUE.equals(product.getTimelineCurrentConfirmed())
    && product.getCurrentStepNo() != null
    && product.getCurrentStepNo() >= definitions.size()
    && ProductStatusConstants.RELEASED.equals(product.getStatus());

private String resolveNodeStatus(int stepNo, int currentStepNo, Product product, int maxStepNo, boolean timelineCompleted) {
    if (timelineCompleted && stepNo == currentStepNo) {
        return TimelineNodeConstants.NODE_STATUS_COMPLETED;
    }
    if (stepNo < currentStepNo) {
        return TimelineNodeConstants.NODE_STATUS_COMPLETED;
    }
    if (stepNo == currentStepNo) {
        return TimelineNodeConstants.NODE_STATUS_CURRENT;
    }
    return TimelineNodeConstants.NODE_STATUS_PENDING;
}
```

`TimelineActionServiceImpl.confirm()` 本身已有最后一步推进到完成后状态的能力，主要是查询侧要把终态显式暴露出来。

### 5.2 前端

前端要做两件事：

1. 当后端返回终态时，阶段卡片直接显示“已完成”。
2. 如果没有 `current` 节点了，详情面板应自动回退选中最后一个节点，而不是回到第一步。

示意代码：

```ts
const activeProductFlowNode = computed(() => {
  const nodes = detailPresentation.value?.timeline || []
  return nodes.find((item) => item.status === 'current')
    || nodes[nodes.length - 1]
    || null
})

const currentTimelineActionLabel = computed(() => {
  if (!activeProductFlowNode.value) return '暂无当前节点'
  if (timelineCompleted.value) return '已完成'
  return currentTimelineConfirmed.value ? '可推进到下一节点' : '等待确认当前节点'
})
```

`timelineAdapter.ts` 里阶段状态建议按“终态优先”处理：

```ts
if (timeline.timelineCompleted) {
  status = 'completed'
} else if (childNodes.some(({ node }) => node.status === 'current')) {
  status = 'current'
} else if (childNodes.length && childNodes.every(({ node }) => node.status === 'completed')) {
  status = 'completed'
}
```

## 6. 目标效果

1. 最后一节点确认后，时间轴阶段卡片变成绿色“已完成”。
2. 最后一节点不再显示“进行中”。
3. 详情面板不再提示还能继续推进。
4. 非最后节点的既有推进/确认行为不受影响。

## 7. 验收逻辑

1. 打开任一走到最后一步的项目。
2. 完成最后一步确认。
3. 刷新页面后检查：
   - 时间轴阶段是否显示“已完成”。
   - 最后节点是否不再显示“进行中”。
   - 按钮区是否不再出现推进类操作。
4. 对新产品线和新型号线各验一次，避免只改到单条流程。

## 8. 风险点

1. 如果只改前端，其他调用时间轴接口的页面仍可能显示旧态。
2. 如果只改后端，前端 `activeProductFlowNode` 和 `buildFlowStages()` 仍可能把最后一步回写成 current。
3. 所以这次建议前后端一起收口，避免状态语义不一致。

## 9. 备注

本次先沉淀方案，不修改业务代码。
后续落地时再同步补测试和页面回归。

### 10.2 后端实现逻辑

1. `TimelineDetailVO` 新增只读字段 `timelineCompleted`，用于向前端明确表达“时间轴已整体完成”。
2. `TimelineServiceImpl` 在查询时间轴详情时增加终态判断：
   - 当前步数已到达定义列表最后一步；
   - 当前节点已确认；
   - 已确认节点 key 与当前节点 key 一致；
   - Product 状态为 `released` 或 `archived`。
3. 满足终态条件后，`resolveNodeStatus()` 对 `stepNo <= currentStepNo` 的节点统一返回 `completed`，避免最后一步继续返回 `current`。
4. 未启动时间轴保持 `timelineCompleted=false`，普通进行中节点仍沿用原有 `completed/current/pending` 规则。

### 10.3 前端实现逻辑

1. `project.ts` 的时间轴接口类型和映射结果补充 `timelineCompleted`。
2. `mapTimeline()` 优先使用后端 `timelineCompleted`；同时兼容旧后端：当没有 `current` 节点且所有节点都是 `completed` 时，前端推断为完成态。
3. `timelineAdapter.ts` 调整当前节点识别逻辑：`isCurrent` 只取决于节点状态是否为 `current`，不再因为 `stepNo === currentStepNo` 把完成后的最后节点重新标记为进行中。
4. `ProjectCenterView.vue` 在完成态下：
   - 当前展示节点回退到最后一个节点，详情仍可查看最后一步内容；
   - 动作标签显示“已完成”；
   - 下一节点显示“已完成”；
   - 不显示“确认当前节点”和“推进下一节点”按钮。

### 10.4 测试过程中发现并处理的问题

1. 前端单测首次发现：完成态下“推进下一节点”按钮虽然不可用，但仍然显示。
   - 处理：将推进按钮显示条件收窄为 `activeProductFlowNode && currentTimelineConfirmed && canAdvanceCurrentTimelineNode`。
   - 目标：终态页面不再给用户继续推进的操作入口。
2. Playwright 首次检查发现：当前运行中的 8080 后端尚未返回 `timelineCompleted` 字段时，前端会在全节点 `completed` 的情况下默认选中第一阶段。
   - 处理：`mapTimeline()` 增加兼容推断逻辑，无 `current` 且全节点 `completed` 时视为时间轴完成，并选中最后节点。
   - 目标：新旧后端切换期间，页面都能稳定显示最后阶段“已完成”。
3. Playwright 初始断言曾检查 `.detail-dialog` 内是否包含项目编码，但该弹窗主体区域不包含头部项目元信息。
   - 处理：验收断言改为聚焦本需求相关的动作条、按钮状态和阶段卡片状态。
   - 目标：测试只覆盖本次功能目标，避免无关 UI 结构导致误判。

### 10.6 最终目标效果

1. 产品时间轴最后一步确认并进入发布/归档状态后，后端返回整体完成态，所有已走完节点显示为 `completed`。
2. 前端项目详情时间轴最后阶段显示“已完成”，最后节点仍可查看，但不再作为“进行中”节点处理。
3. 终态下隐藏确认和推进按钮，避免用户误以为还需要继续操作。
4. 旧后端未带 `timelineCompleted` 字段时，前端仍可根据全节点 `completed` 自动兜底为完成态，保证发布切换过程页面可用。
