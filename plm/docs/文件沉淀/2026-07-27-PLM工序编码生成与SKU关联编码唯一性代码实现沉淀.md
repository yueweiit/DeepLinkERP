## 2. 目标效果

- 模具编码统一为 `M + 产品特定编码 + 材质编码 + 手机型号编码`，例如 `MFA101291`。
- 工序、半成品、成品编码统一为 `N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码`。
- 产品线工艺路线先使用占位：手机型号 `0000`，颜色 `00`，例如 `NFA1020000000`。
- 新型号 / SKU 继承工序时重算真实编码，例如半成品 `NFA1020129101`，成品 `NFA4030129101`。
- 最终工序 `4030` 自动生成成品编码，成品编码优先作为 SKU 关联主键。
- 导入和搜索支持完整 `M` / `N` 编码、5 位产品短码、9 位新型号 / SKU 短码。
- 数据库层补充唯一索引，避免产品特定编码、成品编码和同一产品下手机型号 + 颜色重复。

## 4. 核心代码逻辑

### 4.1 统一编码生成器

`ProductBusinessCodeGenerator` 保留模具编码生成，并新增完整 `N` 编码解析：

```java
public String generateProductStateCode(String productSpecificCode, String operationCode,
                                       String phoneModelCode, String colorCode) {
    String product = requiredCode(productSpecificCode, "产品特定编码不能为空");
    String operation = requiredCode(operationCode, "工序编码不能为空");
    String phone = requiredCode(phoneModelCode, "手机型号编码不能为空");
    String color = requiredCode(colorCode, "颜色编码不能为空");
    return PRODUCT_STATE_PREFIX + product + operation + phone + color;
}
```

解析时从右向左识别颜色 2 位、手机型号 4 位、工序 4 位，剩余部分作为产品特定编码。`4030` 被识别为成品工序。

### 4.2 工艺路线保存

`ProcessRouteServiceImpl` 保存工序时不再使用材料/状态编码拼接产品工序编码，而是生成上下文：

```java
return businessCodeGenerator.generateProductStateCode(
    codeContext.productSpecificCode(),
    operationCraftCode,
    codeContext.phoneModelCode(),
    codeContext.colorCode()
);
```

产品线场景写入：

- `phone_model_code = 0000`
- `color_code = 00`
- `code_generation_context = product_line_route`

新型号 / SKU 场景优先使用 Product 或 DTO 中的真实 `phone_model_code`、`color_code`。当工序编码为 `4030` 时，同步写入 `generated_finished_product_code`。

### 4.3 工序继承

`ProcessRouteInheritanceService` 继承产品线工序时只继承顺序、工序库编码、参数、质量要求等工艺信息，不复制源产品线的 `0000` 业务编码。目标产品如果是新型号 / SKU，会按目标手机型号与颜色重新生成工序编码和成品编码。

### 4.4 Product 成品编码与唯一性

`ProductServiceImpl` 新增产品业务编码字段归一化：

- `product_specific_code`：产品线特定编码。
- `phone_model_code`：新型号 / SKU 手机型号编码。
- `color_code`：SKU 颜色编码。
- `finished_product_code`：成品编码，默认按 `4030` 最终工序生成。
- `import_short_code`：外部 5 位 / 9 位短码。

应用层校验：

- 产品线 `product_specific_code` 唯一。
- 有效 `finished_product_code` 唯一。
- 同一 `parent_product_id` 下 `phone_model_code + color_code` 唯一。

### 4.5 导入识别

`MasterDataImportExportServiceImpl` 增加产品模板字段与导入预览识别结果：

- `normalized_code`
- `detected_object_type`
- `matched_product_code`
- `matched_finished_code`
- `match_status`
- `match_message`

识别优先级：

1. 完整 `M` 模具编码。
2. 完整 `N` 半成品 / 成品编码。
3. 5 位产品短码。
4. 9 位新型号 / SKU 短码。
5. 其他编码标记为待人工确认或错误。

### 4.6 前端预览

`ProjectProcessRoutePanel.vue` 前端预览公式与后端保持一致：

```ts
function previewBusinessOperationCode(operation: ProcessOperationSavePayload) {
  const productSpecificCode = normalizeBusinessCode(operation.productSpecificCode || props.productSpecificCode || deriveProductSpecificCode(), '')
  const operationCraftCode = findOperationCraftCode(operation)
  const phoneModelCode = normalizeBusinessCode(operation.phoneModelCode || props.phoneModelCode, '0000')
  const colorCode = normalizeBusinessCode(operation.colorCode || props.colorCode, '00')
  if (!productSpecificCode || !operationCraftCode) return operation.businessOperationCode || ''
  return `N${productSpecificCode}${operationCraftCode}${phoneModelCode}${colorCode}`.toUpperCase()
}
```

材料/状态继续作为工艺属性保存，但不参与产品工序编码尾段。

## 6. 好处

- 编码来源统一，前端预览、后端保存、导入解析不再各自拼接。
- 产品线工艺可以先沉淀通用路线，新型号 / SKU 继承后自动替换真实手机型号和颜色。
- 成品编码成为 SKU 精确关联主键，BOM、工艺中心、库存反查更稳定。
- 唯一索引把重复成品编码、重复产品线特定编码挡在数据库层。
- 导入数据时能按编码长度和前缀快速判断对象层级，减少人工查找成本。
- 搜索可直接命中产品特定编码、手机型号编码、颜色编码、成品编码。

## 8. 后续维护建议

- 上线前先在数据库执行重复数据排查，重点检查 `finished_product_code`、`product_specific_code`、`business_operation_code` 是否已有重复值。
- 产品特定编码、手机型号编码、颜色编码应逐步进入基础资料或编码中心维护，减少人工输入差异。
- 如果未来产品特定编码长度不固定，完整 `N` 编码解析应优先结合产品特定编码字典，而不是只依赖固定截位。
- 导入时对 `match_status = conflict` 或 `error` 的行保持禁止提交，避免把错误归属写入 Product。
- 成品编码只作为 SKU 关联主键和反查入口，不建议让用户在普通流程里手工拼接。
- 工序编码规则再调整时，应同步修改 `ProductBusinessCodeGenerator`、前端预览函数、导入识别测试和数据库唯一性说明。

## 9. 2026-08-04 编辑路线业务工序编码冲突修复

### 9.1 问题现象

编辑 `NWV4030-CUSTOM-A` 工艺路线时，保存接口返回：

```text
businessOperationCode already exists: NWV4030000000
```

该编码对应产品线通用路线的组合：

```text
产品特定编码 WV + 工序 4030 + 手机型号 0000 + 颜色 00
```

数据库中已有该路线的历史工序记录。编辑流程会先重建当前路线工序，因此当前路线旧工序应被视为可复用对象，不能被当作其他路线的冲突数据。

### 9.2 代码改动

后端：

- `ProcessRouteServiceImpl.update` 重建工序时传入当前路线 ID。
- `ensureBusinessOperationCodeAvailable` 检查全局唯一时排除当前路线的旧工序。
- `softDeleteOperations` 改为使用明确列名的 `UpdateWrapper` 批量软删除：
  - `deleted_flag=1`
  - 更新 `updated_at`、`updated_by`
  - 条件限定当前路线、`process_type=operation`、active 数据

前端：

- `ProjectProcessRoutePanel.vue` 新增 `editingProcessId`。
- 打开编辑弹窗时固定路线 ID。
- 保存时优先使用固定的编辑路线 ID 调用 `PUT /process-routes/{processId}`，避免选中项变化导致误走新增接口。

其他路线仍然遵守 `business_operation_code` 全局唯一约束，不会放宽重复数据校验。
