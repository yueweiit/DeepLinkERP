# 2026-07-27 PLM 工序编码生成与 SKU 关联编码唯一性改造方案

## 1. 任务理解

本次先输出实现方案文档，不直接修改业务代码。目标是把现有工序自动生成编码、SKU 关联、导入识别和搜索查询统一到新的编码规则上：

- 模具编码：`M + 产品特定编码 + 材质编码 + 手机型号编码`，例如 `MFA101291`。
- 半成品 / 成品 / 工序状态编码：`N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码`，例如 `NFA1020129101`、`NFA4030129101`。
- 导入外部短码时，5 位编码识别为产品层，9 位编码识别为新型号 / 成品 / SKU 层，字母也计入长度，全部按文本处理。
- SKU 关联优先使用成品编码；成品编码主要用于 SKU 精确关联、BOM / 工艺 / 库存反查，不作为用户手工拼接字段。
- 一个新型号在 SKU 粒度下只绑定一个成品编码；不同产品下的同一手机型号视为不同新型号，成品编码也必须不同。
- 产品线工艺路线中的手机型号编码位置先使用 `0000`；新型号 / SKU 继承工序后，详情工序编码自动替换为真实手机型号编码，成品编码自动带颜色编码。

## 2. 所属 PLM 业务链路

本需求属于 PLM 内部 Product、Process、Inventory 三条链路的交叉规则：

| 链路 | 作用 |
| --- | --- |
| Product | 承载产品线、新型号、颜色版本和 SKU 业务明细，不新增 SKU / PhoneModel 根对象 |
| Process | 维护产品线通用工艺路线、新型号继承工艺路线、工序状态编码 |
| Inventory | 承载模具、半成品、成品等可流转编码，成品编码用于 SKU 关联和库存 / BOM 反查 |

边界说明：本方案不做 ERP / MES / WMS 正式集成，只预留导入、编码映射、反查和搜索能力。

## 4. 目标编码规则

### 4.1 两层识别

导入、搜索和保存前预览都采用两层识别：

| 输入类型 | 判断规则 | 处理方式 |
| --- | --- | --- |
| 完整模具编码 | `M` 开头，按 `M + 产品特定编码 + 材质编码 + 手机型号编码` 解析 | 匹配 Inventory 中的 tooling / fixture 或模具档案 |
| 完整半成品 / 成品编码 | `N` 开头，按 `N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码` 解析 | 工序 `4030` 识别为成品 / SKU，其他工序识别为半成品 |
| 5 位短码 | 标准化后长度为 5 | 识别为产品层短码 |
| 9 位短码 | 标准化后长度为 9 | 识别为新型号 / 成品 / SKU 层短码 |
| 其他 | 无法解析 | 导入预览标记异常，搜索作为普通关键字 |

标准化规则：去首尾空格、字母转大写、按文本保存、保留前导 0，不自动删除中间横杠或空格。

### 4.2 工序编码生成

统一公式：

```text
工序业务编码 = N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码
```

生成上下文：

| 场景 | 产品特定编码 | 工序编码 | 手机型号编码 | 颜色编码 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 产品线工艺路线 | 产品线 `product_specific_code` | 工序库 `operation_craft_code` | `0000` | 无颜色时用通用占位 `00`，有颜色上下文则用颜色编码 | 用于通用路线预览和模板，不作为正式 SKU 成品码 |
| 新型号 / SKU 继承路线 | 继承产品线的 `product_specific_code` | 原工序编码 | 新型号真实 `phone_model_code` | SKU / 颜色明细的 `color_code` | 生成可用于半成品 / 成品追溯的正式编码 |
| 最终工序 | 同上 | `4030` | 同上 | 同上 | 生成成品编码，作为 SKU 关联主键 |

示例：

```text
产品线通用路线：NFA1020000000
新型号半成品：NFA1020129101
新型号成品：NFA4030129101
```

### 4.3 SKU 关联口径

不新增 SKU 根对象。SKU 继续作为 Product 下的业务类型 / 明细承载，同时在 Product 或 Inventory 中保留成品编码：

- SKU 查询、BOM 关联、工艺路线关联优先使用 `finished_product_code`。
- 旧数据只有 `product_code` 时，继续兼容显示和搜索。
- 成品编码为 `N + 产品特定编码 + 4030 + 手机型号编码 + 颜色编码`。
- 数据库层保证同一个有效成品编码只能归属一个 SKU 业务明细。

## 5. 数据模型与唯一性

### 5.1 Product 字段补强

建议新增迁移文件：`plm-server/src/main/resources/db/migration/V20260727_1300__product_business_code_fields.sql`

```sql
alter table if exists plm_product
    add column if not exists product_specific_code varchar(20),
    add column if not exists phone_model_code varchar(20),
    add column if not exists color_code varchar(20),
    add column if not exists finished_product_code varchar(80),
    add column if not exists import_short_code varchar(20);

update plm_product
set product_specific_code = upper(product_code_prefix)
where product_specific_code is null
  and product_code_prefix is not null;

create unique index if not exists uk_plm_product_specific_code_active
    on plm_product (product_specific_code)
    where product_specific_code is not null
      and product_type = 'product_line'
      and deleted_flag = 0;

create unique index if not exists uk_plm_product_finished_product_code_active
    on plm_product (finished_product_code)
    where finished_product_code is not null
      and deleted_flag = 0;

create unique index if not exists uk_plm_product_variant_color_code_active
    on plm_product (parent_product_id, phone_model_code, color_code)
    where phone_model_code is not null
      and color_code is not null
      and product_type in ('model_variant', 'sku')
      and deleted_flag = 0;
```

字段说明：

| 字段 | 用途 |
| --- | --- |
| `product_specific_code` | 正式产品特定编码，例如 `FA`，优先替代历史 `product_code_prefix` |
| `phone_model_code` | 新型号 / SKU 的手机型号编码，例如 `1291` |
| `color_code` | SKU / 成品颜色编码，例如 `01` |
| `finished_product_code` | 成品编码 / SKU 关联主键，例如 `NFA4030129101` |
| `import_short_code` | 外部 5 位 / 9 位短码，保留导入追溯 |

### 5.2 Process 字段补强

建议新增迁移文件：`plm-server/src/main/resources/db/migration/V20260727_1310__process_operation_code_context.sql`

```sql
alter table if exists plm_process
    add column if not exists product_specific_code varchar(20),
    add column if not exists phone_model_code varchar(20),
    add column if not exists color_code varchar(20),
    add column if not exists generated_finished_product_code varchar(80),
    add column if not exists code_generation_context varchar(30);

drop index if exists idx_plm_process_business_operation_code;

create unique index if not exists uk_plm_process_business_operation_code_active
    on plm_process (business_operation_code)
    where business_operation_code is not null
      and process_type = 'operation'
      and deleted_flag = 0;

create index if not exists idx_plm_process_code_context_search
    on plm_process (product_specific_code, phone_model_code, color_code, operation_craft_code)
    where deleted_flag = 0;
```

`code_generation_context` 建议值：

| 值 | 含义 |
| --- | --- |
| `product_line_route` | 产品线通用路线，手机型号位置为 `0000` |
| `model_variant_route` | 新型号继承路线，使用真实手机型号编码 |
| `sku_route` | SKU / 颜色明细路线，使用真实手机型号编码和颜色编码 |

### 5.3 Inventory / 成品唯一性

如果成品也进入 Inventory，继续使用 `plm_inventory.inventory_code` 承载成品编码，数据库已有唯一约束 `uk_plm_inventory_code` 可保障编码不重复。导入时需要额外校验：

- `inventory_type = finished` 时，`inventory_code` 必须是完整成品编码或可反查到 `finished_product_code`。
- `inventory_type = semi_finished` 时，`inventory_code` 可以是非 `4030` 工序的 `N` 编码。
- `inventory_type = tooling / fixture` 时，`inventory_code` 可以是 `M` 模具编码。

public ProductStateCodeParts parseProductStateCode(String code) {
    String normalized = requiredCode(code, "产品状态编码不能为空");
    if (!normalized.startsWith(PRODUCT_STATE_PREFIX)) {
        throw validation("产品状态编码必须以 N 开头");
    }
    // 固定口径：N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码。
    // 产品特定编码长度建议优先按基础资料字典匹配；没有字典时兼容当前两位示例。
}

public boolean isFinishedProductCode(String code) {
    ProductStateCodeParts parts = parseProductStateCode(code);
    return DEFAULT_FINAL_OPERATION_CODE.equals(parts.operationCode());
}
```

private String resolveBusinessOperationCode(Product product, ProcessOperationDTO dto,
                                            String operationCraftCode, CodeContext context) {
    if (Boolean.TRUE.equals(dto.getBusinessOperationCodeManualFlag())
        && StringUtils.hasText(dto.getBusinessOperationCode())) {
        return normalizeBusinessOperationCode(dto.getBusinessOperationCode());
    }
    if (!StringUtils.hasText(operationCraftCode)) {
        return null;
    }
    String productSpecificCode = resolveProductSpecificCode(product);
    String phoneModelCode = resolvePhoneModelCode(product, context);
    String colorCode = resolveColorCode(product, dto, context);
    return businessCodeGenerator.generateProductStateCode(
        productSpecificCode,
        operationCraftCode,
        phoneModelCode,
        colorCode
    );
}
```

## 8. 导入和搜索目标效果

### 8.1 导入效果

| 示例 | 识别结果 | 目标动作 |
| --- | --- | --- |
| `AB123` | 5 位产品短码 | 匹配 / 创建 Product，不创建 SKU |
| `AB1234567` | 9 位新型号 / 成品短码 | 匹配 SKU 候选或进入成品编码确认 |
| `MFA101291` | 模具编码 | 解析产品特定编码 `FA`、材质 `10`、手机型号 `1291` |
| `NFA1020129101` | 半成品编码 | 解析工序 `1020`，不作为 SKU 成品关联 |
| `NFA4030129101` | 成品编码 | 精确匹配 SKU，反查产品、手机型号、颜色 |

### 8.2 搜索效果

全局搜索或列表搜索输入任意编码时：

- 输入完整 `NFA4030129101`：直接命中 SKU / 成品、相关 BOM、最终工序。
- 输入 `1291`：命中手机型号编码相关新型号、SKU 和工艺路线。
- 输入 `FA`：命中产品特定编码相关产品线、模具、半成品 / 成品。
- 输入 5 位产品短码：命中产品层数据。
- 输入 9 位成品短码：命中 SKU / 成品层数据。

建议新增索引：

```sql
create index if not exists idx_plm_product_business_code_search
    on plm_product (product_specific_code, phone_model_code, color_code, finished_product_code)
    where deleted_flag = 0;

create index if not exists idx_plm_inventory_code_type_search
    on plm_inventory (inventory_code, inventory_type)
    where deleted_flag = 0;
```

## 9. 验收用例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A1 | 产品线工艺路线新增工序，产品特定编码 `FA`，工序 `1020` | 自动生成 `NFA1020000000` |
| A2 | 新型号继承产品线工序，手机型号编码 `1291`，颜色编码 `01` | 工序编码重新生成为 `NFA1020129101` |
| A3 | 最终工序 `4030`，手机型号 `1291`，颜色 `01` | 成品编码为 `NFA4030129101`，写入 `finished_product_code` |
| A4 | 同一 SKU 再次导入同一成品编码 | 允许更新非关键字段，不改写归属 |
| A5 | 同一成品编码归属不同产品 / 新型号 | 导入预览标记冲突，禁止提交 |
| A6 | 不同产品下同一个手机型号，各自生成成品编码 | 两个成品编码不同，互不覆盖 |
| A7 | 导入 5 位短码 | 识别为产品，不自动创建 SKU |
| A8 | 导入 9 位短码 | 识别为新型号 / SKU 候选 |
| A9 | 导入完整 `N` 编码但工序不是 `4030` | 识别为半成品，不作为 SKU 成品关联 |
| A10 | 搜索完整成品编码 | 命中 SKU、BOM、工艺路线和库存成品记录 |

## 10. 实施顺序

1. 增加数据库字段和唯一索引，先兼容旧数据，不立即删除 `product_code_prefix`、`mold_code_prefix`、`material_status_code`。
2. 补齐 Product DTO / VO / Entity 字段，产品线维护 `product_specific_code`，新型号 / SKU 维护 `phone_model_code`、`color_code`。
3. 扩展 `ProductBusinessCodeGenerator`，统一生成和解析 `M` / `N` 编码。
4. 改造 `ProcessRouteServiceImpl`，后端保存时按新公式生成工序业务编码。
5. 改造 `ProcessRouteInheritanceService`，继承路线时不复制旧业务编码，而是按目标产品 / SKU 上下文重算。
6. 改造前端 `ProjectProcessRoutePanel.vue` 预览逻辑，保证保存前展示与后端一致。
7. 改造导入预览识别、冲突校验和提交拦截。
8. 改造 BOM / 工艺中心 / 库存列表中的 SKU code 展示，优先用 `finished_product_code`。
9. 补充单元测试、前端测试和导入验收用例。
10. 试运行一个产品线和一个新型号，再批量迁移历史数据。

## 11. 风险点与处理

| 风险 | 处理 |
| --- | --- |
| 历史数据只有 `product_code`，没有产品特定编码 / 手机型号编码 / 颜色编码 | 迁移时先保留空值，导入预览和详情页提示补齐，不强行推导 |
| 现有 `product_type = sku` 与开发提示词“不得新增 SKU 根对象”有冲突表象 | 不新增 SKU 根表；现有 `sku` 仅作为 Product 的业务类型兼容，后续可收敛为 Product 明细 |
| 产品线通用路线没有真实颜色 | 使用 `00` 通用占位，只用于产品线通用路线预览；正式 SKU 成品码必须使用真实颜色编码 |
| 产品特定编码长度未来变化 | 解析优先依赖基础资料字典，不只按固定截位 |
| 手工修改业务编码导致公式不一致 | 保留手工标记，但保存时增加公式校验和风险提示；发布 / 锁定后不允许随意改编码 |

## 12. 目标效果

改造完成后，系统应达到以下效果：

- 工序编码、半成品编码、成品编码都来自同一套生成器。
- 产品线工艺路线可先用 `0000` 占位，方便先沉淀通用工艺。
- 新型号 / SKU 继承工序时自动带出真实手机型号编码和颜色编码。
- 最终工序自动生成成品编码，成品编码成为 SKU 关联主键。
- 编码在数据库层具备唯一性约束，避免重复成品和重复工序业务编码。
- 导入数据时可以按完整 `M` / `N` 编码、5 位短码、9 位短码稳定识别对象类型。
- 搜索时可以通过产品特定编码、手机型号编码、颜色编码、成品编码快速反查产品、SKU、BOM、工艺路线和库存记录。
