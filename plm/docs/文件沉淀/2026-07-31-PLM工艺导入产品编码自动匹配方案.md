# PLM 工艺导入产品编码自动匹配方案

## 1. 背景

当前系统管理 / 数据导入页面支持按对象导入历史基础资料，其中 `Process 工艺记录` 导入用于沉淀工艺路线、工序、历史工艺记录。现有提交逻辑会把导入成功的工艺数据写入正式业务表 `plm_process`，同时写入 `plm_import_batch` 和 `plm_import_detail` 记录批次、每行结果和失败原因。

当前工艺导入的产品归属字段是 `product_code`。代码在预览校验和提交写入时，主要通过 `plm_product.product_code` 精确匹配产品。如果 Excel 里填的是成品编码、历史短码、SKU 编码、型号短码等非 `product_code` 的业务编码，系统不能稳定自动匹配，容易出现“归属 Product 不存在”或导入后 `product_id` 为空的情况。

## 2. 当前逻辑

### 2.1 工艺导入提交链路

页面操作：

1. 上传预览：调用 `/api/v1/import-export/process/preview`，校验文件内容。
2. 提交导入：调用 `/api/v1/import-export/{importToken}/commit`，写正式数据。

后端关键逻辑：

1. `validateProcessRow` 校验 `product_code`、`process_code`、`process_type`、`status` 等字段。
2. `findProductByCode(product_code)` 只按 `plm_product.product_code` 查找产品。
3. `insertProcess` 写入 `plm_process`，将匹配到的产品写入 `product_id`。
4. 每行成功 / 失败写入 `plm_import_detail`。

### 2.2 已有可复用能力

`product` 导入已有编码识别能力，会识别：

1. 成品编码：匹配 `plm_product.finished_product_code`。
2. 5 位产品短码：匹配 `plm_product.import_short_code`。
3. 9 位型号 / SKU 短码：匹配 `plm_product.import_short_code`。
4. 模具编码：能解析但目前倾向人工确认。

这些逻辑目前主要服务 `product` 导入，`process` 导入还没有完整复用。

## 3. 目标

工艺导入时，系统应能根据 Excel 中的产品相关编码自动匹配到已有产品，减少人工手动填 `product_code` 的成本。

目标效果：

1. 用户可在工艺导入模板中填标准 `product_code`，保持现有行为。
2. 用户也可填历史编码、成品编码、短码等业务编码，系统自动找到对应 `plm_product`。
3. 预览阶段明确展示匹配结果，避免提交后才发现挂错产品。
4. 匹配不到已有 SKU 时，如果能定位到上级产品或型号，则自动创建 SKU。
5. 匹配冲突或上级产品也不存在时，不自动落库，提示人工修正。
6. 提交导入后，`plm_process.product_id` 必须指向匹配到或自动创建的 SKU。

## 4. 推荐方案

推荐采用“显式编码字段 + 多规则匹配 + 预览确认”的方式。

### 4.1 模板字段调整

保留现有字段：

1. `product_code`：仍作为标准产品编码字段。

新增建议字段：

1. `product_match_code`：用于填写任意可识别的产品业务编码。
2. `product_match_type`：可选字段，用于指定编码类型，降低误判风险。

`product_match_type` 可选值：

1. `product_code`
2. `finished_product_code`
3. `import_short_code`
4. `auto`

为了兼容旧模板，若没有 `product_match_code`，系统仍使用 `product_code`。

### 4.2 匹配优先级

当导入一行工艺数据时，按以下顺序匹配产品：

1. 如果 `product_code` 能精确匹配 `plm_product.product_code`，优先使用该产品。
2. 如果 `product_match_code` 存在，并且 `product_match_type` 明确指定，则按指定字段匹配。
3. 如果 `product_match_type = auto` 或为空，则自动尝试：
   - `plm_product.product_code`
   - `plm_product.finished_product_code`
   - `plm_product.import_short_code`
   - 必要时按现有编码解析器识别 M/N 成品编码或短码。
4. 如果只匹配到 1 个产品，则视为匹配成功。
5. 如果匹配到多个产品，则视为冲突，预览报错，不提交该行。
6. 如果匹配不到已有 SKU，但能定位到唯一上级产品或型号，则预览标记为 `auto_create_sku`，提交时自动创建 SKU。
7. 如果 SKU 和上级产品都匹配不到，则预览报错，不提交该行。

### 4.3 工艺父级匹配

`parent_process_code` 仍用于匹配父级工艺或路线：

1. 若当前行是 `operation`，建议要求父级 `routing` 已存在或在同批次内较早行导入。
2. 若没有父级，但产品匹配成功，允许作为独立工序导入，后续在工艺路线页面人工整理。
3. 若业务要求工序必须挂路线，可在第二阶段把 `operation` 的父级路线设为强校验。

## 5. 预览展示

预览结果建议增加以下字段，便于用户确认：

1. 原始产品编码：用户填入的 `product_code` 或 `product_match_code`。
2. 匹配类型：例如 `product_code`、`finished_product_code`、`import_short_code`。
3. 匹配产品编码：最终匹配到的 `plm_product.product_code`。
4. 匹配产品名称：最终匹配到的 `plm_product.product_name`。
5. 匹配状态：`ready`、`error`、`conflict`、`manual_confirm`。
6. 提示信息：说明为何匹配成功、失败或冲突。

预览通过后再提交，提交时不重新“猜测”另一个产品，而是使用预览时已经确定的匹配结果。

## 6. 落库规则

提交成功时：

1. 如果匹配到已有 SKU，`plm_process.product_id` 写入该 SKU 的 `plm_product.product_id`。
2. 如果没有匹配到 SKU，但定位到上级产品或型号，则先自动创建 SKU，再把 `plm_process.product_id` 写为新 SKU 的 `product_id`。
3. `plm_process.product_specific_code` 优先取匹配或新建 SKU 的 `product_specific_code`；缺失时继承上级产品。
4. `plm_process.process_code`、`process_name`、`process_type`、`sequence_no`、`version_no`、`status`、`quality_requirement` 按现有字段写入。
5. `plm_import_detail.raw_payload` 记录原始编码、匹配类型、匹配产品编码、是否自动创建 SKU，方便追溯。

提交失败时：

1. 不写 `plm_process`。
2. 写 `plm_import_detail`，状态为 `fail`。
3. `error_message` 写清楚失败原因，例如“产品编码未匹配到 Product”或“产品编码匹配到多个 Product”。

## 7. 异常处理

### 7.1 SKU 匹配不到但父产品存在

处理方式：预览标记为 `auto_create_sku`，允许提交；提交时先创建 SKU，再导入工艺。

提示文案：

`未找到 SKU，提交后将在匹配到的上级产品下自动创建 SKU。`

### 7.2 SKU 和父产品都匹配不到

处理方式：预览失败，不允许提交该行。

提示文案：

`未找到 SKU，且无法定位上级产品，请补充 parent_product_code 或检查产品编码是否已在产品主数据中存在。`

### 7.3 匹配多个

处理方式：预览失败，不允许提交该行。

提示文案：

`产品编码匹配到多个 Product，请改用标准 product_code 或指定 product_match_type。`

### 7.4 编码格式非法

处理方式：预览失败，不允许提交该行。

提示文案：

`产品编码格式无法识别，请填写标准产品编码、成品编码或导入短码。`

### 7.5 只匹配到已归档产品

历史工艺导入本身常用于归档资料，建议允许匹配 `released` 和 `archived` 产品，但预览中标识产品状态，便于确认。

## 8. 数据兼容

该方案应保持旧模板可用：

1. 旧模板只填 `product_code` 时，行为不变。
2. 新模板可额外填 `product_match_code` 和 `product_match_type`。
3. 导出 Process 时，可继续导出标准 `product_code`，也可附带导出匹配说明字段。

## 9. 推荐实施步骤

第一阶段：后端匹配能力

1. 新增 `resolveProductForProcessImport` 方法，统一处理工艺导入产品匹配。
2. 在 `validateProcessRow` 中使用该方法校验产品归属。
3. 在 `insertProcess` 中使用同一套匹配结果写入 `product_id`。
4. 在预览行 values 中记录匹配结果，避免提交时结果漂移。

第二阶段：模板和前端预览

1. 工艺模板增加 `product_match_code`、`product_match_type`。
2. 预览表格显示匹配产品编码、产品名称和匹配提示。
3. 失败行突出展示原因。

第三阶段：测试和数据验收

1. 测试标准 `product_code` 匹配。
2. 测试 `finished_product_code` 匹配。
3. 测试 `import_short_code` 匹配。
4. 测试未匹配到 SKU 但能定位父产品时自动创建 SKU。
5. 测试 SKU 和父产品都匹配不到时失败。
6. 测试重复匹配冲突。
7. 测试成功导入后 `plm_process.product_id` 指向已有或新建 SKU。
8. 测试批次表和明细表记录正确。

## 10. 验收口径

满足以下条件即可认为方案落地成功：

1. 用户导入工艺文件时，不强制只能填系统标准 `product_code`。
2. 成品编码或历史短码能自动匹配到已有 Product。
3. 预览阶段可以看清楚每行最终挂到哪个产品。
4. 未匹配到 SKU 但父产品存在时，系统自动创建 SKU，并把工艺挂到新 SKU。
5. 父产品缺失或匹配冲突不会误写 `plm_process`。
6. 导入成功后，在工艺路线 / 工艺记录查询中能按 SKU 或上级产品看到对应工艺数据。

## 11. 推荐结论

可以做，而且建议做。

最佳落点是在 `Process 工艺记录` 导入链路中增加一个统一的产品匹配器，不建议只在前端做字符串转换。原因是导入提交、导出、批次追踪、后续脚本导入都依赖后端一致的匹配规则。前端负责展示匹配结果和提示，后端负责最终判定与落库。
## 12. 补充规则：未匹配到 SKU 时自动创建

根据业务确认，工艺导入场景下“产品应该是都有的”，真正缺失的通常不是产品大类或型号，而是具体 SKU 记录。因此匹配策略应从“匹配不到即失败”调整为：

1. 先尝试匹配已有 SKU。
2. 如果没有匹配到 SKU，再尝试定位上级产品或型号。
3. 只要能定位到上级产品或型号，就自动创建 SKU。
4. 自动创建 SKU 后，工艺记录挂到新 SKU 的 `product_id` 上。
5. 如果连上级产品或型号也定位不到，才预览失败。

### 12.1 自动创建 SKU 的前提

自动创建 SKU 必须满足以下条件：

1. 导入行能提供一个可作为 SKU 识别依据的编码，例如成品编码、9 位短码、SKU 编码或 `product_match_code`。
2. 系统能根据该编码解析或匹配到上级 Product，通常是产品线或型号。
3. 同一个 SKU 编码在 `plm_product` 中不存在。
4. 同一个导入文件内没有重复 SKU 编码。
5. 导入行没有其他硬错误，例如 `process_code` 重复、`process_type` 不支持、`status` 不支持。

### 12.2 自动创建 SKU 的父级定位

父级定位建议按以下优先级：

1. 如果模板中明确填写 `parent_product_code`，优先按该字段匹配上级产品。
2. 如果没有 `parent_product_code`，根据 `product_code` / `product_match_code` 解析产品短码、型号短码或成品编码。
3. 如果编码能匹配到已有型号，则新 SKU 挂到该型号下。
4. 如果编码只能匹配到产品线，则新 SKU 挂到产品线下，但预览提示“仅匹配到产品线，建议补充型号”。
5. 如果无法定位任何上级产品，则该行失败，不创建 SKU。

### 12.3 SKU 创建字段

自动创建的 SKU 建议写入 `plm_product`：

1. `product_type = sku`
2. `parent_product_id = 上级产品或型号 product_id`
3. `product_code = 自动生成或使用导入 SKU 编码`
4. `product_name = 上级产品名称 + SKU 编码`，如果模板有 SKU 名称则优先使用模板值
5. `finished_product_code = 成品编码`，如果导入编码是成品编码
6. `import_short_code = 短码`，如果导入编码是 5 位或 9 位短码
7. `product_specific_code / phone_model_code / color_code` 尽量从上级产品继承，或从编码解析结果补齐
8. `version_no = V1` 或使用导入行版本
9. `status = archived`，历史导入默认归档；如果业务希望继续可用，可改为 `released`
10. `remark` 标记“工艺导入自动创建 SKU”

### 12.4 预览状态调整

预览阶段需要区分三种成功状态：

1. `matched`：匹配到已有 SKU 或 Product。
2. `auto_create_sku`：未匹配到 SKU，但已定位上级产品，提交时会自动创建 SKU。
3. `error`：SKU 和上级产品都无法定位，不能提交。

前端预览文案建议：

1. 匹配已有 SKU：`已匹配 SKU：{product_code}`
2. 自动创建 SKU：`未找到 SKU，提交后将在 {parent_product_code} 下自动创建 SKU`
3. 无法创建：`未找到 SKU，且无法定位上级产品，请补充 parent_product_code 或产品编码`

### 12.5 落库顺序

提交导入时，每一行按以下顺序处理：

1. 再次读取预览阶段确定的匹配结果。
2. 如果是 `matched`，直接使用已有 `product_id`。
3. 如果是 `auto_create_sku`，先插入 `plm_product` 创建 SKU。
4. 使用已有或新建 SKU 的 `product_id` 插入 `plm_process`。
5. 在 `plm_import_detail.raw_payload` 中记录 `auto_created_sku_product_id`、`parent_product_id`、`match_status`。

### 12.6 风险控制

自动创建 SKU 有误建风险，因此建议加三条保护：

1. 只允许在 `process` 历史导入中自动创建 `sku`，不自动创建产品线或型号。
2. 父级产品必须已存在，否则失败。
3. 预览阶段必须明确显示即将创建的 SKU，用户确认后再提交。

### 12.7 更新后的推荐结论

最终推荐规则为：工艺导入先自动匹配已有 SKU；如果没有匹配到 SKU，但能定位已有父产品或型号，则自动创建 SKU 并挂载工艺；如果父产品也不存在，则失败。这样既符合“产品应该都有”的业务前提，也能避免因为历史 SKU 主数据不完整导致工艺导入大量失败。

## 13. 补充规则：按产品自动生成一条工艺路线

根据进一步确认，导入表中体现的是“产品的工艺路线资料”，不应要求用户在 Excel 中额外维护一条路线主记录。导入时系统应为每个对应产品自动生成一条工艺路线，再把该产品的工艺内容归属到这条路线下。

### 13.1 生成原则

1. 每个最终匹配到或自动创建的 SKU / Product，在一次导入批次中自动生成一条 `process_type = routing` 的工艺路线。
2. 同一个产品在同一个导入批次内只生成一条路线，后续同产品行复用这条路线。
3. 如果该产品已有可复用的历史导入路线，可按业务策略选择复用或新建；推荐默认新建，避免覆盖旧历史。
4. 导入行如果是具体工序，则写为 `process_type = operation`，并把 `parent_process_id` 指向自动生成的路线。
5. 导入行如果本身只是路线摘要，则只生成路线主记录，不额外生成工序。

### 13.2 自动路线字段

自动生成的路线写入 `plm_process`：

1. `product_id = 匹配到或自动创建的 SKU/Product 的 product_id`
2. `process_type = routing`
3. `process_code = 自动生成路线编码`
4. `process_name = 产品名称 + 工艺路线`
5. `version_no = 导入行版本号，缺省为 V1`
6. `status = 导入行状态，缺省为 archived 或 confirmed`
7. `remark = 工艺导入自动生成路线`

路线编码建议格式：

`ROUTE-{product_code}-IMP-{import_batch_id}`

如果同一产品同批次重复出现，复用同一条路线；如果跨批次重复导入，可以生成不同批次路线，方便追溯。

### 13.3 工序挂载规则

如果导入表中每一行代表工序，则系统处理顺序为：

1. 先完成产品匹配或 SKU 自动创建。
2. 按产品获取或创建本批次自动路线。
3. 插入工序 `operation`。
4. 将工序的 `parent_process_id` 指向自动路线的 `process_id`。
5. 工序的 `sequence_no` 使用导入表中的顺序号；缺失时按该产品在文件中的行顺序自动生成。

这样导入后在工艺路线页面看到的是：

1. 产品 / SKU 下有一条路线。
2. 路线下有导入的工序明细。
3. 后续可以在页面上继续编辑、冻结或归档。

### 13.4 与 parent_process_code 的关系

导入模板中可以弱化甚至取消 `parent_process_code`：

1. 如果用户填写了 `parent_process_code`，优先按用户填写的父级路线挂载。
2. 如果没有填写，则使用系统为该产品自动生成的路线。
3. 如果填写的父级路线不存在，不建议失败整个产品导入；推荐预览提示，并允许用户选择“改用自动生成路线”。

第一版实现建议直接采用：`parent_process_code` 为空时自动生成路线；不为空时按现有逻辑匹配。

### 13.5 预览展示

预览阶段需要让用户看到系统即将创建路线：

1. `matched_product_code`：匹配到或自动创建的 SKU/Product 编码。
2. `auto_route_code`：提交后将创建或复用的工艺路线编码。
3. `auto_route_name`：提交后将创建或复用的工艺路线名称。
4. `route_action`：`create_route`、`reuse_batch_route`、`use_existing_route`。
5. `operation_action`：`create_operation` 或 `route_only`。

推荐文案：

`已匹配产品，提交后将自动生成工艺路线 {route_code}，并把本行工序挂到该路线下。`

### 13.6 更新后的最终导入流程

最终推荐流程为：

1. 读取导入行。
2. 根据编码匹配已有 SKU。
3. 未匹配到 SKU 时，定位上级产品或型号并自动创建 SKU。
4. 按最终产品获取或创建一条自动工艺路线。
5. 将导入行写入路线或路线下的工序。

### 14.6 对当前文件的最终结论

该文件不是“路线主表 + 工序明细”的完整 PLM 结构，而是历史工序清单。导入时系统应自动补齐 PLM 层级：
