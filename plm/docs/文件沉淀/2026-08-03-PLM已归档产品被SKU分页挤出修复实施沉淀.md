# 2026-08-03 PLM 已归档产品被 SKU 分页挤出修复实施沉淀

## 1. 现象

项目管理 -> 已归档 -> 产品管理 页面只显示 1 个产品：`PRD-超队30-0001`。

数据库中实际存在 7 个 seeds 历史产品线：

| 产品编码 | 产品名称 | 状态 |
| --- | --- | --- |
| `NBA4030` | 亮甲Rainbow 2.0 | `archived` |
| `NBD4030` | 圣殿Case Blindaje | `archived` |
| `NDN4030` | Alterna幻甲 | `archived` |
| `NFA4020` | 幻影Fantasía Case | `archived` |
| `NFB4020` | titanio 骑士2.0 | `archived` |
| `NHA4030` | 超队Súper Capitán | `archived` |
| `NWV4030` | waves薇武士 | `archived` |

## 2. 根因

前端 `ProjectCenterView.vue` 原加载逻辑只请求：

```ts
getProjects({ page: 1, size: 200 })
getProjects({ page: 1, size: 200, status: 'released' })
getProjects({ page: 1, size: 200, status: 'archived' })
```

本次导入了 3830 条已归档 SKU，且创建时间比原产品线更新。后端项目列表按 `updated_at desc` 排序，`status=archived` 的第一页 200 条会优先返回 SKU，7 个产品线被分页挤到后面。

页面再在前端执行：

```ts
archivedProductRows = archivedProjects.filter(item => item.productType === 'product_line')
```

所以已归档产品区只剩 `released` 查询带回来的 1 个老产品。

## 3. 修复方式

修改文件：`plm-web/src/views/project/ProjectCenterView.vue`。

新增加载口径：

| 数据 | 查询 |
| --- | --- |
| 已发布产品线 | `status=released&productType=product_line`，分页拉全 |
| 已归档产品线 | `status=archived&productType=product_line`，分页拉全 |
| 已归档 SKU | `status=archived&productType=model_variant`，分页拉全 |

保留原有总体查询和已发布/已归档首屏查询，用于兼容全部项目和历史逻辑。

## 4. SKU 归档展示规则

SKU 管理首页第一层固定按真实产品线展示，不再按 SKU 名称、品牌或 `seriesName` 首词临时生成产品卡片。

归属判断按以下优先级执行：

1. 优先使用 SKU 的 `parent_product_id` 关联产品线。
2. 父产品关联缺失时，使用 SKU `product_code` 或 `finished_product_code` 是否以产品线 `product_code` 开头进行匹配。
3. 两种方式都无法匹配时，不生成伪产品卡片，避免出现 `ZTE`、`MOTOROLA`、`OPPO`、`APPLE` 等品牌空卡片。

因此，“已归档（SKU）”页面的产品卡片必须来自“已归档（产品）”中的真实产品线；孤立 SKU 仍保留在数据库和归档 SKU数据集中，但需要先补齐产品归属后才能在产品卡片下查看。

## 5. 目标效果

已归档（产品）页面不再被 SKU 分页影响，应能显示产品线：

| 产品编码 | SKU 数 | BOM 数 | 标准路线数 |
| --- | ---: | ---: | ---: |
| `NBA4030` | 628 | 6 | 4 |
| `NBD4030` | 218 | 1 | 1 |
| `NDN4030` | 36 | 1 | 1 |
| `NFA4020` | 1609 | 4 | 1 |
| `NFB4020` | 90 | 4 | 1 |
| `NHA4030` | 1068 | 4 | 1 |
| `NWV4030` | 181 | 4 | 1 |

如同时存在已发布产品线，例如 `PRD-超队30-0001`，仍保留在“已归档（产品）”视图中，因为当前页面定义把 `released/archived` 都归为历史完成态。

## 7. 后续建议

如果后续 SKU 数继续增长，建议后端为已归档页提供专用聚合接口，直接返回“产品 -> SKU/BOM/路线计数”，避免前端为了产品卡片一次性拉取大量 SKU。
