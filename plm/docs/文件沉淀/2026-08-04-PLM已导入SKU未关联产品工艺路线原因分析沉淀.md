# 2026-08-04 PLM 已导入 SKU 未关联产品工艺路线原因分析沉淀

## 背景

问题：`seeds` 已导入的 SKU 在系统中没有关联到对应产品的工艺路线。

本次先查原因，不做数据修复和代码修复。

涉及数据来源：

- `PLM/seeds/deployment_master_data_seed.json`
- `PLM/seeds/master_route_seed.json`
- `outputs/plm-seed-db-import/2026-08-03-import-report.json`

涉及代码：

- `scripts/import_plm_seed_color_process_to_db.py`
- `plm-server/src/main/java/com/yuewei/plm/module/process/service/impl/ProcessCenterServiceImpl.java`
- `plm-server/src/main/java/com/yuewei/plm/module/bom/service/impl/BomLedgerServiceImpl.java`

根据 `outputs/plm-seed-db-import/2026-08-03-import-report.json`：

| 对象 | 导入结果 |
| --- | ---: |
| 产品线 | 7 条已存在 |

结论：不是“工艺路线没有导入”，也不是“SKU 没有导入”。断点在 SKU 与工艺路线的关联匹配逻辑。

## 系统当前如何关联 SKU 与工艺路线

当前系统没有一张明确的 `SKU -> process_route` 关系表。

实际关联链路是推导出来的：

```text
plm_process routing
  -> plm_product_bom_route.process_id
  -> plm_product_bom_route_color
  -> 按颜色匹配 plm_product SKU
```

### 工艺中心匹配逻辑

`ProcessCenterServiceImpl` 中：

- 先查某条工艺路线关联的 active BOM route。
- 再查 BOM route 下 active 的颜色。
- 再取产品下的 SKU 候选。
- 最后用 `matchedRouteForColor(sku.getColorCode(), sku.getColor(), bomRoutes, colorsByBomRoute)` 匹配。

关键点：当前匹配用的是 `sku.getColor()` 和 `ProductBomRouteColor.colorName` 的名称归一化比较。

没有优先用 `color_code`。

### BOM 台账匹配逻辑

`BomLedgerServiceImpl` 中：

```text
routesByColor(active routes) -> key = ProductBomRouteColor.colorName
listSkus() -> byColor.get(product.getColor())
```

关键点同样是按颜色名称精确匹配，不按颜色编码匹配。

## 根因

### 根因 1：SKU 颜色名和 BOM route 颜色名不是同一种语言

导入脚本写 SKU 时：

```text
plm_product.color = mes_sku_master.color_name_zh 或 mes_sku_master.color
plm_product.color_code = mes_sku_master.color_short_code 或 color_code
```

导入脚本写 BOM route color 时：

```text
plm_product_bom_route_color.color_name = plm_code_item.code_name
plm_product_bom_route_color.color_code = BOM 编码解析出的两位颜色码
```

seed 数据中 SKU 颜色多为中文，BOM route color 多为西语/英文。

示例：

| 产品 | SKU 颜色 | BOM route color | 颜色编码 |
| --- | --- | --- | --- |
| `NBA4030` | `黑色` | `Negro` | `02` |
| `NBA4030` | `透明` | `Transparente` | `31` |
| `NFA4020` | `皇家蓝` | `Azul Rey` | `08` |
| `NFA4020` | `宝蓝色` | `azul real` | `13` |
| `NWV4030` | `泡泡糖粉` | `Chicle Rosa` | `86` |

这些颜色编码一致，但名称不一致。当前系统按名称匹配，因此匹配结果为空。

### 根因 2：部分 SKU 颜色编码没有对应 BOM route

seed SKU 中存在销售色或历史色，BOM route 只覆盖投产/参考 BOM 色。

示例：

| 产品 | SKU 有但 BOM route 没有 |
| --- | --- |
| `NBA4030` | `40`、`43`、`64` |
| `NBD4030` | `43` |
| `NDN4030` | `40` |
| `NFA4020` | `04`、`43` |
| `NFB4020` | `43` |
| `NWV4030` | `17`、`43`、`56`、`64` |

这些 SKU 即使改成按 `color_code` 匹配，也没有可匹配的 BOM route。

### 根因 3：导入的 BOM 是参考资料，不是正式 BOM

导入脚本创建 BOM 时使用：

```text
bom_scope = candidate
source_type = seed_reference
status = draft
```

这符合之前“先归档参考关系、不当成正式发布 BOM”的决策。

影响：

- 工艺中心如果看 `plm_process -> active bom route -> color`，理论上可以显示参考关联。
- BOM 正式台账如果只看 `formal + released`，不会把这些参考 BOM 当正式 BOM 展示。

因此“SKU 没有关联工艺路线”在不同页面有两层含义：

1. 工艺中心/路线关系为空：主要是颜色名称匹配失败。
2. 正式 BOM 台账不显示：这是 `candidate/seed_reference/draft` 的业务边界。

如需在运行库复核，可执行：

```sql
select
  p.product_code as product,
  sku.product_code as sku_code,
  sku.color as sku_color,
  sku.color_code as sku_color_code,
  br.route_code,
  brc.color_name as route_color,
  brc.color_code as route_color_code
from plm_product sku
join plm_product p on p.product_id = sku.parent_product_id
left join plm_product_bom_route br on br.product_id = p.product_id and br.status = 'active' and br.deleted_flag = 0
left join plm_product_bom_route_color brc on brc.product_bom_route_id = br.product_bom_route_id and brc.status = 'active' and brc.deleted_flag = 0
where sku.product_type in ('model_variant', 'sku')
  and sku.deleted_flag = 0
  and p.product_code in ('NBA4030','NBD4030','NDN4030','NFA4020','NFB4020','NHA4030','NWV4030')
order by p.product_code, sku.color_code, sku.product_code;
```

重点看：

```text
sku.color_code = brc.color_code
sku.color != brc.color_name
```

## 目标效果

历史导入 SKU 关联产品工艺路线时，应该按以下优先级：

1. `sku.color_code = product_bom_route_color.color_code`
2. fallback：标准化后的 `sku.color = product_bom_route_color.color_name`
3. 对没有 BOM route 的销售色，显示“未覆盖工艺路线”，不能强行挂到相似颜色。

## 建议修复方案

### 方案 A：修改查询匹配逻辑，优先按颜色编码匹配

改动点：

- `ProcessCenterServiceImpl.routeSkus()`
- `ProcessCenterServiceImpl.matchedRouteForColor()`
- `BomLedgerServiceImpl.routesByColor()` / `listSkus()`

建议改为：

```text
先用 color_code 匹配；
color_code 为空时再用 color_name 归一化匹配。
```

优点：

- 不改历史数据。
- 能正确处理中文、西语、英文颜色名差异。
- 保留销售色未覆盖状态。

## 方案 A 落地结果

方案 A 已落地到以下两个查询服务：

- `plm-server/src/main/java/com/yuewei/plm/module/process/service/impl/ProcessCenterServiceImpl.java`
- `plm-server/src/main/java/com/yuewei/plm/module/bom/service/impl/BomLedgerServiceImpl.java`

实际匹配规则调整为：

```text
1. SKU 有 color_code：只按 color_code 匹配 BOM route color。
2. SKU 没有 color_code：才按 trim + lowercase 后的 color_name 匹配。
3. SKU 有 color_code 但该编码没有 BOM route：保持未关联，不回退到相似颜色名称。
```

第三条是为了避免把销售色 `43 Black` 错误挂到生产色 `02 Negro`。

新增回归测试：

- `ProcessCenterServiceTest.relationsMatchesSkuByColorCodeWhenColorNamesDiffer`
- `BomLedgerServiceImplTest.skuMatchesRouteByColorCodeWhenColorNamesDiffer`

测试场景使用：

```text
SKU：color_code=02，color=黑色
BOM route color：color_code=02，color_name=Negro
预期：SKU 能关联到对应 BOM route / process route
```

## 结论

已导入 SKU 没有关联到对应产品工艺路线，主要不是导入缺 route，而是系统现有关联逻辑按颜色名称匹配，和 seed 数据的中西文颜色名不一致。

应该先修查询逻辑：用颜色编码作为主关联键，颜色名只作为 fallback。这样能让已有导入数据中编码一致的 SKU 正常关联到产品工艺路线，同时保留未覆盖颜色的差异清单。
