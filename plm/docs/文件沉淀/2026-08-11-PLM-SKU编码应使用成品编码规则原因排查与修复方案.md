## 1. 任务理解

当前 SKU 管理列表中，`SKU 编码` 列显示为：

```text
PRD-ALTERN-0004
PRD-ALTERN-0004-02
```

这不是业务期望的产品线编码或 SKU / 成品编码。用户确认后的正确规则分两层：

```text
产品线编码 = N + 产品特定编码 + 成品工序编码
SKU 编码 / SKU 成品编码 = 产品线编码 + 手机型号编码 + 颜色编码
```

示例：

```text
新产品线：NHA4030
具体 SKU：NHA4030129102
```

具体 SKU 拆解：

| 片段 | 含义 |
| --- | --- |
| `N` | 产品状态 / 工序状态编码前缀 |
| `HA` | 产品特定编码 |
| `4030` | 成品工序编码，来自产品线最终成品工序 |
| `1291` | 手机型号编码 |
| `02` | 颜色编码 |

注意：这里的“产品编码”指 `N` 体系编码，不是 `PRD-...` 项目编码。产品线层只到成品工序编码，例如 `NFB4020`、`NDN4030`、`NFA4020`、`NBA4030`、`NBD4030`、`NWV4030`、`NHA4030`；SKU 层在产品线编码后继续追加手机型号编码和颜色编码，例如 `NHA4030129102`。

## 2. 所属 PLM 业务链路

所属主线：新产品线 / 新型号线 / SKU 颜色发布链路。

业务链路：

```text
新产品线建档
  -> 确认产品特定编码和产品线成品工序编码
  -> 生成产品线编码 product_code，例如 NHA4030
  -> 新型号线建档
  -> 确认投产工序
  -> 确认投产颜色
  -> 后端创建 Product 类型的 SKU 明细
  -> 生成 SKU finished_product_code，例如 NHA4030129102
  -> SKU 管理 / BOM / 工艺路线展示 SKU 编码
```

核心对象：

- `Product`：承载产品线、新型号、SKU 业务类型，不新增 SKU 根对象。
- `Process`：承载工艺路线和 `4030` 成品工序编码。
- `Inventory`：后续承接成品库存追溯，本次不扩展外部集成。

### 3.5 后端仍有一个隐患：SKU finishedProductCode 可能为空

文件：

```text
plm-server/src/main/java/com/yuewei/plm/module/bom/service/ProductionConfirmationService.java
```

创建 SKU 时：

```java

```

`resolveAvailableFinishedProductCode()` 会检查成品编码唯一性：

```java
Long count = productRepository.selectCount(new LambdaQueryWrapper<Product>()
    .eq(Product::getFinishedProductCode, generated)
    .ne(currentSkuId != null, Product::getProductId, currentSkuId)
    .eq(Product::getDeletedFlag, 0));
return count == null || count == 0 ? generated : null;
```

现有测试中还固化了“如果父项目已经占用成品编码，SKU 的 `finishedProductCode` 为空”的行为：

```text

```

这会导致 SKU 管理页即使改成显示 `finishedProductCode`，也可能遇到空值，只能回退到 `PRD-...`。  
因此修复要分两层：

1. 前端 SKU 编码列优先显示 `finishedProductCode`。
2. 后端确认 SKU 成品编码的唯一归属和迁移策略，避免新 SKU 缺失 `finishedProductCode`。


## 7. 后端修复方案

### 7.1 明确 SKU 成品编码归属

当前风险：父新型号和 SKU 明细可能抢占同一个 `finished_product_code`，导致 SKU 的 `finishedProductCode` 为空。

建议目标：

- `product_type='product_line'` 的新产品线应使用产品线编码，例如 `NHA4030`、`NFA4020`，不能使用 `PRD-...` 作为业务展示主编码。
- 产品线成品工序编码应来自最终成品工序，不应全部固定为 `4030`；例如骑士系列已有 `4020`。
- `product_type='sku'` 的颜色 SKU 应持有最终 `finished_product_code`。
- 父新型号如果只代表型号项目，不代表具体颜色 SKU，则不应占用具体颜色成品编码。
- 如果历史父项目已经占用，应在创建 / 同步 SKU 时迁移给对应 SKU，或至少保证 SKU 页面可显示对应成品编码。

### 7.2 调整 `resolveAvailableFinishedProductCode`

当前逻辑发现任意 Product 占用即返回 `null`。  
建议改为允许同一项目链路内的父项目向 SKU 归属迁移：

```java
private String resolveAvailableFinishedProductCode(Product project, String colorCode, Long currentSkuId) {
    String generated = resolveFinishedProductCode(project, colorCode);
    if (!StringUtils.hasText(generated)) {
        return null;
    }
    List<Product> conflicts = safe(productRepository.selectList(new LambdaQueryWrapper<Product>()
        .eq(Product::getFinishedProductCode, generated)
        .ne(currentSkuId != null, Product::getProductId, currentSkuId)
        .eq(Product::getDeletedFlag, 0)));
    boolean externalConflict = conflicts.stream()
        .anyMatch(conflict -> !Objects.equals(conflict.getProductId(), project.getProductId())
            && !Objects.equals(conflict.getParentProductId(), project.getProductId()));
    return externalConflict ? null : generated;
}
```

更稳妥的实现方式：

1. 先不自动清空父项目 `finishedProductCode`。
2. SKU 创建时如果成品编码被父项目占用，但颜色 / 手机型号一致，允许 SKU 保存该成品编码，并后续用迁移脚本清理父项目占用。
3. 若数据库唯一索引禁止重复，则必须先迁移父项目字段，再给 SKU 写入。

### 7.3 历史数据迁移 SQL 草案

用于检查 SKU 应有成品编码：

```sql
select sku.product_id,
       sku.product_code,
       sku.finished_product_code,
       'N' || sku.product_specific_code || '4030' || sku.phone_model_code || sku.color_code as expected_finished_product_code
from plm_product sku
where sku.product_type = 'sku'
  and sku.deleted_flag = 0
  and sku.product_specific_code is not null
  and sku.phone_model_code is not null
  and sku.color_code is not null
  and coalesce(sku.finished_product_code, '') <> 'N' || sku.product_specific_code || '4030' || sku.phone_model_code || sku.color_code;
```

用于检查产品线编码不符合 `N + 产品特定编码 + 成品工序编码` 的数据：

```sql
select product_id,
       product_code,
       product_specific_code,
       finished_product_code
from plm_product
where product_type = 'product_line'
  and deleted_flag = 0
  and (
      product_code is null
      or product_code !~ '^N[A-Z0-9]+[0-9]{4}$'
      or product_code like 'PRD-%'
  );
```

历史产品线修复不建议只靠截位猜测成品工序编码，应优先使用工艺路线最终成品工序或 seed 映射表确认。例如 `NFA4020`、`NFB4020` 不能被批量改成 `NFA4030`、`NFB4030`。

修复 SKU 缺失成品编码：

```sql
update plm_product sku
set finished_product_code = 'N' || sku.product_specific_code || '4030' || sku.phone_model_code || sku.color_code,
    updated_at = now(),
    updated_by = 'system-sku-finished-code-repair'
where sku.product_type = 'sku'
  and sku.deleted_flag = 0
  and sku.product_specific_code is not null
  and sku.phone_model_code is not null
  and sku.color_code is not null
  and (sku.finished_product_code is null or sku.finished_product_code = '')
  and not exists (
      select 1
      from plm_product conflict
      where conflict.deleted_flag = 0
        and conflict.product_id <> sku.product_id
        and conflict.finished_product_code = 'N' || sku.product_specific_code || '4030' || sku.phone_model_code || sku.color_code
  );
```

冲突数据只输出报表，不自动覆盖：

```sql
select conflict.product_id,
       conflict.product_type,
       conflict.product_code,
       conflict.finished_product_code
from plm_product conflict
join plm_product sku
  on conflict.finished_product_code = 'N' || sku.product_specific_code || '4030' || sku.phone_model_code || sku.color_code
where sku.product_type = 'sku'
  and sku.deleted_flag = 0
  and conflict.deleted_flag = 0
  and conflict.product_id <> sku.product_id;
```

## 9. 风险点

1. 不要把 `PRD-...` 项目编码继续当作 SKU 编码展示。
2. 不要把所有产品线成品工序编码硬编码成 `4030`；历史数据中存在 `4020`，应以产品工艺最终成品工序为准。
3. 不要用颜色名称 `Negro` 参与成品编码拼接，只能使用颜色编码 `02`。
4. 如果 SKU 的 `finishedProductCode` 为空，前端只改显示仍会回退到错误口径，需要后端 / 数据修复。
5. 父新型号与 SKU 明细抢占同一成品编码时，需要明确归属，避免唯一索引冲突。
6. BOM 侧已优先显示 `finishedProductCode`，修复 SKU 管理页时应与 BOM 口径保持一致。

## 10. 实施顺序建议

1. 先确认产品线层 `productCode` 应展示为 `N + 产品特定编码 + 成品工序编码`，例如 `NHA4030`、`NFB4020`。
2. 前端 `SkuView.vue` 把 SKU 编码列改为优先显示 `finishedProductCode`，产品入口卡片保留产品线编码口径。
3. 后端确认 `ProductionConfirmationService` 创建 SKU 时必须写入 `finishedProductCode`。
4. 处理父项目占用成品编码导致 SKU `finishedProductCode` 为空的问题。
5. 增加历史数据检查 SQL，识别产品线 `productCode` 异常、SKU `finishedProductCode` 缺失或不符合公式的数据。
6. 补前端 `SkuView` 单测、后端 `ProductionConfirmationServiceTest`。
7. Playwright 验证产品入口显示 `NHA4030`，SKU 管理页显示 `NHA4030129102`。

## 12. 本次结论

正确规则是：

```text
产品线编码 = N + 产品特定编码 + 成品工序编码
SKU 编码 = finished_product_code = 产品线编码 + 手机型号编码 + 颜色编码
```

例如：

```text
NHA4030
NHA4030129102
```

当前截图显示 `PRD-...` 的根因是 SKU 管理页展示了 `productCode`，而不是 `finishedProductCode`；如果新产品线也显示 `PRD-...`，则还需要把产品线层展示 / 后端生成收口到 `N + 产品特定编码 + 成品工序编码`。  
同时后端存在 SKU `finishedProductCode` 可能为空的隐患，需要一起收口。

本次已按方案完成代码改造。
