# 2026-08-03 PLM 产品颜色工序关系对应系统落地沉淀

## 1. 本次范围

本次把 `2026-08-03-PLM-seeds产品颜色与工序对应关系沉淀.md` 对应到当前系统的数据对象、字段和模块页面口径。

本次只生成沉淀文档，不导入系统、不写数据库、不改代码。

## 2. 系统承接结论

产品颜色与工序关系不要落在单一表里，应拆成 5 类系统资料：

| 业务资料 | 系统承接对象 | 当前处理方式 |
| --- | --- | --- |
| 产品线 | `plm_product`，`product_type=product_line` | 系统已有 seed 产品线，可作为父级 |
| SKU/型号颜色版本 | `plm_product`，`product_type=model_variant` | 作为产品线子级承接 SKU |
| SKU/BOM适用颜色 | `plm_product_bom_route_color` | 挂在 BOM路线维度 |
| 生产颜色确认 | `plm_product_production_color_decision` | 记录哪些颜色被确认生成SKU |
| 工序/路线节点 | `plm_process` | 路线和工序节点承接工序、输出基础码、颜色上下文 |

现阶段不建议新增独立 `sku` 类型。虽然部分索引代码已兼容 `product_type in ('model_variant','sku')`，但系统基础约束仍以 `product_line/model_variant` 为稳定口径，现有 SKU 先按 `model_variant` 承接。

| `NBD4030` 圣殿 | `plm_product.product_code=NBD4030` | `BD` | Blindaje |
| `NDN4030` 幻甲 | `plm_product.product_code=NDN4030` | `DN` | Alterna |
| `NFA4020` 骑士 | `plm_product.product_code=NFA4020` | `FA` | Fantasy/Fantasía |
| `NFB4020` 骑士 2.0 | `plm_product.product_code=NFB4020` | `FB` | Titanio |
| `NHA4030` 超级队长 | `plm_product.product_code=NHA4030` | `HA` | Súper Capitán |
| `NWV4030` 薇武士 | `plm_product.product_code=NWV4030` | `WV` | Waveshell |

产品线只承接稳定资料：

| 系统字段 | 填法 |
| --- | --- |
| `parent_product_id` | 空 |
| `product_code` | 产品线编码，例如 `NBA4030` |
| `product_name` | 标准产品名 |

| `status` | 历史产品线建议 `archived` |

## 4. SKU层对应

SKU层对应“产品 + 手机型号 + 颜色”的具体成品版本。

| 来源字段 | 系统字段 | 说明 |
| --- | --- | --- |
| `mes_sku_master.article_code` | `plm_product.finished_product_code`，也可作为 `product_code` | SKU主识别键 |
| `mes_sku_master.sku_code` | `plm_product.import_short_code` | 外部短码/历史码 |
| `mes_sku_master.product_code` | `plm_product.parent_product_id` | 先反查产品线 |
| `mes_sku_master.product_name` | `plm_product.product_name` | SKU展示名 |
| `mes_sku_master.phone_model` | `plm_product.model` | 手机型号展示名 |
| `mes_sku_master.model_code` | `plm_product.phone_model_code` | 手机型号编码 |
| `mes_sku_master.color_name_zh` 或 `color` | `plm_product.color` | 颜色展示名 |
| `mes_sku_master.color_short_code` / 数字色码 | `plm_product.color_code` | 系统颜色编码优先用数字编码 |
| `mes_sku_master.version` | `plm_product.version_no` | 版本号 |
| `mes_sku_master.bom_code` | 后续关联 `plm_product_bom.bom_code` | 不直接放产品主字段，必要时写备注快照 |

SKU唯一性以系统索引口径为准：

| 唯一性口径 | 系统对应 |
| --- | --- |
| 成品编码唯一 | `finished_product_code` 有唯一索引 |
| 同一产品线下同一机型+颜色唯一 | `parent_product_id + phone_model_code + color_code` 有唯一索引 |

注意：薇武士 `NWV4030` 的 SKU 主档中，部分 `color_code` 写的是中文名，数字编码在 `color_short_code`。系统落地时应优先取 `color_short_code`，中文名只作为 `color` 展示。

## 5. 颜色字典对应

系统颜色字典当前通过 `plm_code_item` 承接，`code_type=color`。

| 来源 | 系统字段 | 说明 |
| --- | --- | --- |
| `mes_color_code.color_code` | `plm_code_item.code_value` | 数字颜色编码，例如 `02`、`31`、`86` |
| `mes_color_code.color_name_zh` | `plm_code_item.code_name` | 中文颜色名 |
| `mes_color_code.status` | `plm_code_item.status` | `enabled` 映射为可用 |

颜色进入系统后的引用位置：

| 模块 | 字段 |
| --- | --- |
| SKU产品 | `plm_product.color_code` |
| BOM路线颜色 | `plm_product_bom_route_color.code_item_id/color_code/color_name` |
| 生产颜色决策 | `plm_product_production_color_decision.code_item_id/color_code/color_name` |
| 工序上下文 | `plm_process.color_code` 或 `process_param_json.colorCode` |

## 6. BOM颜色对应

已有BOM颜色应挂在 BOM路线下，而不是只写在 SKU 的 `color` 文本里。

| 来源字段 | 系统对象/字段 | 说明 |
| --- | --- | --- |
| `bom_main.bom_code` | `plm_product_bom.bom_code` | BOM头编码 |
| `bom_main.parent_code` | `plm_product.product_code` 或 `finished_product_code` 的候选 | 当前更像历史成品/BOM父项编码 |
| `bom_main.version` | `plm_product_bom.version_no` | 通常 `V1` |
| `bom_main.output_qty` | `plm_product_bom.quantity` | 产出数量 |
| `bom_main.custom_bom_specification` | `plm_product_bom_route_color.color_name` 的来源快照 | 需要映射到颜色字典数字编码 |
| `bom_child.target_route_code` | `plm_product_bom_route.route_code` | BOM所属路线 |
| `bom_child.target_route_node_code` | BOM行或备注中的路线节点追溯 | 当前表没有专门节点字段，可先作为行备注/映射资料 |

## 7. 工序路线对应

产品路线和工序状态基础码要落在 `plm_process`。

| 来源字段 | 系统字段 | 说明 |
| --- | --- | --- |
| `process_routes.route_code` | `plm_process.process_code` | 路线编码，`process_type=routing` |
| `process_routes.route_name` | `plm_process.process_name` | 路线名称 |
| `process_routes.product_code` | `plm_process.product_id` | 关联产品线 |
| `nodes[].operation_code` | `plm_process.business_operation_code` 或工序库引用 | 工序业务编码 |
| `nodes[].step_name` | `plm_process.process_name` | 工序节点名称 |
| `nodes[].step_no` | `plm_process.sequence_no` | 工序顺序 |
| `nodes[].config_json.outputBaseCode` | `plm_process.material_status_code` | 工序输出基础码，例如 `NFA3020` |
| `nodes[].config_json.outputType` | `plm_process.finished_product_flag` | `finished` 为成品节点 |
| `nodes[].config_json.outputColorCode` | `plm_process.color_code` 或 `process_param_json.outputColorCode` | 固定部件颜色 |
| `nodes[].config_json.outputDimensions` | `plm_process.process_param_json` | 记录输出维度 |
| `nodes[].config_json.inputDimensions/materialDimensions/planningDimensions` | `plm_process.process_param_json` | 记录生产计划维度 |

编码生成上下文：

| 系统字段 | 用法 |
| --- | --- |
| `product_specific_code` | 从产品线取 `BA/BD/DN/FA/FB/HA/WV` |
| `phone_model_code` | SKU层取具体手机型号编码；产品线模板可用占位或空 |
| `color_code` | SKU颜色或节点固定颜色 |
| `generated_finished_product_code` | 最终节点可生成成品/SKU编码 |
| `code_generation_context` | 标记产品线模板或SKU实例上下文 |

## 8. 生产确认对应

BOM模块已有生产确认对象，适合承接“这个产品正式选哪些工序、哪些颜色生成SKU”。

| 业务动作 | 系统对象 | 说明 |
| --- | --- | --- |
| 选择产品BOM路线 | `plm_product_bom_route` | 一个 BOM 下可以有路线变体 |
| 选择路线工序 | `plm_process_production_operation_selection` | 记录正式生产工序选择 |
| 选择生产颜色 | `plm_product_production_color_decision` | 记录确认颜色，可关联创建出的SKU产品 |
| 创建SKU | `plm_product` 子级 `model_variant` | `created_sku_product_id` 可回填到颜色决策 |

颜色确认建议：

| 来源颜色类型 | 是否进入 `plm_product_production_color_decision` |
| --- | --- |
| SKU主档颜色 | 是 |
| BOM已有颜色 | 是 |
| 只在半成品/部件出现的固定色 | 否，除非业务确认它也是成品颜色 |
| 待确认颜色 | 先不进确认表，放待确认清单 |

## 10. 系统落地顺序

后续如果要真正添加到系统，建议顺序如下：

1. 确认颜色字典已存在：`plm_code_item.code_type=color`。
2. 确认产品线已存在：`plm_product.product_type=product_line`。
3. 建 SKU：按 `article_code/finished_product_code` 建 `model_variant`，填 `parent_product_id + phone_model_code + color_code`。
4. 建/导入产品路线：产品线下建 `routing` 和工序节点，节点带 `material_status_code` 与 `process_param_json`。
5. 建/导入历史BOM：`plm_product_bom`、`plm_product_bom_item`。
6. 建BOM路线：`plm_product_bom_route`，并写入 `plm_product_bom_route_color`。
7. 做生产确认：写 `plm_process_production_operation_selection` 和 `plm_product_production_color_decision`。
8. 对待确认项先停在预览/清洗清单，不进入正式SKU。

## 11. 需要补齐的系统能力

当前系统能承接大部分关系，但要完整落地这份颜色工序表，建议后续补几个小能力：

| 能力 | 原因 |
| --- | --- |
| 产品工序状态基础码导入/维护 | 当前通用工艺导入偏路线实例，不能完整表达 `base_code + 颜色 + 工序` |
| 工序节点 `config_json` 可视化维护 | `outputBaseCode/outputType/outputColorCode` 是关键规则，不能长期只靠JSON |
| SKU颜色导入时自动回退 `color_short_code` | 解决薇武士等数据里 `color_code` 写中文名的问题 |
| BOM颜色规格到颜色字典映射表 | 解决 `MORADO/NEGRO/ROSA NEON - FIUCSIA` 到 `01/02/48/17` 等编码的映射 |
| 待确认清单页面或导入预览状态 | 处理白色成品SKU、骑士2.0缺工序颜色、薇武士橙色BOM缺失等问题 |

## 12. 本次结论

这份产品颜色与工序关系对应到系统后，主线是：

1. 产品线留在 `plm_product.product_type=product_line`。
2. 现有SKU先作为产品线下的 `model_variant`。
3. SKU颜色落 `plm_product.color_code`，并由颜色字典校验。
4. BOM适用颜色落 `plm_product_bom_route_color`。
5. 正式生产颜色选择落 `plm_product_production_color_decision`。
6. 工序与输出基础码落 `plm_process`，复杂维度保留在 `process_param_json`。
7. 白色、骑士2.0工序颜色、薇武士橙色BOM等问题先作为待确认，不自动生成正式SKU或BOM绑定。
