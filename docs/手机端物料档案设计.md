# 手机端物料档案设计

日期：2026-09-30
状态：已实现，保留设计与验收依据。
范围：在手机端库存区域增加物料查找、详情和新增，并衔接已有库存查询。

## 1. 现状与设计依据

本方案核对了当前 `mobile_operations` 代码以及 `dev.localhost` 的只读元数据。

- 库存页现有“物料需求”“物料移动”“库存查询”三个入口。
- 库存查询以 `Bin` 为结果主体，物料档案存在不代表一定有仓库库存记录。新增物料或从未入库的物料也应能被查到，因此物料档案列表必须以 `Item` 为主体。
- 当前站点有 83,152 条物料，全部启用；列表和选择器必须在服务端搜索、排序和分页。此数量仅为核查时快照。
- 当前编号设置为 `Item Code`，没有针对 Item 的 Document Naming Rule。首期由用户填写编码，保存时检查唯一性，不依据编码前缀自行推导流水号。
- 当前必填字段是物料编码、物料组、库存单位。名称不是系统必填，标准控制器在名称为空时使用编码。
- Item 无提交状态，保存即建档，不设计“保存草稿 / 提交”流程。
- 站点已有规格、物料简称、助记码、SKU、外部编码、物料分类和 MES 默认发料单位等自定义字段，应复用现有字段。
- 当前角色配置中 Item Manager 有创建权限，Stock User、Stock Manager 本身只有读取权限。实际能力以当前账号的全部角色和用户权限为准。

## 2. 入口与页面流程

库存页增加“物料档案”卡片，说明为“查找、查看和新增物料”。首页库存作业区和侧边菜单同步增加入口，底部导航保持“库存”。

```text
库存
├─ 物料档案
│  ├─ 搜索 / 筛选 → 物料详情 → 查看库存
│  └─ ＋新增物料 → 保存 → 物料详情
├─ 库存查询
├─ 物料需求
└─ 物料移动
```

新增按钮放在物料档案页标题旁，查找和查看统一由列表进入。

建议路由：

| 页面 | 路由 |
| --- | --- |
| 物料档案列表 | `/mobile/inventory/items` |
| 新增物料 | `/mobile/inventory/items/new` |
| 物料详情 | `/mobile/inventory/items/<编码>` |
| 对应库存 | `/mobile/inventory/query?item_code=<编码>` |

编码作为 URL 参数时必须编码和解码；路由解析区分路径与查询参数。返回列表时保留关键词、筛选和滚动位置。

## 3. 查找物料

- 顶部固定搜索框，输入部分编码、名称、规格或助记码即可查询；SKU、外部编码作为补充匹配字段。
- 沿用编码优先原则：完整编码 → 编码前缀 → 编码包含 → 名称匹配 → 规格及辅助字段匹配；排序后再分页，同一优先级以编码稳定排序。
- 输入防抖约 300 毫秒，每页 20 条，提供“加载更多”。列表使用独立分页接口，不受现有下拉候选最多 30 条的限制。
- 筛选包含物料组、启用状态、库存 / 非库存物料。上级物料组筛选包含其下级组；不要求用户记住完整组名。
- 默认展示启用物料，可切换全部或停用。空关键词可显示最近更新的第一页，并明确当前排序。
- 每张卡片显示编码、名称、规格、物料组、库存单位和状态；点击卡片打开详情。
- 没有匹配项时保留关键词，有创建权限者可进入新增页。名称或规格检索词不能自动当作已确认编码。
- 区分“没有匹配物料”“没有读取权限”“查询失败”，不把接口异常当作零结果。

档案列表不要求存在 `Bin`，也不逐条请求库存数量。这样可以查到未入库物料，并避免大列表产生大量请求。

## 4. 物料详情

基本资料显示编码、名称、规格、物料组、库存单位、启用状态，以及库存、采购、销售属性。辅助资料按有值显示助记码、简称、SKU、外部编码、MES 默认发料单位、描述和已有图片。

底部主要操作为“查看库存”；只读账号可以查看资料，有库存权限者再进入对应库存页面。库存页面预选该物料，保留公司、仓库和库位筛选。

联动需要补充：

- 现有查询只有 `item_search` 模糊检索参数。新增 `item_code` 精确参数，从详情进入时按所选物料查询，避免同前缀的其他物料混入。
- 无 `Bin` 记录时显示“该物料暂无仓库库存记录”，不显示“物料不存在”；有记录且数量为零时正常展示零库存行。
- 没有库存读取权限时显示对应提示，不能返回零库存。
- 当前通用库存模糊搜索先截取最多 2,000 个物料名再查库存，存在遗漏可能。物料详情的精确查询绕开该截断；通用搜索若扩展规格等字段，应改为权限感知的完整条件查询，不能复制这个上限。

## 5. 新增物料

使用单列手机表单，主要字段常显，辅助字段折叠。物料组与单位均使用可搜索候选列表，必须选中真实记录。

| 字段 | 首期交互 | 对应字段 |
| --- | --- | --- |
| 物料编码 | 必填、手工填写；检查重复并提供已有档案入口 | `item_code` |
| 物料名称 | 推荐填写；保持系统规则，留空使用编码 | `item_name` |
| 物料组 | 必选；支持层级浏览及搜索 | `item_group` |
| 库存单位 | 必选；从有效单位中选择，保留当前单位名称 | `stock_uom` |
| 规格型号 | 常显选填 | `custom_specifications` |
| 库存、采购、销售属性 | 明确展示开关，初始值读取站点元数据 | `is_stock_item` / `is_purchase_item` / `is_sales_item` |
| 描述 | 折叠选填，按安全文本处理 | `description` |
| 助记码、SKU、外部编码、物料分类 | 折叠选填 | 对应现有 `custom_*` 字段 |

站点同时存在 `custom_short_name` 与 `custom_item_short_name`，两者标签都为物料简称。详情按来源区分已有值；新增字段映射需核对 CRM / MES 的使用方，不能以相同标签为由自动合并或互相覆盖。

MES 默认发料单位与库存单位可能不同。首期可展示已有值；如果开放录入不同单位，必须同时处理对应 UOM 换算，不能只增加一个下拉框。

保存行为：

1. 客户端检查必填项及候选选择状态，避免重复点击；重复编码提前提示，但最终以服务端唯一性校验为准。
2. 服务端检查当前用户的 Item 创建权限，仅接收允许的字段，使用标准 Item 文档插入流程，执行现有校验和创建事件。
3. 保存成功后进入详情，显示“物料已创建”；可继续查看库存或再新增一条。
4. 保存失败保留已填内容并显示具体原因；网络超时不能直接声称保存失败，重试前核实对应编码是否已创建。

该页面负责建档，库存数量通过现有入库或盘点单据产生。首期不提供期初库存、价格、财务默认值、模板变体、批次序列号配置，以及编辑、删除、停用。后续维护功能单独按权限与业务规则扩展。

## 6. 实现拆分

参考 BOM 模块，将物料功能放在独立后端与静态资源中，主页面仅注册路由、入口与资源。

- 后端建议新增 `mobile_operations/items.py`，提供列表、详情、创建选项、物料组 / 单位候选、创建接口。
- 前端建议新增 `public/js/mobile_items.js` 与 `public/css/mobile_items.css`，沿用现有手机端卡片和操作栏风格。
- 提取可复用的搜索条件与排序构造，保留现有单据选择器的启用状态及场景过滤，不将档案列表结果原样用于所有单据。
- 所有读取按账号权限执行；详情校验单条 Item 的读取权限，创建不使用 `ignore_permissions=True`。候选、筛选计数、库存联动同样遵守权限。
- 自定义字段读取前检查存在性及字段读取权限，文案接入现有中 / 英 / 西语言体系，描述与名称按安全文本渲染。
- 保持页面切换后的事件隔离和请求序号校验，旧搜索响应不能覆盖新条件。

当前已交付列表、详情、精确库存联动和新增保存。编辑、删除、停用及期初库存仍保留在电脑端，后续单独评估。

## 7. 验收重点

- 只输入部分编码能找到目标；完整编码排第一；同名不同规格可区分；分页不遗漏同一筛选下的结果。
- `%`、`_` 等搜索字符按字面匹配；中文、特殊字符编码及较长物料名正常显示。
- 未入库物料能查到；详情区分没有库存记录、零库存、无库存权限和接口错误。
- 只读用户看不到新增按钮，直接调用创建接口也不能创建；物料和库存各按自己的权限控制。
- 必填缺失、重复编码、无效单位 / 物料组给出明确错误；保存失败不清空表单。
- 手机新增的物料可在电脑端查到，允许用于对应业务时也能被手机物料需求、物料移动、BOM 选择器找到。
- 手机保存经过标准校验及已安装的创建事件；验证时使用测试环境，避免给业务账号发送测试通知。
- 当前 8 万余条物料不全量下载；快速切换条件、返回页面及加载更多不出现过期结果覆盖。
- 新增接口使用标准 Item 插入流程，集成测试覆盖新增、重复编码、分页搜索、详情、自定义字段、候选项和 Guest 权限；测试数据在回滚事务中清理。
- 静态 JavaScript/CSS 已运行语法检查并通过 `bench build --app mobile_operations`；精确库存接口已在 `dev.localhost` 以只读方式联调。
