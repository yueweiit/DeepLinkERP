# 凭证草稿工作台与月末统一记账方案

日期：2026-09-21。本文记录实施前的设计。基础两阶段现已实现，启用步骤、实际操作和边界见[凭证准备与月末记账操作](凭证准备与月末记账操作.md)。完整三大报表的未记账预览仍属于附加范围。

## 1. 结论与目标

可行，适合目前“银行回单制证、集中核对、按月记账”的使用方式。把日常核对安排在记账之前，可以减少因修改摘要、科目和费用拆分产生的取消、修订和冲销记录。

建议日常只用三个入口：**银行回单导入 → 查凭证 → 月末处理**。手工凭证、Excel 导入的记账凭证也进入同一个草稿工作台。

实际操作顺序应为：

```mermaid
flowchart LR
    A[上传回单并确认导入] --> B[自动生成未记账凭证]
    B --> C[查凭证：核对和修改]
    C --> D[月末检查与试算]
    D --> E[统一审核记账]
    E --> F[损益结转与正式报表核对]
    F --> G[结账冻结与归档]
```

“月末统一记账”可以做成月结页面中的主要操作，但后台必须先记账、后结账冻结。正式记账前的编辑只保留修改历史；实际已经记账的凭证仍需受控更正。

本方案参考用户描述的金蝶使用习惯，不假定所有金蝶版本都采用相同流程。

## 2. 目前为什么会繁琐

| 现有行为 | 对操作的影响 | 建议调整 |
| --- | --- | --- |
| 回单导入已有识别、建议科目和生成 Journal Entry 草稿功能 | 普通笔次、社保和异常笔次的操作分散，处理后还要切换页面 | 上传后集中核对，一次提交批量生成可制证记录 |
| “查凭证”查询已提交的 China Accounting Voucher，并要求来源已经提交或取消 | 记账前的草稿看不到；想在这里修改时，通常已经需要取消修订 | 同页显示 Journal Entry 草稿和已记账快照 |
| 中国会计凭证根据实际总账分录生成，并在提交时分配正式字号 | 尚未记账就创建正式会计快照，会与当前快照、核销、报表检查冲突 | 草稿展示直接使用来源凭证；正式记账时生成会计快照 |
| 当前快捷批量操作把审核与记账连续完成 | 只是想完成核对，也可能过早记账 | 增加“核对完成/待记账”，与真正记账分开 |
| 月结、损益结转检查要求银行凭证已记账 | 不能直接把现有结账按钮用于自动提交草稿 | 增加月末流程控制，区分记账前检查与记账后检查 |
| 科目余额、三大报表主要读取实际总账 | 月中只存草稿时，报表不会包含这些发生额 | 提供明确标记的未记账试算；正式报表保持实际记账口径 |

因此，这项工作包含凭证状态、查询编辑和月末流程改造，不能只改几个按钮名称。

## 3. 财务人员如何操作

### 3.1 回单导入：一次确认，集中处理异常

1. 沿用中国财务入口选择的公司，选择银行账户并上传 PDF。
2. 上传后自动识别，直接展示交易笔数、收入/支出合计、建议分录，以及重复、待确认或冲突记录。
3. 核对预览后点击 **“确认导入并生成草稿”**。这个动作确认导入，不代表会计记账。
4. 页面展示“新增草稿 X 张、关联已有凭证 Y 张、待处理 Z 笔”，可以直接进入本批次的查凭证页面。

普通业务与已配置好的社保业务使用同一批量入口。社保在预览表中集中显示所属期、五行分录和“本所属期尚未计提”的确认，避免逐张打开相同的处理弹窗。已经计提的月份应采用付款冲应付的处理方式，不能因为有默认规则就再次计提。

科目不明确、业务已存在但关联不明确、日期/金额冲突的记录保留在“待处理”，不填入随意选择的费用科目或临时平衡科目。已确认且符合条件的记录可以先生成草稿，批次明确显示“部分完成”，剩余项在原页面补齐后继续处理。

历史补回单保留独立模式，只补原件和来源关联。新模式上线时不自动把历史补回单批次切换为制证模式。

### 3.2 查凭证：作为统一的凭证工作台

保留“查凭证”这个熟悉的名称，页面增加 **全部有效凭证、未记账、待记账、已记账、历史修订** 筛选。默认按当前公司和所选月份显示有效记录，旧的取消、修订记录收进历史查看。

每张凭证显示日期、草稿编号或正式字号、摘要、分录、金额、来源、核对状态，并能直接打开对应回单。顶部汇总凭证张数、借贷合计、未处理问题数。

点击“编辑”在同页凭证面板中修改，保存后立即更新列表。主要支持：

- 修改摘要、费用/往来科目、往来对象、成本中心等。
- 在借贷平衡的前提下拆分或调整分录，并保留负借方等现有费用冲减口径。
- 核对附件、回单明细、社保所属期和现金流项目建议。
- 批量标记核对完成，或由有权限的审核人在同页完成审核。

银行回单对应的本方账户、币种、银行净收支金额和方向继续与原件核对。修改费用拆分不应改变实际银行收付款；若原件识别错误，返回回单更正流程。凭证日期调整应显示原交易日期、填写原因并重新检查期间，不能用修改草稿绕过已冻结期间。

未记账凭证保存多次，仍然是同一张草稿，不产生总账冲销。已核对或审核的草稿发生实质修改后，相关核对/审核结论失效，重新进入待核对状态，并保留修改人、时间和差异。

不再把“保存并记账”作为新模式下的日常默认动作。需要月中提前记账时，有权限人员仍可明确执行记账，页面提示该批凭证之后不能作为普通草稿编辑。

### 3.3 月末处理：在一个页面完成

选择公司、月份后，页面先显示未完成事项和试算结果，所有问题都能直接跳到对应凭证或配置。日常“核对完成”与正式“审核”是否合并，按公司权限和工作流决定；需要复核人员时，仍由具备权限的人完成。

主操作建议为 **“检查并统一记账”**，随后在同页核对正式报表并执行 **“确认结账”**。满足全部条件的步骤自动衔接，只有存在问题或需要财务确认时停下，不要求用户逐个打开底层单据。

| 阶段 | 系统执行内容 | 完成条件 |
| --- | --- | --- |
| 记账前检查 | 检查本期草稿、回单待处理项、科目及辅助核算、借贷平衡、重复制证、期间、审批、报表配置；展示试算 | 没有阻断项，凭证范围和版本已确认 |
| 统一记账 | 按日期和稳定顺序提交待记账凭证，生成总账和会计快照，分配正式字号 | 每张凭证记账成功，快照完整 |
| 核销及现金流检查 | 执行银行核销；把已核对的现金流建议对应到实际分录，并核验完整性 | 未匹配或有差异的事项已处理 |
| 损益结转 | 生成并处理本期结转凭证 | 实际总账处理完成，不能只依据“已提交”判断 |
| 正式报表核对 | 计算实际已记账报表，执行现有勾稽、映射、完整性等检查 | 检查通过，财务确认结果 |
| 结账 | 保存报表快照，冻结期间，生成归档包 | 明确显示结账状态和归档进度；归档失败可重试 |

当前损益结转可能通过后台任务处理，归档也在提交后异步执行。新页面应显示这些阶段的真实进度，不能出现“按钮成功即全部完成”的误导。

## 4. “草稿也生成会计凭证”的实现方式

建议满足“草稿立即可以在查凭证中查看、编辑、预览打印”的使用效果，底层保留一个可编辑来源：

| 状态 | 使用的数据 | 是否写总账 | 页面操作 |
| --- | --- | --- | --- |
| 未记账 | Journal Entry 草稿 | 否 | 编辑、核对、标记待记账 |
| 待记账 | 已核对/审核但尚未提交的同一份草稿 | 否 | 待统一记账；修改后重新核对 |
| 已记账 | 实际总账及正式 China Accounting Voucher 快照 | 是 | 查看、打印、按条件受控更正 |
| 所属期间已结账 | 已记账记录及该期报表快照 | 已存在 | 查看归档；更正遵循重新开账及更正流程 |

“已结账”是期间属性，与凭证审核状态分开。草稿取消使用应有作废记录及来源释放规则，避免直接删除后重复导入；这种作废不产生会计冲销。

不建议另造一张可以独立编辑的中国会计凭证草稿，再与 Journal Entry 双向同步。否则修改其中一张后，还需要处理金额、分录、审核状态和附件不同步的问题。查凭证服务统一两类数据的展示，草稿保存仍写回 Journal Entry；真正记账时转为显示正式快照，同一来源在列表中只出现一次有效记录。

草稿编号使用稳定的临时标识，预览打印标记“未记账”。正式字号在记账时按公司、期间和凭证字生成；同一批次按日期、稳定次序分配。批次中一张失败时先暂停后续分配，重试从失败处继续，避免后日期凭证先取号。已有正式字号不自动重排；多批记账或后来补录较早日期的凭证不能承诺全月字号永远严格按日期排列。

已记账但未结账也不等于可以直接改总账。保留受控更正及历史记录，默认列表可折叠历史。若进一步要求“已记账凭证任意反记账、直接改后重记且不留冲销”，会涉及 ERPNext 总账、往来和银行核销机制，超出本方案。

## 5. 报表、银行及社保的影响

### 5.1 未记账试算与正式报表分开

现有财务报表即使标为“草表”，也主要根据实际总账计算，不代表包含未记账凭证。

基础改造必须配套 **“含未记账凭证的科目余额试算”**：读取实际总账和本次纳入范围的有效 Journal Entry 草稿，展示已记账金额、未记账金额、预计余额。明确列出草稿范围及异常，不将不平衡或缺失必填项的记录默默计入可用试算。

试算需要按期间、科目币种及本位币、成本中心等一致口径计算，保留负借方和社保五行语义；数据读取使用一致版本，防止凭证在查询过程中刚刚提交而被重复统计或漏算。试算不通过向 GL Entry 写入临时记录来实现。

基础版本的资产负债表、利润表、现金流量表仍以实际已记账数据为准，页面明确提示未记账凭证数量。月末统一记账后，在结账冻结前核对正式结果。

若财务要求在任何凭证正式记账之前就能查看完整三大报表，应另加入“含未记账凭证的预览报表”。这需要扩展报表数据来源、未结转利润、现金流分配、比较期及辅助核算等逻辑，工作量明显增加，不能只在现有报表增加一个勾选框。缺失现金流分类时应展示未分配差额，不能显示为完整正确的报表。

正式报表快照、归档始终以实际已记账数据为依据。

### 5.2 银行交易和核销

- 回单确认后可建立银行交易与草稿的关联，但只有会计记账后才进行正式核销。
- 页面区分“已生成凭证，待记账”和“未匹配凭证”，避免把已处理的草稿误当作缺失。
- 按银行账户与交易流水号去重，同回单重传、与 XLSX 交叉导入、批次重试均复用原记录。
- 已存在付款单或已记账凭证时，优先核对并关联，不能重复生成收付款凭证。
- 回单没有完整银行期初期末余额；对账单及流水核对仍保留。

### 5.3 已确认的社保规则继续使用

当前样本继续生成一张凭证的五行分录：管理费用公司部分、其他应收款个人部分、计提应付工资、支付冲应付工资、银行付款。当前金额为公司承担 7,850.41 元、个人承担 3,323.11 元、实际银行付款 11,173.52 元。

摘要月份取回单所属期，凭证日期依据实际交易日期；五行不因汇总或合并科目而消失。这里借方、贷方各合计 22,347.04 元，现金支出仍为 11,173.52 元，页面需要区分分录合计与银行收支，避免被理解为重复付款。

## 6. 实施范围与兼容性

建议按公司启用“凭证准备与月末记账”模式，并配置起始期间。原有已记账、已结账历史继续使用已有编号、快照和归档；历史修订记录可以默认折叠展示，不删除。

首次上线从尚未记账的完整月份试用。现存 Journal Entry 草稿可进入工作台，但自动制证不等于人工已审核，不能自动标为待记账。

基础范围包括回单生成、手工录入及 Excel 导入的 Journal Entry。付款单、采购/销售发票等原生业务单据可能在提交时立即记账；本次不把整个 ERP 改成月底才入账。已有已记账业务应计入试算和正式报表，并在回单匹配时防止重复制证。

新模式下需同时处理原记账凭证表单、列表批量提交、导入/API 等入口的规则。默认引导进入准备流程，真正记账保持明确动作和权限，后端校验一致；仅隐藏按钮无法保证流程一致性。

界面沿用当前公司上下文和公司本位币，当前公司显示 CNY。主要菜单保留回单导入、查凭证、月末处理；银行交易、会计快照、核销详情和技术任务作为详情入口保留，方便查错。

## 7. 关键技术控制

- **数据与审核版本：** 保存草稿保留版本记录；记账前核验审批对应的内容版本，防止审核后内容被替换。
- **公司与期间互斥：** 月末任务记录公司、月份、凭证清单和版本。在批处理和最终检查期间阻止其他入口并发新增、修改或提交该期会计数据；内部任务受控执行。失败暂停时明确恢复可操作状态，继续前重新检查。
- **权限：** 查询草稿、编辑、审核、记账和关账各自验证权限。用户不能通过新聚合查询看到无权读取的其他公司或敏感凭证。
- **可恢复批次：** 每张凭证记账作为独立事务单元。中途失败显示已完成和剩余清单，停止结账；成功凭证不自动冲销，重试不重复提交、不重复取号、不重复核销。
- **分阶段检查：** 待记账草稿是记账阶段的输入，在最终结账阶段仍然是阻断项。不能为让月结通过而简单删除原有检查。检查范围覆盖本期手工及导入草稿，不只检查银行关联草稿。
- **现金流衔接：** 草稿阶段可以记录分类建议及确认版本，正式记账后依据实际分录匹配并重新验证；无法可靠对应时退回待核对，不悄悄套用旧分配。
- **异步衔接：** 等待损益结转总账处理成功和所需快照齐全后再冻结。归档任务单独展示成功或失败状态，支持重试。
- **退出新模式：** 关闭功能开关只改变入口和后续工作方式，不反向撤销已完成的记账或结账；进行中的任务须先暂停并核对状态。

## 8. 修改位置与难度

| 工作项 | 主要位置 | 难度 |
| --- | --- | --- |
| 回单上传后集中预览、批量生成草稿、异常留待处理 | `services/bank_receipt_import.py`、回单导入表单及公共展示脚本 | 中等，已有大部分底层能力 |
| 查凭证纳入草稿、同页编辑、状态与历史分组 | `report/china_voucher_ledger`、`services/source_voucher_edit.py`，必要时新增专用工作台页面并兼容旧入口 | 中等偏高 |
| 核对/审核与记账分开，保护原生入口 | `services/voucher.py`、工作流配置、记账凭证前后端校验 | 中等偏高 |
| 月末任务、分阶段检查、失败续跑、期间互斥 | `services/closing.py`、`doctype/china_closing_run`、批量记账与核销服务 | 高，是核心工作 |
| 含未记账科目余额试算 | 财务报表服务新增只读试算数据源 | 中等偏高 |
| 三大报表全部支持含未记账预览 | `services/financial_statement.py`、现金流服务及财务报表入口 | 高，建议独立扩展 |

基础方案总体为**中高难度**。现有解析、草稿制证、正常提交、正式快照、核销和结账能力可以复用，预计主要在 `china_finance` 内完成；设计上沿用 ERPNext 正常记账机制，不以修改核心总账为前提。具体改动范围需在实现与回归时确认。

建议分两个可验收阶段实施，最终交付一个连续的使用流程：

1. **日常凭证准备：** 简化回单入口，草稿进入查凭证并可编辑，核对完成与记账分开，支持草稿试算和历史折叠。这一阶段先解决频繁取消修订的问题。
2. **月末统一处理：** 串联按日期记账、正式快照、核销、现金流、损益结转、报表核对、冻结及归档，完成权限、并发和失败重试回归。

完整三大报表的未记账预览作为附加范围单独评估。基础两阶段已有正式报表的月末核对环节。

## 9. 验收标准

1. 上传样本回单，仍完整识别 36 笔，收入 160,165.00 元、支出 160,549.35 元；确认后可制证记录集中生成草稿，异常项明确列出。
2. 新草稿立即出现在查凭证；调整科目、摘要、分录并重复保存，不新增正式快照、总账或冲销记录。
3. 社保保留五行分录、正确的所属期摘要和公司/个人分摊；1 元代发手续费仍与工资分开。
4. 未记账试算只计入一次有效草稿；记账前后金额衔接一致，已提交来源不重复统计，公司及币种隔离正确。
5. 待记账凭证被修改后，旧审核不能继续用于记账；过期页面保存、并发修改和越权访问被正确处理。
6. 正常月末流程无须逐张打开凭证或手动跳转到底层核销单据；正式结果通过检查后才能结账。
7. 月末任务中断、重复点击、重试不会重复制证、取号或核销；没有完成全部必需阶段时不显示全部完成。
8. 冻结月份、存在正式损益结转的期间按规则限制修改；已记账更正仍留痕，历史编号和归档可追溯。
9. 与历史补回单、XLSX 流水、已有付款单、手工凭证、Excel 导入及现有财务报表兼容；服务器已有正确数据不因启用新模式而被改写。
