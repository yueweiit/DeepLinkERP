# AI 草稿费用公开 ID 回传修复设计

## 背景与根因

AI 填充确认页会将钉钉流程号替换为不可逆的公开标识，以避免向浏览器暴露内部流程 ID。费用提案的 `proposal_id` 包含流程号，因此也被替换。页面回传公开 `proposal_id` 后，预览服务却直接与锁内重建的原始 `proposal_id` 比较，导致同一条费用被误判为“不属于当前草稿”。

## 设计

保持现有公开数据脱敏和服务端锁内重建不变。在预览服务中，对同一份锁内原始 catalog 生成公开 catalog，建立“公开费用 ID → 原始费用 ID”映射。客户端提交的 `fee_ids` 先与公开 catalog 严格校验，再映射为原始 ID 交给现有投影逻辑。

物料行 ID、逐字段候选 ID、装箱归属和服务端锁、指纹、并发校验保持不变。未知、重复或伪造的公开费用 ID 仍被拒绝。

## 兼容性与安全性

- 已生成的 `READY` 草稿可直接重试预览，无需重新分析。
- 浏览器继续只能看到脱敏流程 ID，不返回原始钉钉流程号。
- 映射仅由当前锁内 catalog 生成，不接受客户端提供的原始 ID 或映射关系。
- 预览仍不修改物料、费用、试算、版本确认或 ERP 状态。

## 测试与验收

1. 先增加失败回归测试：原始费用 ID 含内部流程号，公开 catalog 返回脱敏 ID，用该脱敏 ID 预览应成功。
2. 验证伪造公开 ID 仍返回“不属于当前草稿”。
3. 验证公开响应中不出现原始流程号。
4. 运行 AI 选择服务和公开载荷相关测试，再运行完整 `overseas_costing/tests` 回归。
5. 重建工作台资源两次，第二次必须返回 `changed: []`，并校验源码与部署镜像一致。

## 非目标

本次不重构整套 ID 协议，不新增 DocType，不改动 AI 候选生成规则，也不触发生产数据填充、试算或 ERP 推送。
