# 试算进入成本核对、运单号回填与紧凑状态栏设计

## 背景与实际问题

批次 202609121455000173161 已成功保存试算结果，但详情页仍被判定为“计算结果已变化”，因此没有进入“成本核对”。实际费用和物料数据并未在试算后变化，根因是试算保存与成本核对就绪判断使用了不同的费用归一化结果计算输入指纹，导致刚保存的结果被误判为过期。

同一批次的国际物流审批评论包含唯一的 “DHL 3080665836”。现有规则虽然能严格识别 DHL 十位运单号，也能保护人工值，但只允许 COMPLETED 的审批自动回填。该审批处于 RUNNING / agree，因此被安全规则拒绝。

详情页同时展示状态胶囊和大块“仍需处理”面板，占用过多垂直空间，并且页面存在重复的试算入口。

## 核心业务状态

“成本核对”表示该批次至少成功保存过一次试算结果，不表示费用数据被冻结。

- 首次试算成功并保存结果后，批次进入“成本核对”。
- 在成本核对阶段仍可修改快递费、清关费、税费等费用，也可重新试算。
- 修改参与计算的数据后，批次继续留在成本核对工作区，但当前结果标记为待更新，ERP 推送保持禁用。
- 再次试算成功后，新结果成为当前有效结果，批次继续处于成本核对阶段。
- 只有当前试算结果有效且已完成人工成本核对时，才允许预览或推送 ERP。
- 暂估费用、低置信来源等软异常只显示警告，不阻止进入成本核对；真实缺失、非法金额或无法计算等硬错误仍阻止试算成功。

## 试算结果一致性

试算保存、结果是否过期判断和成本核对列表筛选必须复用同一个“规范化计算输入”构造器。该输入包含物料、采用费用、费用口径、汇率和 SKU 分项，禁止各入口自行拼装不同的哈希投影。

保存成功时同时固化规范化输入指纹和计算摘要。后续只有规范化输入真实变化时才把结果标记为待更新，不能因虚拟默认费用、费用选择顺序或历史规则装饰差异产生假过期。

成本核对列表的准入依据为“存在至少一次成功保存的试算结果”，ERP 推送准入另行校验当前结果是否有效、人工核对是否完成以及既有 ERP 前置条件。

## 运单号自动回填

活动中且未作废的国际物流审批可以提供运单号，不再强制要求审批已经 COMPLETED。自动回填仍必须同时满足：

- 来源是当前批次的国际物流审批，不接受费用审批或其他来源。
- 审批没有被拒绝、撤回、终止、删除或标记无效。
- 评论中只存在一个符合已知承运商严格格式的唯一候选。
- 当前运单号为空，或者当前值由同一自动来源维护；人工填写值永不覆盖。
- 写入来源审批、评论、承运商、候选值、操作者和时间等审计信息。
- 多候选或与现有值冲突时只记录冲突并提示人工处理，不自动选择。

发布后重新同步批次 202609121455000173161 的来源数据，使唯一候选 3080665836 按上述规则回填；该动作不修改费用、试算结果、版本确认或 ERP 状态。

## 前端方案

采用已确认的 A 方案：

- 状态与唯一试算入口位于第一行。
- 未成功试算时按钮显示“开始试算”，已有试算结果时显示“重新试算”。
- 页面其他位置不再重复展示第二个试算按钮。
- 存在阻断时才显示一行浅黄色紧凑提示，首条原因直接展示，其余原因通过“更多 N”展开。
- 没有阻断时不保留提示行空白。
- 状态行和提示行在窄屏允许合理换行，但不恢复成大块卡片。
- 在成本核对阶段修改费用后，紧凑提示显示“费用已修改，请重新试算”，同时明确 ERP 推送不可用。

## 兼容性与非目标

- 不新增 DocType、数据库字段或迁移。
- 不改变费用编辑、试算计算公式和成本版本确认规则。
- 不自动完成人工成本核对，不自动确认版本，也不自动推送 ERP。
- 不覆盖任何人工运单号。
- 不将审批评论中的普通数字、金额、日期或模糊文本当作运单号。
