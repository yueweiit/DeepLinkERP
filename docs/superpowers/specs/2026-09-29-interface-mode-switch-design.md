# DeepLinkERP 经典 / DL 界面模式切换设计

日期：2026-09-29

## 目标

为 DeepLinkERP 增加可管理的界面模式：

- 管理员设置全公司的默认模式。
- 每个用户可以选择跟随公司默认，或覆盖为经典模式 / DL 模式。
- 初次上线的公司默认值为 DL 模式；新用户默认跟随公司。
- 模式切换只影响导航和 Desk 首页布局，不改变权限、菜单数据、路由或业务数据。

## 已确认的入口设计

采用“设置页 + 左下角头像菜单”方案。

### 公司默认

在现有 `Deeplinkerp Settings` 工作区增加“界面与导航”快捷入口。该入口打开新的单例设置 `DeepLinkERP Interface Settings`，其中包含：

- 公司默认界面模式：`经典模式` / `DL 模式`
- 初始值：`DL 模式`
- 读写权限：仅 `System Manager`

修改公司默认后，不强制刷新其他在线用户。用户下次刷新或重新登录时采用新的有效模式。

### 用户覆盖

复用 Frappe 左下角现有用户头像区域。点击后显示一个轻量菜单：

- 跟随公司默认（同时显示当前公司默认值）
- 经典模式
- DL 模式
- 个人资料

用户默认选择“跟随公司”。选择个人模式后，保存成功才刷新当前页面；刷新保留当前 URL。保存失败时不刷新、不改变当前模式，并显示错误提示。

## 模式定义

### 经典模式

- 保留 DeepLinkERP 品牌名称、Logo、favicon 和现有权限过滤。
- 使用 Frappe 原生侧栏、原始 Desk 首页模块布局以及当前站点原有扩展。
- 不生成 `.dlp-mes-navigation`，不添加 `dlp-mes-navigation-enabled` body class，也不隐藏 `custom_filters` 的原有栏位。

### DL 模式

- 使用正在验收的深蓝统一侧栏、线性图标、父子菜单、最终菜单整行高亮和紧凑 Desk 首页。
- 所有带子菜单的顶层模块都是“分组开关”：点击图标、文字或右侧箭头中的任意位置，只展开或收起该模块，不执行父级路由。
- 多个顶层模块可以同时展开。真正的页面导航只由展开后的子菜单项执行。
- 没有子菜单的顶层入口仍然直接导航。
- 右侧箭头保留 36×36px 点击区和约 18px 图标，但它与父级整行共享同一个折叠动作，不再承担独立于文字的行为。

同一页面会话内，已展开的多个模块在子菜单路由切换后继续保持。浏览器整页刷新或重新登录后重置展开状态，只自动展开当前页面所属模块；不使用 `localStorage` 或数据库保存菜单展开状态。

## 配置与数据模型

### 公司设置

新增 Single DocType `DeepLinkERP Interface Settings`，字段：

- `default_navigation_mode`
- 类型：Select
- 合法值：`classic`、`dl`
- 默认：`dl`

独立 Single DocType 避免污染 Frappe `System Settings` 核心字段，也避免与现有 `Deeplinkerp Settings` Workspace 同名。Workspace 只增加一个指向该设置表单的快捷入口。

### 用户设置

复用 Frappe `DefaultValue` / `frappe.defaults`，键名为 `deeplinkerp_navigation_mode_override`：

- 无记录：跟随公司默认
- `classic`：个人经典模式
- `dl`：个人 DL 模式

不使用 `localStorage`，因此同一用户换浏览器或电脑登录仍保留偏好；也不为 Frappe `User` 核心 DocType 新增自定义字段。

### 有效模式解析

服务端使用一个共享解析函数，规则为：

1. 若当前用户覆盖值为 `classic` 或 `dl`，使用个人覆盖。
2. 否则使用公司默认。
3. 公司设置缺失、尚未迁移或值非法时，回退到 `dl`。

服务端在 `boot_session` 中返回：

```json
{
  "company_default": "dl",
  "user_override": null,
  "effective_mode": "dl",
  "can_manage_company_default": false
}
```

客户端只消费服务端解析后的结果，不自行重复权限或优先级判断。

## 组件边界

### 服务端模式模块

新增独立模块负责：

- 校验 `classic` / `dl` 值。
- 读取公司默认与当前用户覆盖。
- 解析有效模式并写入 bootinfo。
- 保存当前登录用户自己的覆盖值。
- 清除“跟随公司”对应的个人覆盖记录。

普通用户只能修改自己的覆盖值。公司默认继续由 Single DocType 的 `System Manager` 权限控制。

### 客户端启动门控

现有 `deeplinkerp_branding.js` 继续负责唯一一次 Desk 生命周期绑定：

- 品牌替换在两种模式下都运行。
- 仅当 `effective_mode === "dl"` 时运行 `renderPersistentNavigation()` 和紧凑首页增强。
- 经典模式不运行 DL 导航构建，因此无需在同一页面热拆卸两套 DOM。
- 用户选择模式后整页刷新，确保新模式从干净的 Frappe 初始 DOM 启动。

现有导航树、权限投影、路由监听和移动端收栏逻辑全部复用；不新增第二个 router listener。

### DL 子菜单投影

为了在不先跳转父级工作区的情况下展开采购、生产、项目等任意模块，DL 导航直接复用 `frappe.boot.workspace_sidebar_item` 中当前用户已获授权的所有工作区子菜单：

- 顶层模块仍来自经过权限投影的 `desktop_icons`。
- 子菜单只从与该顶层模块匹配的 `workspace_sidebar_item.items` 读取，不请求第二套菜单 API。
- 子菜单 DOM 和链接优先复用 Frappe 现有 `frappe.app.sidebar.make_sidebar_item` / `frappe.ui.sidebar_item` 渲染与路由生成能力，不复制 DocType、Report、Workspace、Page、URL 等路由规则。
- 当前工作区继续复用 Frappe 原生侧栏节点；其他已展开模块使用同一 boot 数据和原生 item renderer 构建可见子菜单。
- 用户隐藏、排序、文件夹、Section Break、权限过滤和 blocked modules 仍以 Frappe boot 数据为准。
- 切换子菜单后只将旧导航 DOM 中的展开 key 传给本次重渲染；整页刷新没有旧 DOM，因此自然回到“只展开当前模块”。

如果某个父级没有任何获授权的子菜单，则它按无子菜单入口处理：存在路由时直接导航，不显示空箭头。

### 用户头像菜单

品牌脚本在 Frappe 创建 `.sidebar-user-button` 后，为其增加模式菜单：

- 保持头像、姓名和邮箱显示。
- 原本“进入个人资料”的动作移动到菜单内的“个人资料”项。
- 菜单显示当前有效模式和个人覆盖来源。
- 支持鼠标、触摸、键盘焦点、Escape 关闭和点击外部关闭。
- 重复路由刷新不会重复生成菜单或监听器。

菜单在经典和 DL 两种模式下都存在，使用户始终能切回另一种模式。

## 切换数据流

### 用户切换

1. 用户从头像菜单选择“跟随公司默认 / 经典模式 / DL 模式”。
2. 客户端调用只允许修改当前用户的保存接口。
3. 服务端校验值，写入或删除 Frappe 用户默认值，并返回新的有效模式。
4. 保存成功后显示简短成功提示并刷新当前 URL。
5. 新 bootinfo 返回新模式；客户端只初始化对应界面。

### 管理员修改公司默认

1. System Manager 从 `Deeplinkerp Settings` 打开“界面与导航”。
2. 在标准 Single DocType 表单中选择经典或 DL 并保存。
3. 已选择个人覆盖的用户保持个人模式；“跟随公司”的用户在下次刷新或登录时采用新默认。

## 权限与容错

- 普通用户不能修改公司默认，也不能为其他用户写覆盖值。
- 保存接口不接受用户标识参数，目标固定为 `frappe.session.user`。
- 非法值拒绝保存；缺失或非法的存量值在读取时按“跟随公司 / DL 回退”处理。
- Guest 不返回可写的个人模式接口。
- 保存失败不更新客户端显示、不刷新页面。
- 公司设置尚未迁移时仍能以 DL 模式启动，避免升级期间 Desk 不可用。

## 兼容与清理

- 不修改 Frappe、ERPNext、`custom_filters` 源码。
- 不复制 `desktop_icons`、`workspace_sidebar_item`、权限过滤或路由状态。
- 经典模式通过“不启用 DL 增强”实现，而不是复制一份旧导航。
- DL 模式沿用现有 `.active-sidebar`、`workspace_sidebar_item`、原生 sidebar item renderer、移动端遮罩和收栏契约。
- 删除已被本设计替代的“文字跳转、箭头单独折叠”设计与实施计划，不保留两套相互冲突的交互。
- 替换当前“仅当前模块可展开”的限制，改为会话内 DOM key 集合；不新增长期存储。

## 测试与本地验收

### 服务端自动化

- 公司默认为 DL，用户无覆盖时解析为 DL。
- 公司默认为经典，用户无覆盖时解析为经典。
- 个人覆盖优先于公司默认。
- 清除个人覆盖后恢复跟随公司。
- 非法值被拒绝或安全回退。
- 普通用户不能写公司默认，用户保存接口不能修改他人。
- bootinfo 包含公司默认、个人覆盖、有效模式和管理权限。

### 客户端自动化

- 经典模式不生成 DL 导航根、不添加 DL body class、不增强 Desk 首页。
- DL 模式只生成一个导航根并保持现有权限和路由行为。
- 头像菜单幂等创建，三个选择正确调用保存接口。
- 保存成功刷新当前 URL；保存失败不刷新。
- DL 模式中任意有子菜单的父模块，点击整行只切换分支且不导航；子菜单项才导航。
- 多个父模块可以同时展开；子菜单路由切换保留会话内展开集合。
- 整页刷新后展开集合重置，只自动展开当前模块。
- 所有工作区子菜单只来自当前用户获授权的 `workspace_sidebar_item`，未知或无权限项目不会被引入。
- 36×36px 箭头、18px 图标、整行键盘焦点和移动端行为满足已确认规格。

### 浏览器验收

在 `http://localhost:64115` 验证：

- 管理员设置公司默认 DL / 经典。
- 普通用户默认跟随公司，并能覆盖后跨刷新保留。
- 1280×800 和 375px 下两种模式无横向溢出。
- 经典模式保留原生导航，DL 模式保留统一导航。
- 采购、生产、项目及至少一个其他父模块可同时展开；点击父级任何位置都不跳转。
- 点击各模块的子菜单后才导航，并在 SPA 路由切换中保留其他已展开模块。
- 整页刷新后只展开当前页面所属模块。
- 切换后 URL、权限、前进后退和深链接保持正确。
