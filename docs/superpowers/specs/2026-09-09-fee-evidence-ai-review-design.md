# 费用状态、凭证 AI 解析与 SKU 税费分摊设计

## 背景与目标

当前“费用与凭证”工作区将费用金额、金额状态和凭证核验绑得过紧，导致空金额不能先关联凭证、首次录入过早变成实际费用，以及付款流水可能与最终账单重复计费。

本次改造建立三层权威数据：

1. 费用规则保存当前费用总额、币种和人工可维护的金额状态。
2. 费用凭证按会计作用分别保存暂估依据、最终账单、付款和退款流水。
3. SKU 分项保存凭证级的税种、HS 组、原币金额、人民币金额、汇率快照、分摊依据和证据位置。

凭证解析仅生成可审核草稿。未经人工整批确认时，不写入费用金额或 SKU 分项，不自动试算、确认版本或推送 ERP。

## 实施边界

## 费用状态与审计

费用状态使用 `MISSING`(待补)、`ESTIMATED`(暂估)、`ACTUAL`(实际)、`NOT_INCURRED`(未发生)和 `INCLUDED`(已包含)。前端使用下拉框直接维护，金额和凭证校验状态不再互相推导。

- 从待补状态首次录入正金额时，默认转为暂估。
- 没有已校验最终凭证时改为实际，或者将实际改回暂估，必须填写原因。
- 未发生和已包含仍必须填写原因，已包含还必须指向被计费的费用。
- 每次状态变更保存变更前后状态、原因、操作者和时间；业务记录保存最新变更快照，完整历史进入审计日志。
- 保存任何费用、凭证或分项只将批次标记为试算待更新。

默认费用尚未落库时，“关联并解析凭证”先物化一条金额为空、状态为待补且不参与计费的费用规则，再关联附件。

## 凭证数据与会计作用

扩展 `Overseas Cost Fee Evidence`，增加凭证类型、会计作用、币种、原币金额、收付方向、最终凭证标识、附件指纹、解析确认快照、审核任务、确认人和确认时间。

会计作用分为：

- `ESTIMATE`：报价、预付款和暂缴资料，用于更新当前暂估。
- `FINAL_BILL`：最终发票、校验通过的完税凭证或结算单，用于确定实际费用。
- `SETTLEMENT`：付款和退款流水，按收付方向累计净额，不与账单相加计费。
- `REFERENCE`：无法确定会计作用的参考资料，不自动影响费用。

暂估期间的试算仍使用当前暂估总额，另行展示已付净额。最终结算优先使用已确认的最终账单金额。没有最终账单时，用户可在费用行手工将“付款减退款”净额填为费用总额并将状态改为实际；该路径必须填写原因并写入状态变更审计，系统不会从结算流水自动替换费用总额。

## AI 审核任务与草稿

新增独立的 `Overseas Cost Fee Evidence AI Run`，复用项目现有的执行令牌、单飞任务、后台长队列、增量进度修订和无屏闪弹窗模式。同一批次、版本、逻辑费用和附件只运行一个任务；输入指纹未变时可复用就绪草稿。

处理分为两层：

1. 确定性解析负责 PDF/OCR 文本、页码、金额、币种、IGI、IVA、DTA、HS 编码、商品名称、数量以及 PDF 页码、文本行、表格单元格或图片区域证据。
2. DeepSeek 只负责凭证类型、暂估/实际建议、付款/退款方向、跨语言商品语义和模糊 SKU 匹配。DeepSeek 输入不包含金额，其输出的数值字段不被接受。

每个金额必须绑定可定位证据，否则不得默认选中。置信度不低于 `0.90`、数值来源一致且无现有数据冲突的建议默认勾选。低置信、歧义、来源冲突、金额不守恒和 SKU 匹配不唯一的项目显示黄色且默认不勾选。

宽弹窗展示凭证总额、会计作用、费用拆分、税种、HS/SKU 匹配、分摊结果、待归类差额和每项来源证据。用户可选择建议并在受控字段中修改凭证分类、金额、币种、状态和 SKU 对应。

DeepSeek 失败时保留确定性解析草稿。OCR 失败时保留凭证关联，生成可人工补录的草稿，而不将整个任务当作业务失败。

## 费用拆分、差额与净额

同一附件可生成多个费用拆分建议。IGI、IVA、DTA 等税款进入进口税费，报关行服务、仓储和操作等进入清关费。凭证总额与可证明明细不一致时，差额保存在审核草稿的“待归类差额”中。AI 可提示可能的清关费、其他费用、退款或解析遗漏，但在人工确认前不计入成本。

最终账单与付款凭证分别保存，任何费用总额计算都不将两者相加。退款能可靠关联原付款时，按原 SKU/税种比例生成负向冲回分项；无法关联时进入待核对，不自行分摊。

## SKU 分项和试算权威顺序

新增 `Overseas Cost Fee SKU Component`，以费用、凭证、SKU、税种和证据位置为粒度。进口税费先按凭证明细归集到 HS 组，再对组内 SKU 分摊：

1. 所有匹配 SKU 均具备有效申报货值时，按申报货值分摊。
2. 申报货值不完整、但所有匹配 SKU 均具备有效采购货值时，按采购货值分摊。
3. 两组依据都不完整时，不生成可默认勾选的分项，转人工核对。

每个税种单独采用确定性最大余数法处理分尾，保证 SKU 原币合计严格等于凭证明细。清关服务费有明确商品分项时按分项归集，否则按适用 SKU 的采购货值统一分摊。

试算的互斥优先级为：

1. 有效且已确认的新 SKU 分项是其覆盖部分的权威来源。
2. 费用总额减去已确认分项后的正剩余额，按该费用现有系统规则分摊，用于未完全被凭证覆盖的暂估。
3. 仅当该费用没有任何新分项时，才允许使用历史 SKU 税费字段作为兼容来源。

费用总额、凭证分项和历史字段不得对同一金额重复计费。

缺失汇率时，允许保存凭证原币金额和原币 SKU 分项，`amount_rmb`、汇率快照可留空。试算必须显示中文缺汇率提示并不计入未换算部分，不得阻止对原币事实的确认保存。

## API 与事务边界

新增以下白名单接口：

- `start_fee_evidence_review(batch_name, version_name, logical_fee_key, attachment, evidence_role, force?)`
- `get_fee_evidence_review_status(batch_name, run_id, after_revision?)`
- `apply_fee_evidence_review(batch_name, run_id, selections_json, edits_json, edit_token, expected_modified)`
- `discard_fee_evidence_review(batch_name, run_id)`

API 层负责批次权限、标识长度和 JSON 大小/类型约束。服务层负责业务验证与事务。

应用草稿时，服务在同一事务中：

1. 重新校验编辑权、批次最新修改时间和当前版本。
2. 锁定 AI 任务、批次、版本、涉及的费用规则、凭证和 SKU 行。
3. 重新计算附件指纹，检测重复凭证与已应用草稿。
4. 校验枚举、币种、正负方向、费用拆分守恒、每税种 SKU 守恒和 SKU 对当前批次的归属。
5. 写入凭证、费用和 SKU 分项，写入审计日志，将批次标记为试算待更新，最后将任务标记为已应用。

任一步失败都回滚全部业务写入，AI 草稿保留为可继续修改的 `READY` 状态。附件变化属于明确例外：任务标记为 `STALE`，不写入业务数据，用户必须重新分析。

## 前端交互

- 费用行的状态列为五值下拉框，需要原因时在保存前收集，而不在保存失败后再补。
- 行内“关联并解析凭证”在金额为空时仍可用，选完附件即启动后台任务。
- 弹窗按进度修订增量刷新，不重建弹窗或丢失已编辑字段。
- 草稿就绪后展示凭证总额、费用拆分、税种、HS/SKU 匹配、分摊结果、差额和证据。
- 人工选择和修改只在点击“确认应用”时提交。关闭或“放弃草稿”不修改费用、试算、版本确认或 ERP 状态。

## 错误处理

- 解析失败：保留凭证关联和可人工补录的凭证分类/金额字段。
- DeepSeek 失败：显示提示，保留规则解析的数值和证据。
- 缺汇率：允许保存原币凭证和分项，试算显示中文缺汇率提示。
- 低置信/冲突：黄色显示、默认不选，但保留人工修改能力。
- 并发编辑或附件指纹变化：不写入业务数据，草稿保留或转为过期。
- 事务中任何守恒、归属或权限验证失败：整体回滚，不留半成品费用或分项。

## 测试与生产发布

实现以失败测试驱动，覆盖：

- 五种费用状态、首次金额默认暂估、特殊状态原因和审计。
- 空金额费用物化和先关联凭证。
- 报价、预付、付款、退款、最终账单和完税凭证的建议、净额和互斥计费。
- 单附件多费用拆分、待归类差额和未确认不计费。
- 同 HS 多 SKU 的申报货值分摊、采购货值回退、每税种尾差守恒和人工核对。
- 多凭证、重复上传、退款冲回、暂估余额与最终结算。
- DeepSeek/OCR 失败、缺汇率、并发编辑、版本切换、附件变化和事务回滚。
- 历史凭证可读，已确认/已归档版本不被覆盖，新旧试算来源互斥。
- 后端完整测试、前端状态源码测试、两份资源构建同步检查、JavaScript/Python 语法和浏览器端到端验收。

发布前通过已验证的生产流水线创建数据库备份和回滚分支，然后仅推送一次 `overseas_costing` 生产分支。流水线运行完整测试、Frappe DocType 迁移、资源构建/同步、缓存刷新和登录页健康检查。部署后验收仅在活动批次上生成并放弃一份草稿，不更改费用、试算、版本确认或 ERP 状态。

采用已确认的方案 A：保留现有 `codex/fee-evidence-ai-review` 工作树中的实现草稿，逐项对照本设计补齐，然后通过生产流水线单次发布。不采用从基线重写，也不拆成后端和前端两次生产发布。
