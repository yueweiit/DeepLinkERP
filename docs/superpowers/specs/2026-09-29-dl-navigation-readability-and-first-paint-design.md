# DL 导航可读性与首屏防闪屏设计

## 背景

DL 模式侧栏已经复用 Frappe 的权限菜单、路由和展开状态，但当前本地预览仍有三个明显体验问题：

1. `.body-sidebar-top` 使用浏览器默认滚动条，出现宽白色轨道和灰色滑块，与 `#001529` 深蓝侧栏冲突。
2. 搜索、通知、Getting Started、用户名称和邮箱仍命中 Frappe 的浅色主题文字规则，实际计算色为 `rgb(56, 56, 56)`，在深蓝背景上几乎不可见。
3. 硬刷新 `/desk/purchase-order` 等深链接时，经典桌面的大号彩色图标会先出现，随后才切换到 DL 导航，造成明显卡顿感。

第三个问题的根因不是业务页面加载失败。DL/经典模式结果已经存在于 `frappe.boot.deeplinkerp_interface_mode`，但当前 `deeplinkerp_branding.js` 要等到 `DOMContentLoaded`，并且等 Frappe 侧栏节点生成后，才添加 `dlp-mes-navigation-enabled`。在此之前浏览器已经绘制经典桌面。

## 目标

- 采用已确认的“平衡清晰”方案，提高侧栏所有非选中元素的可读性，同时保留一、二、三级菜单的视觉层级。
- 将默认宽白滚动条替换为 6px 圆角滚动条，轨道透明，滑块低干扰但可辨认。
- DL 模式硬刷新时立即显示深蓝品牌外壳，不再显示经典桌面大图标。
- 继续复用当前导航模型、原生菜单节点、路由监听、权限和模式切换，不建立第二套菜单或加载状态数据。
- 经典模式、移动端行为和业务内容区保持不变。

## 非目标

- 不实施业务内容区夜间模式。
- 不修改 Frappe/ERPNext 核心模板或核心资源。
- 不新增后端接口、数据库字段、缓存或数据迁移。
- 不改变菜单顺序、权限、展开规则、高亮规则和模式设置入口。
- 不增加转圈动画、进度条或新的持久化导航状态。

## 方案选择

采用客户端同步准备态，不覆盖 Desk 服务端模板。

`deeplinkerp_interface_mode.js` 在脚本求值时读取已有 boot 信息，并立即在 `<html>` 上标记 DL 准备态。导航 CSS 已在 Desk `<head>` 中加载，因此准备态标记一旦存在，就能在经典桌面绘制前隐藏旧图标，并把左侧区域绘制成 DL 深蓝品牌外壳。现有 `renderPersistentNavigation()` 成功后结束准备态并显示真实菜单。

未采用的方案：

- 覆盖服务端 Desk 模板：首屏最早，但会引入 Frappe 核心模板耦合和升级维护成本。
- DOM 完成后增加全屏遮罩：实现简单，但仍然发生经典桌面绘制，只是遮住症状，并且更像页面卡死。

## 状态与数据流

### 1. 首次脚本求值

`deeplinkerp_interface_mode.js` 继续作为模式判断的唯一来源：

- 有效模式为 `dl` 时，在文档根节点添加准备态标记，并将文档标记为忙碌。
- 有效模式为 `classic` 时不添加任何准备态视觉规则。
- boot 信息不可用时不猜测模式，保持 Frappe 原生行为。

准备态只在整页加载时进入。单页路由跳转、前进后退和菜单点击继续走现有刷新生命周期，不重复显示首屏外壳。

### 2. 准备态显示

准备态 CSS：

- 左侧保持 220px 宽和 `#001529` 背景。
- 显示 28px DLP Logo 与 DeepLinkERP 名称。
- 隐藏经典桌面彩色图标网格和原生菜单正文，避免旧导航露出。
- 主内容区保持中性空白，不显示转圈动画或伪造的菜单骨架。
- 准备态元素不提供可点击入口，避免用户点击即将被替换的节点。

### 3. 导航就绪

现有 `renderPersistentNavigation()` 仍负责：

- 获取 Frappe 已授权的 `desktop_icons` 和 `workspace_sidebar_item`。
- 认领原生工作区菜单节点及其事件。
- 构建当前 DL 导航、恢复层级和更新路由高亮。

当真实导航已经插入、活动项已经同步后，再在同一刷新周期内结束准备态、清除忙碌标记并显示真实侧栏。准备态不使用渐变动画，避免用户再次感觉界面响应迟缓。

### 4. 降级

准备态由单一、可取消的看门狗保护：

- 导航在 2 秒内完成时取消看门狗。
- 超过 2 秒仍未生成时，结束准备态并恢复 Frappe 原生界面，同时输出一次明确警告。
- 后续现有重试若成功生成 DL 导航，仍可正常接管界面。
- 看门狗不得在路由事件中重复创建，也不得影响经典模式。

## 视觉规格

保持现有 MES 风格基础色与层级背景：

- 侧栏背景：`#001529`
- 一级菜单背景：`#001b33`
- 展开子菜单背景：`#000f1c`
- 选中项：`#1677ff` 蓝底、白色图标和文字
- 一级菜单文字与图标：`#c1d0df`
- 搜索、通知及底部辅助信息：`#9fb4c8`
- 二、三级菜单文字与图标：`#afbfce`
- 展开箭头：`#d0dbe6`
- 用户名：`#d8e3ed`
- 悬停：现有 `rgba(255, 255, 255, 0.08)`
- 键盘焦点：现有 `#69b1ff` 轮廓

滚动条只作用于 DL 侧栏的实际滚动容器 `.body-sidebar-top`：

- 宽度 6px。
- 轨道透明，不产生白色槽。
- 滑块使用半透明蓝灰色并采用完全圆角。
- 悬停时滑块适度提亮。
- Firefox 使用 `scrollbar-width` 和 `scrollbar-color`，Chromium/WebKit 使用对应伪元素。
- 内容不足时沿用浏览器行为，不显示无意义滚动条。

颜色覆盖使用侧栏内的精确选择器，覆盖 Frappe 子元素自身的深色规则；不通过全局 `color` 或 `!important` 泛化到业务内容区。现有选中、悬停和焦点状态继续拥有更高优先级。

## 组件边界与复用

- `deeplinkerp_interface_mode.js`：继续拥有有效模式解析，并新增可测试的准备态开始、完成和超时降级控制。
- `deeplinkerp_branding.js`：继续负责品牌与真实导航渲染；仅在导航成功后通知模式控制器结束准备态。
- `deeplinkerp_navigation.css`：增加准备态、可读性和滚动条样式，不复制菜单结构。
- `deeplinkerp_navigation.js`：导航模型、排序、权限、路由匹配和展开交互保持不变。
- `branding.py` 与现有设置 DocType：公司默认和用户覆盖语义保持不变。

不会新增平行的导航组件、菜单缓存或独立模式判断。旧版彩色桌面图标仍保留给经典模式；DL 模式只在首屏准备态和最终导航中隐藏它们。

## 兼容性与可访问性

- DL 模式：桌面、平板和手机继续使用现有侧栏收起、移动端遮罩和路由行为。
- 经典模式：不添加准备态，不应用 DL 色彩与滚动条规则。
- 键盘：现有焦点轮廓保持可见，选中项仍设置 `aria-current`。
- 屏幕阅读器：准备态期间文档标记为忙碌；真实导航完成或降级后清除。
- 用户权限、隐藏项、用户排序、管理员入口和深链接不变。
- 同一文档只允许一个看门狗和一个 DL 导航节点。

## 测试设计

### 自动测试

- DL 模式 boot 数据会同步进入准备态。
- 经典模式和无效/缺失 boot 数据不会进入 DL 准备态。
- 导航成功会清理准备态、忙碌标记和看门狗。
- 2 秒超时会恢复原生界面，且只记录一次警告。
- 重复初始化不会生成多个看门狗或导航节点。
- CSS 源测试覆盖确定的颜色、6px 滚动条、透明轨道、Firefox 与 WebKit 规则。
- 现有导航排序、权限、层级、高亮、模式切换和路由测试必须继续通过。

### 本地浏览器验收

在现有 Frappe v16 Docker 预览 `http://localhost:64115` 中验证：

1. DL 模式硬刷新 `/desk/purchase-order`，首屏只出现深蓝品牌外壳，不出现经典大图标。
2. 菜单完成后采购订单保持蓝色高亮，采购分组保持展开。
3. 搜索、通知、一级菜单、子菜单、Getting Started、用户名与邮箱均清晰可读。
4. 滚动菜单时没有白色轨道，滑块宽度和悬停状态符合规格。
5. 采购、生产、中国财务/财务、AI 助手等深链接硬刷新均保持相同行为。
6. 切换到经典模式并刷新，经典界面正常显示且没有深蓝准备态。
7. 再切回 DL 模式，准备态和真实导航正常衔接。
8. 验证桌面、平板和手机宽度，无横向溢出，收起按钮和移动端遮罩正常。

## 验收标准

- DL 模式的任何已授权 Desk 深链接硬刷新时，经典桌面大图标不再可见。
- 首屏外壳不会阻塞超过 2 秒；异常时可以恢复原生界面。
- 侧栏滚动条没有白色轨道，宽度为 6px。
- 截图中指出的深色文字全部达到肉眼可辨的 A 版亮度，同时一、二、三级菜单仍能区分。
- 经典模式和原有导航行为无回归。
- 自动测试与本地浏览器验收均通过后才视为完成。
