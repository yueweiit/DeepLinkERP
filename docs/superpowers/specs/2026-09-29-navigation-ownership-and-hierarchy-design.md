# DeepLinkERP 导航归属与 MES 层级配色设计

## 目标

修复从采购等工作区跨模块进入 `/desk/bom` 时，Frappe 原生生产子菜单被错误挂到旧模块下面的问题；同时让 DL 模式的一级模块与二级菜单使用不同背景色，并保持顶部品牌始终显示 DeepLinkERP。

## 已确认交互

- 有子菜单的一级模块整行点击只展开或收起，不导航。
- 二级菜单点击后才导航。
- 同一页面会话内允许多个一级模块同时展开；完整刷新后重置为当前模块展开。
- 一级模块背景使用 `#001b33`，二级菜单区域使用 `#000f1c`。
- 当前二级菜单继续使用 `#1677ff` 蓝底白字。
- 展开的一级模块使用白色图标、文字和箭头；未展开项使用 `#91a3b7`。
- 顶部品牌固定为 DLP 标志和 DeepLinkERP，不随当前工作区改成“采购”或“生产”。

## 根因

Frappe SPA 跨工作区跳转时，URL、原生侧栏内容和 `.active-sidebar` 会先更新，而 `frappe.app.sidebar.sidebar_title` 仍可能短暂保留旧模块。当前模型在顶层路由无法直接匹配 `/desk/bom` 时回退旧 `sidebar_title`，于是把已经更新为生产内容的原生节点挂到采购分支。

## 方案

### 当前模块归属

继续以授权后的 `desktop_icons` 构建一级树，以 `workspace_sidebar_item` 作为二级菜单权威快照。增加一个纯函数解析当前原生激活叶子：

1. `?sidebar=` 明确指定模块时优先使用。
2. 顶层模块路由精确匹配时使用该模块。
3. 读取原生 `.active-sidebar` 的标签与链接，并在授权的 `workspace_sidebar_item` 中寻找唯一所属模块。
4. 标签相同的候选项以链接目标和当前 URL 共同消歧。
5. 只有以上都无法判断时才回退 `frappe.app.sidebar.sidebar_title`。

解析只决定现有原生节点挂到哪个一级模块，不复制路由生成、权限过滤或菜单数据。非当前模块仍由现有 Frappe sidebar item renderer 从授权快照渲染。

### 品牌头

DL 模式始终创建并维护独立的 `.dlp-mes-navigation__brand-fallback` 品牌入口，并隐藏 Frappe 会被路由更新的原生 `.sidebar-header`。退出 DL 模式时移除品牌入口并恢复原生头部，经典模式不受影响。

### 视觉层级

- `.dlp-mes-navigation` 的一级 group row 使用 `#001b33`。
- 一级 group 的 `.dlp-mes-navigation__children` 使用 `#000f1c`，形成连续的二级区域。
- 原生和投影出来的二级项保持透明底，悬停为 `rgba(255,255,255,.08)`。
- `.active-sidebar` 继续使用 `#1677ff`，优先级高于二级区域背景。
- 嵌套文件夹继续依靠现有缩进区分，不为每一层新增颜色状态。

## 兼容与退出条件

- 不修改 Frappe / ERPNext 核心，不新增 API、数据库字段或第二套路由表。
- 继续保留权限、排序、隐藏项、文件夹、深链接、前进后退和移动端关闭行为。
- 当前 DOM 适配依赖 Frappe v16 的 `.active-sidebar`、`.item-anchor` 和 `.sidebar-header`；只有升级后官方提供稳定扩展点且相同浏览器用例通过，才能删除该适配。

## 验收

- 从 `/desk/buying` 打开生产，再进入物料清单后，生产展开且原生节点只挂在生产下面，物料清单蓝色高亮。
- 刷新 `/desk/bom` 后仍定位生产，不回退采购。
- 一级 `#001b33`、二级 `#000f1c`、选中项 `#1677ff` 的计算样式互不相同。
- 顶部始终显示 DeepLinkERP。
- 经典模式、移动端、权限、无子菜单入口和会话内多展开行为保持不变。
