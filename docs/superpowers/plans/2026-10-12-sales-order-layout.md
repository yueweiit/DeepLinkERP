# 销售订单布局改造实施计划

目标：沿用用户确认的白底、有边框、紧凑顶部草图，取消小框纵向滚动。

基线：复用已附着的 `purchase-receipt-only` 工作树 `50a75152d5`；主站代码为
`6b5e8ba324ab`。不改海外核算分支、不新增后端接口、不改变业务单据。

## 已确认范围

- 复用 `compact_list.js` 的筛选、工具栏、权限过滤和明细表渲染；销售仅提供布局配置。
- 右侧内容页负责纵向滚动，侧栏保持固定；明细取消限高，宽表内部横向滚动。
- 日期起止、客户、审核、公司保留；品目编码及原生高级条件放入“更多筛选”。
- 合并视图标签、选择计数、生产放行、字段分组、密度、列设置和导出工具栏。
- 保留默认财务视图、个人列配置、原生筛选及生产放行规则。
- 明细白底、淡蓝表头、可见边框；名称、规格、摘要、仓库最多三行且可悬停看全文。
- 编码、日期、金额不截断，数字右对齐；全部获授权字段和行继续展示。
- 用户追加确认：用右下角“回到顶部”按钮替代表头跟随逻辑；滚动超过 300px 后显示，
  尊重系统减少动画设置，离开销售路由隐藏并清理监听。保留逐单展开，不新增批量业务动作。

## 验证与发布

1. 在现有测试中替换被废弃的销售限高断言，先观察失败，再实现；共享采购和库存保护保留。
2. 复用既有 `po-grid-qa.localhost` / `qa_procurement_5` Docker 环境，创建仅合成的
   52 行长文字草稿；确认 GL、SLE、付款、应收、交货、工单和集成日志数量不变。
3. 浏览器验收 1920、1280、390 像素：整页滚动、三行上限、完整编码金额、横向滚动、
   回到顶部、筛选、分页、勾选及详情；生产放行仅验证资格，不执行业务确认。
4. 运行全量前端、资源契约及修改文件语法检查；更新修改资源版本。
5. 经规范与质量审查后冻结 SHA，复用唯一发布负责人执行主站 UI-only 串行发布，
   不迁移、不 metadata apply、不同步、不备份数据库或附件。
6. 在线实际控件验收后，按精确所有权和引用证明清理本轮传输缓存，保留回滚镜像及审计。
