# 运营支出字段、待办理与付款交互执行清单

已确认设计：现有运营页、来源适配和付款账本内修复，不建平行系统。

## 分项

- [ ] 来源投影：归属单位、账户性质、项目、需求日期、总经理审批、备注；冲突不猜测。
- [ ] 待办理与统计：未付/部分付/历史未知未结束申请；展示与付款资格分离；异常余额独立统计。
- [ ] 精确默认列序与旧布局备份升级；金额与币种分列；导出同配置。
- [ ] 财务菜单正常宽度与可拖动滚动条；桌面非遮挡抽屉、移动遮罩、切页/未保存/保存竞态保护。
- [ ] 付款记录与第一笔/新增/历史核对入口；部分付款预览；不转账、不自动记账。
- [ ] 全量来源核对，窄范围修复采购模板缺失/同步失败，不搬入运营页。
- [ ] 单元、原生 QA、浏览器验收；独立规格与质量复核。
- [ ] 协調单一串行发布：阿里云来源向后兼容先行、Vultr Branding 后行，生产只读验收。

## 性能及安全边界

当前约 372 申请。分类、各页数量一次扫描 O(N)，有界批量 JSON 投影及哈希关联 O(N+C+U)，审批事件一次解析排序 O(E log E)。空间 O(N+C+U+E)。禁止逐单查询人员或重复解析历史。

法律公司与来源归属单位分开。未知历史显示 —，负余额单独异常。审批模板/必审证据不明继续阻止新增付款，出纳网站标记仅供展示。生产禁止付款/接管/凭证业务测试。保留现有脏文件及回滚接口。

## 默认列

钉钉申请单号、付款状态、应付款公司、申请人、账户性质、摘要、应付金额、已支付金额、待付款金额、货币类型、项目归属、收款人、需求付款日期、总经理审批、备注、操作。

按后续确认，钉钉申请单号是首个业务列，桌面仅此列固定；技术复选框保留禁用且不固定，手机不固定列。单号直接链接原单，移除抽屉重复原单按钮。

## 同库财务一致性补强

复用既有 Source、Takeover、Payment、Mapping、Event 与原生 Journal Entry，不新增财务账本。写路径后置断言失败必须抛出异常，交由 Frappe RPC 同事务回滚；只读详情仍可显示待核对提示。锁定凭证父子项，Event 反向关联使用当前读，防止旧快照越过新关联。保存结果日志记为 validated，不冒充事务已经提交。

阿里云 SQLite 和 Vultr MariaDB 不共享数据库事务。沿用 OA 唯一身份、来源冻结所有权、稳定请求号和恢复重试；本地失败后不得解冻旧系统的付款权，以免双付。生产不以测试名义接管、登记、冲正或生成真实凭证。
