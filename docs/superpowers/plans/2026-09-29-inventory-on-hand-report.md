# 库存库位明细实施计划

## 复用与边界

- 保留 ERPNext 标准“可用数量”和 `Stock Projected Qty`。
- 复用 `Item`、`Warehouse`、标准 Page、标准 Data Import 和现有物料追溯字段。
- 新增一个库位快照 DocType 和一个独立页面；不新建仓库层级、不修改库存流水、不复制库存调账逻辑。
- 删除旧 `Inventory On Hand` Script Report 及重复测试，避免并行入口。

## 实施步骤

1. 新增 `Inventory Original Location Snapshot`：保存快照范围、库位数量、来源审计字段和唯一幂等键，并允许有权限角色使用标准 Data Import。
2. 新增“库存库位明细”Page：
   - 固定展示 11 个业务字段；
   - 按正式物料编码和仓库分组；
   - 原始库位与库位数量逐行展示，其余字段真实 `rowspan`；
   - 支持公司、快照、仓库、原始库位、物料关键字、物料组筛选；
   - 编码只显示正式编码并链接 Item；
   - 原始库位筛选时保留完整物料仓库小计。
3. 新增合并单元格 Excel 导出，并按单位控制 0/2 位小数显示。
4. 在库存 Workspace Sidebar 的标准“可用数量”之后幂等插入页面入口，不替换标准入口。
5. 新页面存在后移除旧 `Inventory On Hand` Report。
6. 生成 2026-09-29 标准导入文件并校验：401 条、377 组、总量 `746,610.49`；色母粒使用最终 kg 编码 `FL007979`、`YL001974` 并追溯到纠正单 `MAT-RECO-2026-45828`。
7. 通过既有 CI/CD 部署、迁移；再用标准 Data Import 导入快照并进行线上只读验收。

## 测试与验收

- 服务测试：分组、完整小计、库位筛选、数量精度、真实 Excel 合并。
- 页面测试：真实 `rowspan`、编码文本/跳转、列顺序、数量格式、源/镜像一致。
- 安装测试：标准入口保留、新入口顺序幂等、旧报表安全退役、自定义字段和导入权限。
- 静态检查：JSON、JavaScript 语法、Python compileall、源/镜像一致。
- 全量 pytest 与 CI 通过后才部署；线上确认 401 条库位记录、三个仓库计数、总量和关键物料单位。
- 完成报告分别列出新增、修改、删除、测试变化和未处理技术债。
