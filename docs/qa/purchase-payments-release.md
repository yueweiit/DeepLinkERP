# 采购付款与紧凑列表验收

## 实现范围

- 采购入库默认展示独立收货状态、关联订单、关联应付的已付/核销与未付。公司、币种等重复字段可从列设置打开；原生高级筛选和批量操作保留在原生视图。
- 订单/入库详情首部提供采购关联摘要。订单已入/待入数量按单位分别计算；待入货品金额明确不含税，不作为应付金额。
- 付款抽屉仅点击后打开；一笔草稿选择一张已提交应付，可部分付款。银行参考号/付款申请编号遵循原生银行必填规则，参考日期沿用付款日期；不伪造银行流水。
- 新建的是原生 Payment Entry 草稿，仍需按已有审批流程提交。抽屉不提交、不操作银行、不写额外 GL，也不生成另一套应付或付款单。
- 采购付款记录仅纳入明确关联采购订单/采购应付的 Supplier Payment Entry；显示分配金额和单据链接，草稿/取消不计已付。订单预付款可从相关入库追溯，未核销时不虚减入库应付。
- 自定义财务凭证继续由 china_finance 根据原生 GL 快照生成；共享应付始终明确整单余额，不能冒充某张入库的分摊金额。
- 销售默认显示客户、产品、数量、单价、业务状态、交期及金额。复用既有 CRM 产品/业务员读接口内部函数；先验证单据、公司、父子字段权限。多明细显示“多明细”，多单位数量不合并。

## 最短操作

采购订单 → 采购入库（可分批） → 如未形成应付，在入库点“确认应付”，核对并提交原生采购应付 → 付款/继续付款 → 创建付款草稿 → 核对并提交原生付款单 → 采购付款记录追溯付款和财务凭证。

所有生产公司现有自动采购应付开关均为关闭，本次保留。已有应付草稿应先打开关联草稿核对，避免另建。跨币种、退款、扣款、复杂付款计划使用原生付款入口。
