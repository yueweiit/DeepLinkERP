# 本票采购支出匹配

批次「资料与费用」沿用现有入口。打开匹配弹窗先读取本地关联和任务；当前未关联且没有有效缓存时，显式提交本票任务。历史初始化仍在全局工具中，批次弹窗不调用初始化接口。

## 采购范围

上游自动登记所有名称包含「采购支出」的流程模板，按企业隔离并保留停用或删除模板的历史范围。明确选择「物流及运输服务」才纳入，不限定海运等下级方式，也不依赖上级分类的旧名称。拒绝、撤销或删除的审批不进入匹配池；审批中的单据可生成候选，不能采用为最终费用。

需要先部署 dingtalk-oa 的 `20260910000000_purchase_template_scope.cjs`。迁移只让新增流程和分类漏项进入增量窗口，原有合格单据不更新指纹。成本系统解析器版本保持不变。

## 任务与接口

- `get_batch_settlement` 返回本地 `matching` 状态、候选与已保存关联，不读取上游或调用 AI。
- `start_batch_matching(batch_name, version_name)` 只补读缺失的本票国际物流审批身份，再执行本票规则。明确规则候选直接保存，未解决或冲突才进入 DeepSeek。
- AI 请求只含本票国际物流和同企业合格采购支出的必要匹配证据。已绑定、未变化的人工否决及其他物流的明确候选不重复分析。
- `find_expenses` 需要非空关键词，搜索结果始终用于当前批次，不自动建立关联。
- `confirm_matches` 接收候选 ID、修订号及可选批次/成本版本，服务端锁定并重新核对；一对一约束仍由数据库保证。

缓存保存于 `oc_ls_state`，每票有独立任务指针，包含来源快照、合格采购池、关联占用、人工否决与匹配策略指纹。候选和无匹配结果都保存；推荐候选失效时缓存同时失效。失败重试复用已完成的单据结果。相同请求不会重复启动有效任务；十分钟未完成可显式重试。AI 请求前结束读取事务，返回后重新验证来源与任务执行权。

关联和资料采用分别记录。采用失败时保留关联及错误说明，旧来源通过现有核算闸门退出当前有效计算；已确认版本保持冻结。更正仍在事务内撤销旧采用关系并建立新关联，随后采用新资料。任何流程都不自动确认候选或推送 ERP。

## 验证与部署

增量测试覆盖分类共享样例、单票隔离、已保存结果复用、来源变更、AI 分块及失败重试、并发否决和确认、附件预览大小限制、前端关闭/导航/旧版本响应保护。上游 SQL 使用独立 PostgreSQL 集成测试。现有发布工作流保持原有 CI 校验和部署备份。

上线后仅定向补入漏项，不自动重新执行历史全量匹配。回退可停止新任务，保留关联、候选、来源及已确认历史版本；数据库范围迁移回滚需参考上游文档，不能删除修复证据以绕过外键约束。
