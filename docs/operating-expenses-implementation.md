# 运营费用接入实施与验收

## 已确认边界

- 保留请款网站，ERP 只同步运营付款申请、费用报销和付款依据。
- 不登记第二份付款，不自动提交、生成总账或结账。
- 财务在侧边面板维护分类、公司、科目及辅助核算，预览后生成原生 Journal Entry 草稿。
- 费用确认与逐笔付款结算独立关联，稳定来源事件防止重复生成。
- 缺失分类、公司、金额、往来或汇率时明确提示，不猜测。

## 来源契约

`GET /api/integrations/erp/operating-expenses` 使用单用途 Bearer token 和明确页签范围；默认禁用。
响应 schema_version=1，申请 source_id 使用逻辑根，payment source_id 使用付款根，版本覆盖申请、付款和附件。
申请分类只接受 payment、reimbursement、unclassified。原始来源没有类型时必须待分类。
公司原值与来源页签只用于人工映射，不直接等同 ERP 法律主体。
同步分页使用 until 水位，包含付款及附件变化；不会更新源网站摘要。
当前可编辑申请金额仍是业务金额；原始申请金额字符串另列保留，并报告既有 SQLite REAL 精度损失，不用历史原值覆盖人工修改。
不同时间的逻辑副本若来源身份或法律公司不一致，将阻断；付款附件按付款根与文件摘要去重。

## ERP 服务实现契约

### 模型与权限

- 新建非会计账本的来源缓存、财务映射及同步设置；原始申请和逐笔付款依据不可由页面编辑。
- 设置单例只允许 System Manager，密码字段保存服务端令牌，查询响应不得包含密码或源服务鉴权头。
- 默认禁用同步。先预览再确认法律公司映射，页签/部门不得自动等同 Company。
- 未映射公司记录只对 System Manager 可见。已映射记录、导出、附件与关联凭证均检查原生公司和文档权限。
- 分类缺失时显示待分类；人工分类维护在财务映射中，保留来源原值和修改记录。

### 接口与同步

- 提供列表、单条详情、保存财务映射、分录预览、生成草稿、已有凭证关联、同步预览/确认、全部结果导出和授权附件代理。
- 列表与导出复用同一白名单筛选和权限口径，币种分别合计；默认 100 条，允许 20、500、2500。
- 15 分钟定时任务只在显式启用后执行。服务端 HTTPS 源域固定为 payment.yueweiportal.com，不跟随重定向；仅独立 QA 允许显式测试地址。
- 增量处理跨周逻辑根和逐笔付款根，记录最后成功水位、错误及来源版本。中断不推进未完成水位。
- 生成草稿之前必须按精确 source_id 再读取当前源数据；来源消失、撤回权限、变成采购或版本改变均阻断，不能依赖旧缓存授权。
- 附件只按来源返回的固定类型 ID 代理，不能传入任意 URL；逐笔付款证明保留根关联，不暴露服务端令牌。

### 财务草稿

- 员工报销使用 Employee 往来，对外申请使用 Supplier 往来；缺失映射不自动创建主数据。
- 费用确认和每笔付款分别使用唯一来源事件键，原生 Journal Entry 来源键唯一约束与锁防止并发重复。
- 同事件同版本重复点击返回已有可读草稿；来源改变后不能覆盖旧草稿或已提交凭证。
- 首次费用确认须确认已实际发生及不存在重复 ERP 覆盖；已有凭证覆盖通过显式关联，不重复确认费用。
- 财务明确填写费用/税额等分录和往来科目，借贷、公司、账户币种、汇率、成本中心/项目均经原生验证。未确定税额不自动计算。
- 付款结算只借应付、贷银行/现金；缺少有效费用确认关联时阻断。异币种需明确汇率/差额处理，不默认为同币种。
- 只调用原生 insert 生成 docstatus=0，不调用 submit、GL 写入、自动会计凭证提交或结账接口。
- 原生 Journal Entry 核销引用只接受已提交的费用确认凭证。费用确认仍为草稿时，结算草稿只保留明确的来源/确认草稿关联并显示“尚未核销”，不得伪造原生核销。运营来源结算若以后在原生界面提交，必须先确认费用凭证已提交并经过原生引用校验；本期验收不提交任何凭证。

## 会计约束

首次费用确认必须确认实际发生、既有 ERP 覆盖情况及科目分类。按财务分录维护原币与账户币种，允许费用、税额等拆分，但不自动计算未知税额。
员工往来使用原生 Employee，对外往来使用原生 Supplier；不自动创建员工或供应商。
逐笔付款仅冲减对应应付，不再次确认费用；缺少有效费用确认关联时阻止生成。
所有凭证都是草稿；来源变更不覆盖已生成内容。原生记账流程不在本期自动化范围。
