# 招商银行回单导入（第一期）

财务人员从回单导入、凭证核对到月末结账和反结账的完整图文步骤，见[银行回单至月末结账与反结账操作 SOP](银行回单至月末结账与反结账SOP.md)。

新版已增加上传后自动识别、集中生成草稿和月末统一记账，完整操作见[凭证准备与月末记账操作](凭证准备与月末记账操作.md)。

中国财务 → 银行与对账 → **银行回单导入**。这是独立的回单入口；原“银行对账”中的 XLSX / 对账单导入继续使用。

## 支持范围

- 招商银行人民币文字版电子回单 PDF，包括一页多张的出账、入账回单。支持普通收付款、收费、代发工资、代发付费、税费及公积金扣款。
- 单次最多 20 MB、100 页、300 张回单。扫描件、加密文件、外币及其他银行版式需要另行适配；不能识别时会显示页码和原因，不会用猜测结果制证。
- 预览展示交易日期、流水号、收支、金额、对方、摘要、建议科目、疑似已有凭证，以及原件页码和页内位置。新业务一次确认即可按建议科目生成全部可处理草稿；异常记录可展开收付款方、账号、开户行及费用/税费明细。
- 交易日期作为记账日期，打印日期和税费所属期间只作业务信息。
- 一笔银行交易关联一张记账凭证（Journal Entry）或已提交付款单（Payment Entry）；凭证中须恰有一行本银行的人民币分录。复杂汇总、内部转账、多人往来分摊应手工制证后逐笔核对，不能把一笔回单金额重复挂到多张凭证。
- 自动生成仅限草稿。正式审核记账继续走现有流程，提交后才影响总账和财务报表。

## 本地多站点的入口检查

当前本地环境的 `8000` 端口对应 `dev.localhost`，`8001` 端口对应 `aaa`。它们共用代码，但数据库、DocType 表结构和工作区菜单分别保存。只更新其中一个站点，另一个站点不会自动出现“银行回单导入”。

2026-09-21 已为 `aaa` 补齐四个回单 DocType、社保规则应付科目字段和中国财务导航。浏览器中已有的旧侧边栏须 `Ctrl+Shift+R` 强制刷新。入口位置：

- “银行与对账”下的“银行回单导入”和“银行回单”；
- “业务控制规则”下的“银行回单科目规则”。

后续升级需对实际使用的站点执行迁移及缓存清理；例如本地 `8001` 使用 `--site aaa`，生产站点使用 `--site deeplinkerp.com`。以实际启动命令中的站点配置为准，不根据 IDE 当前打开的 `site_config.json` 判断。

## 首次准备

1. 点击“中国财务”，选择实际记账公司。
2. 在“银行账户”确认：本公司账户、已启用、银行为招商银行、已关联本公司的人民币 Bank 明细科目，并填写**完整银行账号**。
3. 回单本方户名必须与公司全称一致。系统会兼容全角/半角括号和空格，但不会把不同公司视为同一家公司。
4. 确认公司科目、成本中心、期间及审核权限已配置。导入人需要回单导入权限；生成草稿还须具有原生银行交易及记账凭证的创建/提交或保存权限。回单入口不绕过原有记账权限。

## 已经记账的月份：历史补回单

对已经导入、审核记账的历史凭证使用此模式，避免重复入账。

1. 新建回单导入，选择公司、银行账户，用途保持默认“历史补回单”。
2. 上传私有 PDF，信息完整时自动保存并识别；若未自动执行，可保存后点击“识别回单”。此时只生成预览，尚未创建银行交易或凭证。
3. 核对收入、支出和笔数。合计按**交易流水号去重**，重复页面仍保留原件位置。
4. 每行点击“核对处理”，选择“关联已有凭证”，核对原凭证后确认。
5. 默认只补关联；如果确实需要补齐银行核销记录，可在首次关联时勾选“同时补建银行交易”。已有银行交易会复用，不重复创建。
6. 需要核销时，确认原凭证已提交，再点击“核销”。只补附件、没有银行交易时显示“已补回单”，无需为了此状态重新入账。

候选凭证是同银行、同金额且日期在前后 7 天以内，或者参考号等于交易流水号的记录。只有交易流水号相同、已有银行交易明确关联或无法查看的候选会阻止自动制证；仅因日期和金额相同的历史凭证只作提示，**同金额不是同一业务的证明**。系统还会显示已有银行交易的关联凭证。

已经只补关联、后来又需要银行交易时，可通过原 XLSX 流水入口补导；相同交易会关联到已有回单，并停止原流水入口的自动重复制证。然后在回单页面核销已有凭证。

## 未记账的新业务：回单生成草稿

1. 新建批次，用途改为“新业务制证”，上传、保存、识别。
2. 系统先采用公司回单规则及回单中的明确业务信息，再复用银行流水的摘要科目匹配规则。按当前已确认口径，带收款人的“报销/报销款”建议到 `660201 管理费用－办公费`；草稿生成后仍可在“查凭证”修改。
3. 点击 **确认导入并生成草稿**。系统处理本批全部记录，不需要逐笔勾选或先打开核对弹窗。每笔独立处理，重复点击会复用已生成结果，不会重复制证。
4. 疑似已有凭证、规则冲突、内部转账及确实无法确定科目的记录不会自动生成。它们保留为异常记录，点击“处理异常”关联已有凭证或人工选择科目。候选均非本业务时，可手工制证后关联。
5. 在“查凭证”集中检查并按报销单修改科目、金额、摘要、日期和辅助核算，再走凭证核对及月末统一记账。新建草稿会关联银行交易，记账后沿用现有自动银行核销流程。
6. 记账凭证和付款单的“银行回单”按钮可查关联记录及原 PDF；银行回单记录保留费用/税费明细、原件页码和处理人。

手续费业务类型优先于摘要中的“工资”；明确的个人所得税明细建议应交个人所得税科目。利息收入继续按财务费用负借方冲减。建议不代表已完成财务审核。

凭证摘要优先使用回单结构化信息：摘要为“报销”或“报销款”时附收款人姓名，例如“报销款-张三”；个人所得税按税费明细的所属时期写成“支付7月个人所得税”。付款跨年时带年份，例如 2027 年支付 2026 年 12 月个税写成“支付2026年12月个人所得税”。所属时期缺失、无效或跨月时保留银行原摘要，不能根据付款日期猜测税款所属月份。

规则更新前已经生成的未记账草稿，可回到原回单导入批次点击 **更新本批草稿摘要**。系统只更新摘要仍为银行原文的草稿；已经记账、已经取消或摘要经过人工修改的凭证会跳过。摘要更新后，原来的核对版本会失效，需要重新执行“核对所选草稿”。

## 悦为社保分摊

2026-09-21 确认的规则如下。百分比按输入数值使用，例如 66.67% 不按 2/3 计算。**每个险种的公司承担额四舍五入到分，个人承担额取该险种总额减公司承担额**，保证合计一致。

| 险种 | 回单金额 | 公司承担比例 | 管理费用－社会保险费 | 其他应收款-社保 |
| --- | ---: | ---: | ---: | ---: |
| 工伤保险费 | 229.20 | 100.00% | 229.20 | 0.00 |
| 企业职工基本养老保险费 | 9,168.00 | 66.67% | 6,112.31 | 3,055.69 |
| 基本医疗保险费 | 1,394.32 | 86.30% | 1,203.30 | 191.02 |
| 失业保险费 | 382.00 | 80.00% | 305.60 | 76.40 |
| 合计 | **11,173.52** | | **7,850.41** | **3,323.11** |

首次使用：

1. 在目标公司的“银行回单导入”点击“设置社保分摊规则”，打开该公司的新规则。也可从“业务控制规则 → 银行回单科目规则”新建。
2. 检查公司、用途“社保分摊”、收支“支出”。按钮预填上述比例及按科目编码查找的 `660208 管理费用－社会保险费`、`122102 其他应收款-社保`、`221101 应付职工薪酬－工资`。第三个科目按现有凭证格式作为计提贷方和支付借方，保留为公司可配置项，**保存后才启用**。找不到科目时须先确认实际科目，不自动新增或替换公司科目。此前已保存的社保规则需补填“社保计提及支付的应付科目”。
3. 设置规则适用的交易日期起止及说明。比例变动时结束旧规则的日期并新增规则；同优先级存在冲突时会停止建议。
4. 返回批次，点击“刷新处理状态”可查看每项险种分摊。点击整批 **确认导入并生成草稿** 时，社保随其他明确业务一起生成五行草稿，不再要求逐笔勾选。
5. 本流程按公司已确认的“回单导入时尚未计提”口径生成计提及支付分录。若某月已通过其他方式计提，必须在月末记账前从“查凭证”修改为实际应付科目，避免重复确认费用。

上述样本所属时期是 `20260801—20260831`，生成**同一张凭证内的五行分录**，先计提、再支付：

| 摘要 | 科目 | 借方（CNY） | 贷方（CNY） |
| --- | --- | ---: | ---: |
| 计提8月公司部分社保 | 660208 管理费用－社会保险费 | 7,850.41 | 0.00 |
| 计提8月个人部分社保 | 122102 其他应收款-社保 | 3,323.11 | 0.00 |
| 计提8月社保 | 221101 应付职工薪酬－工资 | 0.00 | 11,173.52 |
| 支付8月社保 | 221101 应付职工薪酬－工资 | 11,173.52 | 0.00 |
| 支付8月社保 | 100201 银行存款－基本存款账户 | 0.00 | 11,173.52 |

摘要月份取税费明细“所属时期”，记账日期仍取回单交易日期（本例为 `2026-08-21`）。如果 9 月支付 8 月社保，摘要仍写“8月”，不会改为“9月”；跨年补缴时摘要带年份，例如“支付2025年12月社保”。所属时期缺失、日期无效、跨月或各险种月份不同，会停止自动制证，需按原件分期核对后手工制证并关联。

五行的借贷合计均为 22,347.04 元，其中计提和支付各 11,173.52 元；实际银行支出仍只有 11,173.52 元。即使启用“合并相同科目”，此类回单凭证的计提和支付行也分别保留，逐行摘要会保留到会计快照和“查凭证”页面。原流水摘要修复工具也会跳过这些逐行摘要。

已经计提的月份不能再按上述方式重复确认费用，应使用实际应付职工薪酬等科目手工制证后关联回单。混入未知险种、滞纳金等项目时不会套用四险种分摊。比例是该公司的业务配置，不推广为所有公司的法定缴费比例，也不会追改历史凭证。

回单记录保留制证时使用的规则、所属期、逐项分摊、计提支付分录及摘要。预览后规则发生变化时，处理会要求刷新并重新确认。本次只影响后续新生成的草稿，不重写已生成或已记账的历史凭证。

## 去重、失败与修订

- 交易身份为“银行账户 + 交易流水号”；业务编号和回单编号另存。工资与 1 元代发手续费业务编号相同但交易流水不同，保留为两笔。
- 同文件重复上传、重新合并 PDF、与 XLSX 交叉导入均复用同一交易。日期、金额、方向、币种不一致则提示冲突，不覆盖原数据。
- 对同银行账户的处理加锁；回单交易身份有唯一约束。单笔失败会回滚该笔新建的银行交易和凭证，不留下半笔制证。
- 批次“处理完成”表示回单均已关联，不代表凭证全部记账；以每行“凭证待记账 / 已补回单 / 已关联待核销 / 已核销”判断后续操作。
- 回单生成的未记账草稿可以在 Journal Entry 列表的“操作 → 删除所选未记账草稿”中删除。删除会解除回单及银行交易的草稿引用，保留原件、流水和防重身份，并将该笔恢复为“待处理”；返回原批次可重新生成。已记账或已取消凭证保留审计记录，不能直接删除。
- 文件或账户选错、扫描件无法识别：作废尚未处理的批次并填写原因，重新新建。识别失败的批次不可继续制证；部分已经处理的批次须完成剩余核对，不能整批作废。
- 已识别原件不得删除、公开或移动；每次处理重新核验原件哈希。原 PDF 仍保留完整文件，页码和页内位置定位回单，第一期不拆成单页附件。
- 已关联凭证的银行金额和方向不能在草稿中改成与回单不一致。撤销已核销凭证须先按原流程取消银行核销；取消后回单仍保留，显示“凭证已取消或缺失”。在导入行点击“关联修订凭证”，选择原凭证修订链上的新凭证并填写说明；不允许自动再生成一张。
- 已记账的金额、科目、凭证字号和会计快照不因补回单而改变。原件关联不等于已经完成电子档案归档，归档仍按现有流程。

## 月结及对账影响

本期已识别但未处理、待分类或凭证未记账的回单会阻止结转。识别失败批次的日期不可依赖，会阻止该公司结转，须处理或明确作废。只补历史已记账凭证且没有银行交易的记录不会要求额外核销；已有银行交易仍遵循原有对账要求。

回单通常不含期初、期末余额。即使所有回单均处理完成，也不能据此确认整月无遗漏。应继续用银行流水/对账单核对完整性和余额；历史凭证已记账但暂缺流水的月份，只补回单关联即可。
