# 发货估值与项目运费

本次发货成本与采购事实分开保存。确定性装箱解析生成
`extra_json.shipment_valuation`，包含发货数量、单位、币种、金额、公式缓存、
单元格证据和来源版本。采购审批未关联不阻止采用已核实的装箱行价格；
既有采购全额不会被覆盖。历史记录没有发货估值时仍沿用旧成本逻辑。

超队套价只作整组控制，独立核实采购配件单价后逐行估值。缺少来源、
币种矛盾、数量或单位改变会使自动估值失效，不退回采购全额；已确认人工估值保留。

现有海运费规则使用 `scope_value_json.project_allocation` 保存项目毛重策略。
内部成本分摊与承运商体积报价分开，项目及项目内发货行均使用 Decimal
最大余数法，分到分，同余数按稳定身份排序。缺少项目或必要重量会明确报错。
确认的整票项目规则优先于凭证 SKU 分项，凭证分项仍留作证据，不覆盖内部规则。
普通费用保存和后续补凭证保留服务器规则，浏览器不能伪造估值或项目政策。

提交的测试仅包含核实后的最小业务字段，不包含完整审批归档、人员信息或原附件。

## 发布与业务验收

通过现有生产仓库的 Overseas Costing CI/CD 发布。部署后先验证 READY 草稿、
项目汇总及业务快照未变；这不等于已经填充。授权用户仍需点击一次“确认填充”，
再“开始试算”。旧 Dirty 试算折叠在历史区域，不作为当前完整成本。
资料预览、取消均不写物料或费用，不触发正式成本确认或 ERP 推送。
