# 凭证准备与月末记账操作

本次实现的流程：**回单生成草稿 → 查凭证中核对修改 → 未记账试算 → 月末统一记账和损益结转 → 核对正式报表 → 确认结账**。

草稿直接使用 Journal Entry 数据，正式记账后才生成总账、正式字号和中国会计凭证快照。日常修改草稿不会产生会计冲销。已经记账的凭证仍使用受控更正，原有历史和归档继续保留。

## 更新服务器

先通过现有发布方式把这次 `china_finance` 代码发布到实际运行的 backend、worker 及静态资源服务。本地改好代码不代表服务器已经更新。

在已更新的 backend 容器 `~/frappe-bench` 下，先备份：

```bash
bench --site deeplinkerp.com backup --with-files
```

如果之前的银行回单第一期已经安装，可以仅同步本次新增字段、报表元数据和菜单。这条命令不自动启用公司、不生成或提交凭证，也不执行科目模板和历史凭证修复：

```bash
bench --site deeplinkerp.com execute china_finance.setup.preparation.sync_preparation_schema
```

如果服务器尚未安装银行回单第一期，应先按[银行回单导入](银行回单导入.md)更新依赖并执行完整迁移。完整 `bench migrate` 也会安装本次字段，无须再重复执行上述同步命令。

```bash
bench --site deeplinkerp.com clear-cache
```

随后按现有 Docker 部署方式重启 backend 和 worker，浏览器 `Ctrl+Shift+R`。新增脚本由 `china_finance/public/js` 提供，应随应用静态资源一起发布，无需改 ERPNext Banking 前端。

本地 `dev.localhost:8000` 和 `aaa:8001` 已同步本次字段与菜单。同步前后的 Journal Entry、GL Entry、Bank Transaction、China Accounting Voucher 数量一致，没有自动开启任何公司的新模式。

## 首次启用，只设置一次

1. 点击“中国财务”，选择实际记账公司。
2. 打开该公司的“中国财务设置”，勾选 **启用凭证准备与月末记账**。
3. 填写 **凭证准备模式生效日期**，建议选择尚未记账的完整月份第一天，例如从 8 月开始处理新业务，就填 `2026-08-01`。不要为了换操作方式把已记账月份退回草稿。
4. 保存。此日期及之后的 Journal Entry 须核对当前版本后才能记账。已记账历史不变；手工、Excel 导入及银行回单草稿共用新流程。

“查凭证”右上菜单也有“凭证准备模式设置”入口。工作台使用原生记账凭证的读取和报表权限，已记账内容还校验会计快照及来源读取权限；仅授权快照的审计用户仍可通过“凭证明细与历史”入口查阅。核对需要财务经理、会计主管或凭证审核角色；实际记账继续校验原生提交权限和已配置的工作流。需要不同人员审核、记账或确认现金流时，由对应人员接续操作。

## 日常操作

### 1. 导入回单

进入“银行与对账 → 银行回单导入”。新业务选择“新业务制证”，历史已记账业务继续用“历史补回单”。

公司、银行账户等信息完整后，上传 PDF 会保存并自动识别。核对交易笔数、收入和支出合计、原件及建议科目。符合制证条件的记录默认勾选，可以取消不想处理的记录。

社保在同一预览中确认所属期及分摊，并勾选“已核对所属期，该期社保尚未计提”。仍按约定生成一张凭证五行分录；没有确认未计提的记录会留待处理，不会被当作普通费用跳过分摊。

点击 **确认导入并生成所选草稿**。页面显示新增、复用和待处理数量。重复上传或重试不会重新生成已关联的凭证；疑似重复、冲突及缺少科目的记录继续在原页面处理。

点击 **查看本批凭证**，直接进入查凭证并筛选本批次和日期。

### 2. 查凭证与修改

“凭证与结账 → 查凭证”默认显示全部有效凭证，也可筛选未记账、待记账、已记账或已冲销。

点击 **编辑草稿**，在同页面板调整摘要、科目、借贷金额、汇率、往来、成本中心及项目。可增加、删除分录行，保存仍须借贷平衡。原回单可直接从面板打开；银行净收支金额和方向不能改成与原件不符。

日期调整必须填写原因，冻结或已经结转的期间不能通过编辑草稿绕过限制。复杂辅助核算可通过“原件与完整凭证”进入完整表单。预览打印标记“未记账”，打印的是打开编辑面板时已保存的版本，应先保存修改再重新打开预览。

已核对的草稿发生实质改动后，核对版本自动失效。再次记账必须重新核对，服务端也会阻止从原生表单、批量提交或 API 绕过此检查。

### 3. 核对完成与试算

勾选凭证的任意分录行，点击 **核对所选草稿**。同一凭证勾选多行只处理一次。弹窗集中显示分录和现金流项目，确认后标为“待记账”，此时仍未写总账。

启用了现金流直接指定时，核对弹窗会显示现金流建议；没有可靠项目的凭证须先编辑选择项目。记账后系统把已核对的项目对应到实际总账分录，再执行正常现金流确认。公司启用职责分离时，不能由同一人绕过原有现金流指定/确认限制。

点击 **未记账试算**，查看期初、已记账借贷、草稿借贷及预计余额，金额统一为公司本位币。无法通过验证的草稿会列出原因，并标记试算不完整；更早期间的草稿会单独提示，不能悄悄计入期初。

正式财务报表仍读取实际已记账数据，并提示当前期间另有多少草稿没有计入。基础版本没有把未记账凭证混入三大报表。

## 月末操作

1. 从查凭证点击 **月末处理**，或打开中国财务菜单中的“月末处理”，选择一个完整自然月。无需先手工生成损益结转凭证。
2. 点击 **检查并统一记账**。系统检查本期回单、全部草稿的核对版本、权限及必要配置；更早期间尚有草稿时需要先处理。
3. 页面逐张显示记账进度，按日期取正式字号，生成正式快照。随后处理回单核销、现金流项目和损益结转。已有业务数据或现金流指定存在问题时，会暂停并显示原因。
4. 状态到“待确认结账”后，点击 **核对正式报表**。确认结果后点击 **确认结账**，生成报表快照并按公司设置冻结期间，归档在后台生成。

当月正式记账前的修改不会冲销；开始统一记账后，已经成功记账的凭证不再作为普通草稿修改。

### 中途失败、关闭页面或重复点击

- 每一步保存进度；关闭页面后，重新打开同一张月末处理单并继续。
- 处理进行中会锁定本期相关写入。需要调整剩余草稿或重新导入时，点击 **暂停处理**，修正、重新核对后继续。
- 失败不会自动取消已经成功记账的凭证；重试跳过已完成部分，不重复提交、取号或核销。
- 如果损益结转已提交后台任务，暂停不会撤销该任务。遇到结转总账失败，先处理原结转凭证的错误，再继续月末处理。
- 后台总账尚未完成时不会允许结账。归档未就绪时页面单独提示，可刷新或点击 **重试归档**。
- 不要为重试同一月份另建多张月末处理单；继续原处理单即可。一个公司同时只允许一个统一处理任务。

## 范围说明

- 采购/销售发票、付款单等原生业务单据继续保留现有提交记账行为。补回单时关联这些已存在单据，避免再生成一张记账凭证。
- 草稿使用临时编号。正式字号在记账时生成，同批按日期和稳定次序取号；历史字号不自动重排，多批记账或后来补录较早日期的凭证不能保证全月字号严格按日期重排。
- 查凭证默认折叠旧冲销记录，通过状态筛选可继续追溯。已记账或已结账凭证的更正仍需走原来的受控流程。
- 功能只按公司启用；同步代码和字段不会自动变更历史凭证、金额、科目或归档。
