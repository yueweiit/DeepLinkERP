# 旧财务凭证清理操作手册

本文记录 `china_finance` 按公司核查、备份和清理历史测试财务凭证的方法，以及 2026-09-20 在 `deeplinkerp.com` 上实际完成的操作。该次清理已返回 `status: removed`，用户确认系统正常；下方命令供以后维护参考，无需为本次结果再次执行删除。

## 1. 适用范围与处理结果

适用于已确认可永久删除的测试财务凭证。工具根据保存的原始预览限定范围，保留基础资料及范围外业务；它不是清空整个公司业务数据的工具，也不代替正式账务的取消、核销或更正流程。

| 数据 | 处理方式 |
|---|---|
| 已取消的 Journal Entry / Payment Entry | 从原始预览中选择，复查后清理 |
| 草稿、已提交来源凭证及 Period Closing Voucher 来源单据 | 保留，不自动取消或删除 |
| 所选来源对应的中国会计凭证、冲销快照、现金流指定、同步异常及子表 | 检查关联后随来源清理 |
| 来源已经不存在的中国会计凭证 | 默认保留，符合条件时通过 `include_orphan_snapshots:1` 纳入 |
| 所选来源的总账、支付分类账 | 按账目状态及业务引用检查；有效总账或不符合条件的支付余额会阻止清理 |
| 取消后出现一侧已解除关联、另一侧仍有效的支付分类账 | 默认阻止；符合严格配对条件的测试残留可通过 `include_cancelled_ledger_residue:1` 纳入 |
| 科目、客户、供应商、银行账户、财务设置、报表模板、科目映射 | 保留 |
| 银行交易、范围外订单、发票、库存、工资及资产等业务 | 不纳入删除；有未处理的业务引用时返回阻塞项 |
| 附件文件、审计记录 | 保留文件内容，将可识别的关联转到删除归档 |
| 站点命名序列及公司期间凭证字号 | 不重置，新凭证继续使用后续编号 |

命令仅允许 System Manager 通过 bench 调用，没有网页删除接口，不会在迁移或定时任务中自动执行。清理工具的代码不涉及新增字段、数据库补丁或前端资源，无需为这些命令额外运行 migrate 或前端构建。

### 2.1 两个命令的区别

| 方法 | 用途 |
|---|---|
| `china_finance.services.finance_cleanup.preview_finance_cleanup` | 只读盘点公司的来源凭证和关联，生成原始预览文件 |
| `china_finance.services.cancelled_finance_cleanup.cleanup_cancelled_finance` | 读取原始预览，复查并生成清理计划；仅 `apply:1` 时实际删除 |

清理命令参数：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `company` | 必填 | Company 单据的准确名称，必须与原始预览一致 |
| `preview_file` | bench 根目录的 `finance-cleanup-preview.json` | 本文始终显式指定站点私有目录中的原始预览 |
| `apply` | `0` | `0` 只预览，`1` 执行删除 |
| `include_orphan_snapshots` | `0` | 纳入符合检查条件的无来源中国会计凭证 |
| `include_cancelled_ledger_residue` | `0` | 纳入符合严格配对条件的取消后支付分类账残留 |

`preview_file` 支持绝对路径；相对路径始终相对于 bench 根目录。bench 内部会切换到 `sites` 目录，工具已处理这一差异。传给 `--kwargs` 的开关使用数字 `1` / `0`，当前 bench 使用 Python 表达式解析，小写 JSON `true` / `false` 不能直接照抄到参数中。

## 3. 操作步骤

### 第一步：生成原始预览

先将包含清理工具的应用代码更新到服务器实际运行的容器。本次完整功能包含 `20337f3`、`dad6202`、`828fe8c` 三次提交。

```bash
bench --site deeplinkerp.com execute china_finance.services.finance_cleanup.preview_finance_cleanup --kwargs '{"company":"YUEWEI CN悦为中国"}' > sites/deeplinkerp.com/private/finance-cleanup-preview.json
```

成功时终端没有输出，因为结果写入文件。查看摘要：

```bash
python -c 'import json; d=json.load(open("sites/deeplinkerp.com/private/finance-cleanup-preview.json")); print(json.dumps({k:d.get(k) for k in ["mode","site","company","source_counts","related_counts","blockers"]},ensure_ascii=False,indent=2))'
```

原始文件应包含 `mode: preview_only`，且站点、公司正确。`docstatus` 的 `0`、`1`、`2` 分别表示草稿、已提交、已取消。

省略日期会核查该公司的全部日期和全部状态。若只核查某个期间，可在第一条命令的 `--kwargs` 中增加 `"from_date":"2026-07-01","to_date":"2026-07-31"`；只看已取消来源时增加 `"cancelled_only":1`。不要在生成清理计划后随意覆盖原始预览，否则范围可能变化。

### 第二步：核对清理计划

下面使用的是本次已核实的两个特殊开关。其他批次应先按第 4 节判断是否适用；无需处理对应数据时省略开关或设为 `0`。

```bash
bench --site deeplinkerp.com execute china_finance.services.cancelled_finance_cleanup.cleanup_cancelled_finance --kwargs '{"company":"YUEWEI CN悦为中国","preview_file":"sites/deeplinkerp.com/private/finance-cleanup-preview.json","include_orphan_snapshots":1,"include_cancelled_ledger_residue":1}' > sites/deeplinkerp.com/private/finance-cleanup-plan.json
```

查看清理计划摘要：

```bash
python -c 'import json; d=json.load(open("sites/deeplinkerp.com/private/finance-cleanup-plan.json")); print(json.dumps({k:d.get(k) for k in ["site","company","status","delete_counts","preserved_sources","preserved_other_snapshots","cancelled_ledger_residue","blockers"]},ensure_ascii=False,indent=2))'
```

确认 `status: ready`、`blockers: []`，并核对 `delete_counts`、`delete_names` 及保留项符合目标范围。此时尚未删除。若需要直接查看结果，可去掉命令末尾的 `> ...` 文件重定向。

原始盘点和清理计划的范围不同：原始盘点会列出草稿、已提交来源及其业务引用；清理计划只选取允许清理的记录。本次草稿付款单关联销售订单，因此原始盘点有阻塞提示；该草稿被保留后，不阻止最终清理计划。

### 第三步：进入维护模式并备份

停止用户录入、接口导入及外部脚本写入。开启维护模式，等已有请求及后台任务结束，再备份：

```bash
bench --site deeplinkerp.com set-maintenance-mode on
```

```bash
bench --site deeplinkerp.com backup --with-files
```

备份输出应列出 `Config`、`Database`、`Public`、`Private`，并以如下内容结束：

```text

```

记录备份文件位置。备份失败时不继续删除，结束本次维护时执行第五步关闭维护模式。

维护模式阻止调度器为该站点继续入队新任务，但不会自动终止已运行任务或外部脚本。清理命令也会检查站点排队及运行中的后台任务；若仍有任务，待其结束后重新备份，再执行清理。

### 第四步：执行实际清理

使用与第二步完全一致的公司、原始预览路径和范围开关，增加 `"apply":1`。以下命令会实际删除通过检查的记录：

```bash
bench --site deeplinkerp.com execute china_finance.services.cancelled_finance_cleanup.cleanup_cancelled_finance --kwargs '{"company":"YUEWEI CN悦为中国","preview_file":"sites/deeplinkerp.com/private/finance-cleanup-preview.json","include_orphan_snapshots":1,"include_cancelled_ledger_residue":1,"apply":1}'
```

命令会再次检查当前状态，不能因为之前 `ready` 就跳过检查。保存终端返回的结果，重点核对：

| 返回字段 / 状态 | 含义 |
|---|---|
| `status: removed` | 删除已完成 |
| `status: blocked` | 发现阻塞项，本次整批未删除 |
| `status: nothing_to_remove` | 当前原始预览范围内没有剩余可删记录，不代表公司全部业务为空 |
| `delete_counts`、`delete_names` | 本次处理的数量和编号；预览或阻塞时只是候选清单 |
| `preserved_sources` | 保留的来源凭证 |
| `record_backup` | 删除前自动生成的记录级导出文件位置 |
| `deleted_document_records` | 对应的删除归档编号 |

仅无报错或退出码为零，不足以判断删除成功，应以 `status` 为准。异常会回滚本次数据库修改；即使已经生成记录导出文件，也不能据此认定删除成功。

### 第五步：关闭维护模式

无论清理成功、被阻止，还是备份/清理报错，只要本次维护结束，都要执行：

```bash

```

## 4. 两个特殊清理开关

### 4.1 无来源会计凭证

`include_orphan_snapshots:1` 只选择原始预览中 `source_exists: false`，且来源类型是 Journal Entry、Payment Entry 或 Period Closing Voucher 的中国会计凭证。执行时复查来源仍不存在、公司及快照关键字段未变。

缺失来源仍有总账、支付分类账、预付款分类账或库存分类账时，整批阻止。来源恢复、来源编号为空、范围外业务引用或跨公司关联也会阻止。发票、库存等其他来源的会计凭证不会被该开关自动纳入。

本次额外 86 张中国会计凭证全部指向已不存在的 Journal Entry，其中 78 张已提交、8 张已取消。它们与另外 7 张关联快照合计为实际清理的 93 张。

### 4.2 支付分类账残留

常规情况下，已解除关联的支付分类账可纳入清理；未解除关联的取消对冲记录，须按日期、来源凭证、科目、往来、关联凭证、币种、成本中心、项目及财务账簿分组后，本位币和账户币金额均为零。

本次 40 条支付分类账中，20 条 `delinked=1`，20 条 `delinked=0`。每组金额相反，但一侧已解除关联，另一侧仍参与有效余额计算。例如同一凭证的 `+830.86` 已解除关联，`-830.86` 仍有效。这会形成残留，不能按“正负合计为零”直接放行。

`include_cancelled_ledger_residue:1` 针对这种已确认的测试残留，要求同时满足：

- 来源是原始预览中选定、当前仍为已取消状态的 Journal Entry。
- 不存在该来源的任何总账记录，没有客户或供应商等往来单位。
- `against_voucher_type` / `against_voucher_no` 仅引用自身来源。
- 在同一日期、科目、币种及上述维度内，两侧按分录行编号、账户类型、到期日、本位币金额和账户币金额逐笔反向精确配对，数量也相同。
- 没有范围外业务引用、跨公司关联或其他阻塞项。

`cancelled_ledger_residue` 列出配对分组、两侧行号、原有有效金额和 `included` 标志。清理会移除当前仍有效的测试残留；不能解释为这些记录在删除前就没有余额。

需要进一步核查时可执行以下只读查询：

```bash
bench --site deeplinkerp.com execute frappe.get_all --kwargs '{"doctype":"Payment Ledger Entry","filters":{"company":"YUEWEI CN悦为中国","voucher_type":"Journal Entry"},"fields":["name","posting_date","voucher_no","voucher_detail_no","account_type","due_date","against_voucher_type","against_voucher_no","account","party_type","party","amount","account_currency","amount_in_account_currency","delinked","cost_center","project","finance_book"],"order_by":"voucher_no,posting_date,name","limit_page_length":0}'
```

## 5. 常见问题

| 现象 | 原因和处理 |
|---|---|
| `SITE does not exist` | 把示例占位符 `SITE` 当成站点名了；本次实际站点是 `deeplinkerp.com`，其他环境以实际站点目录为准 |
| `Got unexpected extra argument` 或 `bash: --kwargs: command not found` | 换行、反斜杠后空格或重复粘贴造成命令拆开；按 `Ctrl+C` 清空当前输入，再复制完整单行命令 |
| 文件名变成 `.jsonjson`、`.json_` | 粘贴时混入了多余字符；核对生成路径与读取路径完全一致 |
| `FileNotFoundError: ...finance-cleanup-preview.json` | 原始预览未生成、路径不一致，或容器重建导致根目录文件丢失；按第一步在站点私有目录重新生成，再核对新计划 |
| `JSONDecodeError: Expecting value` | 文件为空、只有空白或不是合法 JSON；查看上一条命令的报错，必要时去掉重定向直接运行只读命令，不要继续执行删除 |
| 末尾 `NameError: name 'china_finance' is not defined` | 本次是 bench 捕获前一个异常后再次求值导致的次级报错；从第一段 Traceback 找真正原因，例如前面的 `FileNotFoundError` |
| `ModuleNotFoundError` 或参数不识别 | 服务器实际运行的应用代码尚未包含对应功能，核对部署版本及容器 |
| `status: ready` | 只是计划通过，未执行删除；只有带 `apply:1` 的命令返回 `removed` 才算成功 |
| `status: blocked` | 查看 `blockers`；即使有 `delete_counts` 也没有删除，不能去掉保护检查强行执行 |
| 提示维护模式未开启 | 执行第三步进入维护模式，再确认备份 |
| 提示有排队或运行中的任务 | 等任务结束，重新备份，再执行；结束维护时关闭维护模式 |
| 来源凭证已变化，或已删除但仍有残留关联 | 重新盘点并核对范围；不要编辑 JSON 来绕过检查 |
| 清理后列表为空，但新凭证编号不是从 1 开始 | 正常，工具不重置编号，避免与历史或其他业务冲突 |
| 清理后仍显示维护页面 | 执行第五步关闭维护模式，再刷新页面 |

原始预览文件的 `mode` 是 `preview_only`；清理计划是另一个文件。不要把 `finance-cleanup-plan.json` 当成 `preview_file` 输入。

## 6. 归档、恢复与检查边界

删除前，工具将完整父子记录及可识别审计记录导出到站点 `private/backups/cancelled-finance-*.json`，权限为 `0600`；同时写入 `Deleted Document`。File、Comment、Communication、ToDo、Version 的已识别关联转到对应删除归档，附件文件内容保留，原共享授权不转移到删除归档。

所有数据库变更在同一事务中完成，异常整批回滚。失败前生成的导出文件会保留供诊断；记录级导出保存的是删除前数据，不是成功回执。恢复应以执行前的完整站点备份为依据，先在恢复副本核对数据库和附件，再安排切换；不要逐张恢复来源、总账或快照造成部分恢复。

工具检查静态、动态及自定义关联字段，包括已取消引用，遇到有效总账、范围外业务、银行核销、跨公司关联、冻结期间或已提交后续损益结转时阻止清理。它不会全面识别 JSON/文本内的历史报表快照或其他模块内部状态，因此仍需执行后的业务复核。

单次查询超过 10,000 条时明确报错，不截断清单继续删除。日期筛选主要限定来源，关联的冲销快照可跨期；后续修订单不会自动扩入范围。原始预览之后新增的来源凭证也不会自动加入。
