# 旧财务凭证清理预览

适用于指定公司旧财务凭证的范围核查。当前提供**只读预览**，没有删除入口，也不在迁移或定时任务中自动运行。

在服务器的 bench 目录执行，替换 `SITE` 和公司全称：

```bash
bench --site SITE execute china_finance.services.finance_cleanup.preview_finance_cleanup \
  --kwargs '{"company":"公司全称"}' > finance-cleanup-preview.json
```

省略日期表示预览该公司所有日期的记账凭证、收付款凭证和损益结转凭证，**不表示已批准删除这些记录**。只有 System Manager 可以调用。

限制日期或仅查看已取消来源凭证：

```bash
bench --site SITE execute china_finance.services.finance_cleanup.preview_finance_cleanup \
  --kwargs '{"company":"公司全称","from_date":"2026-07-01","to_date":"2026-07-31","cancelled_only":true}' \
  > finance-cleanup-preview.json
```

日期筛选针对来源凭证，损益结转使用期间截止日期。对应的冲销快照即使日期在范围外、状态仍为已提交，也会列入关联信息。已取消凭证的后续修订单不会被自动扩入范围。

## 本次服务器核查

已确认目标公司为 `YUEWEI CN悦为中国`，范围为全部旧财务凭证及关联，目标凭证均为可删除的测试数据。基础配置和其他业务仍须保留，相关业务引用以服务器预览结果为准。

本次新增的是 Python 只读命令、测试和文档，没有新增数据库字段、迁移补丁、前端资源或第三方依赖。代码进入服务器实际运行的 `china_finance` 应用目录后，即可在该环境的 bench 目录执行。仅运行本预览命令不需要额外执行 migrate 或前端构建；已有部署流程可照常使用。

将 `SITE` 替换成服务器真实站点名（不一定与访问域名相同）：

```bash
bench --site SITE execute china_finance.services.finance_cleanup.preview_finance_cleanup \
  --kwargs '{"company":"YUEWEI CN悦为中国"}' > finance-cleanup-preview.json
```

不传日期或 `cancelled_only`，会核查全部日期、全部状态的来源凭证。命令不会实施删除。检查生成的 JSON 中 `source_counts`、`related_counts`、`blockers` 和其他来源凭证清单后，再确定关联记录的具体处理方式。若提示公司不存在，以服务器 Company 单据的准确名称为准，不要改成模糊匹配。

## 查看结果

| 字段 | 含义 |
|---|---|
| `site`、`company`、`scope` | 实际查询站点、精确公司和筛选范围 |
| `source_counts`、`sources` | 来源凭证数量、状态和编号，docstatus 0/1/2 分别为草稿/已提交/已取消 |
| `related_counts`、`related_records` | 对应总账、支付分类账、会计快照、现金流指定单、同步异常、结转处理及报表快照；仅用于核查，不代表自动删除 |
| `bank_transactions_to_preserve` | 涉及的银行交易，默认保留原始银行记录 |
| `bank_allocations_to_review` | 涉及银行交易的全部核销行，标明哪些属于所选凭证，便于识别共享核销 |
| `blockers` | 范围外引用、跨公司关联、发票等业务引用、冻结期间及后续结转 |
| `other_accounting_vouchers_to_preserve` | 其他来源或找不到来源的中国会计凭证，单独核查，不自动删除 |
| `audit_and_attachment_links` | 可识别的附件和审计引用，保留文件内容 |
| `attachments_to_preserve` | 直接附在来源或关联单据上的文件，保留内容和当前关联 |

预览包含静态、动态及自定义关联字段，也检查已取消引用。JSON/文本内的历史快照以及业务模块内部状态仍需人工核查；`blockers` 为空不代表可以绕过业务流程直接删除。

单次查询超过 10,000 条会明确报错，不截断后声称清单完整。关联记录数量过大时也会停止，需针对实际数据另行分批。

## 后续清理边界

先确认公司名称、日期范围，以及凭证确为可永久删除的测试数据。实际执行前备份数据库与 public/private 附件，在恢复副本验证，并停止相关录入、导入和后台补建/结转任务。

- 保留科目、客户、供应商、银行账户、财务设置、报表模板及科目映射。
- 发票、库存、工资等业务产生的凭证，沿来源业务核查，不能只删总账或会计快照。
- 银行核销只解除目标凭证的分配，不能误清同一银行交易上其他凭证的核销。
- 按依赖关系处理修订、冲销、现金流指定、结转及快照；冻结期间和后续结转须先确定重新开账范围。
- 已核销发票、资产、库存、跨公司业务有引用时先处理业务状态，不能用强制删记录掩盖关联。
- 不重置 `CNV`、记账凭证等站点命名序列；部分清理不重置公司期间凭证字号。
- 清理后检查残留引用、借贷平衡、银行未核销金额及保留业务的余额。只删中国会计凭证而保留来源与总账，定时任务可能再次补建。

服务器预览是确定实际删除方案的依据。当前代码不会执行上述删除操作，也未包含 `apply` 或强制删除参数。
