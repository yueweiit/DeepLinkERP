# 采购支出统一来源与 DeepSeek 接入

用户确认的 2026-09-10 实施口径，替代此前装箱仍从国际物流采用的设计。

- 已确认一对一关联时，装箱、SKU、数量、物理量、运费、正文、评论和附件均由采购支出形成；候选不切换。
- 缺资料、读取失败、待审批和审批失效均不恢复国际物流。历史记录和人工原始值保留，但不参与当前核算。
- 明确商品单价（含零）优先；仅完全缺少商品价时，使用独立商品采购价格证据。物流计费单价不是商品价。
- 统一服务端 source_context 约束读取、推荐、缓存、导入、AI 请求、预览和写入。旧任务在关联、快照或策略变化后失效。
- 已确认版本冻结；新来源即使未齐资料也形成唯一待补调整稿。采用关系、费用、物料与版本原子写入，编辑锁期间排队。
- 现有新版工作台展示当前来源及原单入口；不另建页面。装箱快照序号不改变原义，另加成本版本引用。
- 基线包含线上 af71d9e30317eaa2077e71ec2527c75a87c3c136（本次已核对远端）。仅隔离站点验证；不自动上线、历史全量初始化或 ERP 推送。

## 验收重点

## 已执行的验收与真实样本边界

隔离站点为 `settlement-test.local`（数据库 `oc-settlement-test-db`），本机端口 64116；原演示站点 64115 的 8 批次、8 版本、300 物料未修改。已执行完整 Frappe 迁移，确认成本版本和装箱快照新增字段；策略升级在隔离库完成 66/66 已绑定批次，无失败。生产站点未迁移、未初始化、未推送 ERP。

三个真实 Frappe/MariaDB 集成脚本分别验证了关联并发与事务回滚、私有附件与冻结版本及双币六位尾差、实际 XLSX 文件到签名预览/完整货物采用/正式试算的完整链路。实际 XLSX 用例运行 `a436546207`：采购支出新清单采用 6 件、12 kg、3 m³；独立原采购数量 2、原装箱重量 888 和原商品价证据保持不变，当前货值为 60.000000。来源评论更新后，旧预览被拒绝且物料未变。

浏览器在当前新版工作台完成同一 XLSX 的选择、读取工作表、原表预览、完整清单确认和采用，最终试算总成本 60.000000 RMB；确认前可查看本次全部来源行。来源更新后，旧物料明确标记历史，当前数量/重量/货值清空待补，旧试算折叠为历史。损坏附件不再阻断普通资料清单。普通页面查询不打开工作簿；只有显式预览才按权限读取当前私有文件。

DeepSeek 测试捕获了真正组装并传给 `_call_chat_completions` 的请求参数，检查正文、评论、附件、字段上下文均为当前采购支出；独立商品采购证据仅用于价格。测试不依赖模型生成内容，未调用外部模型。浏览器旧导入路径曾自动创建隔离 AI 排队任务（0%、资料均未读取），已通过“放弃任务”结束；完整采购支出采用现已无需强制再启 AI，原“自动填充资料”按钮保留。取消窗口仍保留草稿，新增明确的放弃操作；放弃后的迟到 worker 不能恢复任务。

最终本地回归：`python3 -m pytest overseas_costing/tests -q` **1,985 passed，8 skipped**。跳过项为需要独立 PostgreSQL DSN 的可选归档适配器集成测试，不代表当前生产 v2 视图已部署。Python 编译、Node 页面脚本语法、镜像 DocType 一致性和 `git diff --check` 通过。独立复审另运行 54 项针对性测试并复现 Wiki 并发、更新后核算阻断和冻结历史，限定范围内无剩余阻断。

真实只读归档样本 `MXT500174`：审批通过，物流及运输服务/海运费用，总额 **13,068 RMB**。正文 46 件、3.96 方、3300 元/方是物流计费依据；两项目金额 7953.92 与 5114.08 合计为整单金额，不能再次加总。已修复真实双语字段“金额importe”的解析，并加入回归。

真实样本的两份 XLS/XLSX 附件尚未归档，上游该流程 `archive_attachments=false`，归档 v2 视图也尚未部署。相似国际物流审批缺少可证明唯一对应的标识，因此没有强行确认关联。此样本已覆盖业务分类、金额、计费价与评论形态；真实附件内容、唯一匹配以及完整货物/同编码多行/数量差异/双清的端到端核对仍需上游归档就绪后补验。其余边界由构造数据与隔离实库测试覆盖，不应称为已完成生产真实样本验收。
