# 凭证批量提交与字号修复

适用于按月份导入凭证后，因批量提交顺序与凭证日期不一致，出现早期凭证为“记12”、较晚凭证却为“记1”的情况。

## 原因与本次修复

字号在记账时生成，按公司、年度、月份和凭证字分别递增。原批量操作直接使用列表勾选顺序；列表通常按最近修改时间倒序，导入较晚的记录反而先提交，所以字号和日期不一致。

更新后，普通批量提交、工作流批量操作及“批量审核并记账”都会先按凭证日期升序处理。同一天按来源单据创建时间、单据编号排序；期末结账批次按期间结束日期排序。原有权限检查、工作流、后台任务及失败处理保持生效。

这是同一批次的排序：分批提交、补录更早日期、并发记账或部分提交失败，仍可能产生日期与字号不完全连续的情况。程序不会在日常记账或更新代码时自动重排已经生成的正式字号。

“查凭证”原来的金额列没有绑定本位币，使用系统默认币种，可能显示 `$`。现在每行分录读取会计凭证的本位币；历史快照未记录币种时使用公司本位币。人民币显示为 CNY 或人民币符号，取决于站点的币种格式设置，不进行汇率换算。

## 1. 发布修复

使用现有自定义镜像发布流程更新 `china_finance`，确保 backend 和 worker 使用同一版本并重启相关服务；宿主机只拉代码不保证运行容器已更新。发布过程中按既有流程执行 migrate/清理缓存，让新 hook 生效。

刷新浏览器并重新运行“查凭证”。如果页面显示之前生成的报表，应重新生成结果，不能只查看缓存。该修复没有修改公司或站点的默认币种。

## 2. 预览已生成字号的修复

以下命令在服务器 backend 容器的 `~/frappe-bench` 内执行。以此次新公司 2026 年 5 月为例，整行复制：

```bash
bench --site deeplinkerp.com execute china_finance.services.voucher_number_repair.reorder_monthly_voucher_numbers --kwargs '{"company":"悦为智能技术（东莞）有限公司","accounting_period":"2026-05"}'
```

默认只预览，不修改数据。查看：

- `site`、`company`、`accounting_period`：应是此次服务器新公司和 5 月。
- `voucher_count`：如仅导入了 5 月普通凭证且尚未结转，应为 14；已有其他同月凭证则包含在内。
- `can_apply`：应为 `true`。
- `blockers`：应为空。
- `changes`：逐张列出来源单据、日期、旧字号和新字号。
- `plan_hash`：本次预览的校验值，实际执行时需要使用。

修复范围是指定公司、整个月份、指定凭证字（默认“记”）下的正式凭证，包含 Journal Entry、Payment Entry 和 Period Closing Voucher。按来源日期、来源创建时间、来源编号重排；期末结账凭证排在该月普通凭证之后。复用本月原有号码集合，不填补历史断号、不降低序列计数，也不处理其他月份或其他公司。

工具面向刚导入的、尚未归档的账。存在已取消/冲销、修订链、来源缺失、字号异常、冻结或已封账期间、关联电子档案时会返回阻塞项，不应绕过这些检查。

## 3. 备份后执行

确认预览涉及的全部凭证均应重排。操作期间暂停该公司该月的导入、提交、取消、修改及归档，先做备份：

```bash
bench --site deeplinkerp.com backup --with-files
```

把下面的 `替换为预览返回的plan_hash` 替换为上一步输出的完整校验值，再执行整行：

```bash
bench --site deeplinkerp.com execute china_finance.services.voucher_number_repair.reorder_monthly_voucher_numbers --kwargs '{"company":"悦为智能技术（东莞）有限公司","accounting_period":"2026-05","apply":1,"expected_plan_hash":"替换为预览返回的plan_hash","reason":"修复初次导入凭证批量提交顺序导致的字号倒序"}'
```

如果预览后凭证或流水号发生变化，会提示重新预览。成功返回 `applied: true`。

更新内容是会计凭证的字号、流水号和唯一键，以及来源单据展示的字号；来源和快照均记录旧字号、新字号、批次及原因。所有交换在同一事务中完成，失败时回滚。不会取消并重新提交凭证，也不会改动总账、会计分录、金额、日期、内部单据编号和现金流量指定关联。

## 4. 检查结果

再次执行第 2 步，正常应为 `changed_count: 0`。刷新记账凭证列表，重新运行“查凭证”，核对日期与字号；借贷金额及合计应保持一致。本月后续凭证继续使用原计数器与现有最大号之后的号码。

如果已输出尚未归档的打印件或导出文件，应重新生成，让纸面字号与系统一致。6 月、7 月如已有同样问题，各自预览并处理，不要将月份改成其他公司的会计期间。
