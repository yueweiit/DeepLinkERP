# 币种显示统一修复

适用于公司本位币为 CNY，但凭证、报表或打印页面金额显示为 `$` 的情况。本次检查范围是 `china_finance` 应用，不修改 ERPNext/Frappe 的全局金额格式器。

## 原因

Frappe 的 Currency 字段需要指定币种来源。金额字段没有配置 `options`，或页面没有提供对应的币种值时，会回退到系统默认币种；默认值为 USD 时就显示 `$`。因此只修复“查凭证”的报表列，不能同时修好凭证表单、子表、列表、弹窗和打印格式。

此次为应用内 18 类单据/明细的全部 54 个 Currency 字段检查并补齐币种绑定，同时修正报表、自定义金额提示和打印入口。

## 修复后的口径

| 金额所在位置 | 使用的币种 |
| --- | --- |
| 会计凭证借贷金额、合计、法定报表、科目映射控制台 | 公司/凭证本位币 |
| 会计凭证“借方/贷方（科目币种）” | 分录记录的科目币种 |
| 税务发票、销售结算、开票申请、进项抵扣批次 | 对应单据或来源单据币种 |
| 销售/采购发票金额 | 发票币种 |
| 发票未收/未付金额 | 往来科目币种 |
| 银行对账的账面期初、本期及期末金额 | 公司本位币 |
| 银行快照、银行未达、银行流水及其差异 | 银行科目币种 |
| 客户/供应商对账金额及差异 | 公司本位币 |

人民币通常显示 `¥`，币种字段或打印页脚显示 `CNY`；符号形式由站点 Currency 格式设置决定。原币为 USD 的金额仍然显示美元符号，不能将全部金额统一替换成 CNY。

覆盖的入口包括：记账凭证表单及明细、列表、查凭证及撤销核销提示、财务报表、科目映射控制台、税务台账与申报底稿、采购/销项对账、业务单据链、银行及往来对账、差异登记弹窗、销售结算自定义字段、A4/A5 凭证打印和报表打印。

### 合计与历史数据

- 单一币种报表保留原有合计；同一金额列出现不同币种时，页面提示并停用跨币种总合计。税务申报底稿按币种分别分组。
- 同一采购订单关联多个币种的发票时，订单汇总视图要求切换到采购发票视图逐张核对。销项税票分摊包含多个币种时要求核对；发票与单一税票币种不同会标记异常，金额分别显示各自币种。
- 开票申请和抵扣批次按来源确定币种，不能将不同币种混为一个金额合计；需要按币种分别建单。
- 升级补齐历史单据缺失的币种字段，以及银行快照和明细的币种；保留已有单据币种。无法确定的来源或混币历史申请/批次会记录到 Error Log，标题为“历史财务单据币种需要核对”，需核对后处理。
- 此修复不做汇率换算，不修改分录金额、正负号、总账、日期、凭证字号或借贷方向。补齐币种的升级脚本保留原修改时间。
- 已保存的 PDF、Excel、邮件附件及归档文件不会被重写。需要新的展示结果时重新生成；已归档材料按现有档案管理流程处理。

## 服务器更新

服务器站点为 `deeplinkerp.com`。先通过当前自定义镜像发布流程把修复代码更新到 backend、worker 等运行容器；如果静态资源在构建镜像时生成，一并更新构建产物。宿主机拉取代码不代表容器已经更新。

按现有发布流程备份后，在 backend 容器的 `~/frappe-bench` 目录执行以下命令，每条整行复制：

```bash
bench --site deeplinkerp.com migrate
```

```bash
bench --site deeplinkerp.com clear-cache
```

`migrate` 会同步字段定义，执行 `v0_6_23.bind_financial_currencies` 历史币种补齐脚本，并通过现有 after_migrate 更新应用维护的自定义字段和打印模板。不能只清理缓存而跳过迁移。

按当前 Docker 发布流程重启相关服务，然后浏览器使用 `Ctrl+Shift+R` 强制刷新。报表重新运行查询；旧的缓存结果和已生成文件不会自动变成新结果。无需取消、重提或重新导入凭证。

## 验收

1. 打开原来显示 `$` 的人民币会计凭证，核对借方、贷方、合计和明细弹窗；金额与原始凭证一致，币种为 CNY/人民币符号。
2. 查看凭证列表、查凭证、财务报表和科目映射控制台，再打印 A4/A5 凭证，确认这些入口一致。
3. 新建或打开银行对账单，检查本位币、银行账户币种和差异登记弹窗；若使用外币银行，账面本位币金额与银行原币金额应分别显示。
4. 存在外币发票或外币科目时，核对其原币金额仍为相应币种；混币报表不出现将不同币种直接相加的总合计。
5. 检查 Error Log 中是否有上述历史币种核对记录。
