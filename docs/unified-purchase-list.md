# 采购订单与 OA 统一列表

## 已批准范围与复用

以 `origin/deeplinkerp_branding` 的 `d7e83ae716a215d8651f9faf6837651f007bf04f` 为基线。复用现有紧凑列表引擎、列/密度偏好、分页、原生 PO 表单和 Excel 下载传输；不新增第二个采购页面。不修改海外成本核算、MES 集成或 OA 同步应用。

默认 `/desk/purchase-order` 显示“全部采购”，可切换“仅订单”“仅 OA”。统一视图仅查看，OA 行不进入原生 PO `list.data`、勾选、工作流或批量操作。切回“仅订单”恢复原筛选、列偏好、选择和原生动作。

关联只读取 PO `custom_oa_purchase_expense`、OA `purchase_order` 明确关系，不使用单号或名称猜测。关联双方只显示一个 PO 行；未转换的 OA 单独显示。冲突时保留每张可见 OA 的来源链接、原审批状态、原精度金额、币种与口径，不强行合并金额。隐藏原 OA 列表导航入口，但保留原表单、深链接、钉钉同步及数据；没有 PO 读取权限的 OA 用户保留原入口。

订单金额、OA 申请金额、已预付分别展示各自币种。OA 金额优先采购明细合计，再处理人确认总额、再付款金额。缺少权限时不推断不可见值；币种未知不推断 CNY，也不纳入合计。公司区分已知、待确认、不可见，待确认筛选不包含权限隐藏的公司。禁止回填历史零金额或自动转订单。

## 实施与兼容退出

- 新增只读 `get_unified_purchase_list`、`export_unified_purchase_list`，查询/计数/合计/导出共用同一权限和筛选管道。
- 引擎仅增加可选 provider。物料需求及原生 PO 路径不更换查询协议；统一记录独立保存，避免原生单据选择与增量刷新误用。
- 新增轻量 PO/OA 适配器；OA 表单继续作为追溯入口，不复制表单和同步逻辑。
- Excel 复用当前下载传输，统一视图由服务端返回安全 XLSX，公式/URL 不执行；数值及来源 JSON 保留原精度。导出不受当前页限制，金额列即使隐藏币种列也补出其币种。
- 保留 OA 旧路由不是永久第二入口：只有用户另行批准历史链接/同步迁移后才可移除。当前没有删除文件或业务记录。
